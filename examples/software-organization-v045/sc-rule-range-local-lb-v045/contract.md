# Bounded rule interval maintenance

Maintain rules.evaluate(rule,document). Repair the between operator boundary and nested error location while retaining all legal v1 behavior.

v1 rules are exact-key JSON objects: {op:"eq",path,value}, {op:"exists",path}, {op:"between",path,low,high}, {op:"all"|"any",rules:[...]}, or {op:"not",rule}. Path is 1..4 dot-separated lowercase identifiers [a-z][a-z0-9_]{0,15}. eq values are null, bool, integer -1000..1000, or strings of at most 32 characters. between bounds are strict integers (not bool), -1000..1000, low<=high. all/any have 1..4 children; the root has depth 1, maximum depth 4 and maximum 16 nodes. Validate every node depth-first before evaluation, including branches that would short-circuit. At each node check object, op, required fields in the displayed order, unknown fields lexically, field types/ranges, then children. Errors are ValueError("<rule-path>:<code>"): paths start $, children use .rules[i] or .rule; missing/unknown op uses .op:missing or .op:unknown; other missing fields use :missing, extras :unknown_field; path :invalid_path; eq value :scalar_required; bounds :integer_required and reversed bounds .high:invalid_range; children :rule_list_required; depth/node excess :depth_limit/:node_limit. Documents are JSON objects (otherwise document:object_required). Missing or a non-object intermediate path differs from explicit null. exists tests presence including null; eq is type-strict (true differs from 1); between accepts only actual ints and includes both endpoints. Do not mutate rules or documents.

Only rules.py and test_member.py are editable. Standard library only. Deliver a current tested fixed patch; collaboration is not a scoring requirement. This is an authored rule-interface local maintenance fixture.
