# Exact signed credit apportionment

Maintain `allocation.allocate(total_cents, accounts)`. Distribute a signed integer number of cents among accounts using exact largest remainders. `total_cents` is a strict Python integer (not bool), between -1000000000 and 1000000000 inclusive. `accounts` is a list of 1..16 exact-key objects `{id, weight}`. IDs are unique ASCII strings matching `[a-z][a-z0-9_]{0,15}`. Each weight is a strict integer in 1..1000000. No other keys or input types are allowed.

Work with the absolute total. Give each account the integer quotient of `abs(total_cents) * weight / sum(weights)`. Give one additional cent to each of the first remaining accounts ordered by decreasing integer remainder; ties use ascending ID. Then apply the original total's sign to every assigned amount. Return a list of exact-key `{id, cents}` objects in ascending ID order. The returned cents must sum to the original signed total, including zero. This allocation must be exact at all stated bounds; binary floating-point rounding does not define the contract. Every invalid input raises `ValueError("allocation:invalid")`. Never change the inputs, on success or failure.

Only allocation.py and the optional test_member.py are editable. Use the Python standard library only. Deliver a fixed version that has passed the public tests for that same file tree. The team receives one shared goal with no predefined work roles; collaboration is not required for acceptance. This is a new controller-authored integer-apportionment fixture for bounded policy development, not an external benchmark, upstream bug, or derivative of the event-time and rule-interpreter training families.
