# Bounded dependency batches

Maintain `planning.plan_jobs(jobs, max_parallel)`. `jobs` is a list of 1..12 exact-key objects `{id, needs}`. IDs are unique ASCII strings matching `[a-z][a-z0-9_]{0,15}`. `needs` is a list of distinct IDs, each naming a job in this same input. No other keys or input types are allowed. `max_parallel` is a strict Python integer (not bool) in 1..8. Validate the complete input before planning: unknown dependencies, duplicate IDs or dependencies, self-dependency, any directed cycle, or other invalid data raises `ValueError("plan:invalid")`. Never change the inputs, on success or failure.

Return a list of nonempty batches, each a list of IDs. Initially no job is complete. At each round, identify every uncompleted job whose dependencies were all completed in earlier rounds; choose the lexically smallest IDs up to max_parallel, in ascending order. These chosen jobs complete together only at the end of the round. A job unlocked by this batch must wait until the next batch even if current capacity is unused. Continue until every job occurs once. Thus results depend on the graph and capacity, not input order.

Only planning.py and the optional test_member.py are editable. Use the Python standard library only. Deliver a fixed version that has passed the public tests for that same file tree. The team receives one shared goal with no predefined work roles; collaboration is not required for acceptance. This is a new controller-authored dependency-planning fixture for bounded policy development, not an external benchmark, upstream bug, or derivative of the event-time and rule-interpreter training families.
