# v0.30 model/interface development pool

These are **six different development contracts from one repository**, not six
independent source repositories or six official benchmark issues. The original
Marshmallow 4.3.1 source is reused byte-for-byte from
`../software-v15/upstream`, at commit
`c7b559a1fa3aba57ca6dba0ab336841c5038a782` (MIT). Its license and notice accompany
every actor workspace. `source-manifest.json` fixes every source, regression,
public contract, starter, reference, public check and hidden-check digest.
No new network acquisition is needed. There is no schema-contribution or TextFSM
confirmation content in these tasks.

The first two cases diagnose API normal-path integration. The next two start
from real application defects; a forced initial run supplies actual failure
feedback, which must not be counted as autonomous test discovery. The last two
start from a shared root goal, empty task board and two equal members. Model
members produce execution tasks and responsibility themselves. Public source API
schemas are requirements, not researcher-created execution task cards.

All cases are `model_interface_development`, with no policy training,
contribution-development or independent-confirmation eligibility. No reference,
independent expected value, bad-control implementation or acceptance file enters
actor-visible files. Public normal checks and hidden independent checks use
different input sets. Hidden checks include nonempty integrated paths and API
use probes. Upstream regressions retain five exact original fixture-free test
functions. This subset is not the complete upstream pytest suite.

The original source has prior project development exposure, including current 9B
frozen-policy interactions but no parameter-training use. This limitation is
retained; no claim is made about absence from candidate pretraining or public
agent training data. Results must report API, repair and O1 categories separately.
`qualification.json` records controller-only CPU reference/bad-control evidence;
none of those runs are model trajectories or allocation support.
