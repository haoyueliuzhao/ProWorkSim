# 有限声明式场景

这些 JSON 使用已有财务核对和有限研究报告模板；不是开放世界生成器。宿主负责公开会话绑定、轮转行动机会和预先声明的外部资料变化；工作人员策略根据自己的公开观察决定业务步骤。

| 规格 | 工作结构与预期 |
| --- | --- |
| `finance-direct.json` | 双方材料直接可见；核对九个键组，保留冲突、不可比、缺失和歧义 |
| `finance-route.json` | 仅将右表改为由提供方掌握，需真实资料请求；完成结果仍按原合同判断 |
| `report-direct.json` | 两项公开财务指标的正文表达及审阅 |
| `report-pending-start.json` | 由统一运行器真实执行到待审起点，保存前缀经历及检查点，再继续审阅 |
| `chain-before-submit.json` | 实际工作上下文中的输出编辑后，声明更正右表；形成当前义务修订 |
| `chain-pending.json` | 已提交待审时更正；形成当前义务修订并保留旧提交 |
| `chain-accepted.json` | 上下游均接受后更正；上游后继核对、发布引出下游后继报告 |
| `finance-display-name.json` | 仅更改工作人员显示名；这是表面变化，不算新工作结构 |

链条初始的 `comparison` 是空草稿。部署公开共享其身份，但没有发布核对答案或伪造接受历史。核对员依靠实际来源制作交付，经真实审阅接受后，按公开业务要求分享并发布。报告作者在没有正式发布时等待；拥有发布后，按合同采用、写作并交审阅者处理。外部更正只写入与发布原始右表，不修改报告、不批准交付、不预填审阅意见。

`projects` 接受两个原模板的有限 recipe、跨模板报告 recipe，或显式 ProjectPackage。对象引用以 `{"$object":{"project":"FINANCE","alias":"comparison"}}` 声明，由宿主依据已安装对象解析。未解决引用、缺少安装权限或互相冲突的项目身份会报告 `unbuildable`；不会降低权限要求或替换缺少的材料。

事件只包含有限的工作阶段、逻辑时间或先前事件条件，以及预声明的公开工具调用序列。`fire_once` 必须显式为 true。同一次外部事件的失败保留实际拒绝，不自动换参数重试。控制器可以检查事件条件所需后台状态；这些状态不直接送入员工策略。控制器动作、环境实际事件、员工实际观察和动作分别记录。

起点可以是 `initial`，或 `executed_prefix` 指定目标条件和机会预算。后者调用相同运行器执行到目标，保存实际经历区间、哈希与动作返回边界的工作人员检查点；不存在写入“已经待审”的后台捷径。无法在声明预算内达到起点，明确记为不可构建。当前例子演示待审起点；条件也可表达实际读取、输出编辑和资料阻塞。

构建复现性比较仅排除根实例/分支标识、动作墙钟耗时和收据/迁移的状态摘要。它保留逻辑时钟、调用与命令标识、状态修订号、权限、对象版本、工作历史及全部不可变文件字节。不同名称或条件的规格不要求产生相同轨迹。

运行完成同时要求达到声明的业务边界、没有被静默遗漏的外部事件，以及没有待处理环境事件。无动作的完整轮转若仍有未触发事件，记录等待而非成功；机会预算耗尽单列。这里的“完成”是制度进度，独立内容评价仍由评价接口另行报告。

以上均为合成资料和规则策略实验，不支持自由报告专业质量、任意策略进程中断恢复、多写者并发或训练收益结论。

显式的 `complete_when` 会在每个完整行动返回后检查。待审等中间点命中时返回 `boundary_reached`；选定项目已经接受而世界中另有未完成项目，也返回该状态并保留未完成义务。全世界制度义务均完成、公开交付中的实际发布要求兑现且无遗漏事件，才返回 `completed`。历史已接受提交只要求其确切版本曾合法发布到声明目标，不要求旧版本始终是最新版本。

`run_scenario(..., max_opportunities=N)` 提供不大于规格预算的单次调用上限，用于保存动作返回边界的检查点。重新调用可以继续同一世界，记录累计机会数，不改原规格或第一次截断结论。`executed_prefix` 的构建前缀使用其独立声明预算，真实前缀经历与后续 episode 分列；不会将前缀机会隐去或当作零成本构建。
