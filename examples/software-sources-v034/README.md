# v0.34 新开发根目标

这里定义两个新的项目自编合同，复用已经固定的真实 Marshmallow `c7b559a1fa3aba57ca6dba0ab336841c5038a782` 源码资产。它们不是两个独立仓库，也不修改 v0.30–v0.33 的合同、验收或分数。本目录只用于 P1 的 `model_interface_development`；参考程序、程序路线和这些开发经历不得改标为正式训练、Contribution 开发或独立确认。

| 根目标 | 可编辑业务模块 | 完整义务 |
|---|---|---|
| `mm-directory-rootgoal-v034` | `models.py`, `consumer.py` | 实际 `RecordSchema.load/dump`、名称去两端空格、整数转换、批次顺序及重复、整数总量、空集合、输入不变 |
| `mm-name-index-rootgoal-v034` | `models.py`, `search.py`, `exporter.py` | 实际共享 `NameSchema.load/dump`、ASCII 名称规范、查询下标与导出结果一致、顺序及重复、空集合、输入不变 |

执行者可另编辑 `test_member.py`。完整、精确的合法输入范围在每个 `contract.md` 中冻结：名称只含 ASCII 字母及普通空格，去首尾空格后非空；目录数量为 0–1000 整数或表达该范围值的十进制整数字符串。数量布尔值、额外字段和其他形状均不在新合同范围，不私下加入验收。旧任务中的未知字段、金额精度和 secret 义务仍按旧合同评分，不能拿新任务成绩追认旧任务成功。

公开检查覆盖各项语义，并执行同一小组原始上游回归；独立检查用不同的非空输入验证可复用 API 与消费端的完整行为。空集合这一唯一输入在公开检查中验证。私有预期值不发送到执行代码进程。`test_visible.py`、合同及源库均只读；`acceptance.json`、`reference/`、本说明和 CPU 路线脚本不进入成员工作副本。

新的 API 观察器分别记录 `source_api_used` 和 `source_api_observation_complete`。在成功安装 API 计数器后发生的业务异常仍可保留实际计数；若观察建立失败或字段缺失，则 `process_observation_complete=false`。`required_process_satisfied=false` 在后一情况下表示没有证明完整过程要求，不能写成 API 确定未被调用。完整评分继续要求内容、原始公共／独立检查和固定交付的合取，观察字段不用于补分。输出比较和输入保持探针均保留 JSON 标量类型，不能把浮点数或布尔值当成合同要求的整数。

每个根目标有四类实际 CPU 程序对照：原始程序、仅替换共享 schema、仅替换 consumer 模块、联合参考。前两种单侧程序保留另一侧的实际起始实现。除这些正反例外，联合程序还记录真实 schema 返回结果并核对目录输出或查询／导出结果的一致性。这是对参考路线的具体依赖证据，不是任意候选实现的形式因果证明。

`tests/test_software_v034.py` 还经真实 SDK／世界接口执行两类合法路线：一名成员集中完成；两个真实私有副本分别修改后，由一方固定发布、另一方显式导入。路线实际创建任务、修改文件、运行测试、发布固定版本并提交，随后做独立验收。两条路线是环境可满足性见证，不是模型指令、教师标签或当前策略方法支持。模型可以采用其他合法方式，不要求消息、双方修改或特定分工。

P1 使用固定四槽窗口，每个现有模型执行两根目标 × 两种 seed。先手、顺序及 seed 由 `software_runtime_v034.inventory()` 冻结。每个 episode 的两个成员共同使用 128 决定、128 次生成尝试、500,000 实际 token、32 次真实 `run_tests`；没有个人 64 步配额。新的呈现 Γ 包含 `software_context_v034` 的相同合同去重，以及另行声明的公开测试反馈精简：通过项只列 ID／要求组／状态，失败项保留业务值、异常及 API 观测，成员自测输出完整保留。完整公开 stdout、通过值和详细 API trace 留在原 test 事件；这项反馈精简不是无损去重或行为等价声明。权限、预算、原始记录与学习状态恢复沿用已经验证的机制。

P0 归档在 `runs/v034-controls/world/`：八个实际程序变体控制、依赖见证、四条完整 SDK 路线和开发期失败都保留。SDK 的参考选择和 token 是明确标记的 CPU 测试夹具，不能冒称两模型实际采样；真实 tokenizer 的离线输入预算证明与夹具的账本计数应分别解释。不得为了重复凑统一日志而重跑已经通过的无关控制。
