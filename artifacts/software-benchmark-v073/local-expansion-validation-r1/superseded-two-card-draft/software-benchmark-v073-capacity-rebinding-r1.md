# v073：按当前可用显卡重新封存部署绑定

v071 准备后，原指定 GPU1／GPU5 的剩余显存不足，因此不能继续使用当时的绑定。v073 保留 v071 源码和授权原件，只为尚未消费的 model-4／model-5 新建绑定；不会重启原已消费身份。

准备时调用原容量检查，候选仍限原允许的 GPU0—7、A80080GB 和至少 50176 MiB 剩余显存，并排除本项目活动驻留已经使用的 UUID。在合格候选中优先 GPU7、再 GPU0；准备记录确定的 UUID，启动时再次核验该 UUID 的实际容量，不在启动过程中悄悄换卡。

实现仅将 v071 启动器的全部本地函数复制到一个独立函数命名空间，替换输出目录、部署版本、两项 GPU 绑定和新入口源码路径；原函数代码不改、原模块全局变量不改。逐卡启动、单项缺容量可继续另一项、已成功项不回滚、已消费身份不重启、最多四个活动驻留、原共享资源账本和模型配置全部沿用。每个授权同时绑定 v073 入口、v071 委托源码和原资源授权。

新增两个必要 CPU 控制通过：动态选择优先级和活动 UUID 排除；所有委托函数确实共用新的命名空间且不修改旧模块。Ruff 通过。测试没有真实 GPU 查询、模型、API、容器或服务操作；实际准备、启动和就绪状态由主流程另行记录。
