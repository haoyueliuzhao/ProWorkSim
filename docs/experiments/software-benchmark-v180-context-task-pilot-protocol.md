# v180：完整单Agent工作轨迹管理实验协议

2026-11-09。当前状态：**12题、6仓库、48个主回合及12个重复回合已预选；12个源镜像均在本地；完整任务尚未派发。** 本文落实审计要求的第二项近期工作——准备四组完整任务协议。恢复入口的真实模型准入已由v179完成。

## 1. 研究问题与共同环境

比较历史管理策略贯穿完整修复过程后的成本、代码正确率和合法交付率。检验最近5轮与10轮的取舍，以及可复用摘要能否摊销成本、是否掩盖失败信号或拉长轨迹。

四组统一使用 **ProWorkSim真实S1受管OpenHands、1名member_001、DeepSeek Flash非思考**。项目的浏览、修改、公开测试、版本、固定补丁与交付规则保持一致；不增加不受管shell，不改变消息路由，不接入参考补丁或隐藏评分反馈。源码清单及正式SDK运行包还需在实际启动前绑定冻结。

共同设置：temperature=1、top_p=1，131,072上下文、98,304输入、32,768单次输出，每回合 **5M实际输入＋输出**。Agent、历史摘要、格式纠正和重试都计入同一个回合预算。供应商不提供本轮可用的seed控制；框架seed用于身份、采样顺序和本地状态，不冒称固定API采样。

四组都有同一v179只读历史恢复入口。只读该回合该成员实际见过的内容，带精确来源、消息索引和工具调用配对；所有回读和格式反馈都消耗真实机会与token。M0因此是“现有历史管理＋共同回读入口”的研究基线，不是完全未经压缩的Raw Agent。

## 2. 四个条件

| 条件 | 历史处理 | 保留及边界 |
|---|---|---|
| M0 | 现有SDK历史摘要策略 | max_size=80事件、keep_first=4、hard_reset_retries=1；保留当前来源绑定与受保护输入 |
| M1-5 | 最近5个完整工具交互周期保留 | 旧工具返回和旧user环境观测替换为强制原文引用；动作链保留 |
| M1-10 | 最近10个完整工具交互周期保留 | 除窗口外与M1-5完全一致 |
| M3-R | 持久化、可恢复的历史摘要 | 旧动作和完整原始观测共同摘要，保留最近10轮，原文与索引持久保存 |

“一轮”是一个完整动作—结果周期及其环境观测，不是一个JSON消息。M1不得悄悄叠加M0的按事件数摘要，否则会把遮蔽变成混合处理；若保留动作及保护区已超出同一输入容量，按预定context-capacity端点闭合并单列，不静默删动作。M3-R同样不能省掉最新未呈现信息或留下孤立工具结果。

M3-R借鉴[The Complexity Trap](https://arxiv.org/html/2508.21433v2#A5)的候选参数，而非宣称论文复现：`N=21`为一次新纳入摘要的轮数，`M=10`为最近完整轮数，正常触发量为 **N+M=31**。若精确输入容量先触发压力，可提前摘要合法旧前缀；保留同样的10轮尾部，记录触发原因。若保护区本身仍无法容纳，不篡改输入。

## 3. M3-R的生命周期

每份摘要保存：摘要ID和前代ID、覆盖起止轮、原始前缀哈希、可读取的原文引用、生成调用身份和时间、模型usage、所覆盖源版本、公开测试证据和交付版本。

1. 没有达到正常阈值或输入压力时不生成摘要。正常生成后连续复用同一摘要，不在每次模型调用前重做。
2. 新代码树、公开测试证据或交付版本变化时做失效检查；预算计数、调度时刻和普通查询不会无故使摘要失效。
3. 旧摘要可以继续作为带日期与覆盖范围的历史材料，但不能把旧“已通过”“已提交”当作当前状态。最近10轮完整事实及当前观察优先。
4. 关键变化将要离开完整尾部时，触发增量更新；将前一摘要与新纳入的**未遮蔽原始动作和观察**交给摘要器，不能重复v175“先遮蔽后摘要”的信息缺口。
5. 无新事件时不对同一前缀反复摘要。摘要失败或没有变短时保留原材料及费用；若仍适配输入，可继续工作，不能因派生统计异常使整个队列退出。
6. 持久化摘要和原文store必须与真实SDK请求路由绑定；只写提示“可以回读”不算完成接入。

`software_context_lifecycle_v180.py`已实现可持久化的阈值、状态失效、增量更新计划和复用计数核心，3项CPU控制通过。它尚不是完整SDK运行器，不能据此宣称完整任务已经接入或已评测。

## 5. 预算与调度

用户选择继续同一250元累计账本。完成v177–v179后累计计费上界21.86307688元，剩 **228.13692312元**，没有增加额度。

60回合的理论生成上限为300,000,000个输入＋输出token，不是预计消费。将旧v155 S1的实际输入、输出和缓存构成按当前账本峰值费率重算，每回合约4.94元，48回合约236.96元、60回合约296.20元。旧账单均费2.47元对应较低的计费基准，不能直接搬到当前预算估算。

这只是**不预设压缩收益的参考情景**，不是新配置的成本预测；压缩也会改变缓存、动作次数与回读。不能保证现有余额覆盖60回合，也不能提前把未测的34%输入节省当成现金节省。

正式调度按预定同题四条件块推进，现金只控制新块准入，已开始的回合自然完成。保留原题单和未启动状态，不依据中期分数换题或只跑较便宜组。费用不足时不把未启动或未闭合任务算作普通失败，也不把已闭合子集冒充完整12题结果。并发数和在途现金预留需在部署时结合真实资源和账目冻结，不通过临时改全局服务器设置获取资源。

## 6. 指标

| 方面 | 具体记录 |
|---|---|
| 输入与总成本 | Agent输入／输出、摘要器输入／输出、实际缓存、物理重试、格式修正、总token与现金；回读内容已包含在后续输入，不再重复相加 |
| 摘要摊销 | 每份摘要生成成本、物理呈现次数、不同决策上的复用、状态变化后的历史呈现、有效性检查及更新原因 |
| 恢复 | context_read次数、返回材料大小、输入呈现估算、真实读取耗时、错误或未读引用、版本混用及恢复后决策 |
| 轨迹 | 模型和世界动作数、实际墙钟时间、重复失败、同版本重复测试、返工、达到token／context／调用／时间端点的原因 |
| 质量 | 唯一最终代码官方正确率、最后合法交付率、代码与交付是否同树、技术未知与环境覆盖限制 |

生命周期核心中的`epoch_valid_distinct_decision_reuses`只在摘要源状态与当前代码／测试／交付身份相同时计数，和普通呈现次数分开。这是保守的操作性代理指标，**不是证明模型语义上用了摘要**。状态已变化但旧摘要仍作为历史呈现时单列。正式有效复用还需结合失效检查和案例审计，不能单靠出现次数作为分母。

摘要摊销分别报告生成成本／不同有效决策复用次数；分母0时记不可摊销。恢复有效率以必要事实在实际读取后被正确用于判断为分子，不能只数调用次数。

主分析保留逐题四组配对与仓库层级。额外重复用于估计随机波动。12题只用于机制筛选，不能证明总体非劣效、稳定性认证或角色感知通信收益。
