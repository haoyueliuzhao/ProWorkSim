# v224.3 组织方案覆盖与真实责任转交

本轮检验两个问题。组织 Agent 在哪些开发状态下会提出可执行的分工调整？成员收到这样的方案后，实际工作归属和最终交付会怎样变化？

## 方案生成

冻结两批完整的历史输入。第一批包括 v224.2 的 Matplotlib、Pytest、Xarray、Sphinx，在首次定位代码时均只有一个根工作包。第二批包括 v222 项目图条件下的 Django、SymPy、Astropy、scikit-learn，均已有两个子工作包，其中仍有一至两个可以调整。两批来自不同仓库和历史协议，差异同时包含任务、初始分工、项目图内容和观察时机。每种状态只有一次决策，允许一次格式纠正。

两批统一使用 DeepSeek Flash 非思考模式。模型读取当时实际可见的题文、项目图与组织状态。沿用 v224.2 的输入和工具规范，补明维持分工时提交空候选列表。方案经过编译、结构或采用动作去重、实际工具参数校验。全部八个状态进入统计。旧运行及旧分数保留。每个状态最多20万输入加输出 token，使用累计1100元账本，为冻结确认预留100元。[输入清单及冻结标识](../../artifacts/software-benchmark-v224-3/oa-replay-r1/plan.json)

| 开发状态 | 提出可执行调整 | 主动维持分工 | 输入 token | 输出 token |
|---|---:|---:|---:|---:|
| 首次定位代码 | 0/4 | 4/4 | 47,920 | 1,298 |
| 已有明确工作包 | 1/4 | 3/4 | 59,430 | 3,534 |

8个状态用了9次 API 请求。Django 经一次格式纠正后返回维持分工。生成阶段共112,182 token，结算0.21722928元。再次询问 Matplotlib 得到有效的维持分工答复，原运行仍保留“系统回退”标记。两批均有些状态缺少复核配置，模型多数选择用现有流程补齐。样本和条件的差异使这次比较只能说明候选覆盖，观察时机的独立影响仍待验证。[逐状态结果](../../artifacts/software-benchmark-v224-3/oa-replay-r1/results.json)

## SymPy 同一保存点的两个分支

唯一通过编译的方案来自 sympy-13615。当时核心修复和验证工作都由001负责，002已在消息中说明其对根因与预期行为的判断。组织 Agent 建议001继续修复，002接手验证，由001复核验证成果。成员陈述的正确性仍须由测试检验。

从同一个 v222 SDK 保存点恢复两个独立分支，保留共同前缀的对话与实际用量，续跑使用 v224.2 的自然协作接口。既有成员历史可能包含旧合同说明，两组收到相同的当前合同。分支差别是发给成员的组织方案。KEEP保留原责任，C1允许尝试这次转交，接收方可以拒绝。共同前缀930,766 token，本题新方案13,872 token，项目图取自归档的确定性图条件。每个分支剩余4,055,362 token。先锁定两个候选与共同初始选择器，再运行并对最终代码、最后合法交付分别评分。两组只增加各自续跑的 API 成本。因覆盖筛选仅有一题可配对，选择这个状态依据候选可执行性，结果适用于该开发状态。[冻结候选](../../artifacts/software-benchmark-v224-3/pair-r1/bank.json)

| SymPy 分支 | 实际分工 | 官方代码结果 | 合法交付 | 逻辑 token | 新增续跑费用 |
|---|---|---|---|---:|---:|
| KEEP | 001保留核心修复与验证，002复核 | 未通过 | 未交付 | 4,959,234 | 5.45元 |
| 转交验证 | 001发出转交，002明确接受，随后修改验证代码并运行测试 | 未通过 | 未交付 | 4,956,477 | 5.41元 |

两个最终补丁都成功应用，官方目标测试 `test_Complement` 均失败。KEEP 另有3个原本应保持通过的测试失败。转交组有6个，其中多出 `test_difference`、`test_image_piecewise` 和 `test_boundary_ProductSet`。两个分支均达到预算边界。在这个保存点上，协作建议改变了成员实际行为，任务正确率与交付率均为0/1。单次配对只能描述此次差异。

按预定效用进行一次开发更新。两组均未正确交付，转交组少用2,757 token，占单题预算约0.055%。该组的相对贡献为0.00002757。首轮欠覆盖值 N 为0，更新的目标概率从50%变为约50.0003%。现有数据对两种分工给出的偏好极弱。审计要求用第二轮开发结果形成另一份策略，再在独立任务上验证。本轮得到一次有完整结果的开发更新，冻结确认仍待后续开发数据。

全部新增147次 API 请求结清，包括8个状态的9次方案请求与两个分支的138次求解请求。实际输入8,098,725 token、输出39,892 token，共8,138,617 token，费用11.08202344元，累计预算余额229.34974864元。[执行与成本明细](../../artifacts/software-benchmark-v224-3/pair-r1/summary.json)
