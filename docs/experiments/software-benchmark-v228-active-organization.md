# v228 组织图能否真正约束工作｜实验协议与准入

2026 年 11 月 23 日。本轮把 v227 的“负责人可以选择是否采纳建议”改成两个可比较的条件。研究问题是，出现困难时，让独立策略 Agent 决定一项合法的局部分工变更，是否会实际改变成员行为，以及最终能否交付正确代码。本轮冻结策略，C/N 的参数更新留待 v229 重新准入。[前轮审计](v226-v227-audit-report-20261123.md)

## 同一工作现场，两种决定分工的方式

| 条件 | 谁决定组织安排 | 谁完成修复 |
| --- | --- | --- |
| W0，成员自主组织 | 两位工作成员可以维持原安排，也可以使用原有的分工、协作与交接工具作出调整 | 原两名成员负责代码、公开测试、复核和正式交付 |
| W1，组织图约束执行 | 独立策略 Agent 从当前合法的局部变换中选择，也可以保持原图。确定性校验器检查版本和证据后，原子激活新版本 | 同两名成员继续完成同一任务。受管工具读取生效的分工，成员可以报告执行障碍 |

两组使用 DeepSeek Flash 非思考模式、同一保存点、同一成员各自的历史、同一公开问题、同一套工作工具和官方评分。指定观察成员在两组收到相同的异常提示。W1 的策略会话只收到获准的结构化证据、工作分工和剩余预算。它通过短证据编号选择局部调整，不能编辑代码、测试或代为提交。每条分支共享 500 万输入加输出 token，包含分支前工作。W1 的策略调用从该分支额度中扣除。比较的是整套控制机制的效果，里面包含额外的决策调用与组织说明成本。

## 组织图具体如何生效

图记录当前成员、工作范围和负责人、复核者、依赖、协作边及诊断交接责任。首版支持维持现状、将独立诊断交给伙伴、补上缺失的复核者，以及调整尚未开工的工作归属。正在实施、有作者、已完成或仍有交接在途的工作包不走直接转交路径；已形成的代码仍由原版本和作者记录约束。已开始的工作可追加独立诊断。依赖与范围沿用现有工作图，首版控制器只开放上述已验证的局部变换。

所有目标在实际工作状态上校验，成功激活后保存前后图、版本、生效时刻、理由和证据。改变负责人会改变原有工作权限。分配诊断会生成具名职责与交接对象，成员须引用自己新取得的工作事件来交接，完成交接前不能签署该候选的复核意见。原有同版本测试、归属、依赖和正式提交要求继续执行。成员可用定向消息报告权限、依赖、在途工作、预算或状态冲突；报告本身不会撤销生效图。每题最多处理一次后续障碍并重新决定，报告的理由按成员陈述记录。

受管接口的 CPU 实验覆盖了负责人实际写权限的转移、旧版本重放被拒绝、虚构诊断证据被拒绝、真实证据交接、阻塞上报以及非法图不改变世界状态。测试用例与此前提案接口控制合计 27 项通过。工程控制与真实模型评分分别报告。[控制器及接口](../../src/proworksim/software_graph_controller_v228.py) · [测试回执](../../artifacts/software-benchmark-v228/control-r1/cpu.txt)

## 首对运行时发现的证据呈现问题

两臂实际恢复了同一 Astropy 保存点。W1 策略会话选择 K（保持原图），生成一个合法版本，职责变更为零。模型在理由中称 E2 和 E4 代表修复得到验证。原始事件表明，同一 RST 测试用例在两个版本上均失败。检查首次决策的请求原件发现，短编号保留了工具、版本和回执摘要，遗漏了用例通过或失败的字段。因此，这个决定不能作为充分理解失败证据后理性保持分工的例证。

在后续任务开始前冻结 r2。它按原观察者、命令标识及原始回执哈希核对证据，把已确认的用例通过、用例失败、合并冲突及明确阻塞原因送入结构化视图。用例不可判定时保持未知，两组的指定工作成员得到相同的来源证据。用首题保存点离线回放后，四个事件依次为编辑、用例失败、再次编辑、同一用例再次失败；使用另一成员的身份读取该组私有回执被拒绝。该复验为零 API。首对保留 r1 身份，其余题目标为 r2，各版本分别报告。[证据回放](../../artifacts/software-benchmark-v228/control-r2/evidence-regression.json) · [修订冻结](../../artifacts/software-benchmark-v228/control-r2/freeze.json)
