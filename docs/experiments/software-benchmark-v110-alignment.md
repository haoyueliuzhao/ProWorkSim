# v110：REF／PROJECT 执行策略与公开测试入口对齐

本次按用户“进一步对齐，同时对齐公开测试入口”的要求，实现结束自检、历史摘要和定向公开测试三项修订。**两组仍以 OpenHands SDK 为基础；PROJECT 继续使用 ProWorkSim 的受管工具、版本记录和交付规则。** 本轮只实现与离线验证，没有启动新评测，不能据此宣称正确率已经提高。

旧 v105—v108 运行源码、候选、成绩、费用及 v109 报告均保留。新配置见 [准备配置](../../config/v110-single-agent-alignment.json)，其中 `execution_authorized=false`，没有新题单、seed、现金授权或自动启动入口；旧实验剩余预算不会自动转入本版本。

## 1. 三项具体变化

| 项目 | 旧差异 | v110 实现 |
|---|---|---|
| 结束自检 | REF 最多得到一次结束前复核；PROJECT 没有对应策略 | 两组使用同一复核文本，最多一次，继续原会话、原预算和原时限。PROJECT 首次 `staff_done` 在正式结束前进入复核，第二次正常结束；已结束成员不会被重新激活。 |
| 历史处理 | REF 有 SDK 摘要；PROJECT 主要依靠历史投影和容量裁剪 | 两组使用同一摘要实现及参数。PROJECT 不再为适配容量静默滑走旧工作记录；摘要只能来自本会话，并保留当前尚未呈现输入和最近完整工具回合。 |
| 公开测试 | REF 可在终端选择测试；PROJECT 原入口通常运行整套公开测试 | 两组获得同一结构化测试选择协议，固定任务解释器、工作目录和默认公开命令。PROJECT 可选择文件、测试节点或相应前端的标签／关键词，不必每次启动整套测试。 |

工作提示也改为共同的中性说明，不再要求 PROJECT 使用其没有的原生终端。测试目标必须从公开问题与仓库中确定，不提供参考补丁定位、隐藏验收或评分反馈。

## 2. 公开测试怎样使用

PROJECT 通过 `run_tests(selection=...)` 选择范围；省略 `selection` 等于 `{"kind":"full"}`，保持原默认入口。REF 在原生终端中可调用同一协议：

```text
/opt/pws-runtime/bin/python /opt/pws-runtime/public-test.py --selection '<selection JSON>'
```

当前 50 题的公开入口配置已核对：40 题 pytest、5 题 Django、5 题 SymPy，全部能映射到相应选择器。这是**配置及协议覆盖检查**，并非重新执行了 50 题的测试。

| 前端 | 可选择的公开范围 | 保持的边界 |
|---|---|---|
| pytest | 文件／节点，以及受限关键词、marker 表达式 | 固定解释器、`-m pytest`、工作目录和超时；不注入任意插件或命令参数 |
| Django | 公开测试模块、类或方法的 dotted label | 保留仓库原测试脚本；不改 settings、环境变量或并行参数 |
| SymPy | 公开测试路径及其原生 `-k` 关键词列表 | 按实际 SymPy 前端解释，不套用 pytest 的布尔表达式语义 |

选择器在执行前校验路径与前端；路径越界、符号链接和不支持的参数会被拒绝，拒绝不消耗一次实际测试。PROJECT 的测试回执记录源版本、选择范围、实际命令和分页输出；**部分测试通过只证明该范围通过**，不能标成全套公开测试或官方隐藏验收通过。

REF 的公共脚本只是便利入口，不是权限屏障。它仍保留原生终端能力，可以另行运行合法命令；actor 中初始只读权限和文件摘要只能证明启动部署内容，不能保证原生 Agent 此后无法修改文件。PROJECT 则由独立受管进程保存获准配置，并逐次验证请求。没有为 PROJECT 新增不受管 bash、宿主监听端口或隐藏评分入口。

## 3. 预算、摘要与交付

本次准备配置沿用 DeepSeek Flash 非思考、单 Agent：上下文 131,072，完整输入上限 98,304，单次输出上限 32,768，累计输入＋输出 5,000,000，模型尝试／Agent 决策各最多 512，软时限 6 小时、硬时限 6.5 小时。尾部输出仍按原剩余预算预约，不增总额。

摘要参数为 SDK `LLMSummarizingCondenser(max_size=80, keep_first=4, max_tokens=None, hard_context_reset_max_retries=1)`。`max_size` 是事件数量阈值，不是 token 上限；实际输入容量仍另行检查。摘要使用同一模型和累计 token 池，计入模型尝试和时间，**不凭空增加一次 Agent 决策或世界操作**。提供方、成员和团队三层用量均记录摘要支出。

为避免摘要把来源或证据混淆，新实现给两组共同增加了来源绑定、当前输入／工具回合保护，以及摘要失败后禁止继续派发的处理。这是明确的新共同策略，不声称与历史 REF 实现逐字相同。摘要标记为可能失真的私有记忆，不能生成权限、测试成功或提交证据。没有可合法压缩的历史，或原预算无法容纳摘要时，仍保留真实边界，不重置额度。

自检不自动执行测试、固定补丁或提交。例如模型先对 v2 完成测试和合法提交，在自检中又编辑为 v3：最终代码候选是 v3，最后合法交付仍是 v2，系统记录 `same_tree=false`。v3 必须自行完成同版本闭合，不能沿用 v2 的交付证据。

## 4. 尚未消除的差异

- REF 保留原生工具和终端组合操作；PROJECT 保留受管单工具动作、权限、版本和显式交付规则。相同调用数仍不等于相同工作量。
- 公开测试选择能力已补齐上述前端，但 PROJECT 的输出仍分页，REF 仍是原生终端输出；任意脚本执行能力没有因此完全相等。
- 摘要策略相同，原始观察内容、工具 schema、PROJECT 的来源与格式反馈投影仍不同。
- REF 仍有原 SDK 卡住检测及最多两次纠正；PROJECT 尚无对应策略。本次没有顺带改变这一生命周期规则。

因此，未来比较仍衡量这些条件下的**项目执行层整体差异**，不能称为只改了一个 API 的纯接口效应。三项修订能否缩小分差、是否降低平均 token／CPU 测试消耗，要由后续明确启动的新实验回答。

## 5. 必要验证与证据

控制采用脚本化响应和计数器，实际构造固定版本 OpenHands SDK 会话、受管世界及闭合导出；不调用真实模型，不启动 Docker、GPU 或基准任务测试进程。

- [结束自检控制](../../artifacts/software-benchmark-v110/finish-review-controls-r1/summary.json)：7 项 CPU 检查和真实 SDK 脚本控制，验证首次结束进入一次复核、原预算不变及世界状态不被自动改写。
- [原生会话控制](../../artifacts/software-benchmark-v110/native-runner-controls-r1/summary.json)：4 项 SDK 控制，验证同一模型／摘要链、会话来源绑定、异常后不再追加请求。
- [公开测试控制](../../artifacts/software-benchmark-v110/public-test-controls-r1/summary.json)：6 项 CPU 检查、5 种真实 SDK schema 往返及当前 50 题前端配置覆盖；包含越界拒绝、源版本和终态锁验证。
- [组合控制](../../artifacts/software-benchmark-v110/combined-sdk-controls-r1/summary.json)：完整经过编辑、选择测试、显式固定／提交、首次结束自检、再次编辑和最后结束。7 次脚本 Agent 响应＋1 次脚本摘要，共 2,240 个模拟 tokens，提供方／成员／团队账本一致；实际闭合保留 v2 提交与 v3 最终树，未自动补测试或提交。
- [历史边界控制](../../artifacts/software-benchmark-v110/history-controls-r1/summary.json)：4 项用量／异常控制及 3 项历史容量控制通过，覆盖未知用量、派发前拒绝、长工具历史、复核后历史、新输入保护和跨成员来源拒绝。
- [部署接线控制](../../artifacts/software-benchmark-v110/deployment-controls-r1/wiring.json)：7 项 CPU 检查通过，覆盖真实配置传递、两个零模型诊断适配器、新身份校验和旧授权拒绝。[离线运行包](../../artifacts/software-benchmark-v110/deployment-controls-r1/bundle.json)成功预加载 SDK 1.49.6 及全部新执行入口，没有下载依赖；尚未进行容器内运行验证。

组合控制仅为缩短测试过程临时将事件阈值设为 12，摘要后恢复生产值 80；正式准备配置没有降低阈值。脚本 token 数用于验证记账，不是 DeepSeek 实测消耗或费用。此前失败的控制原件保留：其中组合控制发现摘要早于普通 Agent 请求的机会绑定，需要独立绑定到同一成员的当前机会，该缺口已修复。

其余历史容量、部署配置和离线运行包验证的汇总见 [实现验证索引](../../artifacts/software-benchmark-v110/implementation-summary.json)。控制早期曾因 SDK 默认行为尝试获取 LiteLLM 价格表，DNS 失败，没有成功外连；后续控制在导入 SDK 前设置离线选项，并拦截外网连接。不能把整个开发过程描述成“从未发生网络尝试”。

本轮未改共享主机挂载、网络、驱动、服务或其他用户任务，未使用 root 权限，也未恢复旧 Qwen／组织实验。
