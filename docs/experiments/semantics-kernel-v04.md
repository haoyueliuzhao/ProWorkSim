本轮将有限经营世界中的共用规则抽入一个窄内核，并由文稿微模板实际复用。**最终代码回归 207 项通过；原 10 类机制通过；4 个文稿配置满足各自预期。跨情境属性首轮为 6/7，组合项因验收脚本比较了公开投影与内部快照而失败，保留该报告，修正比较对象后单独复验。**下文分开记录首轮与复验，不能将它们冒充一轮全通过。

本轮 API 调用、模型采样、GPU 使用、参数训练均为 0。目标是内在规则一致性；没有证明专业领域真实性、模型能力提升或训练收益。上一轮 7 个 API 世界及其 6/7 结果保持原样，没有为了补齐成功而重跑 unavailable。

| Apply / Derive / 保持检查 | `World.act` 与定向回复事件 | 同一 `World.act`，配置自己的效果范围和有限审阅 |

`growth_delta` 与经营阶段扩张移入 `domains/operating_toy.py`；`core/` 不增加“文稿”“经理”“model/memo”等领域判定分支。原 `kernel.py` 是经营工具门面，并未宣称这个旧文件的每一段逻辑都已领域无关。

正式确认使用版本 `credential` 与 `attestations`。新格式缺少整个登记容器或组织配置时，不会自动回退旧投影获得权力。旧 `basis_approvals` 仅保留历史格式投影。

适用性改为按工作上下文查询。同一当前文件可能对 work-1 为 current、对 work-2 为 stale；全局摘要为 unknown，保留两条关系。它不改变旧提交按固定版本计算的历史有效性。程序错误和机构错误仍可发生；有权批准不是独立质量通过。

## 3. 开发回归及发现的问题

最终整套测试 **207 项通过（14.51 秒）**，Ruff 通过。时间是该次本机测试观测，不作为性能对比或吞吐结论。

开发过程中确实发现并修复了以下问题，不把它们隐藏成“从未失败”：

- 原工具接入显式 frame 时，真实授权日志、需求事件和条件绑定的路径最初漏列；检查拒绝越界。修正为实际授权记录和对应条件的精确范围，而非关闭保持检查。
- 通用提交新增 `requirement_snapshot` 后，完整快照内的私有 `acceptance_spec_ref` 曾进入公开工具结果；3 项原有模型运行／恢复测试捕获。嵌套观察投影修复后通过，内部历史仍保留完整快照。
- 回复重开和工具提交曾沿用被替代前驱的旧状态；有权批准也需核对当前前驱。提交、回复、批准和公开 `dependency_readiness` 现共用当前实例解析；新增两方向与待审组合回归。
- 新 schema 缺少整个确认登记时曾可能降级读取历史投影，已限制旧格式降级范围；新格式缺失产生不可判定或缺权。

另外，程序属性开发草案曾 7/7 通过；之后观察投影修复改变了工具返回的字段集合，暴露了正式首轮中的验收脚本错误。开发草案不替代正式冻结结果。

首轮记录为 **6/7 属性、39/40 检查、9 个实际世界目录**。其中前 6 个通过属性合计 36 项检查、8 个世界；第 7 项只执行了第一种顺序的前 4 项检查，第二种顺序尚未运行。这不是 7 个独立任务，也不能丢掉失败后写成完整组合覆盖。

| 属性 | 首轮实际证据 |

| 变更／晚回复／撤回组合 | 第一种顺序的历史固定字段比较失败，原因与复验见下一节 |

独立写入顺序比较选取预先声明的业务字段作为投影；投影内仅移除 `artifacts.*.versions.*.logical_time`，运行身份和日志不纳入比较。文件哈希、版本、来源引用、机构记录和批准时间均保留；该结论仅针对声明的投影。两份规范化文件字节一致，SHA256 为 `f4f6cb2ebf816bf43838400cd7579fea52f61806d5b21cd6b424cde63005fe3c`。这只支持所测两个独立对象的交换结果，不证明共享对象或任意并发操作可交换。

首轮 2 个 business complete 世界中，1 个是正确完成的上下文适用性世界，另 1 个是故意错误公式却获授权批准的世界。后者独评有 4 项失败：股价、P/E 和两项扰动检查。不能将 2 个 business complete 改写为 2 个正确成功。

“声明采用”世界保留了多个错误输入与输出，其评价还有产物可读性失败；它证明“读过／声明过不等于正确”，不是隔离单一能力因素的对照实验。

## 6. 组合脚本失败与单项复验

首轮脚本把工具 `submit` 返回的公开投影当作完整持久化快照。公开投影正确滤掉了 `acceptance_spec_ref`，内部 `requirement_snapshot` 保留它；因此整个快照字典不相等。直接检查 `pending-submission-and-reply` 与 `old-reply-delivered` 两个原始检查点，submission_id、artifact_versions、required_basis、requirement_snapshot 的真实历史内容均未变化。

修正仅改变验收对照来源：用提交前后实际 state 中的 submission 比较这 4 个固定字段，并增加两份原始检查点路径、状态／文件哈希和固定字段哈希。未修改世界、放宽不变字段或重跑模型。原首轮错误报告及 traceback 保留。

复验目录 `runs/core-composition-v04-recheck/`，证据见 [v04-core-composition-recheck.json](v04-core-composition-recheck.json)。结果为 **1/1 组合属性、21/21 检查通过，两个世界均完成且替代提交独立有效**。首尾均为干净提交 `92c1e4f`，内核源码摘要与首轮相同。脚本 SHA256 从首轮 `5621b9c45d80f51e6a06096cd33b3fbc882b1642282575ae53ea90b8846857e9` 变为 `851e95cd63c4e4a3faa73fb7e7c0fc4aacd35e70b5400881766419c48e8394ce`。

因此，预定的 7 组属性现均有通过证据：6 组来自原冻结首轮，1 组来自修正后单项复验，共 36+21 项有效属性检查。这里没有把初轮 39/40 覆盖，也没有声称重新执行了一轮 7/7 的完整实验。

两种顺序不是要求结果相同：先撤回再修订，旧提交保留 withdrawn；先修订再撤回，针对旧工作撤回应被拒绝，原待审提交因需求替代失效。两者的旧回复均不得解开新条件或授权新凭据，历史文件均保持。随后用新真实请求获取当前确认并完成替代工作。

为了构造待审提交与旧请求并存，脚本对真实已排队回复作一次明确控制器干预，延后 20 tick；原／新到期时间、请求 ID 和前后状态哈希单列在 `harness_actions`。这不是分析师行动或模型自发行为，也不是任意随机异步过程的统计研究。

## 9. 结论边界与剩余工作

本轮支持一个有限、可组合的内核已经被两个对象词汇不同的模板实际调用。它比增加新的情境分支更接近当前目标，但尚未形成任意组织行为的统一模拟器。

仍需保留的边界：

- 完整经营编译、表格语义、局部事件政策和评价仍在领域适配层，未宣称所有旧代码已经重构完。
- 工作当前依赖就绪有统一查询；所有 activity status 尚未统一为可由日志完整重建的投影。状态快照、条件历史和兼容 blocker 仍并存。
- 确认权力是当前静态组织配置；未实现随时间动态撤销授权或追溯授权制度。
- 路径 frame 覆盖声明的工具和定向回复／恢复等动作；不替代通用并发数据库、任意插件副作用分析或专业可解性证明。
- 经营模型和文稿质量检查均是有限合成规则。内在一致性得到程序证据支持，外部专业合理性仍需要单独校准。

后续优先在明确范围内减少适配层的重复状态推进，并检验更系统的关系重算及恢复协议；训练与更大规模模型评测仍不是本阶段的完成依据。
