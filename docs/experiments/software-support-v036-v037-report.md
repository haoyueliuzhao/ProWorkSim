## 7. 缓存优化：有限控制通过，真实9B加速未测

优化针对所有候选从同一完整common重复计算同一批决策的成本。正式方案缓存原决策、实际loss权重的真实裁剪前叶梯度，键精确绑定原token/分母/优势、完整actor/critic/两optimizer/RNG、源码与`float.hex(weight)`。命中只在原设备按原行序相加，不对单位叶梯度事后乘权；每个候选仍分别做原clip和AdamW更新。共同无梯度概率门也按相同状态绑定复用。

| 工程控制 | 结果 | 证据边界 |
|---|---|---|
| CPU tiny Qwen：FP32与mixed BF16 | 两配置B/加权/重复加权比较通过 | 有限合成小模型；非9B结果 |
| 原mixed BF16 + FP32 head/LoRA + efficient-only CUDA | 21项张量树比较逐位一致 | A100 GPU5 tiny；不替代9B完整执行 |
| 额外全FP32 CUDA | 严格逐位门失败，最大梯度绝对差4.66e-9 | 整份双配置CUDA receipt.passed=false保留 |
| BF16单位叶梯度事后乘权捷径 | CPU相对L2差约0.008469，CUDA约0.007759 | 未通过严格门，不用于生产 |
| 完整updater CPU对照 | 冷B32miss/0hit；热B0/32；加权2/30；重复加权0/32 | 梯度、参数、critic、两Adam、RNG逐位一致 |

CUDA tiny探针耗时28.858681秒，最高allocated17.87MiB、reserved22MiB；与B同卡共享，计时不用于外推9B加速。首次CUDA计数器lazy initialization错误发生在模型构造前，修正初始化顺序后执行同一门，原错误保留。没有降低阈值掩盖全FP32 CUDA失败。

按实际冻结权重、原行及精确浮点键的纯CPU库存计算：27试训原18,414次反传对应4,338个唯一键，减少76.4418%，次数比4.2448。这个比例不是端到端实测加速。正式G/I权重未知，不能预填其命中数。

本次导入原B不提供逐行缓存：剩余26试训从空缓存需4,300键，只覆盖644个B单位键；正式B还需38个新键，正式G/I最多再增加454。因此新执行预计需4,338—4,792次实际反传，旧B的682次另账。名义梯度载荷19.33—21.36GB，另有元数据/序列化/检查点开销。全部评估仍保留。

**实际v037新worker=0、真实新反传=0、缓存命中=0、新optimizer=0、新采样=0。** 优化实现和条件接管已准备，但在无卡等待期间后续被取消，故不能报告真实9B节时、吞吐提升或效用改善。
