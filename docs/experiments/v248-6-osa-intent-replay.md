# v248.6｜OSA 提案格式修订与原回答回放

本轮验证一个问题：组织策略模型已经表达了判断，是否会因重复填写执行器已知的信息而被拒绝？在上一轮两个真实任务的 14 次原始回答上离线核对，原先通过的 9 次均保留，原先失败的 5 次中有 3 次可以提取完整决策。另 2 次缺少重评字段，仍然拒绝。SDK 控制中的模型由本地脚本替代，本轮 API 支出为零。[逐次结果及供应商响应指纹](../../artifacts/software-benchmark-v248/intent-replay-r1/results.json)

## 现在谁负责什么

P2 要求模型选择维持、暂缓，或从当前现场的候选目录中选一项调整。模型负责判断当前分工卡在哪里、引用公开证据、解释预期用途和验证方式、估计协调成本，并说明何时重评。执行器依据所选候选及其对应的现场快照填入有序操作、成员进出、生产者与接收者、预留行动和组织图版本，再交给原有控制器核对实时状态、权限和资源。选择维持时，图版本自然保持不变。工具接受完整的直接参数，也能识别仅多包一层 `request` 的对象或 JSON 字符串。模型生成的残缺参数不会被自动补全。[中译审阅稿](v248-osa-prompts-zh.md) · [P2 接口](../../src/proworksim/software_organization_intent_v248_6.py)

每份回答按当时发送给模型的完整现场独立核对。读取原始供应商响应，提取保留在 P2 中的判断字段，再与原候选、成员、证据、成果、费用估计及执行顺序逐项核对。一个原 CHANGE 在回放中可用，并不意味着该题当时已经执行了这次复核，也不能将之后的历史决策串接成一条新的运行轨迹。

SDK 控制另外验证了简化提案可以推动真实成员加入、获得行动机会、交接补丁和退出，以及旧图拒绝、幂等重放及部分执行后重新决策。14 次历史决策均来自旧提示词，因此 12/14 是原回答的离线可解释数量。新提示词下模型能否少生成残缺参数、任务正确交付是否改善，仍需独立线上观察。本轮保留原实验代码和交付分数。[回放与控制程序](../../tools/check_osa_intent_v248_6.py)
