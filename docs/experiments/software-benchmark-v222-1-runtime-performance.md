# v222.1 本地执行层性能修订

2026年11月20日。已实现按不可变版本缓存文件指纹，修复同一动作中反复序列化、计算同一仓库内容哈希的问题。权限、工具、模型输入规则、原有SHA256定义、测试要求和合法交付判断保持不变。

## 找到的实际瓶颈

v222的scikit-learn前缀每次工作机会约51秒，本地处理占主循环97.5%；其状态文件约656MB。在已结束前缀的独立副本上，剖析一次`org_status`加完整`observe`，共耗时38.99秒，其中`org_current_identity`调用9次、累计26.16秒，约占67%。

这个函数每次都把同一版本的完整文件集合编码成JSON，再计算文件和元数据的哈希。结束检查、组织状态和模型观察会重复调用它。因此，之前将本地耗时笼统归为大状态持久化不够准确：**更直接的热点是同一版本文件指纹的重复计算。** 全状态哈希和持久化仍有成本，但此次没有重构状态格式。

剖析仅使用已结束任务的私有副本，未向在途进程附加调试器，未调用模型。两次初始诊断因手工构建的观测夹具缺少属性而失败，原日志保留；根因数字来自补齐夹具后的第三次完整成功调用，不能把失败诊断计为性能结果。

## 做了什么

新模块`software_runtime_performance_v222_1`只保存最多256份短小的版本身份结果，不再缓存另一份大仓库正文。查找键包含成员、对象、版本、该版本登记的内容哈希和实际版本文件身份。

每次查询仍先执行原有`_bundle`权限及当前版本解析，然后才能访问缓存。缓存同时核对已解码快照的文件身份；新版本、原路径替换、回滚后复用版本编号或文件元数据变化都会使旧结果不可复用。缓存返回独立副本，调用者不能修改后污染下次结果。若快照超过原解码缓存容量或读写身份不一致，则沿用原计算路径，不安装该次缓存。

文件哈希仍严格等于原来的`digest(json_bytes(files))`，元数据同理；没有更换哈希算法、放宽测试或省略权限检查。缓存是进程私有优化，不进入世界事实、候选补丁或模型消息。重启后可从原状态重新建立。

## 实测收益

对同一个已结束的scikit-learn前缀建立两份独立可写副本，分别运行旧版和优化版。两边执行完全相同的两次组织状态调用及完整模型观察。

| 测量 | 原版 | 优化版 | 加速 |
| --- | ---: | ---: | ---: |
| 第一次动作及观察，含缓存建立 | 36.34秒 | 13.39秒 | 2.71倍 |
| 第二次动作及观察，复用同版本 | 32.50秒 | 6.13秒 | 5.30倍 |

优化版两次调用共命中17次、重新计算1次。两组结果和完整观察在仅排除墙钟时间及含时间的状态摘要后逐字节哈希一致；原始历史状态哈希未改变。

这是一份真实大仓库状态上的局部性能控制，不是整个模型实验提速5.3倍的证明。代码编辑会生成新版本，需要重新计算；模型响应、公开测试、评分和首次环境准备未被这项优化消除。暂未测量多个仓库、多次重复或线上长时间稳定性。
