# v224：项目状态与组织分工的两轮小规模开发

日期：2026-11-21。状态：运行前冻结协议；结果另存，不在本文件中追写结果。

本轮继续用户批准的审计路线：先让模型根据实际项目状态提出可执行的分工方案，再用真实续跑结果更新下一批任务的方案选择规则。既不预先规定“换分工更好”，也不把缺少复核者直接解释为需要重组。

## 1. 本轮要回答什么

上一阶段已完成维持分工与新方案的真实续跑，但样本少、部分检查点没有实际收集测试。v224检查两件事：能否在真正做过代码修改和测试的状态中形成有依据的替代方案；前一批方案的效果，能否通过共享选择规则改变后一批的选择概率。

四个新开发任务分成两轮，每轮两题。每题先运行一个共同前缀，再从同一个保存状态分别继续 KEEP 和至多两个模型方案。因此最多12条主续跑，不保证一定产生12条：未出现合格状态不补题；模型没有提出可用替代方案时只保留KEEP，不能声称完成一次策略学习。

这是开发试验，不是独立确认。后续v225不自动启动；先审阅本轮候选覆盖、真实行动、完整评分和实际更新次数。

## 2. 任务、初始分工与实验条件

| 开发轮 | 任务 | 公开问题概要 |
|---|---|---|
| 第一轮 | matplotlib-24026 | 堆叠图的颜色别名和坐标轴颜色循环 |
| 第一轮 | pytest-7432 | runxfail不应改变skip/skipif的位置报告 |
| 第二轮 | xarray-3095 | 不同复制入口应保持坐标的字符串类型 |
| 第二轮 | sphinx-9229 | 多种类型别名的文档显示 |

题目来自原固定Verified资产；每个仓库先按固定SHA256顺序取六个候选，再由助手仅依据公开题文选择具有多个相关行为的任务。排除近期已用开发题，不读取历史分数或参考补丁来选题。这不是随机代表样本，也不是从未暴露过的测试集。具体候选、seed、镜像和原题文哈希见同目录协议题单。

每题保留两个实际成员，使用DeepSeek Flash非思考模式及原受管OpenHands执行层。输入上限98,304、单次输出上限32,768；历史摘要、工具权限、代码/交付双端点、官方评分器均沿用v223.1已验证配置。组织方案调用是只读角色，不增加第三名世界成员。

初始分工由成员根据原始题目自然建立。题文中的四段引用只作追踪标签，不要求拆成四个独立任务，也不能借此增加验收要求。允许正常派工、接收和配置独立复核；不要求故意留下缺口。共同前缀要求先完成真实工作和合理公开测试，再开始所有剩余工作；这是取样脚手架，会影响可获得的中途状态，须作为外推限制。

**KEEP**：保持检查点时的任务范围、负责人和依赖，允许补齐通常的复核设置、继续修复及交付。**C1/C2**：模型依据同一项目图提出的至多两个结构性替代方案，可以改变尚未开始的工作范围、负责人、实施/证据方式或依赖。它们不是预设的两类组织，名字只是该题候选编号。仅补齐复核配置不算独立结构方案。

## 3. 何时允许提出新方案

检查点要求：member_001有实际工作编辑；其最后一次工作编辑之后执行过公开测试，收集数大于零且至少有实际通过、失败或错误等用例结果；仍有未开始的可变工作；团队尚未终止，剩余额度至少200万token。

这个门只说明“现在可以评估分工”，不说明“现在必须改变分工”。旧组织需求检测保留为被动线索。零测试收集不再合格；测试失败也可以提供真实信息。该门只依据001有权限看到的事件，因而不覆盖伙伴先完成工作而001尚未测试等状态。

项目图沿用事件增量维护：记录工作与代码区域、测试与版本、补丁与采用、成员责任等关系。真实回执、静态关联和模型假设分层保存；旧版本测试不冒充当前证据，依赖声明不冒充语义证明。只读图审阅输出与公开状态共同提供给组织架构角色，不提供伙伴私有历史、参考修复或官方评分反馈。

每题至多两次方案请求，第二次仅纠正格式或合法性错误。第一份响应已有有效方案时不为凑满两个而继续请求。静态合法、结构不同和工具参数校验通过才保留；这不保证真实成员随后接受或执行。无有效响应时系统回退KEEP，单列回退，不当作模型主动认可KEEP。

所有候选先冻结，才读取任何续跑结果。每个候选从同一前缀独立恢复，无共享后续补丁或反馈。KEEP明确收到维持分工指令，不能被共同架构建议误导成执行另一方案。其他方案仍须真实select、offer、accept及后续实施，不由宿主直接改负责人。

## 4. C/N怎样影响下一轮

选择器用12个有界特征描述项目状态与候选分工：预计负载平衡、跨负责人依赖、验证欠账、预计集成欠账、协调步骤、预算压力×协调、依赖×验证、跨多个需求的工作比例、独立复核比例、已有代码区域证据覆盖、失败测试×分散实施、未验证关系×分工改变。它不使用题号、仓库名或候选ID做学习特征；这些是状态描述与启发式估计，不是成功奖励。

每题在结果出现前计算选择概率并固定随机数，选中的候选优先派发，作为该策略的主选择；同题其他候选也真实续跑，作为完整对照。模型仍可能拒绝建议，故同时记录“选择了什么”和“实际执行了什么”。

**C（贡献）**来自同题真实结果：效用=合法正确交付指示值−0.1×该分支逻辑总token/500万；再减去当前选择概率加权的同题平均效用。代码正确率另外报告。一次续跑是有噪声估计；全部失败时仍可能仅产生成本差异，不能解释为提高了成功率。

**N（欠覆盖探索）**比较当前候选集合中参考概率质量与实际选择概率质量，取正的log比。分别按粗粒度的项目—组织映射特征分组和角色标记结构分组计算，各占一半。映射特征采用固定区间0、(0,.25]、(.25,.75]、(.75,1]；结构签名包含成员角色、复核角色、工作方式、范围数和依赖角色对，排除工作ID。它不是完整图同构，也不是跨任务累计访问次数，更不等同人类意义上的创新性。

初始选择概率与均匀参考相同，因此第一轮N为零。第一轮结束，用完整同题结果形成C/N目标分布，拟合共享12维参数；第二轮用更新后的参数选择。第二轮评分后可再更新一次，但该第二次更新在本轮没有第三批新任务检验。只有候选至少两个、全部评分明确、特征存在差异的题才用于更新；不拿部分结果、未知或单KEEP伪造更新。

固定参数：epsilon=.05、Tc=Tn=1、alpha=beta=1、rho=.8、eta=.5、探索混合=.05、漂移正则=.1、400步、学习率=.05。完整参数见selector-spec.json。模型权重不训练；更新的是小型组织选择器系数。

## 5. Token、现金与执行

每条逻辑任务仍最多500万输入加输出token，包含共同前缀、图审阅、方案生成和该分支续跑。前缀最多200万，图审阅最多8万，方案总计最多20万；续跑取500万减实际已消耗，不另送额度。每题共同开销物理只付一次，比较每个分支时分别计入，不能把分支逻辑均值直接当API总账。供应商usage为总量依据，缓存命中输入不重复相加。公开测试CPU时间另报。

沿用累计1100元账本，准备时已结算813.20397632元，余额286.79602368元；本轮新增预算0。为后续确认留100元，新准入以累计1000元为界，可使用186.79602368元。先预约共同准备，完成后按实际剩余token一次预约该题完整候选集合；不先启动一个候选再因现金不足丢掉其余候选。在途任务不因现金线中断，原token/时间边界不变。费用估计上限按现有8000纳元/token记，实际按账本结算。若仍有活动任务可释放预约则等待；否则记录未准入，不无限等待、不偷减支持集。

最多8路生成、4路环境启动、2路异步评分；每轮只有2个前缀，续跑最多6路。普通用户协调服务上界64CPU/512GiB；单执行和评分容器4CPU/16GiB、无GPU、无宿主目录绑定、无网络。只创建和清理本批对象，不修改共享服务器设置。异常按题隔离，评分故障最多对同一锁定候选重试一次；三个不同任务出现同类公共故障才暂停新增准入。没有自动新模型重采、补题或v225启动。
