## 3 本轮具体资源政策

### 3.1 取消人为并发上限

物理GPU0—7均可使用，不再设置“最多3个resident”的固定限制。派发由原任务依赖、每卡实际可用容量、设备身份及现有本项目任务占用决定；每张卡同时只放一个本项目resident。仍在运行的原Q+所用GPU2在其完整退出前不派新worker。

原开发库存由4个每组4槽的宿主worker拆为16个每组1槽的worker，使每个已具备状态依赖的原slot都可独立申请显卡。原slot_id、root、seed、先手、状态分支、成员生命周期、总额度、验收与顺序标识保留。新worker名与原worker归属一一记录；宿主拆分不产生新增模型样本。可用显卡按当前空闲容量降序争取，不设置额外60秒稳定等待，不以GPU利用率作为空闲资格。

### 3.2 同进程固定显存预占

新worker装载模型前先建立其自身CUDA allocator缓存。单次派发的预占目标固定为：`min(73728 MiB, 当前实测空闲显存−1024 MiB)`；最低目标45056 MiB（44 GiB），因此装载前至少需要46080 MiB（45 GiB）实际可用显存。目标、实际采样、GPU UUID与worker身份写入冻结的派发记录。

预占采用未初始化uint8分配，随后释放张量引用，使空间留在同进程allocator缓存供模型装载和后续计算复用。不会把大块无用张量一直持有到模型调用，避免自身预占挤占模型所需空间。该操作不执行模型推理、不生成训练材料、不改变参数、精度、注意力实现或RNG采样配方。

预占成功后的装载资格只允许把该worker自身、同UUID、精确PID的已预占空间加回其可用容量；不能把其它进程显存当作本任务可用资源。缓存证据与模型占用分别记录；启动占位产生的峰值单独保存，并在模型加载前重置峰值监测计数，避免把占位峰当成训练张量峰。环境明确使用native CUDA allocator，仅改变显存分配政策，未更改算子、dtype或采样。若模型加载前发生真实预占竞争，仍停留在零模型调用的资源等待阶段，只重试资源取得，不重试已开始的模型更新。

预占是本进程可复用缓存，不是操作系统或集群调度器提供的独占GPU租约。实际OOM、进程异常或硬件错误仍须如实保留；不能承诺外部环境变化下绝对不中断。

### 3.3 停止规则的明确改变

取消“共享设备空闲显存低于6144 MiB即杀死本worker”的规则，也取消与高显存预占冲突的原56 GiB本进程显存上限。设备空闲显存仍作为诊断记录，不能单独触发运行中训练终止。真实OOM、进程死亡、设备/进程身份不符、无法确认费用或状态等实际故障仍按完整性机制处理。

存储、CPU内存、设备身份、遥测真实性、训练调用计数、各槽业务预算与模型请求记录等必要守卫保留。资源等待与真实计算分别记账；预占等待不计入训练计算区间，但实际GPU worker占用时间照记。原Q+仍由原监督器独立持有，本轮不信号、移动、重启或热改该进程。
