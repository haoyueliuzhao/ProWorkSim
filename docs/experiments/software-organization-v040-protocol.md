# v0.40：互补初始诊断与共同交付说明的冻结协议

本协议在任何v0.40模型调用前制定，实施2026-10-09用户“参照审计修订并开展后续实验”的授权。依据为[用户提供的审计正文](../reference/audit-v039-next-v040.md)；正文链接的额外完整方案、算术附件和脚本未作为本地原件读取，不声称已读取这些额外文件。

本轮先修正执行前成功阻断的普通未知工具名错误分类，再观察两个因素：初始技术证据是共享还是分置，以及共同交付说明是否改变成员的工作组织。全程冻结原9B 3/3 common，不重复出生/替换接口诊断，不设置X3外生出生。

## 1. 保留旧结案，另立16槽新库存

v0.39原24槽继续保持21已知、1技术未知、2未启动。那一条的固定树原检查通过，不改变正式未知；新错误政策可能带来后续新行为，不能把它假定为继续也必然成功。不重放旧槽，不把两条未启动库存补齐后改称原比较完整。

新库存为两个具名承接态开发变体×两个信息条件×两个说明条件×两个新seed，共**16条**。每槽128决定、128attempt、500000实际token、32次run_tests；合计上界2048次attempt、800万token、512次成员测试工具调用。上界不是实际消耗、GPU时长预测或达到期望行为的采样目标。

所有条件初始两名中性成员，活动上限4、累计出生上限6，允许自主创建、退出和替换。等待者占活动容量，退役身份不复用。无永久经理、无预建执行任务、无固定实现/验证岗位、无最低消息/任务/成员数量；集中完成和始终不增员均合法。旧26次Contribution试训、3次正式更新、48条TextFSM独立确认与缓存生产验证继续暂停，新增反向及actor/critic更新均为0。

## 2. 普通动作错误与真实完整性故障分开

v0.39的`work_done`在没有执行世界动作、原输出和费用可信时被旧SDK归入不可恢复权限边界。v0.40对当前新运行器明确选择新的错误政策，不自动把名字换成`staff_done`。

| 情况 | 本轮行为 | 评价与记录 |
|---|---|---|
| 未知工具名，身份/记录可信，执行前拒绝 | 不调用executor、不产生对应世界动作；原错误反馈进入下一真实输入，成员自行纠正 | 可恢复动作错误；原决定、输出和token照计 |
| 普通公开参数schema错误 | 保持真实拒绝与后续反馈路径 | 可恢复；不免费重试或重置预算 |
| 明确禁止的controller能力请求被执行前阻断 | 权限保持关闭，单列过程违规，返回拒绝后仍可继续 | 记录可信时不自动转技术未知；可判定的正式R受过程违规约束为0，内容原检查另存 |
| 工具调用身份错配、未授权效果真实发生、世界/记录/结果不可信等真实完整性故障 | 保持原关键停止边界 | 正式结果未知/阻断，不伪装修复 |
| 合法staff_done | 成员主动永久停止自己的机会 | 不自动提交、完成其他成员或改业务结果 |

禁止模糊匹配、隐藏fallback或将未知名字映射为真实工具；controller工具不在成员可调用表中。拒绝后的下一机会是实际采样，使用原共享预算。普通错误不能抹掉先前错误；实际禁止过程也不能靠最终内容通过补偿。

共享SDK只增加一个受保护的未知工具名分类钩子，其默认仍等价于原行为；新`OrganizationHarnessWorker`明确选择v0.40分类，初始成员和真实出生的新会话使用同一政策。除该非数值SDK文件外，继承的Python源码逐字核对；变更文件的新旧hash、CPU资格和新协议版本进入计划。actor、critic、优化器、采样和推理数值源码不因错误分类而改动。

必要CPU控制使用原v0.39真实`work_done`输出作反例，核对提交前/后未知名的零执行、文件/固定提交不变、错误与费用保留、下一实际输入含反馈；同时覆盖controller拒绝、真实关键边界、合法done及预算不重置。不加载9B重证同一错误分类，不重跑整套旧平台资格。

## 3. 两个承接态开发变体

| 新root | 原开发来源 | 初态性质 |
|---|---|---|
| sc-record-views-handoff-v040 | v039 record-views | 已有共享记录、报告与查询分支，保留少量顺序/位置兼容缺口 |
| sc-record-catalog-handoff-v040 | v039 record-catalog | 已有目录、报告与查找分支，保留少量重复键顺序/空值存在性兼容缺口 |

公开根合同、真实schema API和共享产品消费要求保留；初态不再是全部抛NotImplementedError的空桩。两个变体重新命名并绑定各自manifest/partition、初态文件hash与公共检查。它们是已用来源上的开发变体，不是新来源泛化、独立benchmark或确认集；不把与旧root的绝对成绩差解释为收益。

预置代码、已有缺口、初始化检查及其诊断全部标为环境准备事实，`model_generated=false`，不能算作当前成员的实现或缺陷发现。完整参考解与私有验收材料仍只在验收侧，初始副本只含允许的代码、公开合同和公开检查。诊断给出实际执行事实、测试输入/观察结果与初始版本，不提供正确补丁或分工方案。

准备阶段分别执行两组公开检查，形成diagnostic_a和diagnostic_b；它们对应不同公开调用方观察，可由成员自己重跑检查再取得。每个worker进程按case/初态文件/driver摘要缓存首份实际准备收据，后续同root槽可重用同事实；每槽记录实际执行次数、缓存复用、原收据和准备耗时，不虚构重复执行。四个独立worker的cache不共享，实际准备执行次数按收据汇总。

成员一次run_tests仍只执行一个完整公开driver，两个诊断组是该同一次实际测试结果的投影；另可运行一次成员脚本，保持每次工具调用最多两个隔离执行。初始准备检查不消耗成员32次测试工具额度，其CPU时间单列且嵌套于worker总时间，不重复计GPU成本。

## 4. 两个实验因素

| 条件ID | 初始证据I | 说明G | 初始两成员可见诊断 |
|---|---|---|---|
| SB | shared | base | 每人A+B两份 |
| ST | shared | team | 每人A+B两份 |
| PB | split | base | 每人一份，按冻结表分配 |
| PT | split | team | 每人一份，按同一冻结表分配 |

四条件的公开根要求、初态代码、工具权限、全部可运行测试和共享预算相同。分置诊断不是永久隐藏答案；任何成员可以通过真实消息得到伙伴报告，也可以自行检查公共代码和运行相同公开测试重新取得事实。初始证据位置与最终工作责任无绑定。

初始诊断由各自实际观测进入SDK/selected输入，计划中的完整诊断表只用于host记录，不能通过case元数据或公共文件把未分配报告暗中加入split成员输入。另有紧凑的公共诊断元数据，不携带宿主缓存路径或其他条件的标识。每槽重新绑定相同初始文件的本世界baseline reference，缓存不复制私有历史。

后续自主出生的成员取得公共基线、共同根目标及预算，但不自动赠送任何初始诊断。父成员可以在自己生成的briefing或消息中分享其实际拥有的信息；新成员也可自行运行公开检查。该规则在四条件一致。

G-base沿用现有业务任务/工具说明，仅统一新错误政策和环境准备事实的必要标记。G-team在相同基础上额外增加下列固定原文：

> The final evaluation concerns one shared team delivery. Members need not each complete an independent full solution. Decide yourselves whether dividing work, sharing discoveries, reusing another member's work, cross-checking, or recruiting would help, and choose the arrangement you consider appropriate. Concentrated completion is valid. No minimum number of tasks, messages, or members is required. All activities spend the same shared budget; the system does not assign responsibilities.

这是一项明确提示干预，不给具体任务分解、顺序、职责或正确代码，不要求首轮通信。若只有team条件出现协作，只能解释为该说明下行为被引出，不能说训练获得了能力。各成员观测持续携带自己获配的初始事实，后续实际输入与历史仍受原上下文选择器约束。信息位置会改变初始及后续prompt长度和取得信息的成本，说明也增加文本；这些都属条件效果，不声称隔离了“纯交流收益”。

## 5. 事前平衡与调度

主seed固定为**202610090301、202610090302**，不使用v039 seed。r0为views-handoff，r1为catalog-handoff。每个root/seed独立worker执行四条件，从同完整common恢复一次，各episode独立新世界/会话并各自重设一次采样seed；出生不重设seed。

| worker | root/seed | 条件顺序 | 先手 | split中A报告归属 | 先手拿到 |
|---|---|---|---|---|---|
| block-r0-s0 | views / 202610090301 | SB→ST→PB→PT | member_001 | member_001 | A |
| block-r0-s1 | views / 202610090302 | ST→PB→PT→SB | member_002 | member_001 | B |
| block-r1-s0 | catalog / 202610090301 | PB→PT→SB→ST | member_002 | member_002 | A |
| block-r1-s1 | catalog / 202610090302 | PT→SB→ST→PB | member_001 | member_002 | B |

每条件在四块中恰有一次首先运行；先手身份、A诊断归属身份各均衡为2次。每root跨seed更换先手，先手分别取得A/B，避免始终先拿同类信息。shared条件保留同分配表用于配对说明，但实际两人各见两份。四条件内共享同root/seed、先手和对应分配，不按结果改表。

最多4个resident，各占一个允许的物理GPU；同episode成员顺序调用。四个root/seed块可以并行，不冒称同团队内部加速。真实完整性故障或资源中止保留原槽、停止该worker剩余条件，其他独立worker可继续；没有slot-result的中断槽也读取已存组织证据/预算，明确标注partial、未结算和未报告成本，不能将实际工作漏作零成本；没有自动重试、额外seed、原槽重采或试到合作才结束。

## 6. 主指标与预定义组织诊断

主指标仍为共同预算内的最后固定交付完整合格。成员自己执行当前版本测试、固定与主动提交；既有提交不自动终止其他成员，不自动补任务或固定。未提交时完整R=0，内容/过程分项保持未知；技术未知不填0，禁止过程标志与内容检查分层记录。

辅助指标为至少一条可核查的跨成员工作使用链，覆盖初始成员及后续出生者：

`具体事实或产物 → 实际分享/发布 → 伙伴实际selected输入 → 相关修改/验证 → 可检查工作结果`

自动代码链的最低证据是：A相对合法初态真正改变公开生产函数/类单元，edit绑定真实模型调用；真实固定发布；B的已执行selected输入取得精确版本事实（不能只有无绑定ID）；B明确整合且整合前该单元与A不同；B随后对保留该单元的精确版本实际测试。测试执行有可检查结果即可记录使用，是否测试通过、是否连接最后fixed及正式R另列，不能把使用自动称作收益或唯一因果贡献。

环境预置代码不算A的新增成果，无变化导入、独立相同代码、只提任务/patch ID均不足。复杂AST、多跳、输入绑定缺失等保留未知。自然消息包含的诊断/事实链仅自动产生语义候选，需要结案时结合原文人工核查；不因时间上发生编辑就自动认定“据此修复”。

`has_evidenced_cross_member_chain`取True/False/null：有上述明确链为True；完整记录且无已证实链或待判候选为False；只有待人工判定信息候选、复杂不支持关系或证据缺失为null。未执行/未测量/技术未知不能自动填False。

初始诊断分别记录原事实ID、初态版本、分配、实际输入可见性、通过消息到达、成员自行检查取得的当前事实。收到消息前已在自己实际输入拥有同报告、同次由环境/自己的测试独立取得、只有分配但尚无实际输入证据等状态分开；不能把重复分享写成互补信息收益。不同版本的重新检查不能伪称同一初始失败重现。

这不是新的庞大Mapper，不建立训练支持n+、频数、q/b或组织拓扑奖励。消息多、任务多、成员多不加分，集中完成也不扣分。

## 7. 结果比较与成本

每root/seed四条件构成一个配对块。冻结计算为：

- 信息位置主效应：`[(PB+PT)−(SB+ST)]/2`。
- 共同说明主效应：`[(ST+PT)−(SB+PB)]/2`。
- 交互：`PT−PB−ST+SB`。
- 另外列出base/team下的split−shared，以及shared/split下的team−base。

先在块内计算，再在原4块上平均。某项所需结果未完整时，该项全库存平均为null，不用成功/通信/三人子集代替原分母。只有两个root与两个seed，结果是有限开发观察，不构成总体稳定性认证。

成本包括全体成员实际调用、输入/输出token、格式/动作拒绝、测试、重复探索、人数变化以及初始准备收据。错误输出照计。初始诊断的环境生成成本不计为成员发现，也不从总worker成本消失。分置条件自行重跑检查/交流取得信息的成本计其实际预算，不额外报销。报告保留所有16槽，包括不交流、不增员、无提交、过程违规、技术未知或未启动。

## 8. 数值、资源与运行边界

继续原完整common的actor、critic、两优化器和训练RNG恢复保护；每episode冻结护栏保护学习状态、身份、软件绑定并恢复RNG，禁止学习logprob/更新入口。保留原16K/2048和精度，不增加摘要模型、上下文或新模型筛选。

物理GPU仅3、4、5、7，诊断查询也限定这些卡。容量不足等待，不借其他卡、不停止无关任务。沿用加载前空闲≥56GiB且连续观察60秒、自有显存≤56GiB、运行中空闲≥6GiB；单worker RSS≤64GiB、旧新轨迹合计≤128GiB、磁盘余量≥20GiB。加载900秒、单episode2400秒、准备/收尾边界600秒；不恢复已撤销的累计GPU、worker或统一墙钟限制。

16条的源码、资产、提示、诊断规则、seed、先手和顺序在启动前提交并从隔离clean源码冻结。持久监督结束后自动生成、提交和推送报告。当前实现阶段的CPU控制、真实模型运行结果与未来参数学习收益严格分开。

## 9. 必要验证与后续边界

只核验新错误政策、两承接态任务及实际初始诊断、shared/split的实际输入边界、base/team固定提示差、出生会话的一致政策、有限工作关系正反例和16槽编排算术。共享SDK钩子补一项旧默认行为控制；不因新版本号重新跑全部旧世界资格或9B出生/替换探针。

若team只增加消息却没有工作使用，报告组织表述被引出而业务合作未建立；若split事实真实共享并与后续工作关联，报告当前互补信息存在作用空间；若使用关系增加但交付没有改善，继续区分实现、验证和集成深度；若集中完成更好或各组仍无实质协作，保留负证据，不逐句调提示直到得到期待行为。

任何进一步扩展、修订后复验或恢复训练需另有明确任务与协议。本轮结果不自动触发144条、旧训练/确认/缓存队列。未来B/G/I比较仍应处于同一组织协议内部；本轮提示或信息布局的效果不是分配算法收益。
