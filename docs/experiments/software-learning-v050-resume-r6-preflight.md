测试覆盖：总计数含两外部更新及本宿主启动意图；多卡同轮逐次检查；占满4时禁止派发；一名额释放只增加一个可用位；资源失败重排仍计入上限；分支完成分别释放原8条候选；身份/终态不足不提前释放；完整报告与原checkpoint/方向/recipe/critic/预算绑定；行政标记与真实额外故障区分；原监督器模块配置不被新适配器修改。

## 原件和费用

[证据目录](software-learning-v050-resume-r6-evidence/)保存行政交接标记、交接前后r5监督器快照、16槽确认回执、CPU控制记录及独立审查。只对精确行政标记开放继承，不忽略其他mechanism-stop。两更新费用仍归各自原宿主，只计一次；新宿主的统计仅累计本宿主实际开发worker与资源启动尝试。

旧r5中转交的16条状态是未启动的行政停止，不能解释为16个新技术未知。其可能出现的closed_with_unknowns汇总原件保留；r6对Q−的完整性只通过原worker自身的报告、检查点和计算账本判断。完整终态比较仅容许父监督器聚合状态从running变为closed_with_unknowns这一元数据变化，不能容许检查点、来源、费用或真实worker终态变化。

## 部署与实际验证界限

源码和上述证据先提交推送，再从干净HEAD创建独立r6运行根并启动。实际总驻留由 `total_residents`、`maximum_residents=4`、`slots_available`显示；依赖等待、并发等待、资源等待单列。r4/r5源码和两个更新进程保持不动。

CPU验证证明调度逻辑可限制为4；部署后实际心跳和并发状态另记运行根 `deployment-observation.json`。本次启动时两更新仍活动、尚无r6开发worker，因此不能将模拟中的满4并发称为真实GPU测量。16条原库存结束后不自动追加实验。
