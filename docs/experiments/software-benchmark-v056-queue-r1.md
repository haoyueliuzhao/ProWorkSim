# v056 Qwen REF预算队列

日期：2026-10-24。队列只消费独立冻结的50题×4预算档、200个槽。源码入口为 `software_benchmark_queue_v056`，CLI为 `tools/run_ref_budget_queue_v056.py`；不恢复v054/v055旧队列。

队列从本轮 `residents/*/ready.json` 发现已加载模型；每个驻留最多一个回合，最多6个生成、2个官方评分。生成关闭并锁定候选后，评分进入独立队列，GPU即可承接下一题；队列不会为每题加载或重启模型。评分run identity保留条件、槽、候选及配置身份，不能跨预算条件复用缓存。

调度按冻结槽序在已准备好环境中选择，不参考成绩。每道题四档均由同一只读模板克隆新工作区，不共享补丁或反馈。最多向前准备两个尚待生成的任务；准备、生成、评分与完成后的缓存回收均有独立作业记录。回收异步执行，不让删除大量文件阻塞派发。

关键保障：

- `state.json`和独立job intent在派发前持久保存；一个槽只创建一次生成作业。重启时接管仍活的PID与start_ticks身份，不重发已进入作业；失踪且无完成证据的作业进入异常集合。
- 每个resident、每个grader及缓存准备使用独立排他资源锁。工作进程持锁跨子进程执行，协调器退出不杀正在运行的任务。重启不重载驻留服务。
- 按当前绑定预约生成64GiB、评分64GiB、冷模板准备128GiB；物理剩余扣除当前预约与新预约后仍需至少128GiB。内存保留128GiB并计活动任务预约；CPU负载过高时只等待，不干预外部进程。Actor的4CPU/16GiB/16,384 PID内核限制继续由runner执行。
- 单槽错误、坏回执或准备失败进入deferred，其他任务继续。评分是否静止依据scorer的同槽容器清理证明，不由退出码猜测；非零但已证明静止会释放grader继续工作，缺证才隔离该资源。共同冻结源码／计划身份改变则停止新增派发。
- 每题四档生成与评分均终态后，生成不可变队列快照，调用新缓存回收CLI再次检查四个消费者、PID/cgroup静止、排他锁和精确目录；只删除本轮该题rootfs。记录、补丁、评分、模型、镜像与资格元数据保留。缺证只记延后，不扩大删除范围。
- 全部槽终态且无在途作业后，按本轮 `service-unit.json` 的精确user unit停止驻留。未证实静止的异常resident保留隔离记录；不按GPU号杀其他进程。

启动需要 `--binding <文件> --binding-sha256 <SHA>`；绑定内容含plan、源码封存清单、评分器清单、镜像清单和评分公共配置。默认状态根为 `runs/software-benchmark-v056/queue-r1`。`--status`只读，不加载模型或派发；`--once`执行一次调度检查。

必要CPU控制：冻结就绪顺序、磁盘／内存门、单槽坏证据隔离、异常评分清理后继续、缺静止证据保留预约、重启接管、派发前意图落盘、一次性无模型子进程拒绝重放。控制不调用模型、Docker评分或真实仓库测试。

资源释放处理之后，退出前调用一次只读结果分析工具，输出逐槽结果和各题预算边界。退出码与日志保存在 `analysis_finalization`；分析异常单列，不重新派发生成或阻碍此前的资源释放。
