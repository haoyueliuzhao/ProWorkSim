## 五种选择器与两次真实更新

共同参照r为本状态冻结、去重的有效候选上的均匀分布，不宣称全组织空间均匀。比较q0、工作台账L_CN、项目关系P_C、项目关系P_CN和始终KEEP；P_CN为主要方法。

沿用七维框架。L为已有台账代理：范围计数下的成员负担、声明跨成员依赖、待验证计数、预计集成计数、动作步骤及预算／依赖交互。P替换前四项，后面三项保持对应计算：

- 负担按每项剩余工作的`(1＋min(4,可见区域数)＋范围锚数/2)`加权，证据模式乘0.5；与已用Token结合。未知区域按零已知区域和基本工作量处理，不认定无需工作。
- 跨成员风险来自持久保留的需求声明及可见代码区域重叠。两者分别仍是声明与协调风险，不伪称必要软件依赖。
- 验证义务使用工作当前修订、对应候选版本的明确复核及可见测试。无测试信息以0.5未知义务处理，有未闭合检查以1处理，再按8归一化；不是精确验证耗时。
- 集成义务使用可见伙伴产物、已采用记录、候选计划采用、伙伴剩余加权负担和已知冲突；均是代理量。

所有定义及缺失处理在开发结果前冻结。两个特征选择器分别从零参数拟合，不复制已拟合系数。沿用原有有界C/N变换和超参数：ε／支持混合0.05、温度1、α／β1、ρ0.8、η0.5、固定400步、学习率0.05；拟合平均KL＋0.05参数漂移平方。共享参数不含题号、仓库名或图ID。

效用U＝合法且正确交付−0.1×完整Token/5M。C为方案效用减当前分布下同题平均效用；N=max(log(r/q),0)。不奖励转交数、图边数或两人都改代码。正常拒绝、部分执行、预算耗尽及未提交保留为结果；技术未知不填普通失败。

窗口1全部有效候选运行后更新三套选择器。窗口2在结果产生前，用第一版P_CN和固定seed计算概率及实际选中方案；选中分支先提交运行，其余分支同样真实评估。窗口2结束后第二次更新，随后封存参数；确认数据不进入拟合。只有完整可判定候选面板参与更新，未知面板的身份与费用另列；若没有可用面板，明确停为无法更新，不假装完成。

## 确认分析

16个确认任务均运行全部有效候选，用相同结果按各选择器概率加权。主要比较P_CN−q0，其次P_CN−L_CN、P_CN−P_C、P_CN−KEEP；报告加权效用、交付、代码、Token、逐题差、仓库均值和留一任务敏感度。

每候选只有一次生成，16题不能当作48个独立任务；全候选计算不消除运行波动。KEEP也承担共同准备，不能等同于完全不生成候选的部署基线；全候选探测成本进入总账，不能用它证明N节省探索预算。
