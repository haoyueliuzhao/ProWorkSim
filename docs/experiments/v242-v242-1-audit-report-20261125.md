# v242–v242.1 双人组织策略实验审计报告

2026 年 11 月 25 日。范围为上次综合审计后的两轮实验。既往轨迹只用于核验观察方法和取样时机。

**两轮合计完成 1 个真实配对，目标为 6 个。** 唯一入选的 SymPy-19954 已有明确的实现者和复核者。允许策略 Agent 调整分工后，它选择维持原安排，两组最终都正确交付。**本轮验证了原分工可以解决这一起验证缺失；改组能否提高交付率仍待验证。** 另有 7 道候选题实际运行了 193 个新增行动机会，均未在观察期内取得预定异常的合格现场。[v242 结案记录](../../artifacts/software-benchmark-v242/multitype-r1/closeout.json) · [v242.1 结案记录](../../artifacts/software-benchmark-v242-1/precursors-r1/closeout.json)

## 一、两种条件怎么比，结果如何

两组从同一时刻保存的代码、分工、成员会话和剩余预算继续工作。**KEEP（沿用分工）**让原来两名成员直接继续。**OSA（允许重新分工）**先让独立的组织策略 Agent 查看发生了什么、哪些工作还欠着、目前由谁负责。它可以维持分工、提出调整或暂缓决定。执行器检查方案后，指定成员会收到当前行动安排。因此，即使 OSA 选择维持分工，两组仍可能有不同的行动提示。两组都用 DeepSeek Flash 非思考模式、相同工具和公开测试、同一官方评分器；每个分支共享 500 万 token，含此前历史，OSA 的决策调用计入本组。[配对协议](../../artifacts/software-benchmark-v242/multitype-r1/SymPy-19954/protocol.json) · [执行实现](../../src/proworksim/software_multitype_execution_v242.py)

**SymPy-19954 的问题出在交付前。** 公开测试已经通过，但实现者 001 尚未固定并完成工作包，复核者 002 也尚未正式接受该版本。OSA 识别出这两项工作及其先后顺序，保留了原职责。它将现场判为“依赖阻塞”，与事前登记的“验证缺失”不一致。下表按事前登记归类。[原始决策、执行与评分](../../artifacts/software-benchmark-v242/multitype-r1/successor-evidence.json)

| 同一现场，每组运行一次 | KEEP | OSA |
|---|---:|---:|
| 官方代码验收／合法交付 | 通过／通过 | 通过／通过 |
| 完成的工作义务 | 2/2 | 2/2 |
| 从分支开始到取得同版本复核证据 | 第 25 个行动机会 | 第 16 个行动机会 |
| 公开测试次数／同人同版本同入口重复测试 | 3／0 | 4／0 |
| 新增 API 请求 | 27 | 20 |
| 新增输入／输出 token | 1,756,804／6,964 | 1,286,695／5,011 |
| 含共同历史的完整任务 token | 2,915,235 | 2,443,173 |
| 续跑费用（元） | 3.0274 | 2.2166 |

两组均在最终版本上留下独立复核和合法提交证据。计入策略决策本身的 2,440 token 后，OSA 分支的续跑用量仍比 KEEP 少 472,062 token。两组分工相同、每组仅一次生成，无法分离行动提示与生成波动的影响。新增职责、额外成果及其采用率均无适用分母。[逐分支用量与工作义务](../../artifacts/software-benchmark-v242/multitype-r1/successor-evidence.json)

## 三、被动保存现场验证到了哪一步

新记录器在成员行动结束、用量结算后检查该成员看到的证据。遇到符合定义的异常且预算足够时，同时保存项目、分工、两名成员的会话和用量。OpenHands SDK 的脚本化控制在第 5 个行动机会捕获依赖阻塞，与同一时刻的对照保存点核对，项目、成员、调度和预算一致。该控制未调用模型。[SDK 控制记录](../../artifacts/software-benchmark-v242-1/precursors-r1/passive-controls.json)

对 5 个既定归档目录内的 **51 条历史分支、27 道不同任务**逐步回放后，得到下表。最后一列表示同类异常首次出现时，至少一个分支尚余 1,048,576 token；现金准入、当时可执行的改组方案及完整可恢复现场仍需另外核验。同一任务可能出现在多行。[逐分支回放证据](../../artifacts/software-benchmark-v242-1/precursors-r1/historical-windows.json)

| 回放中看见的异常 | 分支数 | 不同任务数 | 达到 token 保留线的任务数 |
|---|---:|---:|---:|
| 连续修复失败 | 7 | 6 | 4 |
| 上游依赖阻塞 | 3 | 2 | 2 |
| 集成冲突或回归 | 1 | 1 | 0 |

两道依赖阻塞题在触发时仍有约 213 万至 301 万 token，适合在自然发生的当刻留存。唯一的合并冲突出现在 SymPy-16450 分支第 40 步，只剩 476,557 token。回放可以定位原始事件，无法事后补出完整保存点。修订后的观察器还用历史案例核验了另一条边界：Astropy-14182 的两组最终版本均通过原目标公开测试，但只有 OSA 通过官方验收，因此局部异常解除和整题正确必须独立评分。[过程与评分的历史复核](../../artifacts/software-benchmark-v242/multitype-r1/successor-evidence.json)

## 四、合并成本与审计结论

| 在线支出去向 | API 请求 | 实际输入＋输出 token | 费用（元） |
|---|---:|---:|---:|
| v242：观察 5 道候选 | 173 | 11,816,776 | 12.2572 |
| v242：1 个正式配对，两条续跑 | 47 | 3,055,474 | 5.2440 |
| v242.1：观察 2 道有前兆的候选 | 35 | 2,240,818 | 2.0162 |
| **两轮合计** | **255** | **17,113,068** | **19.5174** |

历史公共前缀 1,151,467 token 计入 SymPy 两个分支各自的完整任务预算，本次费用仅计新增调用。候选观察占两轮新增 token 的 **82.1%**、费用的 **73.1%**。v242 首次恢复五个旧环境时出现工具登记不匹配，均在模型调用前终止；适配后五条均已运行。两轮结案回执共确认 18 个容器已移除，本批预约已释放。在 230 元累计上限下，期末可用 **68.6620 元**，已扣除历史保留额 0.262144 元。[v242 用量及资源](../../artifacts/software-benchmark-v242/multitype-r1/closeout.json) · [v242.1 用量及资源](../../artifacts/software-benchmark-v242-1/precursors-r1/closeout.json)

**审计判断：现场识别与保存已有工程证据，组织调整收益尚缺直接对照。** 本批唯一正式配对中，OSA 保持了分工。下一次最有辨别力的验证，是在原本就要进行的双人工作中捕获一次自然依赖阻塞，从该现场运行 KEEP 与 OSA，依次核对职责是否改变、成果是否被下游采用、阻塞是否解除，以及最终代码和交付是否通过。仅在同一现场确实出现分工差异时，才能进一步分析此次改组带来的行为差异。成员数量和 C/N 策略在本轮均未调整。
