# 中途允许调整分工的 15 题对照结果

按事先固定的全部 15 题，最终代码通过官方评分：KEEP 13/15（86.7%），OSA 12/15（80.0%）。OSA 减 KEEP 的通过率差为 -6.7 个百分点。独立 API 账本上限 190 元，已结算 126.70 元。

KEEP 让两名成员继续按原分工工作。OSA 在同一保存点多一次组织决策，可以改变分工、维持或暂缓。两组都用 DeepSeek Flash 非思考、T1 上下文和项目受管接口；每支的 500 万 token 包括共同历史。OSA 的决策调用计入本支。任务来自历史开发题，覆盖 7 个仓库。

## 两组都失败的具体例子

- Astropy-14598 的两支都通过 175 项原有回归，唯一目标用例都因长 FITS 字符串的单引号数量不符而失败。KEEP 修改写入时的切分，OSA 修改读取时的解析并增加测试；这两种修法都遗漏了官方覆盖的边界。
- Django-12663 的两支都通过 135 项原有回归，但在同一延迟对象子查询测试中失败。KEEP 分支在需要数字 ID 时交给字段一个 Manager 对象；OSA 分支交给字段的仍是包装后的 SimpleLazyObject。两份候选都没有修通目标行为。
