# v0.29 新来源当前策略经验分配：冻结协议与实现说明

本轮执行用户提供的 [v0.28 审计与 v0.29 建议](../reference/audit-v028-next-v029.md)。原 v0.28 按有限软件可行性与接口修复结案，原8槽跨接口结案账、9次历史尝试及原净AST Mapper结果不作改写。本轮结果必须分别标注 CPU 机制资格、真实模型工作、实际参数训练和独立确认效果。

## 授权与执行清单

审计原文的“GPU5单实例”已被用户后续明确指令覆盖：GPU0–7均可使用。累计GPU时长、worker累计时长、统一墙钟和队列截止均不设旧上限；该授权并不增加下表冻结任务数。没有创建显存预留进程，也不终止其他任务。每个resident owner单卡；支持采集只用一个owner，候选和正式分支可在空闲卡并行，最多8个owner。

## P0：共同执行合同

三来源原始资产、上游提交、修改和分区沿用已固定的 v0.28 新来源资产。本轮新增 `software_collaboration_v029.py` 将它们接入 WorldCore 与现有 SDK，保留恢复版工具、私有工作副本、固定发布、版本绑定分页、三方合并、动态职责和事件唤醒；不增加经理或替成员修代码。

每份完整有效交付必须固定在实际交付版本上，并同时满足：

1. 来源库与consumer的独立有限API验收。
2. 已登记的所选上游回归。
3. 在固定非空consumer输入上，执行期间观察到修复库API的真实调用，且输出正确。

调用观察基于同一固定树导入的code object和consumer调用栈；不改变库行为。sqlparse观察parse及Comparison.left/right；schema观察Schema初始化、description和json_schema；TextFSM观察初始化、ParseText及List.OnSaveRecord。该有限探针不证明任意反评分投机、所有输入被使用或唯一因果贡献。`independent_acceptance`记三项合取；`api_acceptance`、`regression_acceptance`、`consumer_api_observation`分别保留原始细节。

训练接口仍是既有 `SharedActor.update_window`、原终端MC、PPO、两个optimizer和原概率/梯度检查。共同起点先严格恢复v025-r1 actor/critic各3步的完整checkpoint，再一次性将旧critic三个数值坐标从provider/implementer/reviewer绑定为member_a/member_b/software_inactive。actor、critic、两个optimizer、RNG和已有步数全部不变。第三坐标不产生角色或动作。此项是统一的数值迁移，不声称旧critic对新软件语义已有校准。新共同checkpoint在P1开始前保存，任何候选恢复后均可重新进入同一个原P1 window id；探测试训不累加。

基础recipe保持actor lr=1e-5、critic lr=0.001、clip=0.2、单epoch、temperature=0.7、最大输出2048、上下文16384；LoRA r=8/alpha=16/dropout=0，q_proj/v_proj。不搜索模型、精度、上下文或harness。

每个请求在模型生成前落盘。完整SDK请求、上下文选择后的实际请求、选择索引、真实tokenizer计数和原始返回token_trace分别保存。学习输入只取resident实际返回的输入/输出token IDs；重新tokenize选中请求仅用于等值核验，绝不把已移除历史补回训练。所有member实际动作保持原始归属，即使代码之后被覆盖。

## P1：有限过程表示与支持门

主Mapper版本为`software-work-process-v0.29`，只用于本轮新来源，不回填旧结果。三个中性类别为`concentrated_delivery`、`contract_work_before_import`、`contract_work_after_import`。它记录契约接触工作与有效伙伴导入的可观察先后关系，不承担最终净代码作者证明或因果归因。

契约接触限于来源冻结的具名方法/consumer函数，以及实际执行并保留的成员断言；代码差异按去文档字符串AST作有限语法识别，结合实际版本与工具回执。无关函数、注释、已撤销修改、无效/无变化导入和仅发送消息不能制造第二类。完整有效交付是映射前提。冲突修复和后续重写可以存在，但必须保留边界，不称为全部输入持续保留。

同一sqlparse case、member_a先手；每个成员最多48次决策（团队96），8条共768次调用上限。固定先手不固定职责，任何成员均可集中完成或协商转交。最低类频数2，不合并先手、情况或用途。

## P2/P3：分配与可解释边界

复用v0.27配置器的单窗口线性覆盖不足、基础锚变体：N_z=max(0,1−K b_z)、q0=b，完整Helmert正负方向有限差分。ratio范围[0.5,2]、TV≤0.2、probe TV=0.05、两锚系数1、beta=0.25。G在同一合格成员块逐原始经历选权，I按可靠过程类别共享权重，二者使用同样的支持和覆盖先验。

G试训数=1+2(n+−1)，I=1+2(K−1)，共享B只执行一次。n+≤8、K≤3，最多19个唯一候选。完整候选清单在任何schema反馈前由实际支持冻结，不能删原材料或临时截断G方向。先运行共享B，兼作第一次真实训练消费和实际成本核验；之后其余候选并行。每个候选均恢复同一完整checkpoint与训练RNG，实际消费同一8条P1经历。原概率/梯度门拒绝或actor零步结果保留并终止该分支，不把未更新模型的开发分数当作更新后C；原学习器允许零梯度critic不走optimizer，实际步数如实记录。

C只能来自候选实际更新后4次schema完整工作结果（已知R0/R1；未知单列）；不使用训练奖励、类别名称、合成效用或TextFSM选权。如果全部开发结果相同，报告贡献方向不可辨识，以及覆盖/基础锚导致的配置变化，不称为识别高价值经验。

配置确定后B/G/I各自重新恢复共同起点完成正式更新。TextFSM仅1个独立任务，每方法4次是局部重复，不能称12个项目或官方完整SWE成绩。分别保留完整交付、API、回归、consumer调用和路线，报告I−B、I−G及原始分子/分母；结果不支持广泛泛化结论。后继sqlparse由各分支自己的新策略产生，暂不额外训练。

## 成本、存储、异常

历史v025-r1一次完整更新有283个backward决策、92,010个输出token，实测41,613.2078秒，约11.56 GPU小时。这是旧任务实测参照，不是本轮时间预测。v028约1.6 GPU小时的冻结采集不能用来估计本轮可能达22次的完整训练成本。本轮分开记录试训、开发、正式更新、独立确认与后继工作。

单卡准入要求A100 80GB、空闲显存≥78,000MiB、利用率≤5%、无其他compute进程，持续60秒；监控不终止其他任务。单worker host RSS≤64GiB，原件总上限128GiB、数据卷预留20GiB；装载900秒、单episode2400秒、边界600秒，training任务无累计/统一墙钟上限。支持采集顺序执行，独立候选最多8卡并行。资源或技术终止均保留已生成原件、未闭合和未启动槽，停止依赖该阶段的后续分支。

运行器使用固定提交的独立checkout，避免日常工作区文档提交改变正在执行的源身份。后台finisher在有限DAG终结后更新 `software-allocation-v029.md/.json`，只提交这两份报告并按用户授权推送main，不添加任务、不重试模型、不移动已有结果。

资格只覆盖本轮新增链路：3来源联合/单侧WorldCore控制、有限过程Mapper正负例、实际token证据与原学习器的CPU低秩采样/反传/概率拒绝、用途和原分母、不具支持停止与完整方向DAG、预建SDK窗口及新来源token余量。它不重做旧50项历史验收，也不把程序控制当真实9B效果。
