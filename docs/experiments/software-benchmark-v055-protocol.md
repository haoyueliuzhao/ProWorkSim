# v055：DeepSeek Flash 六条件强模型对照

记录起始于 2026-10-21，运行准备延续至 2026-10-22，时区 Asia/Shanghai。用户授权新增强模型对照、尽量提高并发、独立直连网络、禁止模型联网查答案，并限定整体人民币预算为 2000 元。随后明确授权自主处理实施问题，单题异常进入集合、主队列继续，末尾统一处理。本记录描述新实验；v054 的本地 Qwen 实验及冻结文件保持原样。

## 任务与六条件

沿用 SWE-bench Verified 官方 test 固定 revision `78f471bf655a3137b2e8a75af1501690ec009ec3` 的全部 500 个任务。使用已经准备并验证的公开仓库初态、修复泄露后的固定镜像身份和官方评分环境；不重新下载权重或大批容器，不按 v054 或本次模型成绩选题。新实验计划 3000 个回合，六组各 500 个不同任务：

| 条件 | 实际求解接口 | 总上下文／单次完整输出上限 | 思考 |
| --- | --- | --- | --- |
| REF-thinking | 固定原生 OpenHands 单 Agent、原五工具与 condenser | 131072／32768 | enabled，high |
| REF-nonthinking | 同上 | 131072／32768 | disabled |
| MATCH-thinking | 原生 OpenHands，匹配项目资源配置 | 18432／2048 | enabled，high |
| MATCH-nonthinking | 同上 | 18432／2048 | disabled |
| PROJECT-thinking | 实际 S1 受管 OpenHands、World、Γ1 信息组织与交付流程 | 18432／2048 | enabled，high |
| PROJECT-nonthinking | 同上 | 18432／2048 | disabled |

每回合继续最多 500000 输入加完整输出 tokens、128 次模型尝试／Agent 决定、90 分钟软期限和 100 分钟硬期限；原生 condenser 与 Agent 共用账本。思考 token 属于完整 completion，计入输出上限、回合 token 和人民币费用，不另送免费推理额度。PROJECT 的公开测试、修改、同版本测试／固定／正式提交语义保持。没有新增不受管 bash、搜索、浏览器、多 Agent 或训练。

3000×500000＝15 亿 tokens 是理论生成上界，不是此次现金预算能够保证覆盖的消耗量。人民币限额先到则停止新调用并保留未完成状态；不能宣称因此完成了完整 500 题的六组评价。

题序沿用既有事前随机化的 500 题顺序，每题六条件构成一块，并轮转块内条件顺序，减少预算耗尽时固定先后偏向。每题原 seed 只作为实验身份记录；官方接口不提供本次可验证的 seed 控制，因此不发送不支持的 seed，也不宣称跨组随机轨迹配对。

## 模型与配置边界

官方 Chat Completions 模型名为 `deepseek-flash`；2026-10-21 官方价格页声明其对应 `DeepSeek-V4.1-Flash-1017`，支持思考与非思考模式、1M 上下文。实际 `/models` 返回的别名、显示名称及每个响应的 model／system_fingerprint 分别留存，不能将商业服务别名视为可校验的权重哈希或不可更新的模型版本。[官方模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

显式发送 `thinking.type`。思考组固定 `reasoning_effort=high`，省略不适用的 temperature；非思考 REF 请求 temperature=0.6，MATCH/PROJECT 为 0.7。按官方接口支持情况省略 top_k、repetition_penalty、Qwen 模板字段等，不能声称不受支持的参数已匹配。Flash 非思考 top_p 固定为 1，故不冒称沿用了 Qwen REF 的 top_p=0.95。工具回合回传模型实际返回的 reasoning_content，SDK 若丢失该字段，仅按原 tool-call ID 和等值参数恢复原字串，不虚构思考内容。[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/) · [工具调用](https://api-docs.deepseek.com/guides/tool_calls/)

MATCH↔PROJECT 在同一模式下比较项目执行层；REF↔MATCH 是资源／推理配置的组合差异。思考与非思考不仅可能改变推理轨迹，还受 provider 支持的采样行为和相同完整输出上限影响。这些不等于一个孤立参数的纯因果效应，亦不能把 API 模型替换后的差异算作项目训练收益。

## 输入计量与接口适配

采用 DeepSeek 官方 `deepseek-recipe==0.2.0` 的 V4.1 渲染和官方 1017 tokenizer。仅从清华／ModelScope 国内直连取得独立 overlay 和 tokenizer，共新增下载 19215853 B，未下载模型权重；具体版本、来源和 SHA 见 tokenizer 准备清单。Hugging Face 元数据直连超时已记录，没有据此冒称与另一镜像逐字节相同。

本地完整请求编码计数加事前固定 128-token 工程余量，用于上下文和每回合请求预约；实际用量最终以 API usage 为准。本地计数不是服务器签发的精确 token 数，代码与报告均明确标记。费用预约独立按 provider 完整 1048576 输入上界计算，不把本地估算当成人民币安全保证。若实报用量超过工程预约，保留已消费记录并将该回合记为技术异常，不静默扩大上下文或重试。

PROJECT 保留 Γ1 信息变换和工具／World 生命周期；远程模型无法提供原本地模型的原始 token-ID 轨迹，因此使用实际请求／响应哈希及 API usage 的独立远程证据协议，不伪造 exact_native、输入 IDs 或本地权重身份。[官方 recipe 与 tokenizer](https://github.com/deepseek-ai/deepseek-recipe/blob/main/docs/tokenizer.md)

## 网络与答案隔离

本实验仅可信模型客户端直连 `https://api.deepseek.com/chat/completions`，固定 TLS 主机、禁止重定向、不读取系统代理，不部署或经过本地 LLM 反向代理。各进程显式清除六种代理环境变量，设置 NO_PROXY；不修改宿主其他项目网络。

模型仅获得原接口的本地 function 工具。不提供 DeepSeek Search／Fetch、server web_search、MCP 或浏览器；请求验证拒绝服务端搜索工具和远程图像／文件 URL。原生终端及公开测试处于私有无外网 namespace，PROJECT 继续使用受管执行边界；即使模型生成 curl、联网 git 或搜索代码，也无法从执行环境取得外部答案。模型既有训练记忆不因这项联网隔离而得到消除，不能据此证明无基准污染。[Search／Fetch 官方说明](https://api-docs.deepseek.com/guides/search/)

真实零模型检查已证实 actor 只有 loopback、外连返回 ENETUNREACH(101)、不可见 API key 或宿主 .env，4 CPU／16 GiB 限制生效。可信私有 SDK 首次因旧 CA 集缺链而 TLS 失败，原件保留；复制本机固定 CA 后仅补测原失败项，官方 `/models` 直连通过，TLS 校验未关闭。正式运行绑定该 CA SHA。隐藏参考补丁、验收测试、评分结果只在评分侧可见，不进入模型对话。

## 人民币预算与并发

全实验共享一个跨进程 SQLite 费用账本，预算为 2000 元，不按 API key 或组分别重复授权。准备、正式、condenser 及有可能已收费的异常都计入。每次网络请求前，以完整 provider 输入上界和显式 max_tokens 按峰价原子预约；成功后按 API cache-hit、cache-miss、完整 completion 结算。reasoning 已包含于 completion，不重复加价。用量未知或进程中断保留整个预约，不自动释放或重放。

冻结的官方 Flash 人民币峰价为每百万输入 miss 2 元、hit 0.04 元、输出 8 元，闲时减半。只有请求起止整个区间连同前后各 300 秒保护区均确定在闲时，才按半价结算；跨边界或不确定时按峰价。工作日 UTC 01:00—04:00、06:00—10:00 保守视为峰时，不推断节假日优惠。每笔保留价格依据与峰价等价费用。账本是保守费用估计，最终可与平台账单核对；不自动充值或提高上限。[官方计费规则](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

官方账户级 Flash 并发上限为 2500，跨 API key 合并计算。本实验共享请求闸门为 64，实际求解回合配置上限提高到 32，评分上限 4。每回合和每个评分任务保留 4 CPU／16 GiB 硬限制；调度根据宿主 CPU、现有 v054 活跃工作、内存余量及请求闸门取最小可用并发，保留系统／其他工作余量，不能仅因官方 API 支持 2500 就启动 2500 份代码环境。已运行任务不因降速门被杀死。[官方并发限制](https://api-docs.deepseek.com/quick_start/rate_limit/)

## 异常、冻结与结果口径

每个新回合有独立 slot、claim、工作区、费用记录和 systemd worker。单题运行、导出、评分异常记录在异常集合，主队列继续，不据成绩更换任务、补提示或自动重跑已经进入模型的回合。普通公共 API 故障采用有界退避，停止加压但继续收集在途结果和运行独立评分。鉴权、支付资格、费用完整性及总预算门仍是硬边界，不能以“异常不阻塞”为由绕过。公共修订必须另记版本和范围。

评分沿用相同官方 SWE-bench 版本及已准入仓库映射。run_id/cache identity 包含六条件、slot、候选补丁、attempt，避免跨组缓存污染。生成结束先锁定唯一终态代码候选，评分不回传模型，不据评分改选。PROJECT 另记最后合法固定提交与交付率；REF/MATCH 交付列为不适用。最后工作树与合法提交不是同一对象时分别保留。

每组报告仍以计划 500 题为分母，区分模型执行、接口覆盖、技术未知、未开始和共享预算行政截断。未定时只给已知成功数／未知范围，不能把未跑和未知填作模型失败，也不把已闭合子集比例冒充完整基准成绩。逐题按任务配对，保留仓库和条件层级。完整性未闭合前不作六组总体能力排序。

## 已完成的中性准入

六条件真实 SDK 合成路径先用程序化响应核对，之后按事前冻结计划每组最多两个真实 API 请求，一次完成工具调用及工具结果续接，共 12/12 成功结算，无重试、未知、正式题、评分或 GPU 调用。实际 90131 tokens，保守已结费用 0.05128168 元；费用保留在正式共享账本。原生请求实报输入较本地计数少 14，PROJECT 多 56，均被事前 +128 余量覆盖。这只是有限输入适配资格，不能宣称任意正式历史的服务器 token 数严格等同。

思考开关按真实请求记录；中性任务中空 reasoning_content／零 reasoning token 如实保留，不伪装为已经产生非零思考。正常路径资格通过不代替新 host 全生命周期拼接检查；正式派发必须在相应检查、六组条件／题单／源码冻结完成之后开启。后续启动状态与首批观察另行追加。
