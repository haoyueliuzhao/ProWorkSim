# v203.2.1 部署修订与准入记录

本轮按v203.2审计修复跨进程持久化、任务级观测完整性和信息边界，并准备新150元、12题REVIEW2被动观测Pilot。[冻结协议](software-benchmark-v203-2-1-passive-pilot-protocol.md)定义实验条件与第一波门槛。

## 已完成的工程修订

| 问题 | 修订及实际验证 |
|---|---|
| 内存待写队列无法跨进程恢复 | SQLite WAL／FULL持久化，唯一观测键、哈希链、持久投影游标；实际进程退出测试保留提交前／后的区别 |
| 同键重试因新时间戳被误判冲突 | 首次采集时间持久化，重送通过索引读取原时间；跨进程控制通过 |
| 旁路失败可能影响原执行 | 构造、写入及收尾错误分别留档；不会重放动作或替换原结果 |
| 生成线程创建的SQLite连接被HTTP线程使用 | 在实际捕获线程开关连接；真实传输方法的CPU HTTPS替身检查证明原请求和响应字节保持一致 |
| 现金已预约但环境尚未启动时失败 | 仅在资源未进入、物理模型请求为0的证明下释放入场预约；已付费身份不能擦除重来 |
| 仅看观察器COMPLETE忽略host未决用量 | 首两队准入同时要求独立host用量完整、实际调用、零未决请求；不使用模型成绩 |
| 全局快照被误作Agent知识 | 成员视图只来自自己的实际请求；未来、他人私有状态、未读取产物全文均不补入 |
| 一个缺口导致整题数据作废 | COMPLETE／PARTIAL／INVALID按任务及维度分开；缺交付保留有效早期责任材料 |

新模型侧仍使用原v141 REVIEW2工具、提示、角色、调度、通信和摘要。没有直接采用v157／v172的通信运行包，因为即使C0也扩展了工具；只复用了其已经修复的非权威观察桥。

## CPU和真实SDK脚本验证

- 持久层7项初始测试及1项新增索引检查通过，另10组实际进程故障控制通过。4个并发生产者的提交总序及各自顺序可恢复；落盘前的缺口如实保留。
- 视图／后处理25项CPU检查通过，覆盖局部有效性、跨成员和未来隔离、主账本／物理字节／旁路对账及六层判断。
- 实际OpenHands SDK 1.49.6加原REVIEW2 Harness的3个独立CPU进程，合计35个脚本物理请求、34个脚本响应、32个执行边界、4次微型公开pytest。正常组及观察故障组均完成原001交付；供应商异常替身组保留原异常。
- 新API初始3项、跨线程及现金释放增量2项检查通过；实际新队列与HTTP方法的8项CPU控制通过。

这里的脚本请求不是DeepSeek收费API调用。首轮SDK脚本日志没有时间戳，未为其补造发生时间；后续r2增加稳定时间戳并只做对应增量控制。首轮关联校验错误地假定payload直接含SDK model_call_id，后来按真实budget response_id映射离线补核，没有重做已经完成的世界动作。

持久层1024条、每条约4KiB的本机控制中，追加中位约0.407ms、p95约0.950ms，CPU约0.478秒、墙钟约0.508秒。Python跟踪内存从128条时18,601B到1024条时19,853B；不含SQLite本地缓存。此结果仅代表该CPU负载，不是长时间生产延迟保证。

证据目录：[持久性](../../artifacts/software-benchmark-v203-2-1/durability-r1/summary.json)、[实际SDK控制](../../artifacts/software-benchmark-v203-2-1/sdk-controls-r1/summary.json)、[时间戳修订](../../artifacts/software-benchmark-v203-2-1/sdk-controls-r2/summary.json)、[视图与完整性](../../artifacts/software-benchmark-v203-2-1/view-controls-r1/summary.json)、[队列及host控制](../../artifacts/software-benchmark-v203-2-1/queue-controls-r2/summary.json)。

## 环境和存储

12题身份及旧环境元数据已准备，当前资格需通过新gold／empty控制核对，历史10题已有资格记录不能冒充当前12题全部可运行。新离线SDK包r2导入及原件检查通过，归档约168MB，未调用模型。

部署检查发现/data0仅余约52GiB，项目Docker同样使用该盘；/data1实际可用约508GiB，但`/data1/zhuxinrui`指回/data0，不能误认为数据已经放到副盘。直接给旧历史目录加符号链接还会破坏`checked(ref)`的规范路径校验，因此未执行整批搬迁。

旧episode私有准入另有256GiB历史默认值，需要与本轮事先声明的128GiB门对齐；不会修改旧批次代码或共享Docker配置。本轮历史归档只针对已结束回合，完整验证原件可恢复后才释放展开数据，并保留账本、候选、评分和恢复映射。具体完成情况以归档回执及下面的启动记录为准。
