## 已有真实资源操作与CPU控制的区别

CPU控制自身没有模型、GPU或反向调用。与此同时，用户要求的资源预占已经实际发生：PID2111917、GPU2、73728 MiB allocator缓存，分配后live占位张量0、模型调用0。启动命令、bootstrap源码、PID/start_ticks、UUID、实际缓存和接管前状态按字节存档。不能将CPU控制的0 GPU调用扩大表述为本轮没有占用GPU。

预占进程不会先退出释放显存。新监督器先绑定所有权，之后原子写handoff；同PID保留torch/CUDA缓存、切换到冻结r4代码并进入Q+。原bootstrap实际argv和stdout路径保持如实记录，逻辑worker入口单列。预占时间与正式worker时间拆分，但总GPU worker时长只计一次。

## 集成审查

最终只读审查无未解阻断：handoff前已登记active所有权；handoff前校验失败不会杀死或释放资源预占；原stdout仍为lease/reservation.log；worker正式入口时间来自bootstrap回执；非子进程代理的255未知标识不冒充OS退出码。无法读取身份与已证退出分别记录，缺少可靠终态不能判成功。

接管直接调用run_worker，入口显式设置原CLI等价SIGTERM处理；每个Q分支保留原合法零步或更新后实际checkpoint准入，未把资源恢复收窄为硬性必须5/5。原数学H1函数、643条输入顺序、Q方向与权重保持，未按开发成绩选择材料。

本轮两个新计算窗口各135481秒。B与三次旧中断全部计入后，上界518399.8845150471秒，在原144小时内；旧各Q累计48小时门已明确替代，r3未消费170001秒不计成本。本回执不证明模型已开始或最终成功，真实加载/native/反向/optimizer分别由正式运行证据确认。
