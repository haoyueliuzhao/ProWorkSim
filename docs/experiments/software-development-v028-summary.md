## 上下文故障与恢复验证

16K来自本项目recipe设置。绑定的模型`config.json`与`tokenizer_config.json`均声明262,144 tokens（256K），但本轮没有进行256K推理容量或质量验证。

原`dev-1-first-1-r0`中，member_a用43行String片段覆盖整个fields.py，测试报错后请求完整diff。WorldCore差异为78,987字符，SDK将整条工具消息裁到50,000字符，模型可见diff剩47,922字符。第31次请求真实输入19,439 tokens，加2,048输出预留后超过16,384，生成未开始即被拒绝。这是上下文接口问题，不是GPU累计时长限制。

修订采用绑定固定版本的diff分页，默认4,000、最多6,000 Unicode字符，并保存完整差异SHA与分页游标；采样前按真实tokenizer计数，必要时只移除较旧完整工具轮次，保留最新反馈、system/user原文和采样设置。原请求、实际选取请求、删除索引与响应分别归档。

| 程序回归控制 | 输入tokens | 结果 |
| --- | ---: | --- |
| 原失败请求 | 19,439 | 复现超限 |
| 同一错误写入，使用新分页回执 | 7,961 | 预留输出后余量6,375 |
| 大diff属于较旧完整轮次 | 6,280 | 完整移除旧轮后可容纳 |
| 大diff仍是必须保留的最新轮次 | 17,481 | 明确拒绝，不丢掉最新反馈 |

同源专项14项门检查通过；20页拼接的完整差异与原WorldCore回执逐字及SHA一致。普通同源SDK/tokenizer资格4条程序路线、58次请求通过，最大输入7,824、最大程序输出635、输出预留后最小余量6,512。以上均未加载模型权重、未进行模型生成；首轮错误使用SDK已裁文本作全量diff参考的失败资格也已保留。

恢复轮172次真实响应均正常返回，最大输入11,540 tokens，没有再次发生上下文超限，亦未触发按token数删旧轮。恢复模型没有调用新增diff分页工具；因此真实运行观察与分页压力路径的CPU资格必须分别表述。三条恢复未交付不能归因于新context_capacity边界。
