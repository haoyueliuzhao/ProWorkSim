## 2. P0一次窄输入核查与新呈现Γ

事前固定原v0.33中两模型、ledger／settings、seed1的四个T槽，每槽抽四个工作阶段：首次实际调用、首次成功编辑后的首个实际调用、首次run_tests后的首个实际调用、终止前最后实际调用。按真实call去重，缺阶段如实标；选择规则与清单先落盘，再作计量。model_attempt开始与结束是同一调用，预算拒绝而未生成的机会不纳入实际调用样本。

每个样本从实际归档请求／上下文投影及原native tokenizer重建，并要求整段input IDs与原token trace相等；不使用字符数估算token。分别量合同、工具schema、任务板、历史观察、版本元数据、代码、最新反馈及残余。token归属有BPE和渲染交互，采用声明顺序的消除增量，使增量加残余精确还原总量，同时报告独立消除差的非可加性；不冒称唯一逐token语义归属。

已取得的CPU计量限于16个所选样本：原实际prompt为165457 token；固定已保留历史，仅去可证合同重复后141143，差24314；完整原请求走新Γ后144876，差20581。两者不同是因为去重后原容量策略可能多保留旧工具轮。约12.4%的后一差值是样本离线呈现计量，不能外推575次旧调用或未来工作成功率。

`software_context_v034`的合同去重层只在受管理user JSON观察中删除：完全相同的`root_goal.description`／`contract`，以及与最新完整合同完全相同的历史合同副本。最新观察保留完整合同；不同合同不删；该层不改其他当前状态、合法工具schema、助手输出或工具反馈。随后仍按原完整工具轮做容量选择，不切断工具调用／响应对。

P0参考路线首次native计量另发现：只做合同去重仍有3个请求在删除可删历史后超过16K，因为新公开测试反馈同时携带分组结果、原始执行结果和包含同一结果的stdout。首份失败计量保留，不作为通过证据。不能将全部反馈删减说成字节级重复去除：部分API返回trace、通过测试的业务值只存在于明细中。

因此本轮在世界端另外冻结公开测试反馈投影。通过的公开测试呈现ID、要求分组、通过状态及分组计数；失败测试保留业务expected／observed、异常、输入保持与API使用／观测完整性诊断；测试执行失败仍呈现失败诊断。原始执行结果、完整stdout和细粒度API返回trace留在审计原件，不在actor反馈中整包重复呈现。当前测试状态、当前版本／SHA校验和成员自测结果继续可见。这是新的反馈信息契约，不声称无损或行为不变，也不改变公开检查、独立验收或收费规则。前述16样本的12.4%只量合同去重，不含此新反馈投影。

原请求、选中请求、删除JSON路径／相等保留位置、文本hash与精确预算准备均归档。原收费账不改，未来实际使用多少就记多少。没有摘要模型、长期记忆系统、自动规划器或自动修复。

即使事实保持，呈现变化也构成新Γ，可能改变行为分布。不能将新输入与旧输入说成行为等价；后续B／G／I必须统一采用此Γ，旧诊断成绩不重判。

## 3. 两个新开发根目标

P1复用已存在、固定revision与许可的真实Marshmallow源码资产：`c7b559a1fa3aba57ca6dba0ab336841c5038a782`。新增的是两个开发合同和应用工作区，不宣称取得两个独立仓库或新来源确认。原库与公开测试只读，参考实现／独立输入仅在控制器侧。

| 根目标 | 完整成果与真实依赖 | 可编辑应用文件 |
|---|---|---|
| `mm-directory-rootgoal-v034` | 可复用RecordSchema规范化扁平name／quantity；catalog消费同一Schema结果，输出有序records与整数总quantity，支持空输入并保持调用方输入 | models.py、consumer.py、test_member.py |
| `mm-name-index-rootgoal-v034` | 可复用NameSchema统一名称规范；find_matches与export_names共享该规范，匹配索引／导出均保持原顺序，导出保留重复，支持空输入并保持输入 | models.py、search.py、exporter.py、test_member.py |

合法输入范围、精确输出和公开例子写入各自合同；名称仅包含声明的ASCII字母／普通空格，去首尾空格后非空；名称索引任务还做ASCII小写并保持内部空格。quantity限定0..1000整数及声明的十进制整数字符串。范围外、额外字段和未声明错误形状不作为隐藏验收义务。

本轮不组合金额大数、复杂精度、深层partial/default覆盖、secret投影等旧规则，也不把旧失败样本直接改成答案提示。输入保持、顺序、空输入、真实API与调用方一致性仍完整验收。

Schema的load／dump要求有明确工程对象：可复用库行为与应用消费者应采用同一规范，而不各维护一套互相偏离的转换。CPU证据记录实际API调用及返回规范结果，并检查它们与consumer最终结果一致。仍允许集中完成、分支实现、协商或重分工；没有强制消息、强制双方编辑或必须导入的加分门。

## 4. 可满足性、依赖与程序路线

每个root分别实际执行原始程序、只修共享Schema侧、只修consumer侧、联合参考四类控制，联合方案必须通过完整公开和独立验收。依赖证据还要直接绑定真实Schema.load／dump和消费者采用的规范结果，不能只因另一侧有starter缺陷就宣布存在依赖。

另以真实工作世界验证集中完成及分支发布／导入两种合法路线：写代码、运行测试、固定patch、必要时导入、主动提交、完整独立验收均经相同世界接口。路线的操作次数及native输入计量／输出预约范围与128／500000／32共同预算比较，说明探索余量。程序见证只证明路线存在，脚本响应不是模型采样，不进入提示或教师训练。

最终路线预算证明复用四条已归档SDK程序路线的47次请求，以最终纯反馈投影函数派生run_tests结果，并对Devstral脚本fixture的不合法call ID作成对合法化；其余请求字段逐项保持。由两模型真实native tokenizer共计量94个条件请求，输出使用可经原native parser还原相同操作的构造编码，并每步预约完整2048上限。这是条件成本见证，不是两模型真实执行过参考路线，也不将fixture的虚拟usage作为真实token账。最后的类型比较修订只离线复核已有观测；旧路线未读取发生hash变化的test_visible.py，但该差异仍在证据边界中披露。

公开检查覆盖各项要求的含义；独立检查使用不同输入。原始参考源码、控制脚本和验收数据始终不可作为成员观察提供，模型的执行任务表仍为空。

过程判定新增两字段：`required_process_satisfied`与`process_observation_complete`。若API跟踪完整，保留真实调用计数，包括异常前调用；若跟踪建立失败或缺观测，完整性为false、满足为未证明，不能将缺trace说成确定没用API。完整R仍要求全部原义务和固定交付同时满足，旧v0.33的R不改。

## 6. 有限局部可行性与结束规则

某模型四条全部可信、完整common恢复且至少一条T完整R=1，才是后续新训练来源支持规划的局部候选。多个候选按事前次序：

1. 四槽完整成功数多者优先。
2. 成功覆盖的新root数多者优先。
3. 全部四槽的实际调用token总和少者优先，不只挑成功子集算成本。
4. 仍平局按9B、Devstral固定顺序。

一条成功仅是有限可行性，不是稳定能力认证，不追认旧筛选赢家，不代表已有两类可靠方法或可辨识梯度。全部业务失败则本批按计划结束；不逐句改提示后重做相同库存。技术未知单列，不补成业务0；一个完整合格模型的候选资格不被另一模型技术停止抹去。

每槽记录固定交付、内容、规定过程满足、过程观测完整性、预算／停止原因及组织事件。任务创建、消息、版本导入等次数是过程观察，不自动变成类别、贡献或合作收益。没有主动提交的可变工作副本不补测并替代episode结果。

## 7. P2支持与P3公平探测的后继冻结

P1闭合后先公开全体结果及各精确情境的分母。P2选择正式训练用途的新任务与当前策略窗口，不能将P1成功池重新标为训练，也不能把不同模型、先手或参数状态混为同一ξ。重复数量与停止规则依据全体有效产出率、估计精度和成本规划；16只是审计给出的讨论档位，不是本计划保证的支持数量。

完整有效工作不等于两种合法方法，频数也不等于可辨识梯度。集中完成可以是一种合法方式，同一方式不能任意拆两类。失败、未映射和低频材料保留基础处理，不删掉后重算有利平均。有限配置研究无支持可按事前规则结案；完整在线线路仍应保留基础回退。

P3使用B（Q=B）、G-raw和I-P共享完整学习起点、原始材料、优势、基础mask和分母。G-raw按同一合格原始成员分支一般元重加权，不读取专用类别／图；已有G-lift仅为辅助。I-P使用中心化Contribution、对数N和历史／覆盖双锚；C必须来自候选实际更新后的开发工作，试训分支不累加为隐含正式更新，独立确认不回流选权。

按全方向有限差分、共享一次B，单成员块n+、K对应的唯一试训数为`1+2(n+-1)+2(K-1)`。n+=4／8／16、K=2时分别为9／17／33次，再加B/G/I三次正式窗口更新为12／20／36次，贡献开发执行另计。实际支持出现后必须先冻结可承担的完整方向或已校准的可扩展方案；可按固定顺序仅配置一个合格成员块，其余材料仍进入基础损失，不能挑掉成功分支缩减G的维度。

同正式更新次数与同总资源是不同问题。若比较总资源效率，要预先说明B节约的外层资源如何用于合理训练，而不是要求其空等。多窗口新策略重新采集／再配置／再更新及O3动态人数仍是后继研究，本轮小任务成功不替代它们。
