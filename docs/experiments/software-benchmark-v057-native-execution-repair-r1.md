# v057 原生执行改进：公开指南与一次有界纠正

本修订针对 v056 已观察到的测试入口选择错误、原生 terminal 命令格式拒绝、重复动作／只思考不行动，以及修复覆盖不完整。它是新的执行条件，不回改 v056 的提示、工具、候选或分数，也不宣称已测得正确率提升。

## 公开执行指南

`prepare_public_guidance` 只接受既有500题公开测试入口注册表中唯一、已准入、`source=public_repository`、`hidden_material_used=false` 的任务条目，并验证其任务、仓库、基线映射和解释器一致。模型可见投影仅含工作目录、实际公开解释器、仓库级公开测试前端和固定中性工作说明；评分端路径、FAIL_TO_PASS/PASS_TO_PASS、参考修复、特定验收文件和原评分不会进入投影。

例如 SymPy 使用该仓库的 `python bin/test`，Django 使用 `python tests/runtests.py --noinput --parallel 1` 作为入口。这里只提供公开入口，不谎称完整测试已通过，也不替模型选择隐藏验收所涉及的文件或测试目标。

固定工作说明要求区分题目的多个行为／接口，查阅公开测试和文档，执行聚焦验证与回归检查，诚实报告未验证部分。terminal 使用规则以明确提示说明：一项合法命令调用、主动串联依赖命令或自行编写脚本、正确处理仍在执行的命令。实现不透明重写、不自动拆分 shell 命令、不增加不受管入口。

## 一次有界的 stuck 纠正

`run_conversation_once_or_recover` 保留同一个 Agent、Conversation、LLM、工作区和累计账本，保持 SDK stuck detector 启用。SDK 首次以 stuck 返回时，若未触碰时间、次数、余额或未知用量边界，可发送最多一条中性纠正消息：指出重复／无有效行动，要求改变获取证据的方式，或诚实结束。后续实际请求仍由原精确计数器准入，纠正文字及新增行动消耗真实预算。

这不是模型请求重试或回合重采：不重置任何账本，不返还 token，不创建第二个 Agent，不恢复旧实验槽。再次 stuck 则结束；ERROR、FINISHED、预算异常等不因该机制继续运行。执行策略只允许进入一次 fresh idle 会话，不能反复调用入口取得新的纠正额度。每次 SDK run 的迭代上限收紧为原账本剩余 Agent 决定数，避免SDK每次run重新计迭代造成实际额度扩张。

所有run返回、纠正发送或拒绝均保存事件，包含前后尝试／决定数和实际已知用量。原始用户问题不改写，公开指南作为明确的新版本附加信息进入输入。

## 必要验证

两个针对性测试验证了公开投影不带隐藏元数据、拒绝错误来源，以及恢复不能突破预算／时间／次数／未知用量边界。

真实 OpenHands SDK 1.49.6 上完成三个 CPU 脚本化控制：

1. 四次相同think触发真实stuck，纠正后一次finish，共5个脚本化响应；原账本延续。
2. 四次think后获得一次纠正，再四次think仍stuck，总计8个响应，未出现第二次纠正。
3. 调用生产 `run_ref_budget_controller_v057.create_conversation` 工厂，保留原生五工具和新reasoning投影；仅执行内置think／finish，外部RPC禁止且实际调用为0，同样通过一次纠正闭合。

控制使用合成token计量单位，验证的是状态机和账本接线，不是实际模型tokenizer或生成质量。网络、权重文件和GPU访问均被审计钩子禁止，实际调用0；未运行基准题或官方评分。Ruff通过。

前两版控制失败记录保留：r1的断言错误来自对多行文本的JSON转义比较；r2已通过两个循环场景，但五工具整合缺少控制启动命令中的既有tools路径。r3按生产wrapper的SDK／tools路径运行，三场景通过。未为这些控制失败修改生产工具或放宽机制边界。

验证索引见 [validation.json](../../artifacts/software-benchmark-v057/native-execution-repair-r1/validation.json)。本实现只建立可运行的新条件；后续是否改善修复覆盖、减少循环及提升成绩，需要新版本下独立的模型评测，不能追改旧结果。
