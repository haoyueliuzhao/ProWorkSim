**Qwen 运行耗时与无动作循环审计（v089，2026-10-29）**

当前慢速不能笼统归因于模型较小或 GPU 算力不足。已找到具体适配缺口：长思考被单次输出上限截断后，没有工具动作或正文进入历史；SDK 只追加“请使用工具”的提示再调用模型。这会消耗大量时间而不改变工作区。另有重复搜索、同版本重复测试和无效测试入口。它们是已观察事实；修正后的速度与正确率收益尚未实测。

本次只读分析已有记录、指定 GPU 汇总状态和本项目进程。未重载模型、修改运行源码、执行容器命令或新增模型请求。对 slot325 已核实 controller 身份，通过只读 get_archive 取得 5 个指定文件，共 2.77 MB；完整原件留在忽略目录，来源、时间和 SHA 见[取样凭据](../../artifacts/software-benchmark-v089/qwen-performance-r1/slot325-live-copy-provenance.json)。

这不是“要求模型永远验证、不许结束”：原生 system 未混入 PROJECT 交付规则，最终自检也不是本例的主要循环来源。静态路径进一步定位到 SDK 的空响应分支与 reasoning 历史适配，详见[REF 要求与 SDK 审计](software-benchmark-v089-ref-requirements-audit-r1.md)。13 次纯思考截断有全量用量证据；第 201→202 次有真实输入前后证据，其余 12 次不冒称都逐份取回了后继输入。

20:40 的另一次动作快照包含 167 条 RPC：119 次 terminal、48 次 file_editor。其中有 4 次连续相同 grep，返回内容也完全相同；最后一次显式源码编辑后，同一 model_inheritance 47 项公开测试成功 3 次，又尝试了 6 个不存在的测试模块和 2 个实际收集 0 项测试的入口。多项失败通过 head/tail 管道返回 shell 退出码 0，正文仍明确 FAILED，因此不能仅以退出码判断通过。还有 6 次原生多命令格式拒绝及 1 次 create 已有文件拒绝。以上为已执行动作，不是隐含自动重试；[结构与例子](../../artifacts/software-benchmark-v089/qwen-performance-r1/slot325-redundancy-examples.json)保留索引与结果标记。公开测试通过不代表官方评分通过，也不能作为强制结束标准。加强验证的提示是否增加这些重复，需要单独对照，当前未证明因果关系。

两个样本组不是完整配对比较。REF 7 题均出现剩余额度不足以预约下一次完整输入＋输出而停止；PROJECT 的终止语义不同，不能因缺少同名字段就宣称没有预算截止。5M/7.5M/10M 是累计输入＋输出上限，不是单次输出长度，也不是预计一定消耗量。长期重复输入会快速用掉额度，但输入 token 比例不能直接代替预填充时间比例。[逐题计时](../../artifacts/software-benchmark-v089/qwen-performance-r1/episode-timing-proxies.json)与[汇总](../../artifacts/software-benchmark-v089/qwen-performance-r1/timing-summary.json)注明计时方法；REF 未计量公开测试不能填成实际零测试时间。

四个既有 resident 均在运行，PID/启动身份与原记录一致。观测中没有评分积压或资源准入阻塞；评分已经异步。任务补位中位数 14 秒，首次模型请求约 55 秒，正常评分在生成结束后中位数约 39 秒完成。公开测试确有 PROJECT 单次 380–429 秒的 CPU 阶段，但它不解释 REF 的长输出回合。[调度与评分证据](../../artifacts/software-benchmark-v089/qwen-performance-r1/scheduler-and-score-gaps.json)。

现有 vLLM 0.32.0 仍为单序列、关闭 prefix cache。三个当时执行 REF 的 resident，其现有日志中 Running=1 样本的输出速率中位数约 28–43 token/s，Waiting 最大为 0；这些是时间窗平均指标，不能精确分离每次 prefill/decode。三个 GPU 汇总样本为 98–100% 利用率，但共享设备数据含其他任务，不能据此认定本项目独占或始终饱和。模型服务宿主内存约 3.5–4 GiB / 96 GiB，未见由自身内存上限造成的等待。[已有 vLLM 日志统计](../../artifacts/software-benchmark-v089/qwen-performance-r1/vllm-last-ten-minutes.json)、[驻留配置](../../artifacts/software-benchmark-v089/qwen-performance-r1/resident-config-and-identity.json)。

优先修订方向如下，均尚未干预在途任务：

1. 修正 Qwen reasoning-only / length 的识别与后续处理，明确保留与续接语义，并给无进展纠正设可观测边界。不能仅把单次输出调小，导致更频繁截断；具体策略须在独立部署修订中验证。
2. 使公开测试结果保留真实退出状态、测试数量和可回读日志；对同版本重复测试、连续相同无信息搜索给出准确反馈。保留模型继续探索的能力，不把公开通过冒作隐藏正确。
3. 再验证 prefix cache 与会话交错。现有关闭缓存来自冻结设计；vLLM 的 hybrid/Mamba 支持有对齐限制，不能直接热开。缓存只节省共享前缀的预填充，不解决上述纯思考输出耗时，见[vLLM 0.32 官方说明](https://docs.vllm.ai/en/v0.32.0/features/automatic_prefix_caching/)。PROJECT 的 CPU 测试空档更适合同卡任务交错；需验证状态隔离和排队计量，不能把 max_num_seqs 改大就声称等价提速。

本报告不计算“预计无损节省 51.4%”：截断调用仍可能包含必要推理，修复会改变后续轨迹。它提供应先修正的机制及可核验基线；最终速度、token 与正确率变化须单独报告。
