# v231 上下文配对试验

2026 年 11 月 24 日。本轮要回答一个问题：在同一个修复现场，如果两名成员的职责、工具和可用预算都一样，减少反复发送的项目状态，最后能否花更少的 token 和费用完成正确交付？v230 已在固定历史动作下测得输入减少 36.78%。v231 允许模型自行决定接下来做什么，因此还要观察是否发生额外回读、返工或交付失败。[v230 回放结果](v230-token-efficiency-report-20261124.md)

## 怎么比较

每题从同一个真实保存点恢复两个独立分支。**T0** 将原有工作观察和工具返回完整呈现给模型。**T1** 保留同一成员有权看到的信息，从完整状态开始，后续状态只发送变化，重复的伙伴消息通过引用定位，较长的测试结果保留版本和诊断并可取回原页。两组共享已经作出的组织决定、唤醒与调度规则、DeepSeek Flash 非思考模型和公开测试入口。正式评分在生成结束、候选锁定后独立执行。

| 任务现场 | 两组共同分工 | 每个分支剩余的输入＋输出 token |
| --- | --- | ---: |
| Astropy-14182 | 001 继续实现，002 独立诊断并交接证据 | 2,548,142 |
| Sphinx-9591 | 001 继续实现，002 独立诊断并交接证据 | 970,203 |
| SymPy-19954 | 维持原分工，由 001 先推进 | 3,847,079 |

这些余额从每队 500 万 token 中扣除了原前缀和已经执行的策略决定。实际费用只记本轮新增请求。三题均是此前暴露过的案例，各条件在每个现场只运行一次，结果按题配对解读。[保存点及原始决定](../../artifacts/software-benchmark-v230/engineering-r1/next-paired-design.json)

## 怎么判断结果

每条分支独立记录供应商实际输入、输出、缓存命中、请求数、费用和墙钟时间。项目工具回执用于计数公开测试、测试结果回读及组织图相关拒绝。另行核对模型实际收到的观察和带版本的异常证据。官方评分分别报告最终工作树是否正确，以及是否形成合法、正确的项目交付。若生成、评分或观测异常，保留原始状态和已花费用；只有两臂均获得明确代码和交付结果才计作完整配对。

协调器同时运行同题的两个生成分支。候选一旦锁定即进入异步评分，最多两路评分。按整对的剩余 token 准入，优先调度余额需求最高的 SymPy，以便实际低于预约的费用能尽早释放。对账使用同一个获准现金账户，同一物理请求身份只消费一次。

## 现金口径

按三个现场历史上对应分支的实际用量和计价，两臂都走相同历史长度时，估算约 **17.07 元**。若各分支都用满剩余 token，总计 **14,730,848 token**，按 v229 平均单价约 **24.33 元**。这两个数都是估算。单价最高的输出 token 按历史协议为 8 元／百万 token，运行器按此计算整对最坏预约，最大的一对为 61.553264 元。实际成本按输入、缓存命中和输出分开结算。v229 结束时结余 70.95876312 元。现金是否转入本轮取决于明确的账户选择。

## 如何复核

- 三个保存点各自恢复到两种条件的首个真实模型派发边界。恢复验证使用本地冻结分词器，物理网络请求为零。首个请求的输入不代表整个任务的用量或正确率。[首请求凭据](../../artifacts/software-benchmark-v231/paired-r1/first-dispatch.json)
- 运行器、历史决定、原始配置和评分脚本的版本随协议登记。归档的代码和交付评分使用各自独立身份。[版本清单](../../artifacts/software-benchmark-v231/paired-r1/freeze.json) · [配对运行器](../../tools/run_context_panel_v231.py) · [结果统计程序](../../tools/report_context_pair_v231.py)
