# v066 评分续跑：原环境资格复用

本修订保留原 v064 官方评分器、测试和参考基线，只改变新批次的资源身份与派发范围。旧记录不改写，原 17 项代码评分和 7 项交付端点不重新评分。新评分入口只接受 v066 输出目录内、属于续跑 inventory 的新闭合结果。

## 复用与新增范围

原 109 项通过的 gold／empty 资格生成新的引用包装，路径为新 coordinator 的 `qualifications/<task>.json`。包装同时绑定原资格、原计划、新计划、续跑 inventory 和源码等价证据。新 `validate_qualification` 识别包装后，调用原 `software_benchmark_scorer_v064.validate_qualification` 验证原件，因此仍执行原始身份、镜像、基线、实际测试结果、命名空间、结束状态和完整清理检查，不能仅凭 `passed=true` 放行。

原 3 项环境失败仍保留为环境未准入，不新增控制或据此换题。其余 388 个环境各需一个 gold 和一个 empty，共 776 个新控制。其中包括旧 `django__django-14122` 被共同停止所中断的控制：它没有取得完整环境资格，因此以新评分身份做两项控制，不伪装成旧控制已完成。

## 等价证据范围

对新旧 scorer、grading environment router、offline Requests、TLS Requests 和 TCP transport 五个组件做 AST 比较。允许的机械替换只有 `v066` 到 `v064` 的命名空间归一化；scorer 新增的 `validate_qualification` 包装入口单独排除，并明确委托原验证器。改变评分函数、测试路径、环境逻辑、超时等均会使比较失败。

两份安装 manifest 中，除版本和已声明的新宿主源文件身份外，其余字段必须完全相同，包括官方依赖、原评分器、诊断解码器、归档与交付验证器、资源限制、能力清单和测试传输语义。新旧宿主派发 guard 本身不宣称等价：其有意使用不同授权、资源和续跑范围。它由新批次 source manifest 和授权另外约束。

## 验证

新增 6 项 CPU 测试通过，覆盖五组件实际源码等价、manifest 限制／解码器／依赖变化拒绝、旧资格验证的调用与失败传播、其他任务资格拒绝、776 控制清单以及旧成绩不可重新评分。Ruff 通过。

这不是新的真实评分结果。准备阶段不启动 Docker、模型、API 或 GPU。真实续跑的环境准入、代码评分和交付评分仍由独立 receipt 与清理证据确定；技术未知继续单列，不填成模型错误。
