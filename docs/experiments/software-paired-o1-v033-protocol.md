## 2. 模型与同一完整学习起点

只使用已有两个对象：Qwen3.5-9B原v025-r1端点在v0.30保存的common（actor／critic 3/3），以及Devstral-Small-2507在v0.31保存的common（0/0）。它们用于有限诊断，不是追认旧选型赢家。原权重revision、LoRA、精度、native codec、单实例共享actor、16384上下文与2048输出上限均保持；不增加常驻副本。

加载后核对实际profile、基座manifest、库版本和原common完整tensor digest；完整恢复actor、critic、两个optimizer、recipe及RNG。每个模型一次评估窗口包含8个独立episode，角色会话和世界不跨episode共享；每个episode按冻结seed重新设置采样RNG，参数及optimizer全程不变。评估结束核对原guard并恢复完整common，包括窗口簿记。开始、途中和结束的行为身份都保留，不能用随机新初始化冒充原起点。

原learning证据中的4条全token概率／反向、一次actor与critic诊断更新、保存重载及更新身份返回按原件SHA绑定；CPU静态与少量机制控制只检查此次真正改变的部分。原max≤0.02、mean≤0.002概率门和数值实现不改，但本轮不执行新的训练更新，也不对旧完整资格重复收费。

## 3. 固定16条库存与配对

根目标仅为已有`mm-ledger-rootgoal`和`mm-settings-rootgoal`。它们是已见开发材料，本轮明确为开发复测，不是新来源独立确认。相同root与seed上的S/T共享业务合同、初始应用代码、公开测试和独立验收；领域义务不删除、不添加已知隐藏失败答案。

seed在运行前冻结为`202610050701`、`202610050702`。每模型的顺序为seed外层、ledger再settings；第一seed为S后T，第二seed为T后S。T的第一机会在第一seed给A、第二seed给B；S始终只有A。这是事前对执行次序和对等成员标签的平衡，不追加第三个条件，也不能当作首手效应实验。

|---|---|---:|---|---|
| 1 | ledger | 202610050701 | S | A |
| 2 | ledger | 202610050701 | T | A |
| 3 | settings | 202610050701 | S | A |
| 4 | settings | 202610050701 | T | A |
| 5 | ledger | 202610050702 | T | B |
| 6 | ledger | 202610050702 | S | A |

两个模型执行同一库存，每模型8槽，总16槽。只执行一次；不会“修改一句提示—补跑旧失败—直到达门”。未启动、技术未知、合法业务失败分别记账，不补零或替换seed。

## 4. S/T实际工作条件

| 项目 | 单执行者S | 双成员T |
|---|---|---|
| 执行任务表 | 空，模型自行创建／修订 | 空，成员自行创建／修订和协调 |
| 根目标与验收 | 与配对T相同 | 与配对S相同 |
| 初始信息 | T各成员合法初始信息的并集 | 原来各成员合法可见条件 |
| 活跃会话与副本 | 仅A，真实建立一个工作副本 | A/B两个私有副本，发布后显式导入 |
| 参数 | 一个固定当前actor | 两会话轮流使用同一个固定当前actor |
| 调度 | 一个可运行成员 | 公平提供轮转机会，保留真实等待与唤醒 |
| 分工 | 允许集中完成 | 允许集中、协助、重分工；不强制合作形式 |

旧合同开头仅涉及“两成员”等组织人数的措辞在新S/T中统一为中性表述；两条件最终公开业务合同必须字节一致，前后hash和中性化范围单列。固定代码、测试driver和独立fixture保持，公开业务约束不变。当前只有对称的初始业务文件，信息并集可在实际port视图和可读文件hash上核对；不会把私有验收、参考解或控制器文件加入S的信息。

S不会额外建立一个不可用的B工作副本来假装单执行者。T工作中的新消息、局部历史、不同私有修改和显式集成是条件差异的一部分，不能共享为全知会话。没有预制“库／consumer”任务卡、经理、第三名成员或动态扩员。

## 5. 团队匹配资源，不按人数翻倍

每个episode共同上限：

| 资源 | S与T相同总额度 |
|---|---:|
| 决定机会 | 128 |
| 模型调用attempt | 128 |
| token | 500000 |
| 实际`run_tests`调用 | 32 |
| 单次输出 | 2048 token |
| 单次上下文 | 16384 token |

T共享同一持久账本，不是每人500000 token或每人64决定。每角色128仅作不高于团队上限的本地守卫；一个成员可以使用剩余全部团队额度，公平调度不强制各消耗一半。格式拒绝、等待、完成控制及失败输出仍消耗真实机会和已生成token。执行的其他工具也受共同决定数限制；测试额度按实际测试执行消耗，模型不能通过两副本分别领32次。

token账以实际选中prompt和原2048输出上限作生成前预约，完成后按原始response实际usage结算；额度不随角色切换重置。原request、选中request、input IDs、actor、window及recipe绑定，重复结算、身份变动、usage失真或越界单独报错。服务异常的未知使用量按已声明的保守预约结算并标出，不假装零成本。预约不是实际用量，二者分列。

只匹配上限，不人为让两条件强制消耗相同次数或token。T带来额外通信或局部重复阅读时，这些成本真实计入同一团队池，正是预算受限条件下的组织过程之一。

## 6. 本次统一接口修订

`submit_integration.message`如果只作为备注，不再要求模型为手续补一句文本；新公开schema将其改为可选，缺省只表示空备注。模型仍必须主动调用submit，现有当前版本测试、当前固定patch、来源与独立验收守卫全部保留。不会替模型补版本、补测试、自动提交或宣布通过。

新增显式`format_feedback_budgeted_v033`政策。普通native格式／公开schema拒绝保留坏输出，工具不执行，消耗当前机会并反馈真实首因；后续机会可继续直到共同总预算。原格式计数仍保存，但不再因连续2／累计4额外永久退休。旧冻结版本和旧分数不变；本轮两模型与S/T统一使用新政策，不声称这是隔离单因素的修复实验。

权限、身份、usage或关键trace／世界记录失真不是普通格式错误。其停止、未知结果和原件要单列，不能通过继续反馈将异常吞掉。有效业务工具返回的普通执行错误仍为实际工作反馈。

## 7. 测量、结果与解释

每槽至少记录：完整原始调用和生成trace、每角色及团队总账、实际测试计数、状态停止与等待原因、固定版本／测试／提交事件、内容正确、规定API过程满足、完整固定交付，以及开始／结束时间和零更新guard。

内容正确与规定API过程从同一独立验收分开表达。`input_unchanged`、字段、异常和业务值等内容义务不能因拆维度删除；`source_api_used`等明确规定的API路径另列。完整R仍要求全部原义务与固定交付。没有提交时，不猜测私有未固定代码会否通过，内容／过程可以标未知，完整交付为失败；关键执行缺陷则整体标未知而非业务0。

每个root/seed给S、T及`T-S`配对表，并计：均通过、仅S通过、仅T通过、均失败、未知。两seed只提供局部描述：

- 仅S通过：组织／局部信息／流程负担的线索，按原事件查依赖断点，不直接宣布协作有害。
- 仅T通过：有限互补或探索迹象，不宣布总体团队优势。
- S/T均失败：不能只责怪协作；区分领域合同、接口手续与资源中断。
- 格式或预算停止减少但内容仍错：工程改善与工作能力分开。

本轮没有单因素消融、参数训练前后比较或独立来源泛化估计。用相同根目标补上上轮不可识别的比较，不将其替代ID-VTDO方法实验。

## 8. 一次性结束与转向支持的规则

不继续沿用旧“所有类别至少2/4”作为无限前置。诊断全闭合后，在同一模型8槽均可信、完整common恢复、零更新的前提下，只要T至少1槽完整通过，就记录有限的局部团队可行性。若两模型都具备，事前次序为：T完整成功数更多；其次S/T均成功的配对数更多；仍平局按9B、Devstral固定顺序。此对象称为“后续新来源支持采集候选”，不称旧筛选赢家或通用能力认证。

所有T仍为0时，不强行选赢家，不重做本16条。下一步应冻结一个领域规则更少但保留真实API—消费者依赖的新根目标，仍空任务表、自主组织，不把正确分工预写进去。

出现局部可行性后，应转入新训练来源当前策略采集，重新测量M、n、n+、v与基础测度b，逐项检查完整有效工作、方法区分、频数和可辨识梯度。当前开发16条及旧36条不改用途；有工作成功也不能自动宣称具备足够配置支持。

控制器自动产生`next-stage-decision.json`，明确实际候选或无可行性及下一来源冻结工作。它不自动执行尚未冻结的几十次试训：真正B/G/I前须根据实际支持维度登记公平探测、完整学习起点、全部原始材料／分母、C的实际更新后贡献开发及不回流的独立确认。既不恢复已撤销累计时限，也不把取消时限当作无限试训或模型搜索授权。

## 9. 监督、资源与占用记账

两个模型最多并行两个owner，每owner单张空闲A100 80GB；GPU优先4、6，其余授权卡可用。仅使用已完成本地权重，不新增下载。可用容量持续稳定60秒后再分配，不为CPU开发提前长时间保留显存；不影响其他进程。

沿用单加载900秒、单episode2400秒、边界600秒、每worker RSS64GiB、旧新原件128GiB及卷预留20GiB的保护门；无累计GPU／worker／总墙钟／队列截止。身份绑定的监督进程只终止自己创建的worker，失败不自动重启；另一模型可独立完成。

每个worker成本保存实际分配起止。总体已记录占卡按每张GPU对worker与显存预约区间求并集，另列重叠与reservation-only，不直接相加已有两套累计值。[历史并集核算](gpu-occupancy-v030-v032.md)提供v0.30—v0.32校正口径，未取得ready时间的区间保留未知，不能用进程存活时长猜测占卡。
