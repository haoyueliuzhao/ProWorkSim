## 2. 软件工作模块的实际能力

[软件设计](../design/software-collaboration-v027.md)及 `software_collaboration_v027.py` 复用 WorldCore 的绑定身份、权限、原子操作日志、不可变版本与既有 Linux 测试隔离。两个成员 `member_a/member_b` 各持私有工作副本，可以：

- 读取、搜索、替换或写入允许的代码与探索测试，查看实际 diff；
- 原子领取、委派任务及声明有向依赖；责任变化不改写早先动作归属；
- 固定补丁、转交并集成对方精确版本；
- 在当前版本运行真实测试、固定提交集成代码，由父进程独立判断。

固定的是权限和工具规则，初始任务均未领取；没有固定谁只能提供信息、谁必须独自编码。任务依赖声明不证明执行使用；没有要求每次文件编辑另填 basis/adopt 元数据。测试执行通过既有 Landlock/seccomp 隔离，提交后的工作副本变化不改变固定交付。

集成使用真实 `git merge-file` 三方合并，不将后写入者覆盖当作自动解冲突。冲突标记保存到成员自己的新版本，必须由后续实际编辑处理。补丁发布和测试动作并不自动提交成果，成员须明确固定并交付。

当前两个开发情境均来自已有 Marshmallow 资产：

| 情境 | 真实联合要求 | CPU 程序见证 |
| --- | --- | --- |
| `marshmallow-interface-dev` | 新 String 可选空白归一化接口与 inventory consumer 共同变化，保留默认、dump和错误行为 | 集成固定树通过父进程29项API输入检查；仅消费者改动在实际执行中失败 |
| `marshmallow-integration-dev` | 空白归一化与 casefold 两个共享模块功能组合，保留原行为 | 各 feature 可以分别通过而合并产生真实冲突；修复后的集成树通过37项API输入检查 |

这些是**接口开发程序见证**。29/37是有限API输入数，不是软件任务样本量或全仓库回归规模；两个情境不是已经冻结的 A 阶段四情境。Marshmallow 没有变成新训练来源或独立确认材料。修改测试框架令子进程自报成功的负控，仍会被父进程实际API结果比较拒绝。

## 3. SDK 原始记录与工作 Mapper

`harness_collection._runtime` 只新增可选接口工厂，默认保持旧入口。`software_runtime_v027.py` 使用既有 HarnessPort、HarnessWorker 和 SDKStaffRuntime，初始化不采样、不操作世界；实际调用仍由绑定的成员机会执行。有限收集器预声明所有槽、当前 owner/window、种子、用途和调用上限，对话关闭后才调用独立验收与只读导出，不加载权重或自动训练。

真实安装的 SDK 已用受控 CPU transport 验证：两成员各三条合成响应、共四次真实软件世界调用，原请求/响应/token字段和 actor/action 回执保留；闭合后成功导出 TeamRollout 和 MemberView。**响应与token是明确标记的测试 fixture，不能称为9B实际生成或概率准入。** SDK与世界接线通过，不等于当前模型已经完成这些工作。

补充的两slot重复控制确认：同一case在不同真实实例/分支及seed下，完整业务初态、SDK policy和xi指纹一致，均可声明并关闭导出；没有为通过检查删除代码、权限、任务、操作ID或放宽原始绑定。运行身份仍各自保留。这项检查不是实际模型请求字节相等或重复运行逐token相等的证明。

`software_training_v027.py` 只读结束快照、独立捕获、WorldCore操作回执和固定版本，不重跑评分。工作有效性继续分为记录、权限、需求/产物关系、完整交付；方法路线按实际文件和产物关系映射为集中交付、分工后顺序消费、独立分支集成或真实冲突解决。类别不按哪条消息填了ID、最终奖励高低或开发成绩产生。

实际跨成员转换至少要求：对方固定输入、该作者在当前经历中确有相应文件编辑、合并确实改变同一路径的字节、actor/action回执匹配。纯声明、无变化合并及累积补丁中仅转带他人修改的情形不会凭发布者名字得到消费边。该证据是文件级执行关系，**不是所有导入代码最终保留或对结果有唯一因果贡献的证明**。

完整固定提交之后的私有编辑从该交付的方法证据中截断，不能反向把后来动作算成先前成功。未知独立结果仍为 null；无法可靠判定路线时保持 unmapped，而不是捏造方法支持。

当前软件条目的冻结 case 明确 `training_eligible=false`。`optimizer_scope_allows_update` 同时读取原始 manifest 的软件用途、reward合同及附加scope；删除scope或伪造 `optimizer_update_allowed=true` 不能把这个开发case变成训练材料。支持统计与原更新器共同执行该限制，语义可达性可报告，但不产生可训练n⁺或actor目标。历史非软件记录沿用原准入规则。

## 4. 通用第一阶配置规则

[配置器说明](../design/experience-allocation-v027.md)保留精确公式、输入、预算、未知处理与求解。新 `experience_allocation_v027.py` 不依赖旧 `joint_a` 或首类别：

| 方法 | 重配坐标 | 共同限制 |
| --- | --- | --- |
| B | 原始经验分配 | 所有准入actor项单位权重 |
| G | 每个合格原始成员轨迹 | 与I相同的合格分支、残余、比例/TV界和开发清单 |
| I | 精确情境下的成员—工作类别 | 类内共享q/b，其他成员/类别不转移质量 |

C由完整Helmert单纯形方向的正负配对有限差分得到；开发清单长度不限于六，未知不能填零。N只由当前已支持类别的覆盖不足计算；G与I使用相同的逐槽覆盖目标。基础锚与覆盖锚的KL系数均正，beta默认0.25但须在反馈前冻结；默认不代表最优。

G必须覆盖所有声明的原始轨迹方向，I覆盖所有类别方向；统一上限不能容纳G时明确拒绝，不随机截断一般基线。共同B回执可共享，成本不重复计数；I省下的探测量不空跑补齐。本版是有限完整方向规则，尚无大窗口低秩/梯度元优化版本。

多个块同时选择使用一阶代理目标，不保证真实开发效用线性叠加，也未声称选出的配置实际优于B。真实正式更新后的独立确认负责测量效果。全部没有可配置自由度时，绑定试训/正式更新接口停止本次有限试验，不自动运行回退B；未完成窗口由结构化诊断保留原M、unknown和not_started状态，不删槽后继续选权。

## 5. 原学习器的真实小模型 CPU 验证

新增 `test_allocation_update_v027.py` 使用实际小型 Torch actor、critic、优化器、采样、完整checkpoint恢复和autograd。它复用已有机械fixture，不是9B，也不执行软件任务。

一次该控制调用先用两次前置更新建立非空优化器状态；随后从同一完整起点分别执行 **9个唯一候选试训**（共享B、6个G、2个I），再执行 **无配置/B/G/I四个更新对照**。所有候选先真实更新再生成开发回执，排除了“先选权才允许试训”的循环接口问题。

开发回执来自预声明的**合成线性效用**，不来自候选模型的软件工作，因此这些真实参数变化不构成C有效性或算法收益。控制直接核验了：

- 每个分支恢复相同actor、critic、两个优化器、步计数和实际Torch随机状态；
- 显式B与不提供composition时的全状态、梯度和损失完全一致；
- G/I非单位权重改变actor梯度与参数，确实进入原损失计算；
- critic、critic优化器/梯度、优势、PPO比值和准入保持一致；
- 原始槽×成员×自身token的分母保持，未选成员与可信失败残余权重仍为1。

本次没有重写旧v0.25配置器、critic公式或参数概率门。新接口的试训/正式配置均需绑定原始 entries、固定声明、Mapper、tokens和response摘要。生产规模软件参数状态、真实开发执行与独立确认仍需另外核验。

## 6. 来源边界与尚未执行的实验

[来源说明](../research/software-sources-v027.md)核对SWE-smith官方固定提交的指定入口、SWE-Gym README和CooperBench README。SWE-smith用于主任务环境，SWE-Gym为备选，不引入其教师/SFT流程。来源门以仓库及谱系传递簇进行保守用途隔离，并检查两成员能力、派生见证摘要、当前参数窗口和独立新预算。

官方来源文件读取和哈希不是完整仓库审计、任务下载或镜像可运行证明。机器计划仍为 `partition=null`、`tasks=[]`，实际SWE任务数为0；当前来源运行门拒绝空清单和未冻结预算。CooperBench原生逐feature/逐patch分数与本项目额外集成测试分列；AsynCodeBench仍为候选，未完成其实现审计。

本次CPU控制没有测量9B在新软件任务中的工作、真实训练支持、候选试训开发收益、B/G/I独立差值或后继在线学习。v0.26的GPU 0/4/5/7、8小时上限和旧期限均未复制为新运行配置；未新建GPU等待队列或启动外部模型API调用。

## 8. 下一步的具体边界

目前可以审阅和执行有限开发接口、SDK接线、来源声明门和B/G/I机制控制。下一步实际研究需要先取得SWE-smith任务与环境，按已冻结用途派生共同可实现的两类协作任务，完成真实依赖及独立验收资格；当前Marshmallow适配器不能冒充已覆盖任意SWE仓库。

随后才能把A建议规模变为具体任务/seed/完整模型状态/资源表，测量上下文余量和单窗口成本，再冻结B的M与支持门、C的探测/正式更新预算和D的独立确认预留。无支持不默认追加基础训练；更新后各方法用自己的新策略重新工作。

本次修订使理论对象、代码入口和后续协议对齐到配置比较，但**经验分配算法的真实效果仍未验证**。旧v0.26的0/16、原中断unknown、无训练更新及2.468925 GPU小时结论原样保留，不能与未来软件绝对成绩相减为算法增量。
