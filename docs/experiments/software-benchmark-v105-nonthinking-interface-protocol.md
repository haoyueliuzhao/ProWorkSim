# DeepSeek非思考模式的50题接口验证

日期：2026年11月2日。用户要求用DeepSeek Flash非思考模式，在REF和PROJECT下测试50题并统计token消耗，随后明确本轮API预算为350元。本轮是新批次，目标是检查既有接口修订在实际单Agent运行中的表现；不恢复Qwen、固定组织实验或已封存的旧异常任务。

## 题单与配置

复用此前在看到成绩之前按仓库分层选定的50道SWE-bench Verified任务身份，覆盖12个仓库。每题各执行一次REF和PROJECT，共100个新回合；新身份与seed一次固定，两组使用同题和相同预定本地seed，从各自独立初态开始，不共享补丁或前一轮反馈。不根据旧成绩选题、删题或换题。该面板已经用于开发校准，不能称为独立确认集或完整500题分数。

模型名为`deepseek-flash`，当前官方说明对应DeepSeek-V4.1-Flash-1017。通过`thinking: {type: disabled}`明确关闭思考，温度为1，top_p记录为1；官方说明Flash非思考模式的top_p固定为1。API未公开seed参数，本地seed只用于冻结任务身份和运行配置，不能承诺服务端逐token复现。[模型说明](https://api-docs.deepseek.com/quick_start/pricing/)、[模式开关](https://api-docs.deepseek.com/guides/thinking_mode/)、[请求参数](https://api-docs.deepseek.com/api/create-chat-completion/)

两组共同上限为上下文131072、完整输入98304、单次输出32768、每题累计输入＋输出500万token，512次模型尝试／Agent决定，6小时软限。正式100回合的累计token上界为5亿；这是上限，不是预计消耗。每次请求均按实际剩余预算收紧可预约输出，两组采用同一规则。

REF保留原生OpenHands工具和执行流程。PROJECT使用真实S1受管接口，接入v103的原子同步、测试前权限拒绝局部化、RPC通道保留及nullable cursor恢复。非思考模式同时适配请求、SDK投影、工具响应、账本与结束判定；不能只把请求开关改掉而保留“必须返回思考内容”的旧检查。

题单与精确条件见[冻结面板](../../artifacts/software-benchmark-v105/preparation-r1/panel.json)。

## 独立预算与用量口径

本轮使用独立账本，总现金上限350元，包含接入诊断、生成、摘要和不确定请求预约；不清除旧账本中的未决收费。现行Flash人民币高峰价每百万token为缓存命中0.04元、未命中2元、输出8元，空闲价减半。以高峰价保守预约和控制上限；按用量计算的保守费用与账户实扣费用分别标识。[官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

逐题保留输入、缓存命中、缓存未命中、输出、思考字段、实际请求数、费用及缺失状态。总token为输入＋输出，缓存输入是输入的组成部分，不能再次相加；思考token若返回也不能在completion之外重复加计。非思考响应的思考字段缺失与显式0分别保留；异常出现思考内容时记录模式偏离，不静默混入普通结果。

每组报告总量、平均量和样本数。实际调用且用量完整的任务均纳入用量均值，包括有完整账单的失败回合；未开始或收费未定不填0。另对同题双方均有完整用量的配对子集统计差额，避免不同缺失集合误导成本比较。350元不保证100回合必然闭合，触及预算时停止新请求、保留当前候选和账单，不自动扩额或重采。

## 接口修正的观察项

- Matplotlib等仓库的未修改外来属主文件不再触发无条件chmod；真实写权限不足时记录明确拒绝。
- 测试前同步拒绝仍保持`executed=false`，不能获得合法交付证据；之后有显式新请求时RPC仍可用。
- 合法`cursor:null`经过SDK后按原值进入受管工具，不放宽其他参数检查。
- 末尾余额足以容纳输入与较小输出时，两组实际请求采用相同的缩小输出上限，账本不超额。
- PROJECT分别记录最终代码正确性、合法交付及版本关系，检查是否仍存在代码正确但因接口错误无法闭合。

每项同时记录是否实际经过相关路径。某错误未出现不等于该机制已被充分验证，不能仅凭总体正确率宣称所有接口问题已解决；旧思考模式成绩也不作为本轮修订的纯因果对照。

## 运行与评分

拟最多8个生成pair与2个评分任务并行，生成和评分异步。使用本项目既有隔离环境和普通用户协调服务，按实时CPU、内存与磁盘余量准入；不新增共享主机资源组，不改挂载、网络、驱动或既有服务。所有对象以本轮独立身份创建，结束后仅清理本轮对象，保留请求、候选、评分和用量证据。

模型请求由普通用户进程直连`api.deepseek.com:443`，不通过代理；模型仅可选择已列明的本地函数工具，不提供Search／Fetch接口或联网搜索入口。Actor与controller使用`network=none`。四个Requests任务保留既定的评分侧私有网络机制，其中1766／1921仅通过限定httpbin HTTP／真实TLS通道评分，不向求解Agent开放该通道。

评分继续使用固定任务、官方测试和唯一最终候选。旧gold／empty控制仅在镜像、基础版本、测试和有效评分机制的等价性成立时复用，来源如实记录；发生变化或证据不足时执行必要新控制。不同条件和新候选使用独立评分身份，不误命中旧补丁缓存。同树合法交付可复用同一官方代码结果，缺少合法提交仍保持单独交付记录。

局部工具、环境、导出或评分异常进入异常集合，不阻塞其他独立任务；身份、账本、清理或共享执行完整性不明时暂停相应派发。已进入模型的回合不自动重采。

具体Docker对象和评分出网的受限范围由本轮运行方案列明并完成准入后执行。准备文件存在不等于已启动；实际进度以本轮协调器记录为准。
