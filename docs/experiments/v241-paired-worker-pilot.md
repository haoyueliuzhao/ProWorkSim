# v241 首批真实 Worker 配对｜诊断职责交给第二名成员后发生了什么

**结论。** 两对真实续跑、四条分支均已正常闭合。KEEP 的代码通过和合法交付均为 0/2；OSA 两个端点均为 1/2。Astropy 的独立诊断得到采用，之后产生了通过官方验收的提交；Sphinx 虽送达了带证据的诊断，仍在预算边界结束。每题每条件只有一次，共两个既有开发任务，不能据此估计总体提升幅度。

## 设计与计量

本批使用 v240.4 达标提示的**第一次预定决策**。在两个持续修复失败的开发现场，分别将同一保存点恢复为两条独立分支。KEEP 保留原有负责人和复核人；OSA 可自主维持、改组或请求证据。两个现场的实际选择都是增加一项新职责：由成员 002 独立诊断，将有来源的发现交给成员 001；001 继续负责实现和最终交付。两条分支之间没有补丁、测试结果或消息共享。此处的两个任务都曾用于开发，不作为独立确认样本。[冻结方案和候选身份](../../artifacts/software-benchmark-v241/paired-r1/protocol.json)

两种条件使用相同的两名 OpenHands Worker、DeepSeek Flash 非思考模式、T1 上下文策略、工具权限、公开测试入口及官方隐藏评分器。每队每题总计 500 万输入加输出 token，包含共同前缀。Sphinx 从余量 972,030 token 开始，Astropy 从 2,550,164 开始。OSA 的决策已在上轮计费，这次只在该分支逻辑预算中扣除原用量一次。两对全部启动前一次预约 ¥56.355104，所有 solver 容器断网，模型由项目原有直连通道提供；评分使用锁定的最终工作树和最后合法提交，结果没有反馈给 Worker。

**观察口径。** 分别核对新图是否与预定方案一致、首个模型行动机会给了谁、第一项诊断工具操作是否得到接受、是否有带本人证据引用的 DIAG 送达、接收方是否登记采用，以及最终代码与交付是否通过。递交诊断能证明团队产生了对应的协作产物；其中的因果推断是否正确、是否改善代码，需要另外的证据。KEEP 没有追加独立诊断要求，该项记为不适用。观察器无法确定的异常状态单列为未知。

**执行修订。** Astropy 旧保存点缺少控制状态中的观察者字段。其同一时刻的任务清单、图记录和第 47 次事件都支持由 001 观察。两组仅在加载视图中补入该身份，原保存点保持原字节。随后 Astropy OSA 的原决策说明为 1,344 字符，超过旧图事件 1,200 字符限制。这一支在首次 Worker 模型调用前关闭并清理了环境。恢复时保持同一方案、证据引用、职责和预算，在图事件中记录带全文哈希的限长说明，决策记录保留全文。三次启动异常均保留，实际 Worker 调用均为零，未重采任何已作答的回合。[观察者来源与边界核对](../../artifacts/software-benchmark-v241/paired-r1/astropy-restore-revision.json) · [理由传输修订](../../artifacts/software-benchmark-v241/paired-r1/reason-transport-revision.json)

### Astropy：独立诊断被采用，最终补丁通过

成员 002 首先搜索了公开测试中的 `test_write_normal`，随后向 001 发送 DIAG，引用了自己的搜索事件 42。001 第一次试图直接登记采用，系统要求先取得消息全文；其后实际读取消息 43 并登记 ADOPT。002 后续还完成了独立复核。该 OSA 分支在逻辑用量 4,344,023 token 时正常提交；官方新增验收 `test_rst_with_header_rows` 通过，原有 9 项回归全部通过。

KEEP 也完成了正式提交且通过原有 9 项回归，但同一项新增验收失败。从两条锁定补丁看，**两组都已将写入分隔线的位置改为随表头行数计算**。OSA 通过的版本还调整了读取表头和数据的起始行，并处理了空表头情况。因此，本例能直接确认「独立分析送达并采用」与「最终交付成功」均发生在 OSA 分支；不能把最终补丁的每个差异或通过结果都归功于那条诊断。

### Sphinx：获得行动机会和诊断产物，仍未交付

002 首次被调度后尝试读取 001 的私有测试报告，因无访问权限被拒。随后它请求失败信息，报告过受阻，并在自己的 v1 工作树上对目标用例运行公开测试，获得 1/1 通过的独立证据。002 引用事件 73 发送诊断消息 77，对比了自身版本与 001 的失败版本。该证据能说明两个工作树的观察不同；消息中对失败根因的解释未被官方结果独立证实。生成结束前没有记录到 001 对该消息正式采用。发送者早期决策列表仅含 NEED、BLOCK，最终交接单独由已接受的 DIAG 消息、证据号及职责的交接状态核实。

两组最终都触及预算边界，没有正式提交。官方评分中两组均通过 44 项原有回归，都未通过 1 项新增验收。公开测试中某些用例在某一成员的工作树上通过，并不足以代表最终代码通过。
