# 非思考接口测试的启动修订

日期：2026年11月2日。接续[v105实验协议](software-benchmark-v105-nonthinking-interface-protocol.md)，任务、模型与预算均沿用用户已批准的50题×REF／PROJECT计划，独立API现金上限350元。本修订处理启动适配问题，不增加模型回合或重采已调用模型的任务。

## 首次启动的实际情况

v105已按授权启动普通用户协调服务。REF的零模型诊断通过；PROJECT完成了真实SDK初始化和工具检查，但导出时，旧闭合函数只接受`v064:`任务身份，因而拒绝本轮`v105:`身份。随后协调器停止。本次两个诊断均没有调用模型；100个正式回合尚未开始，API账本尚未创建。

两对诊断的4个容器和2个专用卷均已清理，协调器预约已释放。它们仍计入原批次454个容器、102个卷的总额度，不能作为未使用额度重新创建。PROJECT原诊断仍为失败：它没有执行最终代码同步，也未留下可恢复完整世界状态，不能用离线修订将其改报为通过。

## 修复内容

1. 新闭合模块核验本轮完整任务身份：任务、PROJECT条件及预定seed必须一一匹配。合法交付仍要求原有同版本测试、固定补丁和提交证据，不以放宽证据要求解决版本编号问题。
2. 新PROJECT启动路径在自己的正式容器内执行一次初始同步预检，核对完整原始代码树。它在模型调用和世界创建前完成，不增加可见工具、不计公开测试次数、不生成交付证据、不锁定最终版本。之后仍可正常编辑、测试和导出。
3. 宿主回合、controller、actor及评分端接入同一新闭合协议，保留旧源码与失败记录。另修正评分入口从旧四评分槽配置继承的CPU范围检查，使其严格匹配本轮获准的两个评分槽。
4. 新统计入口读取本轮实际协调器记录，从已核验的任务身份取得条件，保留逐题输入、输出、缓存用量、费用与完整性状态。

新闭合与同步预检15项、运行绑定6项、评分及统计入口3项必要CPU控制均已通过；这些控制证明相关程序分支的行为，不等同于真实模型或官方测试已经通过。来源见[闭合与预检记录](../../artifacts/software-benchmark-v106/closure-preflight-controls-r1/summary.json)、[运行绑定记录](../../artifacts/software-benchmark-v106/runtime-control-r1/summary.json)、[评分与统计记录](../../artifacts/software-benchmark-v106/scoring-control-r1/summary.json)。50题的原评分环境资格全部复用，本次新增环境控制为0。

## 授权和统计边界

继续使用同一个普通用户服务名称、原100条正式任务、原资源身份池和350元账本；新增容器额度、专用卷额度、模型回合均为0。最多8个生成pair与2个评分并行，合计不超过64 CPU／320 GiB。两组首个正式回合各取得一次可信API用量结算后，才开放后续并发。生成与评分异步，单题异常独立留档；账单、身份或清理完整性问题按原规则处理。

API直连、非思考模式、无模型联网搜索，以及Requests评分的限定出网范围保持原批准方案。修订不操作共享服务器配置，不启动GPU或旧实验。

实际运行状态以后续协调器记录为准。未开始、技术未知或用量不完整的任务不能填为零消耗或普通失败；未完成完整面板时，平均token必须注明其样本数。只有真实运行经过相应接口路径并取得可信记录，才据此评价修正是否有效。

## v106实际启动结果

v106服务已启动，真实DeepSeek非思考接入的两次中性请求通过，独立账本结算保守费用0.00077056元，无不确定收费预约。正式调度循环在创建任何任务环境之前停止，异常为`NameError: _GeneratorContextManager is not defined`。100个正式回合均未派发，新增容器、卷及GPU使用为0，协调器预约已释放。

根因是线程池上下文管理器经`contextmanager`装饰后，其函数元数据看似属于队列模块，实际却依赖Python `contextlib`的全局命名空间。私有队列复制函数时错误替换了该命名空间。后续最小修订保留这个不含项目权限或任务配置的原包装函数，并增加实际调度进入、派发及收尾的CPU控制。已成功的API接入证据和费用保留，不再重复两次诊断；v106的失败记录不改写。
