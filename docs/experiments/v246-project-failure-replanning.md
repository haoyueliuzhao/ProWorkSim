# 项目图上的重复测试失败如何触发组织调整

完整任务的新入口是 `tools/run_full_osa.py`。项目图在每次成员行动结束时读取已经执行的公开测试回执，将失败关联到成员、工作包、测试目标和实际被测的代码版本。每个异常节点保存失败回执、状态以及由它引发的历次组织决策。OSA 读取本次异常、相应测试证据和当前交付清单；组织控制器核对当前可行的分工、接收者与资源。到第 12 次行动仍未发生异常决策时，保留原例行检查。之后仍可多次决策。

**什么时候再次判断分工。** 本次把以下阈值作为工程默认值：

- 同一工作区和工作包的同一测试目标，在两个不同代码内容上失败，触发一次判断。同一版本连续三次实际运行仍失败，也可触发。重复读取已有回执不计数。对于连续三次失败、涉及的目标均不同的情况，记录为工作包测试持续受阻，具体根因仍须定位。
- 项目图分别标出具体用例失败、测试函数回溯、测试收集错误，以及只能定位到一次测试选择范围的失败。另一个成员在自己工作区测试通过，不能清除当前成员的失败。通过同一目标或同一选择范围的相应测试可解除该异常。
- OSA 可维持原分工、选择可行的移交或安排独立诊断。每次决定都绑定异常和组织图版本。维持分工后出现新的失败证据仍可再次唤起；刚处理过的相同证据不会循环发起请求。同一组证据支持的多个同时失败目标合并处理。单题决策次数没有固定上限，继续使用原团队 token 总预算。前一项调整已承诺的行动机会会先履行，待执行的新异常仍保留在项目图中。

**5 题公开轨迹回放。** 下表是旧运行中在哪个行动机会已经出现了足够的异常证据。历史动作保持原样，每次达到触发条件即记录并消费该次证据，因此这些数字不能预测线上改组后的轨迹。

| 任务 | 可触发的行动机会 | 观察 |

| Astropy-14598 | 65 | 同一个长字符串引号用例再次失败 |
| Django-12663 | 43、52、59、75 | 公开回溯标明了反复出错的测试函数，最后一次对应另一个子查询用例 |
| Matplotlib-23299 | 55 | 同一个绘图集成测试反复失败 |

| scikit-learn-25747 | 无 | 公开测试只有一次失败，后面有通过记录 |

**执行验证。** 在真实双成员 SDK 中使用脚本代替模型做了三次决策。第 1 次维持分工，第 2 次将工作包交给另一名成员，第 3 次指派独立诊断。检查了实际组织图版本 1、2、3、工作包负责人、诊断责任人、受保护的执行机会、三个独立请求身份，以及累计的 OSA 用量。此控制证明同一任务可以实际改组两次。历史轨迹回放和脚本控制均未调用付费 API，也没有产生新的正确率。上轮未启动的 7 题仍暂停。
