# v203.3.3：真实任务状态上的诊断委派试跑

## 1. 本轮检验什么

本轮在同一个真实、尚未完成诊断的任务状态上，比较“原开发者继续诊断”和“尝试把诊断交给伙伴”。模型仍是 DeepSeek Flash 非思考，组织仍为 REVIEW2：001负责实现和最终交付，002负责独立复核。它不是五种组织的大规模横向比较，也不是自动发现最佳分工的算法实验。

前置SDK续接已在真实OpenHands SDK、真实摘要事件、真实CPU公开测试条件下通过三项比较：连续运行与恢复KEEP、两个恢复KEEP、恢复KEEP与REASSIGN。这些控制的模型响应是脚本，不算真实修复成绩。详见[v203.3.2报告](software-benchmark-v203-3-2-resume-and-delegation-report.md)。

## 2. 两个条件

- **KEEP：保持责任。** 从保存点恢复，不添加提示、不补做管理动作，001保留原诊断任务。
- **REASSIGN：尝试交接诊断。** 从同一保存点恢复，向001追加一条事先固定的指令，请其通过已有offer／accept及信息交接工具尝试转交诊断任务。模型可以拒绝或执行不完整，全部保留在分配条件中。研究代码不直接修改owner，不生成诊断答案或补丁。

两组同一题目、初始仓库、检查点、角色权限、工具、历史摘要算法、上下文和输出上限。只改变是否给予上述预先安排的诊断委派指令。001继续承担实现及交付，002承担最终复核；002先参与诊断可能改变其复核独立性，这是要记录的机制影响，不能假定没有影响。

## 4. 预算和恢复

用户新增授权**80元**，单独账本，旧130元及其余额均不转入。团队原始上限5M输入加输出，续跑只能使用保存点剩余额度，不能重新领取5M。上下文131072、单次输出32768、全输入98304，温度1、top_p=1，关闭思考和供应商联网搜索，直接连接官方API，不使用代理。

启动一个槽位前，按其剩余Token上限与官方峰值最高单Token价格预约足够费用；已开始槽位不会因为另一个任务花费而被现金线中断。结束后释放未用预约。这个保守准入可能在现金尚有余额时暂不启动下一完整槽位；不将预约金额当实际费用。80元不保证覆盖8个前缀和全部16次续跑。

费用以每个实际响应usage为准，缓存输入包含在输入中，不重复相加。现金按峰值价计算上界，不冒充账单实付。原件请求、响应、model、fingerprint、计量和时间保留。完整返回的临时429／5xx最多3次物理尝试；不明确是否已消费的传输故障保留费用未知，不盲目重放。原费用及失败不会被恢复覆盖。

前缀实验实际只支付一次，实验总成本=全部尝试前缀＋所有续跑；某个部署方案的完整任务成本=其前缀＋一次续跑。摘要、管理、回读、测试和返工均计入。检查点保存及进程停顿不占两分支的剩余任务时钟，但其准备耗时另报。

## 5. 执行与资源

本次使用普通用户SDK控制进程和每题独立的原仓库容器。模型只有原受管工具，不能执行宿主命令。容器network=none、drop ALL、无宿主目录绑定、无监听端口、无GPU；每容器4CPU／16GiB，最多2路。普通用户协调服务8CPU／64GiB上限。只清理按本批唯一ID和所有权标签创建的对象，不修改主机挂载、网络、驱动或其他服务。

新actor保留r5公开测试脚本预加载修复。恢复分支在原始零测试同步预检后，只把actor的逻辑测试编号恢复到保存点N；world中的测试次数、预算、证据不会清零。SDK的会话文件写向新分支，历史逻辑事件保留，新增物理请求和费用使用新身份。

首个真实题前缀作为本批内的供应商接线检查，不另挑“容易成功”的题。首个阶段出现工程故障先修复，后续候选异常独立保留。保存点资格须审阅后才能启动续跑，不能把“已经保存了文件”当成科学准入。

## 6. 输出与解释边界

主结果是最后合法提交版本的官方通过情况；锁定最终工作树的代码正确率单列。提交缺失、交接拒绝、交接失败、错误诊断、KEEP更好均保留。评分或执行技术未知显示未知及原因，不填成代码失败；未启动槽位单列。

报告每题两组实际输入、输出、管理与回读、公开测试次数、修改者、诊断责任、复核记录、交付和耗时。不能仅看两组平均Token就推断通信增多或减少，也不从4个状态声称一般组织优势。后台observer只能记录，不向模型注入其未获授权的伙伴私有信息。

本文件为启动协议，不是结果报告。初始状态：零API原仓库接线通过，4项新账本CPU控制及4项既有ITT控制通过；真实请求和已完成数量以本批运行目录为准。
