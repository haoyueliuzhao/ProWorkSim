# v232.5｜正式交接能否从“送达”走到“已处理”？

**首个处置窗口确实产生了证据请求，但本次未形成正式诊断交接。** 002 明确索取失败详情，001 作出回复。002 读到答复后试图交接，引用了伙伴的消息号；项目正确拒绝了这项引用。此时唯一的补证机会已经用于读取答复，002 再查文件或跑测试又被新规则拦住。本轮定位到一处规则冲突；接收者如何处置正式诊断仍未获得在线样本。

前一次 Sphinx 续跑为纠错和接收留出了预算，但 002 尚未决定交接时，下一次普通请求的预约已超过可用额度。主动回读试验因此没有产生一次提示曝光。本轮从同一异常保存点独立续跑一次，检验把处置要求和行动机会提前能否改变这一链条。[上轮报告](v232-4-optional-readback.md)

## 本轮改动

- **发送方 002** 获得初始诊断机会后，系统优先调度一次正式处置。它可以引用自己的有效事件提交发现（DIAG），说明具体阻塞（BLOCK），或指出缺少的一项证据（NEED）。NEED 允许再做一次成功的证据操作，随后再次处置。未获接受的尝试保留为未闭合。
- **接收方 001** 收到被项目正式接受的诊断后，可以读取原文，并记录采用、暂缓或拒绝的理由。若它已有同版本证据，也可以引用本人在当前工作树上的读取、搜索或测试事件并说明无需回读的理由。内容进入了真实请求、项目接受了处置、后续动作符合诊断，是三个分开的判断。系统检查身份、版本、消息号和已有证据，不替成员裁定技术意见是否正确。
- 两条规则在同一续跑中启用。预算内新增一份发送方处置容量和一份接收方后续回应容量，共按七个完整请求上界准入。所需容量来自已有 970,120 个成员 token。DeepSeek Flash 非思考、T1、双人 D1 分工、旧纠错与接收机制、全文入口及官方评分沿用原设置。旧组织决策 1,910 token 保留在逻辑额度中，本轮不重新收费。[冻结协议](../../artifacts/software-benchmark-v232-5/disposition-r1/protocol.json)

**零费用机制检查。** 使用真实 OpenHands SDK 和本地脚本响应测试四条路径。DIAG 后完整回读并 ADOPT、DIAG 后引用己方同版本事件并 SKIP 均有回执；NEED 后能够查证再发 DIAG；BLOCK 记录为发送方受阻，未算作诊断送达。四条路径的付费模型调用数为零。[SDK 凭据](../../artifacts/software-benchmark-v232-5/disposition-r1/sdk-control.json)

第 68 次机会，002 给出了两个工具调用，SDK 要求每轮只选一个，未进入项目执行。第 69 次机会，首次正式处置的可用量为 **256,966 token**。002 尝试直接读测试报告，被要求先作处置。第 71 次机会，它通过 NEED 请求 001 提供 v7 失败的具体详情，项目登记为消息 **66**。之后直接读取另一成员的报告因权限不足被拒。001 在第 73 次机会发出答复，登记为 **67**；002 在第 75 次机会成功读取了这条给自己的消息。

第 77 次机会，002 提交 `DIAG 67`。67 是 001 发出的消息，无法满足“引用本人在分工生效后获得的查阅、搜索或测试证据”这一条件。项目拒绝了正式交接。002 随后的读文件和运行测试意图，又因 NEED 的一次成功操作已被读取伙伴回复消耗而被拒。等到第 80 次机会，剩余普通可用量只有 54,883 token，下一次请求须预约 124,321，未能派发。诊断职责最终仍为待交接。001 发出的消息 67 是对证据请求的答复，不能算作对正式诊断的接收处置。[逐机会动作、拒绝原因与结算](../../artifacts/software-benchmark-v232-5/disposition-r1/results.json)

**对自主性的判断。** 显式的早期处置机会在本例中让具体缺证得到表达。程序同时要求引用本人证据，却把获取外部线索与独立核验共用一次额度，产生了可定位的流程冲突。成员能否自由选择技术路线与这两类活动怎样记账应分别处理。本例没有合格诊断送达，严格接收规则对采用、暂缓、拒绝或免回读的真实影响尚不可估计。两轮各只有一次生成，不能将请求数或费用差异解释为稳定收益。

## v232.6 零费用修订

补充规则仅作用于已获接受的 NEED。若成员通过原有权限读取由指定伙伴在该请求之后发给自己、同一工作包的一条消息，这次读取记为“取得伙伴线索”，仍保留一次独立源码查阅、搜索或公开测试。成员仍须引用自己新产生的有效证据才能完成 DIAG；系统不会将伙伴的消息号视作本人成果，也不会替成员发消息。阻塞报告仍可使用。

在真实 OpenHands SDK 的本地控制中，已按顺序观测到 NEED、成功读取定向答复、读取源码、提交合格 DIAG，随后接收方回读并记录 ADOPT。该控制的模型响应由脚本生成，证明规则链路可执行，不能用来更改此次 Sphinx 的未交接结果。v232.6 仅完成了零 API 验证。[修订代码](../../src/proworksim/software_handoff_evidence_v232_6.py) · [SDK 凭据](../../artifacts/software-benchmark-v232-6/need-followup-r1/sdk-control.json)

本轮实际新增 **781,143 输入＋3,022 输出 token，1.38375096 元**。共享账本累计 **113.26785944 元**，余额 **31.10680696 元**；没有未结算请求，执行环境已清理，评分端未报告清理错误。
