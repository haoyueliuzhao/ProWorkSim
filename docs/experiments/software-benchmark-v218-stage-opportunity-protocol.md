## 目标与边界

先检验能否消除“前缀已完成所以等待”的阶段混淆，并取得真实可比较的协作候选。保留两成员、DeepSeek Flash非思考、原模型/采样/上下文/工具权限、同版本证据与正式交付规则，每条逻辑任务500万输入加输出Token。没有恢复训练、扩员或隐藏测试反馈。

本轮不是旧失败题补考；8个题目不与v217面板重合，但历史全量评测曾曝光，不能称全新独立测试集。与旧批不同任务的平均分差，不作为阶段修订的因果效应。

## 修订内容

1. 前缀提示明确：形成第一次代码/测试并不是模型等待的目标，只有外部控制器会保存中途检查点。恢复时向两个实际成员发送明确的新阶段消息，旧“达到前缀后暂停”目标已经失效，继续完整原题。
2. 全员不可调度且尚无DELIVERED/ABORTED时，可向实际等待且未因错误停止的成员发送阶段提醒。每回合最多两次，同一工作状态不重复；不唤醒技术故障停止者，不改权限、责任、证据或候选。提醒成本进入下一真实请求的账本，仍先检查时间和Token。再次共同等待时标记`quiescent_without_delivery`，不把它叫正式完成。
3. KEEP仍允许补齐缺失的验证与协作设置。因此纯补设置的提案不另算结构调整；调整候选须真实改变责任、实现/证据模式、依赖或分包，且满足原工具合法性。按结构去重，不为了凑两条候选强制转交或虚构依赖。
4. 新选择准入只看结果前的信息：至少KEEP加一个合法结构调整，剩余续跑额度至少200万，项目特征能区分候选。没有资格则记录原因和准备成本，不跑名义上无比较价值的主面板、不按成绩补题。

## 调度与异常

环境控制、前缀/候选准备可跨阶段并行；本阶段某题准备好即进入分支，不等待同窗其他前缀。学习窗口间只保留必要的策略更新依赖。生成完成立即释放槽位，官方评分独立最多2路。生成上限12路、环境启动4路，并受主机余量/现金约束；当前单窗口最多6或12条，不宣传持续12路吞吐。

普通用户协调服务64核等价CPU、512 GiB内存硬上限、460 GiB高水位、swap禁用；共享服务器配置、挂载、网络、他人服务不变，无GPU占用。容器继续network=none、drop ALL、无宿主目录绑定。所有新任务使用已验证v217.2大状态缓存。

单任务异常单独留档，不阻塞其余题；无明确官方结果的评分可用同一锁定候选重试一次。至少3个独立任务出现同类型基础设施故障才暂停新准入。已调用模型的身份不自动重采。正常代码失败或未交付不当成技术故障。
