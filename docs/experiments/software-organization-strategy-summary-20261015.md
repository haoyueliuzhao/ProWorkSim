# 不同人数与组织策略：实验结果汇总与分析

**ProWorkSim｜数据截至2026年10月15日｜整理日期2026年10月16日**

本报告将原报告五组完整主对照的 **116次运行归并为10种组织策略**。同一策略跨任务、预算和输入表示合并为一项，不再按实验版本展开。全部使用同一个冻结的Qwen3.5-9B模型；参数更新后的学习实验不纳入本表。

补充：[四人组结果与轨迹原因分析（2026年10月18日）](software-organization-four-member-analysis-20261018.md)，包含固定四人、四候选和四阶段的逐槽结果、关键轨迹及失败机制。

## 1. 组织策略：自由组织与人工预设架构

**自由组织**指人类设定人数、工具权限和总预算，但不预先指定经理、实现者、测试者或提交者。成员自行决定分工、沟通、共享成果和交付方式。因此，**固定两人或四人，不等于人工设计了分工架构**。

**人工预设架构**则事先规定执行顺序、成员职责、代码权限和阶段预算。“独立候选＋选择”与“分阶段协作”均属于此类。

自由组织的具体方式如下：

- **单人自主求解：**唯一成员承担阅读、实现、测试与提交，无隐藏伙伴。
- **固定双人／固定四人自由组织：**从空任务板开始，不预设岗位或工作阶段；可以分工、重叠探索、共享和整合成果。允许永久退出，不补员。
- **双人起步自主扩编：**从2人开始，自主决定是否招募、分工、退出或重组；同时存活上限4人，累计成员上限6人，均包含初始成员。
- **单人起步自主扩编：**从1人开始，同时存活及累计成员上限分别设为2人或4人。允许始终保持单人，不强制用满名额。

人工预设架构的具体安排如下。预算比例均为**共同团队预算的初始分配**，人数增加不会增加总预算。

| 人工预设架构 | 具体执行流程 | 职责与代码权限 | token预算分配 |
| --- | --- | --- | --- |
| 双人独立候选＋选择（I2） | 成员1、2分别独立生成候选 → 原成员1选择、验证并提交 | 生成时分支相互隔离；选择阶段可采用和测试候选，不能编辑或合并代码 | 两名生成者各35%；选择阶段预留30% |
| 四人独立候选＋选择（I4） | 成员1、2、3、4分别独立生成候选 → 原成员1选择、验证并提交 | 与双人候选相同；选择者仍是原成员1，不增加额外经理或专家 | 四名生成者各17.5%；选择阶段预留30% |
| 双人分阶段协作（P2） | 成员1实现 → 成员2复核、修订、验证并提交 | 成员1修改、测试并固定候选；成员2取得成果后可以编辑或整合代码，负责最终提交 | 实现60%；复核修订提交40% |
| 四人分阶段协作（P4） | 成员1实现 → 成员2独立复核 → 成员3修订整合 → 成员4验证并提交 | 成员1、3可修改代码；成员2、4可读取、采用和测试，不能编辑或合并；只有成员4正式提交 | 实现35%；复核20%；修订25%；验证提交20% |

这些架构还有三项影响结果的约束：

1. **独立候选不共同编写答案。**生成阶段不能读取其他分支的代码、私有历史、消息或专属报告。每人最后一份合法固定成果才算候选；选择者最终提交必须保持所选候选的代码，不能合并候选，也不能利用私有验收预先挑选答案。
2. **阶段交接需要实际执行。**分阶段协作只调度当前阶段成员，后继不会自动继承前驱工作区，需要显式取得已发布成果。最终提交者须对自己当前版本实际运行公开测试，再固定同一版本并提交；前驱测试不能代替。四阶段架构的最终验证者即使发现代码问题，也无权直接修补。
3. **阶段划分限制可用资源。**独立生成者之间不能借用预算，剩余只能转入选择阶段；流水线余额只能向后传递。这里的“人数”是独立会话和工作区的数量，均使用同一模型，不代表同等数量的GPU同时推理。

## 2. 按组织策略合并的实验结果

**合并规则：**按初始人数、人数权限和执行架构归类。同类策略内的任务、预算、输入表示及初始信息／说明变体合并统计。可扩编策略即使实际未增员，也不改记为普通单人或固定双人；上限2人与上限4人的策略分别保留。

成功率＝成功运行数÷纳入运行数。平均完整token消耗＝全部纳入运行的实际输入与输出token之和÷运行数，**包含失败运行、全部成员和阶段，以及首次提交后的消耗**，不是成功任务的平均成本。成功要求最终固定交付通过完整合同验收并满足过程要求；正常未提交计为不成功。

**合并表是历史运行总览，不是同条件排行榜。**各行任务和条件构成不同：双人起步自主扩编包含16次初始信息／工作说明变体；单人与四阶段协作分别包含2次修订输入表示的运行。116次运行也不是116个独立任务，部分业务任务被反复使用。因此，不能直接用50.00%与45.00%的差值认定自主扩编优于单人，也不能用混合预算后的平均消耗判断同等产出的成本差。

## 3. 实验结果对比分析

**增加人数没有带来稳定的完整交付收益。**直接比较固定双人与固定四人的8次配对运行中，双人为3/8，四人为1/8；平均消耗分别为48.88万和49.26万token。另一组单人、固定双人、双人起步自主扩编的8次配对运行中，三者均为4/8，且每个配对任务的成败一致；双人和可扩编条件的平均消耗分别是单人的1.468倍和1.541倍。这支持“本批增加人数未稳定改善交付”，不支持“所有任务都应只用单人”。

**扩编权限没有转化为实际扩编。**双人起步可扩编的32次运行均保持2人；单人起步可扩至2人或4人的12次运行均保持1人。这些结果反映的是提供扩编工具和权限后的整体表现，无法估计真正招募新成员后的收益。上限4人的策略在50万预算下达到2/4成功、同期单人为1/4，但前者仍由1人完成，不能归因于四人协作。

**人工预设架构尚未稳定超过单人。**在25万团队预算的同任务对照中，单人、双人候选和双人分阶段协作均为1/4，平均消耗分别为17.22万、24.17万、22.56万token；四人候选与四人分阶段协作均为0/4。提高到50万预算后，四人候选为1/4，追平同期单人，但平均消耗48.44万，对比单人的25.88万，约为1.87倍；四阶段协作仍为0/4。增加候选或阶段会同时改变单个成员的预算及交接要求，不能把这些差异仅解释为人数本身的作用。

**四阶段协作明显受到输入表示影响。**两道任务的同期对照中，将同一输入中严格重复的内容改为可还原的引用后，四阶段协作从0/2变为2/2，硬context拒绝从6次降至0次；两次成功都记录到伙伴成果被最终成员取得、测试并交付。这支持输入容量约束会影响该流程的交付机会。但相同修订表示下，单人也为2/2，平均消耗14.39万token，四阶段为43.06万，约为单人的2.99倍。主表四阶段的2次成功全部来自这两次修订表示运行；合并后的16.67%不代表它在所有表示下的固定水平。这只是两个既有任务上的机制对照。

**信息分布和工作说明可能影响自由组织，但证据有限。**16次信息／说明对照中，“各获一份诊断＋强调共同交付”为3/4；“各获全部诊断＋常规说明”“各获全部诊断＋共同交付说明”“各获一份诊断＋常规说明”均为2/4。共同交付说明没有指定岗位或强制分工，仍属于自由组织。多成功1次是观察结果，尚无已确认的跨成员成果使用链，不能据此认定分工或知识共享产生了稳定收益。

## 4. 相关结论

1. **单人是当前较有依据的成本基准。**多个同条件对照中，单人以更低token消耗取得相同或并列最高的成功数；这项判断来自配对结果，不来自混合样本的总排名。
2. **人数配置、自由组织和人工架构需要分开解释。**固定多人可以自由分工；独立候选和分阶段流程则预设了职责、顺序和资源分配。现有结果尚未证明任一多人方式具有稳定优势。
3. **发生协作不等于协作提高了效果。**部分运行已确认伙伴代码进入最终交付，但不能据此证明伙伴不可替代，或相对单人提高了成功率。自主增员则尚未实际发生，收益仍未知。
4. **输入表示、预算分配和交接规则与人数同样值得关注。**四阶段流程在输入修订后可以成功，但本次对照仍无相对单人的成功率或成本优势。各细分条件仅2、4或8次运行，样本有限，不足以确定普遍最优架构。
