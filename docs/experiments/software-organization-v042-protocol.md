# v0.42 完整报告、有限页面与自主读取协议

日期：2026-10-10。依据用户提供的[v0.41审计](../reference/audit-v041-next-v042.md)。本协议登记一个3072字符分页候选及有条件的最多16槽模型库存。v041按“CPU呈现修订完成、完整反馈容量未通过、16槽全部未启动”封存；保留其两候选源码快照，不以最终归档提交替代当时执行身份。

## 1. 本轮只改变测试反馈访问方式

保留v041第二候选静态信息精确去重，不继续寻找可删除字段；原v040两承接态任务、业务代码/合同/验收不变。不换模型、扩大context、增加摘要模型或协调者，不重构全部观察。

一次测试事件e仍执行一次原公开/成员测试，其可分页正文严格限定为原v040允许模型看到的投影`F_e=Pi040(raw_result_e)`。宿主机完整stdout/API细迹、隐藏验收和其他成员私有事实不进入报告。固定序列化形成正文，按原字段、组和条目顺序分片，按序连接各页必须精确还原该完整允许正文。初始诊断与后续测试、不同测试事件即使内容相同也不合并。

`run_tests`返回事件和源版本、状态与检查范围、机械诊断目录、第一页精确正文，以及页范围、剩余页和cursor。目录仅抽取现有组/条目ID及状态，保持原顺序；不提供价值排序、修复建议、分工或任务板。

唯一新增读取工具为`read_test_result(report_id, cursor)`。它只读取原测试成员已保存的报告，不运行测试、不访问任意主机文件、不用当前代码替换旧版本。报告ID不是访问许可：伙伴和新成员不能靠知道或猜中ID读取他人的报告；伙伴只能收到实际分享的正文或自行复测。编辑后旧cursor仍指向同一旧结果，重复读取同一页返回相同片段，末页结束标志明确。

正文单页最多**3072个Unicode字符**，优先在原条目边界断页，超长单项按稳定位置精确分片并明确未完。只有这个页长候选；字符数不是token证明，不按模型效果调整页长。

翻页是成员自己的工具行动。模型调用、决定与token均消耗原共享预算；读存量页不增加`run_tests`次数，不刷新预算，也不算重新发现问题。成员可以继续读、分享、自行复测、修改或停止。**不要求读完才允许固定/提交，不把未读完视为过程违规，不奖励页数。** 新observation不得把整报告重新拼进上下文；当前页完整保留，旧页按同一完整历史回合规则选择。完整保存、历史读过和当前同时可见须分别表述。

分页是新的Γ，不能再声称旧整包最新返回逐字同屏，不能与v040/v041混为同协议样本。

## 2. 容量定义与硬门

模型上下文16384，输出预留2048。两种完整原生长度分别记录：

- `P_selected`：实际选中请求。硬门为`P_selected≤14336`。
- `P_protected`：同一请求经过相同静态去重，移除全部允许移除的旧完整工具往返后仍须保留的请求。保护当前观察、system/user和最新完整页/工具往返，按完整原生请求重新编码。工程门为`P_protected≤13312`，即另外预留1024 token。

1024是本轮声明有限形状的工程余量，不是理论保证；不能施加在保留更多旧历史的`P_selected`上。它仅用于CPU声明形状的资格判定，真实运行不额外据此拒绝生成或停机；实际运行硬门仍只有完整selected请求的16384/2048边界。`P_protected`也不是信息论最短表示。每种长度均保留完整请求、原生渲染、input IDs/hash和余量，不能用字符数或分段token相加代替。
