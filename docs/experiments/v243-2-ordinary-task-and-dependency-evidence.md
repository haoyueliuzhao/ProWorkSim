## 修复从短前缀恢复到完整任务时的停机状态

第一次恢复后，系统给团队设置了 500 万 token 的总额度，却保留了 001 在 200 万 token 前缀阶段的停机状态。原记录显示，当时可用 41,823 token，下一次请求未能预约。恢复后新增的 11 个行动机会全部给了 002；团队在累计用量 2,466,969 token 时提前结束。核查预先登记的 8 份保存点，8 份都有至少一名成员因前缀 token 上限停止；这是该候选池的工程特征，不能换算为整个基准的比例。[成员状态盘点和正负控制](../../artifacts/software-benchmark-v243-2/ordinary-r1/stage-controls.json)

修订后的普通任务入口按成员、原预算事件、保存点身份和当前额度核对，仅释放已获扩额的前缀 token 停机状态。现金暂停、技术故障、主动结束、任务已终止和当前余额不足均保留原状态。恢复不退还已消耗用量、不代写补丁、不替成员发言。[普通任务入口](../../src/proworksim/organization_harness.py) · [恢复判据](../../src/proworksim/software_prefix_resume_v243_2.py)

首次锁定的代码也保留了评分器的原始记录。该记录给出技术未知；运行日志显示补丁已干净应用，测试启动时在候选的 `django/db/models/lookups.py` 第 26 行出现缩进错误。原基线同文件可编译，锁定候选在同一行独立复现了错误。该阶段补充归因为候选代码失败。这份离线诊断没有返回给成员。[原报告及候选归因证据](../../artifacts/software-benchmark-v243-2/ordinary-r1/first-score-adjudication.json)

## A2：哪些回执能证明下游真的可以开工

核对三个预登记的历史 A2 窗口时，发现原指标按 `recipient` 查找补丁交接的输入参数，工具实际使用 `to_member`，回执使用 `recipient`。原统计还要求先看到上游完成工作包，会漏掉先固定并交接、后登记完成的真实顺序。本轮修订了归因：绑定上下游任务、成员、补丁编号及交接事件；分别记录定向发送、回读、无冲突采用，以及下游就绪或实际开工。分支前就已存在的产物单列，不能算作策略新增的代码。[归因实现](../../src/proworksim/software_dependency_chain_v243_2.py) · [原始窗口与核查结果](../../artifacts/software-benchmark-v243-2/ordinary-r1/historical-dependencies.json)

| 真实历史窗口 | 触发后的关键操作（分支内步号） | 可支持的判断 |

| Matplotlib-25775，历史 ADAPT | 第 12 步阻塞；15 固定补丁、17 定向交接、19 登记上游完成；26 仍阻塞，28 下游集成，30 就绪，32 开工 | 上游完成并发送后，下游仍需实际采用 |

另在真实 OpenHands SDK 与项目工具上，从“已有补丁、下游尚未采用”的受控状态激活 D4 交接和 D7 调度。首个行动机会给了上游负责人；随后依次取得定向交接、下游回读、无冲突集成、就绪与实际开工回执。本项使用脚本化决策和成员回复，外部模型调用为零，验证范围是工具与调度的执行链。[SDK 控制记录](../../artifacts/software-benchmark-v243-2/ordinary-r1/d4-control.json)

## 如何继续原会话并计费

恢复以旧请求为单位核对成员、请求身份、模型实际输入、原回答、执行回执、调度和用量。第一次免费回放找到了原墙钟耗时与回放耗时之间的差异；原记录中的耗时及相应派生摘要恢复后，其他世界字段必须一致，再载入完整的原状态。第 50 步时累计账面用量恢复为 2,466,969 token，001 在第 51 步重新行动。

恢复过程又暴露了一处执行错误：调整 SDK 截止时间后，测试容器的 RPC 仍绑定旧时间，导致 001 已请求的公开测试未执行。修订后同时绑定 SDK、公开测试入口与容器的截止时间。最后一次恢复核对了前段 12 份及后段 7 份历史请求，对照了已完成的工具操作，并让第 57 步原本中断的测试实际运行：113 项通过。到这个边界累计用量 2,970,985 token，剩余 2,029,015 token，19 份历史请求的回放费用均为零。之前已经结算的费用保留，评分只使用各阶段事先锁定的候选。[恢复登记与原测试标识](../../artifacts/software-benchmark-v243-2/ordinary-r1/recovery-rpc.json)
