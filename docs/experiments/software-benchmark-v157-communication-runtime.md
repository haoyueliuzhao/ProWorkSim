# v157 真实通信运行层实现说明

本说明记录 Communication Pilot V1 的运行接线，不报告真实模型实验的结果。正式题单、现金授权和两波调度由主协议及部署清单管理；这里的 CPU 控制没有发生真实 API 调用。

## 实际改变的部分

三种条件均使用原 REVIEW2：member_001 开发并最终交付，member_002 独立复核。原生 OpenHands SDK、私有会话、模型采样、历史摘要、自检提示、同版本测试和固定交付规则保持不变。运行层没有新增自主成员、未受管命令入口、自动合并、自动测试或自动提交。

- **C0**：保留原默认观察中的最近 4 条消息、最近 4 条交接及每条 500 Unicode 字符预览。新增的来源索引及分层读取能力在三组一致提供，不把 C0 悄悄改成完整原文默认推送。
- **C1**：对合法发布的完整消息，调用固定的通用摘要服务选择原句事实，再以统一字段呈现。
- **C2**：使用同一压缩模型与输出上限，传入接收者实际职责，使服务按开发者或复核者的需要选择和排序原句事实；默认呈现来源索引与摘要，原始材料按需读取。

C1/C2 是**模型选择和排序原句的抽取式通信压缩**，不是允许模型自由改写事实的摘要。压缩请求没有工具权限，不改变消息的发送时间、接收对象或成员职责。一次已发布消息对同一接收者只压缩一次，后续重复呈现沿用该版本的结果；重复呈现仍随接收者实际模型输入计费。

## 发布、默认呈现与回读

来源生产器只读取实际提交到 World 的 `work_message`、`handoff` 等定向通信事件。消息作者、接收者、事件序号、原文、已公开版本引用及原句跨度写入不可变存储。失败的工具请求不构成发布，发送者未公开的工作区、笔记和测试日志不会自动送给压缩器。

全部条件仍为 **38 个工具**。既有 `read_work_event(sequence)` 增加可选的 `level`、`version_hash` 与分页字段：

| 调用 | 返回内容 |
| --- | --- |
| 不指定 level | 原来的完整事件，保持旧行为 |
| L2 | 精确的受保护原句及其发送者声明语义；无法安全结构化时回退原文 |
| L3 | 该已发布版本的完整原始文字 |

L2 目前是**已发布的关键声明**，不能解释为独立验证过的测试证据。原事件中已有的补丁或版本引用仍保留；不会因为压缩器能在主机上访问文件，就赋予接收者新的读取权限。所有层先通过原 World ACL，保留发送者和接收者原有的事件读取权限；不同条件不能绕过这一边界。指定错误内容版本会被拒绝。读取操作仍消耗正常工具机会，读取内容在进入下一次模型输入时计费，不手工再增加一次 token 消耗。

## 原句结构化的可信边界

`source_facts` 用确定性的句子边界和编码场景规则建立原文跨度。测试、失败、否定、未知、风险、路径、数字、版本等标记受保护；结论和下一步动作保留。已识别且不含这些保护标记的背景或解释性修改句可以作为可选信息，避免所有消息都退化为无法压缩的原文。

`facts_complete=True` 只表示生产器对原文非空白字符建立了完整的确定性跨度，**不表示已经证明语义事实完整或发送者说法正确**。未识别的自然文、代码围栏等回退原默认预览。模型只能选择已存在的 fact ID，不能生成新事实；漏掉受保护事实、混用版本、返回非法结构或渲染超过上限，同样回退原预览，已经发生的费用保留。

因此，实际自然文仍可能产生保守回退，或在可选事实判断中存在未被词法规则识别的语义风险。后续需要报告压缩适用比例、回退类型和独立保真审计，不能仅凭原句抽取声称“无信息损失”。

## 输入来源与实际费用

请求原件与实际 provider usage 仍分别留存。输入来源分账明确为估算；API usage 才是实际团队输入、输出和现金总账依据。压缩器输入、输出、重试及未定预约均进入与两位成员和历史摘要相同的 5M 团队池和本轮现金账本，没有第二个压缩预算池。

真实 SDK 请求中的压缩表示进一步拆成两类：原句片段归 `Peer-message`，主机添加的字段名、fact ID 和声明标签归 `Base/Template`。来源索引归 `Artifact`，按需回读正文归 `Retrieved`。摘要父来源仅代表可追溯关系，不等于父原文已经向成员呈现。历史摘要使用同一个原 SDK 算法和模板，只扩展来源标注。

一次辅助服务网络失败在 host 完成有限重试后，可以回退原预览继续团队任务；费用不明时保留全部预约并减少可用余额。原始实际总量仍标未定，不填 0。源绑定、权限或账本完整性错误继续作为执行故障处理。

原自检实现曾把任何未定费用一律当作无法结束。v157 只允许“已结束请求、host 完整保留预约且不确定性仅来自压缩器”的回合合法结束；是否追加原有一次自检按已知用量加未定上界保守判断。原提示、次数和时限不变，不清除未知费用，也不将保守上界冒充实际用量。

## 必要控制

`tests/test_communication_execution_v157.py` 覆盖实际 World 发布、原 500 字符 C0、压缩结果缓存、同 ACL 和版本拒绝、原句跨度与包装标签分账、缺关键事实的已付费回退，以及压缩网络未知后的保守自检和合法结束。

`tools/check_communication_sdk_v157.py` 使用现有 pinned OpenHands SDK、真实小型仓库和 CPU 公测、真实 provider SQLite 与请求捕获，但把物理网络 transport 换为明确的脚本服务。控制包括 C0/C1/C2 正常闭合，以及一次压缩服务发生未知网络结局后仍完成复核和交付的独立控制。它同时核对成员观察中的预算、调度预算和 host 同池计量。控制结果见最终准入报告指定的证据目录，不将脚本 token 或合成现金结算当成真实消费。
