# v0.24 训练与时间信用：终态只读分析

本轮两种方法各完成两次真实整窗更新，且共同第一窗严格复用了同一份当期经历与完整 learner 起点。Handoff-RTG 确实减少了交接后动作获得的既成 0.2：共同 D0 中26个决定的目标由0.2变为0，正优势决定从47个降至21个。这个机制变化没有成为本轮工作优势；完整评价的预定 Handoff-RTG−MC 差值为−25个百分点。不能把“减少交接后正优势”当作工作能力改善。

本附录读取自动归档的 `credit-pilot-v024.json` 与必要原始训练记录，独立复算目标、优势、分母及身份链；只新增本 Markdown 和同名 JSON。没有调用模型、grader、概率重算、世界重放、测试或 checkpoint tensor 加载，没有修改原始记录和分数。自动归档提交为 `0969432`；总体评价与资源结论见[本轮总报告](credit-pilot-v024-final.md)。

## 2. D0 隔离出了实际的时间信用差异

共同 D0 的六槽终局奖励按原顺序为：

| 槽 | 职责 | 原终局 R | 完整职责 |
|---|---|---:|---|
| train-1-0 | A | 0.2 | 否 |
| train-1-1 | B | 1.0 | 是 |
| train-1-2 | 独立实现 | 0 | 否 |
| train-1-3 | 独立复核 | 0 | 否 |
| train-1-4 | A | 0.2 | 否 |
| train-1-5 | B | 0 | 否 |

B 的第一窗初稿事前设为正确。这一条完整职责是对已正确准备产物完成当前合法独立复核；不能解释成成功修复错误初稿。两条 A 都只有合法适用依据送达，没有正确构建或完整交付。

两个 A 的首次实际送达分别发生在原事件序号32、55，早付0.2，终点补差均为0。事件回执 hash 与原 rollout 中的 `environment_event` 匹配，action sequence 早于实际送达；所有18条新经历的账本都保持原终局总和及原终点。**本次实际运行没有出现负终点补差**；负补差能力仍由先前 CPU 机制控制支持，不能称作本轮已观测的业务现象。

在两臂完全相同的81个原决定中：

- MC 将0.2分给 A 的全部34个决定。
- Handoff-RTG 仅使交接发生前及产生交接的8个决定保留0.2；26个交接后决定变为0，其中 provider 7个、implementer 19个。
- B 成功槽的13个决定仍以1.0为目标；其他非 A 决定完全不变。
- 共同起点 critic 值全为0，因此26个目标变化在第一窗也恰好对应26个正优势变为零，正优势总数47→21、零优势34→60。

这些是对原始 `model_call started` 序号与实际账本重新做求和的结果，不仅照抄消费声明。逐行确认 `advantage = return_target - old_critic`，并核对“6个计划槽×实际活跃成员×该成员全部实际输出 token”分母；输入 token mask 为0、自有输出 token mask 为1。没有因为无产出、拒绝或格式失败而筛掉有完整实际输出证据的决定。

D0 中带拒绝工具动作且具有正优势的决定为 MC 5个、RTG 2个；没有实际世界动作但具有正优势的决定为 MC 6个、RTG 1个。这只描述同一数据上的信用改变，不证明这些行应该删除，也不证明这些行造成了能力变化。决定数不是梯度贡献百分比。

## 3. 第二窗：两条新策略的经历与 critic 都已不同

| 同一第二窗槽 | MC 终局 R／完整职责 | Handoff-RTG 终局 R／完整职责 |
|---|---|---|
| A，重复0 | 0.2／否 | 0.2／否 |
| B，重复0 | 0／否 | 0／否 |
| 独立实现 | 1.0／是 | 0／否 |
| 独立复核 | 0／否 | 0／否 |
| A，重复1 | 0.5／否 | 0.2／否 |
| B，重复1 | 0／否 | 0／否 |

第二窗情境、seed 和预算按协议对应，但两臂各自由更新后的本分支采样，原始行为与回报已分化。MC 获得一条独立正确构建并固定交付的完整实现、一条 A 的送达后正确构建；RTG 两条 A 均只有送达。两臂第二窗 B 初稿均事前设为错误计数，均未完成完整修复职责；两臂的独立复核也都未取得其评分项。这些是训练采集中的事实，不替代冻结 endpoint 评价。

已有行为记录显示，MC 第二窗实际 `sql_build` 工具调用5次、`submit` 调用2次（其中1次被拒）；RTG 为4次、0次。`sql_build` 被实际调用或工具响应 `ok=True` 不等于内容正确，正确构建与完整交付仍使用原独立业务分项判断。两臂无实际世界动作的决定分别6个、9个；这不是生成错误率或全部请求失败率。

第二窗的 critic 已分别学习：

- MC 原 critic 值范围约 `[0.0037207, 0.0054539]`，目标0的31个决定具有负优势，55个正回报决定具有正优势。
- RTG 原 critic 值范围约 `[0.0036601, 0.0051095]`，10个交接前／产生交接的 A 决定仍以0.2为目标，具有正优势；其余68个决定目标0、优势为负。
- 其中 RTG 的25个 A 交接后决定，终局 R 仍为0.2，但当前回报目标已为0，减去正 critic 后形成负优势。这不是负的终点结算，不是新增加业务惩罚，也不是把目标为0的行删掉。

因此不能将第二窗“55对10个正优势”全部解释为同一数据上的时间信用效应：策略、实际行为、终局成果和 critic 已同时沿各自方法演化。D0 提供直接机制对照，第二窗提供各方法继续在线学习的整体记录。

## 4. 数值、梯度与工作结果各自表示什么

原记录的 actor 梯度范数依次为 MC第一窗0.02547、RTG第一窗0.02438、MC第二窗0.03400、RTG第二窗0.00560，均有限非零。两臂第一步各改变589,824个 actor 元素；第二步分别改变1,114,092与1,114,005个元素。这证明更新确实发生，并不衡量工作质量，也不证明较小梯度导致较差结果。当前未启用分组梯度捕获，不能从正优势决定数推导某类行为占了多少实际梯度。

现有完整评价的主差值 RTG−MC 为−0.25，方向不支持“交接提前结算在本样本改善完整工作”。更合适的结案表述是：**时间信用机制真实改变了学习信号；本次有完整配对的 pilot 中，Handoff-RTG 的完整职责表现低于 MC，没有取得预期工作收益。**不据此断言所有任务上 MC 更好、RTG 无效，或已经识别 v0.23 下降的机制。

限定仍包括：一个共同初始化，每臂仅两次更新；六个评价情境各重复两次，不能视为十二个独立任务；终局部分奖励与完整职责仍非同一个目标；分母包含随机实现的成员输出长度，两种方法是不同 surrogate，不声称无偏梯度等价。第二窗更新并非固定 D0 的重复，因此其结果包含各自采样和 critic 差异。GPU 共卡条件不同，总报告单列了竞争，不能用训练耗时差宣称一种信用配方计算效率更高。

本轮没有 ID-VTDO 调权或新外部模型评价，不能从内部时间信用结果推出组成优化或广泛协作迁移的正负结论。
