# v079：API 环境启动并发由4增至8

v076运行观察中，CPU和内存尚有余量，但四个环境启动名额持续占满，派发至SDK就绪的时间中位数约78秒、均值约105秒。这一时间包含环境物化和排队，不能单独解释为Python导入耗时。已完成任务持续腾位，使实际API回合数长期低于目标44。

本修订只为后续独立API协调器提供私有资源适配层：最多8对环境同时启动，仍为API最多48、Qwen最多4、全局52个逻辑槽。每个actor/controller的CPU与16 GiB内存限制、原CPU片段映射、原分配锁、主机256 GiB内存安全余量、启动中每对32 GiB估计余量、评分余量、磁盘空间和实时压力监控保持。全部新API容器继续受已经获准的224 GiB父资源组约束，不新建或更改该系统资源组。

旧Qwen仍使用自己的四启动名额规则。新API发现Qwen尚未补足应有席位时，停止新增API环境，但不取消已有API或Qwen回合，也不阻止评分申请。若Qwen恰在八个环境启动期间完成一题，它的新回合仍可能短暂等待已在启动的环境完成SDK准入；此后API不抢先补满这些名额，避免持续阻碍Qwen补位。Qwen剩余不足四题或正式结束后，保留席位相应减少。进度文件缺失或异常时，默认仍保留四席。

部署只改变后续API任务的宿主调度。`software_benchmark_resources_v076.py`及正在运行的Qwen模块、模型可见配置和单题预算均未修改。新的`EpisodeBindings`明确拒绝运行Qwen回合，资源申请还会在原分配锁内再次核验Qwen补位优先权；API派发上限不是仅在进度输出里修改一个数字。

八项必要CPU控制通过，覆盖16线程竞争时仅允许8个环境启动、Qwen空位阻止新API申请而允许评分、原物理CPU/内存/压力门、原模块全局状态不变、原容器限额及API专属绑定。静态检查通过，未执行任何模型、Docker或服务操作。验证凭据位于[启动资源控制](../../artifacts/software-benchmark-v079/startup-resource-validation-r1/validation.json)。实际并发和提速效果须由部署后的运行数据确认。
