# v057 共享服务器挂载事故与恢复记录

日期：2026-10-24。本文件是脱敏摘要；不包含其他用户姓名、路径、进程号或容器身份。

## 事故说明

本项目在验证用于评分的 **slirp4netns 网络方案时，导致共享服务器出现挂载异常**。原方案对隔离边界的判断不足，验证操作的影响进入了共享宿主环境。这是本次项目操作造成的事故，不能只归类为一个评分容器启动失败。

发现后，工作范围收缩为事故取证和恢复，停止推进模型、评分、NAT及新容器实验。恢复依据是已有挂载记录、保留的命名空间、明确的存储配置与迁移核验记录；没有通过目录同名猜测丢失挂载的来源。

## 恢复范围与核验结果

| 类别 | 已完成的恢复与必要核验 |
| --- | --- |
| 系统挂载 | 恢复进程管理、安全、终端、共享内存及相关内核视图；核对类型和可见性。终端与共享内存视图保留原文件系统设备身份。 |
| 本项目数据绑定 | 按原登记源目录恢复两个数据卷绑定，以设备、目录inode、所有者及原身份标记核对。 |
| 受影响的数据绑定 | 依据原存储配置及历史已挂载记录恢复已确证映射；最后两处来源经当前配置、迁移后核验和后续挂载检查交叉确认后恢复。 |
| 活跃容器视图 | 从仍保留的原视图恢复overlay和网络命名空间挂载，核对原进程身份、设备／inode和命名空间身份；没有以新建容器替代原对象。 |
| 传播别名 | 区分同一共享挂载的别名视图与独立文件系统，核对恢复后的可见性，避免把别名重复建立为另一套对象。 |

最终只读核验覆盖事故日志中的 **26条挂载记录**：其中 **20条持久挂载或传播别名均已可见，缺失数为0**；其余6条属于已删除的本项目临时NAT路径，不应作为持久挂载重新创建。这26条记录不等于26个独立文件系统。

另对进程管理、安全、终端和共享内存四项核验了文件系统类型；原终端及共享内存的设备身份保持。原活跃容器进程的身份与启动标识、网络命名空间inode仍与保留证据一致。

数据绑定和活跃容器视图的恢复使用原目录或原命名空间对象；部分系统虚拟文件系统按原类型和选项重新挂载。已记录的恢复动作未执行文件复制、覆盖、删除、格式化或全盘修复，也未为这些恢复停止或重启相关活跃进程。取证限于必要的存储配置、挂载记录和路径身份元数据，不读取业务数据或进程内存。

## 核验边界

上述结论证明的是**已知挂载及对象视图的恢复状态**，不是全服务器历史状态或所有任务业务状态的完整证明。

- `binfmt_misc`的挂载与enabled状态已恢复，但缺少完整的历史注册handler前态，不能证明所有历史handler均已完整复原。
- 没有对所有用户的业务进程、任务进度或数据文件做全量完整性检查，因此不能声称所有任务未受影响，也不能作“零数据损失”承诺。
- 原始日志、挂载表、目录身份和操作回执只留在本机私有证据区，不纳入远端提交。本文件仅保留脱敏后的恢复类别、结果与限制。

## 实验继续硬暂停

项目级共享服务器事故保护保持 `hold=true`。新NAT、新评分容器、评分环境准入、16项候选补评及新模型宿主运行入口均受硬门控；只读检查和必要恢复／清理不受此实验派发门限制。

挂载恢复不会自动解除保护，也不构成恢复实验的授权。当前不能宣称新的评分环境已通过准入、16项补评已完成，或适配修订带来了正确率收益。原候选和历史评分继续保留，不因事故恢复而改判。

后续解除硬暂停须取得明确恢复授权，并完成隔离边界的独立审查；资源验证、评分环境准入和正式实验应按重新确认的顺序实施。本次恢复收尾不启动任何模型、评分或NAT任务。
