# v120：工具参数误拒修复与首次任务接续

v120修复PROJECT工具参数校验中的系统性误拒，并继续原50题中尚未调用模型的23题。模型、提示、工具schema、预算、history、actor和公开测试证书沿用已封存配置；变更仅涉及参数一致性判断和有序停止新任务的调度方式。

## 修复内容与验证

旧校验直接比较保留字典插入顺序的JSON字节。模型回包中的`path_prefix、text`经SDK变为`text、path_prefix`，虽然键和值相同，仍被当成参数改写。数值`1`与`1.0`的等值转换也可能触发同类误判。

新校验按JSON值比较：忽略对象键序，接受等值数值；数组顺序仍必须一致，布尔值与数值仍区分。原始模型参数字节保留，不替模型重写参数，也不放宽实际世界工具的schema、权限或版本规则。若参数未满足工具要求，仍给出普通受管拒绝，模型可在下一次有预算的机会中处理。

实际SDK控制复用了原8000回合的真实参数顺序，验证旧路径在调用工具前误拒、新路径能够执行两次搜索；另验证`start_line=1.0`收到普通工具拒绝后会话仍可继续，并完成一次结束自检。共5条脚本回复、1,405个脚本token，三层记账一致；没有调用真实模型或API。[SDK控制](../../artifacts/software-benchmark-v120/cursor-sdk-control-r2/summary.json)、[工厂与bundle接线证明](../../artifacts/software-benchmark-v120/runtime-wiring-controls-r1/summary.json)

新增drain模式只停止新的任务准入。在途生成按原预算和截止时间继续收口，已有评分及清理继续完成；不强制取消这些任务，也不自动重试已调用模型的回合。运行源码仍保持冻结。[参数与drain控制](../../artifacts/software-benchmark-v120/tooling-and-drain-controls-r1/summary.json)
