## 2. 计量门究竟修改了什么

v156已证明完整请求捕获、SDK来源绑定和CPU账目控制可行，但3份历史实际请求的本地官方tokenizer结果分别比API少47、47、56 token，无法声称来源类别与供应商token逐个精确对应。这一事实及原拒绝准入报告保持不变。

本轮按用户接受的双口径执行：

- **总量用API实际usage。** 每个物理请求分别记录输入、输出及缓存命中；缓存命中是输入子集。重试、压缩、摘要均计入团队总账，不通过逻辑请求数推算费用。
- **来源使用明确标注的本地估算。** 八类来源互斥，保留实际请求字节范围、事件及版本。分片估算不按比例拉齐API总量，也不将字节覆盖率冒充供应商token覆盖率。
- **只移除“供应商来源逐token精确映射”这一必要条件。** 原件／usage完整性、来源估算覆盖至少98%、未归因不超过2%、单请求未归因比例p95不超过5%、身份／权限／版本及账目一致性仍是门槛。

Team Input/Output/Total是总账；Peer Exposure、重复呈现、回读、压缩器消耗等是分析子账，存在重叠，不能再与总量相加。最终报告同时给出API实际均值、来源估算及未归因比例。

[用户修订原件](../../artifacts/software-benchmark-v157/user-amendment-r1/authorization.json)；[历史P0计量门的本轮解释](../../artifacts/software-benchmark-v157/user-amendment-r1/measurement-revision.json)。后者只适用于已有CPU控制，不能替代新部署或真实第一波的检查。

## 3. 通信与权限边界

C0保留原接口最近4条、每条500字符的默认预览，三组有相同的合法原件索引和回读入口。C1/C2只替换同一槽位中的内容呈现；不改变角色、发送规则、接收对象、权限和历史摘要算法。由呈现影响后续模型行为是实验要测的现象，不要求不同回合恰好发送相同消息。

压缩采用来源片段选择和重排，不让模型任意改写事实。实际发布时将原文绑定不可变ID、发布事件、发送者、接收权限及字符跨度。关键版本、测试状态、否定、风险与未知保留；不将发送者自述当作工具证明。无可信分片、压缩失败、引用错误或关键内容缺失时回退原预览，已消耗的压缩token和费用仍记账。

C2默认呈现L0索引和L1核心信息，L2已发布关键陈述／证据引用及L3原文按相同权限读取。**L2中的发送者陈述不是评分器独立核验的事实**；没有已发布工具证据时，不补造测试结果。原件只能来自已发布材料，不能以压缩为由开放另一成员私有工作区、私有历史或隐藏评分信息。原文被发布、被接收、被呈现、被回读、被采用和被验证是独立状态。

保真复核在结果产生后进行：关键交接全部抽取，普通交接按冻结种子至少25%抽取；生成隐去条件和最终成绩的双人审阅包。抽样及包生成不等于审阅已完成，没有审阅记录时相关指标保持待审，不能编造“无信息损失”。

## 4. 执行与异常恢复

仅使用本轮隔离容器、专用卷及普通用户协调服务，不更改共享服务器挂载、网络、驱动、守护进程或其他用户任务。默认network=none、drop ALL、无宿主目录绑定、无GPU。本轮不恢复训练或本地模型。

生成和官方评分异步进行。单题网络错误采取有限物理重试，保存原件及费用；不能确定是否收费的请求保留预约。局部容器／导出／评分异常进入单独恢复集合，正常队列继续。已锁定候选只重评同一版本，不能因低分重跑模型或另选补丁。共享账本不一致、源文件漂移或普遍测量失效属于共同故障，应暂停受影响部分并保留证据。

第一波结束只核对请求／usage对账、来源覆盖、版本权限、队列与资源完整性。不根据通过率调整C2、换题或提前宣称完成。第二波沿用同一冻结实现。最终分别报告代码正确率与合法交付率，并保留未完成／未知及其实际成本。
