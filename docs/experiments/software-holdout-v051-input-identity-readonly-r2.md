# v0.51 HOLD 初态身份比较的只读修订 r2

本修订处理初态资格测量中的一个遗漏字段，不修改共同源码 0770d02、真实模型可见输入、tokenizer、Γ、题目、seed、解码或运行预算。原来源资格和原初态资格均保持原字节。新证据只分析已经保存的请求，不重建 SDK 会话、不重新编码、不加载权重、不执行测试或模型。

## 原始结果保持

唯一来源资格的 24 个逻辑状态去重为 13 次实际执行。iniconfig 1/2、dominate 1/2 通过；funcy 1/2 缺少测试依赖 whatever，python-slugify 1/2 不满足原测试 ID 一一映射。后四题继续来源阻断，不补依赖、不改映射、不重试资格。

来源通过的四题按原四状态、两角色完成 32 个真实初态 SDK 请求形状。32/32 的 selected 输入加 2048 输出均不超过 18432；实际底层编码 64 次、精确缓存命中 160 次、模板渲染 64 次。原测量仍为 completed=true、passed=false、qualified=[]：它将四题全部判为跨状态业务输入不等。原结果不能改写为通过。

## 遗漏字段及修订范围

原件只读比较发现，八个 task×role 组各自的四状态请求恰好只有 observation.instance_id、observation.branch_id、team_model_budget.state_sha256 三处叶差异。原比较规则已归一化 instance_id 和预算摘要，遗漏了 branch_id。封存的世界创建代码为 instance_id 和 branch_id 分别调用 uuid.uuid4().hex，HOLD observation 原样公开这些字段；native 输入仍保留消息内容。

因此 branch_id 是**实际模型可见的随机命名空间标识**，不是非输入宿主元数据。它不来自业务源码、检查点标签或生成成绩。独立只读审阅支持在分析等价比较中仅额外归一化 `/observation/branch_id`，保留原已声明的 opaque 字段规则，并要求其余完整请求内容一致。具体原值、字段路径、32 个请求与投影引用、封存来源及审计程序均由独立审计回执绑定。

这不是原始输入逐字节相同的证明，也不证明模型对随机 ID 不敏感。真实请求、实际长度差异和未来独立世界的随机标识不变；正式每次请求仍执行原硬容量门。资格期间的四状态只有元数据装配，没有宣称已经加载权重或通过正式参数/RNG guard。

## 新回执与正式范围

新增 `v051-holdout-initial-input-identity-readonly-v2` 摘要，明确标记为在原资格之后的只读测量修订，引用原 false 摘要及其全部 32 个请求/投影。新摘要不取代原件，不伪装成原事前比较规则已经通过；实际输入与共同执行条件完全保持，新增 SDK、tokenizer、业务测试、模型调用和参数更新均为零。

在独立审计证明上述唯一遗漏后，原来源通过的四题取得修订后的输入身份资格；其余四题维持来源阻断。模型准入仍单独签发，并只允许这四题各四状态的原 16 槽。完整原 32 行库存保持，另 16 行无 attempt、F/Q=null，不借用其预算。可派发上限为 8,000,000 token、2048 决定/attempt、512 次团队公共测试；每槽仍为原 500,000/128/128/32。四状态、配对 seed、先手、顺序、3.10 测试环境、只读 checkpoint 与最大四 GPU 驻留均不变。
