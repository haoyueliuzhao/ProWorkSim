19:19 的只读快照为 75/1500 个生成回合闭合、5 个在途、1420 个待运行，73 个槽的全部必要端点已有明确结果。生成闭合与官方评分闭合不是同一计数，PROJECT 还可能具有交付评分端点。本时点不能报告完整500题完成率。详细快照见 `artifacts/software-benchmark-v054/deferred-fault-rollout-r1/recovery-observation.json`。

## 已部署的局部异常处理

新服务为 `proworksim-v054-formal-queue-deferred-r1.service`。它使用原队列目录及独占协调器锁，原已登记的生成、评分 worker 继续独立运行。一次性接管凭据固定了五个在途 job 的原身份，未创建新正式 claim。

明确归属单题的生成闭合、评分、worker消失或终态证据异常，进入 `technical_unknown` 和独立异常集合，继续派发其他可证明独立的任务。不会自动重跑已经进入模型的槽，也不会把未知费用记为零。若数值会话或费用完整性不确定，只隔离对应 resident 的新领取机会，不发送停止信号；其他健康 resident 可继续工作。

当前 PID、socket、ready 或 poison 故障按 resident 隔离。源码、共享策略、注册链、全局 claim 身份和无法确定范围的控制器完整性故障仍停止新派发；共享 CPU 预准备生命周期故障仍保留原停止门。因此，此修订解决的是已明确范围的局部异常，不能声称任何系统故障都能安全忽略。

独立调度策略位于 `runs/software-benchmark-v054/deferred-fault-policy-r1.json`，SHA256 `fe8bffd246f3f72d1cd38ff9a9ba44af3c05fe2b75185ac3fdaa159d3487d23e`。源码及边界说明见[调度实现](software-benchmark-v054-deferred-fault-queue-r1.md)和[资源健康隔离](software-benchmark-v054-deferred-live-pool-r1.md)。

## 性能证据与预计时间

暂停前 r11 GPU6 的44.616分钟窗口内闭合10个 MATCH／PROJECT 回合，约13.448回合/小时。355次实际生成阶段累计39.321分钟，占该窗口88.13%。这里是宿主记录的生成阶段 wall time，不是纯CUDA kernel时间或 `nvidia-smi` 的平均利用率。并发会话的墙钟不能简单相加当作总耗时，也不能将不同难度任务的均值差当作优化的因果效应。

正常官方评分样本27个，耗时中位数30.93秒，单独另列一次1800秒超时；恢复时没有持续评分积压。现有两个评分worker容量暂非主要瓶颈，增加评分并发并不能解决异常导致的整队列停顿。最直接的可避免损耗是单题评分未知引发约两小时的全局派发暂停；本次已修订其作用范围，并启用已经准备好的 GPU3 并发。

两张 MATCH／PROJECT 卡各20条已结请求样本中，原生生成调用占该请求执行时间约96.6%–97.9%。GPU6样本保留此前已读的两条和截止时最新18条，不称随机抽样。实际运行时对部分 causal convolution 和 gated delta rule 使用 PyTorch 参考实现，具有值得后续独立验证的优化方向；目前没有实测优化 kernel 的加速倍率。替换这些实现可能改变数值与采样行为，需另行准入和版本标识，本次未在活跃模型环境安装或替换它们。详细样本定义见[性能分析](software-benchmark-v054-performance-recovery-r1.md)。

按 GPU6 已观察吞吐、GPU3尚未形成稳定长窗口吞吐，以及题目难度和CPU测试波动，恢复后暂估2–4天，即大致10月23日至25日，末尾异常处理另计。这是容量情景外推，不是统计置信区间或保证截止日期；没有假定GPU7一定能提前转组，也没有假定后续不会出现共享系统故障。
