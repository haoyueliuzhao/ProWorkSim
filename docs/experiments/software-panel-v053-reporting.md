# v053：固定分母和层级报告口径

日期：2026-10-20。报告器仅读取已经生成的 worker 回执、固定 panel 和可选 host 状态；不执行模型、测试或补评分。`src/proworksim/software_panel_report_v053.py` 负责统计，`scripts/software_panel_v053_report.py` 负责文件来源核对与输出。

## 主面板和未知结果

主结果只使用 200 个不同任务的 `repeat_index=1`，每题权重为 1/200。设成功为 S、已知失败为 F、未知为 U，始终保持 S+F+U=200。仅当 U=0 时给出主完成率 S/200；U>0 时主完成率为 null，同时给出识别界限 `[S/200, (S+U)/200]`。识别界限不是统计置信区间。

未启动、资源等待、正在运行、技术未知分别保留。它们在尚不能判断结果时都保持 `R_code=null`。技术未知不能填成模型失败，也不另算“已闭合任务完成率”来替代固定分母。

机器报告同时保留：

- 280 个预定 slot 的状态、task ID、repository、repeat index、seed、回执引用和 token 账本；
- 200 个任务的第一次结果与全部预定重复结果；
- 20 个仓库各自 10 个主任务的成功、失败、未知和主完成率。

## 不确定性

仅在 200 个主结果全部已知时计算两类区间。

1. **Wilson 95% 区间**使用 n=200 的独立 Bernoulli 工作假设。它忽略同仓库任务的相关性，只作任务层级的描述；不把它称为已经处理聚类的区间。
2. **仓库整簇 percentile bootstrap 95% 区间**固定 seed `202610200531`，做 20,000 次重抽样。每次从原 20 个仓库中有放回抽 20 个，保留该仓库全部十题，计算重抽样面板均值，再取线性插值的 2.5% 和 97.5% 分位点。不把同题重复或同仓库十题拆成新的独立来源。

只有 20 个仓库簇，percentile bootstrap 的覆盖可能不理想。区间仅配合当前仓库均衡抽样设计解释，不是整个 SWE-smith 自然分布的无条件推断，更不是 SWE-bench Verified 分数。

仓库自己的十题 Wilson 区间也保存在机器报告中，仍遵循已知结果齐全才给点估计／区间的规则。任务层级保留原始三态结果，不构造单题稳定性认证。

## 40 题三轮诊断

重复子集固定为 40 题，分别报告三轮的 40 题完成率及未知界限。只对三个结果全部已知的任务分入 `0/3`、`1/3`、`2/3`、`3/3`，其余任务单列 `unknown_three_run_task_count` 和 task ID；五组数量之和始终是 40。

另保留有限翻转诊断：

- 已知观察中同时出现 0 和 1 的任务数；
- 40 题的混合结果比例，任何三轮结果尚未齐全时点值为 null，并给确定翻转数／仍可能翻转任务的识别界限；
- 仅当全部 40×3 结果已知时，给出每题三对运行、共 120 对的结果不一致比例。

三轮最多只能描述本次有限波动；不把“三次至少成功一次”作为主结果，不生成 280 回合混合平均的主完成率。模型失败类型同时给主 200、额外 80 和全部 280 的计数，后者仅是运行库存的故障描述，不重新定义任务权重。

## 实际 token 与失败归因

主 200、额外重复 80、全 280 分开汇总。每个 native generation receipt 在自己的 slot 内只能计费一次；不同 slot 的同名 attempt ID 不会互相去重。实际输入／输出 token、已经证实的实际合计、不确定预约和缺少账本证据分别保存。预约上界不能冒称实际费用。

完整已观测费用只有在已观测计算均已结清时才给值；完整计划的最终费用还要求该范围所有回合均已闭合。单回合最终 token 分布的 min、25%／50%／75%／95% 分位点、max、mean 只有对应范围每个最终费用均已知时才给值，否则为 null；原始每回合费用与已知小计仍全部保留。环境准备、CPU 测试和 GPU 驻留不混入生成 token。

host 已标记 `technical_unknown`、但 worker 未留下闭合报告时，报告器承接该技术未知状态，不能因缺少 `model-entered.json` 而退回“未启动”。对于 SIGKILL 等无闭合报告情形，只读该唯一尝试的原始 provider `prepared/started/complete` 回执，核对 slot window、actor、输入、输出和实际 usage 后汇入已知费用；未完成开始记录的预约仍单列。没有原始费用证据时，单回合费用为 null，不默认 0。只有绑定的显式未开始记录等零生成证据才能确认为 0。此恢复不产生模型调用或新评分，原来的 R 仍为 null；恢复来源与 worker 原始闭合回执分别标记。

`complete/R_code=0` 保留正式 worker 的失败原因；`technical_unknown` 保留技术原因和错误来源，不转成模型失败。技术原因允许多标签，因此原因计数总和可能超过技术未知回合数。资源等待重试必须同时证明没有进入模型加载、没有 resident、没有模型调用且实际 token 为 0，才能作为额外调度尝试而非额外独立回合计数。

## 来源和执行

所有 worker 文件必须匹配完整预定 row（包括 task、seed、repeat index）及 panel SHA。CLI 核对 `source_plan` 文件 SHA、其 panel 绑定和正式结果内的 panel 绑定。不同 run plan 的回执不得混入同一结果，即使任务 panel 相同；公共故障修订后的不同配置必须另行报告。正式回合重复回执被拒绝，不按成绩选择其中一条。

示例：

```bash
.venv/bin/python scripts/software_panel_v053_report.py \
  --panel docs/experiments/software-panel-v053-panel.json \
  --reports-root <本次固定plan的worker输出根目录> \
  --state <本次host状态快照.json> \
  --output docs/experiments/software-panel-v053-report-final.json \
  --markdown docs/experiments/software-panel-v053-report-final.md
```

阶段报告应使用新的输出文件名；已有不同字节的报告拒绝覆盖。报告程序不会将尚未发生的 280 回合标成完成。当前实现验证使用合成 fixtures，不代表正式模型成绩。

必要合成控制覆盖：第一次运行与重复结果权重分离、三态重复分组、未知不补零、完整 280 库存、资源等待不额外计题、重复 formal 回执／错误身份／重复账单拒绝、Wilson 端点。首次控制发现全 0 场景的 Wilson 浮点下界出现约 `1.7e-18`，已将理论端点显式保持为 0／1；没有使用正式成绩来调整统计方案。
