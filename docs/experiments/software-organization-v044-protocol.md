## 2. 归档、实际呈现和格式恢复分开

运行器完整归档原格式反馈、原输出、解析阶段与诊断、归属和费用；只有模型实际看到的消息按本协议投影。不能仅凭任意user文本中出现public_format_feedback字段识别为可删除消息，必须绑定运行器事件、成员、原call、响应身份及消息内容。来源或时序不清楚、文本匹配歧义时保守保留并给出诊断。

| 状态 | 当前请求规则 |
|---|---|
| 最新普通拒绝尚无真实selected输入及真实生成/入账证据 | 保留当前纠错正文，不能为fit直接丢弃 |
| 前一拒绝已实际呈现，下一生成仍产生新的普通错误 | 新拒绝承担当前纠错；旧拒绝标为superseded，不能叫已修复 |
| 实际看到错误后产生通过原生解析与公开schema的调用 | 旧普通格式反馈可历史化，不再永久占用prompt |
| 格式合法而业务执行被拒 | 只历史化旧语法反馈，新业务拒绝保持原真实回执 |
| 权限、身份、过程违规或critical记录问题 | 不套用普通错误清理，不放宽原执行边界 |

“已呈现”以同成员原selected内容、真实原响应及团队计费记录绑定，SDK发出消息或仅prepare不能替代。新成员有独立反馈状态，不复制父成员错误历史或补发免费预算。CPU程序响应标注程序来源，不写成模型实际行为。

最新普通反馈保留：对应call、拒绝状态、没有执行动作、原主要reason、真实native与adapter错误阶段、已知字段位置/缺失项/预期与实际类型/有证据的解析位置。完整hash、重复版本/来源、整段重复通用合同及未启用退休门说明留在完整审计记录，不反复放入纠错正文。不能让adapter最后一个错误覆盖原native失败。

不自动改工具名、补recipient、合成正确参数或代码，不免费重试；下一次真实模型机会仍消耗原团队预算。被看见不等于纠正，格式合法不等于业务成功。
