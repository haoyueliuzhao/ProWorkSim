# 剩余 14 项未知：原因与恢复边界

日期：2026-10-25。依据 v060 补评后的 200 回合测量快照及原始生成记录进行只读分析。未启动模型、Docker、评分、网络或系统管理操作，未改写原结果。

**“未知”表示尚无可信的官方代码评分，不表示故障原因都不知道。** 14 项可分为：8 项历史摘要接口故障、5 项模型服务停止期间的生成中断，以及 1 项生成已经结束但候选导出未完成。两题 Requests 的评分环境问题已经在 v060 消除，与这些未知不同。

## 1. 已确认的原因

| 类型 | 数量 | 直接证据 | 对结果的影响 |
| --- | ---: | --- | --- |
| 历史摘要请求与模型服务不兼容 | 8 | 每项前 40 次 Agent 调用成功；第 41 次首次 condenser 请求携带 `tools=[]`、`tool_choice=none`，vLLM 返回 HTTP 400，指出工具数组不能为空 | 控制器记为 AccountingFault 并中断，没有锁定可评最终候选 |
| 用户服务停止期间的生成中断 | 5 | 两项 tokenizer 连接被拒绝、两项生成响应被远端关闭、一项 tokenizer 返回 HTTP 500：`cannot schedule new futures after shutdown` | 未完成原定生成；两项在途请求没有完整用量回执 |
| 正常生成结束后的候选导出中断 | 1 | scikit-learn-14894／500万已有 finished、closed、静止证明、候选占用记录和完整终态快照，但没有最终补丁、候选锁或 episode 结果 | 不能直接评分，但具备从原快照恢复候选的基础 |

这些不是官方测试判为错误，也没有被记录为累计 token 预算耗尽。尤其第一类每项已确认用量仅约 79.9万—97.9万 token，远低于其 200万／500万／1000万上限；第 41 次是触发摘要的请求，不是本实验的调用硬上限（512）。日志明确指向空工具数组，不能将其改称为 131K 上下文溢出。

8 项摘要故障的修复已经在 v056-r2 实现：对没有工具的摘要请求省略相应字段，计数与实际派发采用同一形式。原请求 4,898 个 input_ids 同值与一次独立中性请求返回 HTTP 200 的证据已保留。修订只应用于当时尚未开始的 190 个回合，已进入的 8 项未自动重跑，因此它们仍保留未知。

## 3. 用户服务停止事件的证据与限制

北京时间 **2026-10-24 14:18:27**，既有用户级 systemd 日志记录 `Stopped target Main User Target`，调度器及六个模型常驻服务随后停止。五项故障控制器文件的最后写入集中在 14:18:27—14:18:32，与共同事件相符；其中一项服务端直接返回线程池已经 shutdown 的错误。

这足以将五项归入服务停止期间的技术中断。**现有证据不足以确定是谁、哪个登录会话或哪个命令触发用户管理器退出，也没有证据将它们归为 GPU OOM。** 文件修改时间用于交叉核对事件次序，不是单独证明信号来源的依据。

历史恢复记录显示，当时发现 `Linger=no`，随后启用当前用户的 linger 并恢复原未开始库存。那是 10月24日的既有操作；本次没有再次修改设置。该恢复没有补跑已中断的六项。

部分旧行仍保存 `generation.quiescent=false`，这是失联当时的状态。后续 **15:39:12** 的专项审计已证明六项原 worker／actor／controller 及锁全部静止，不能把旧字段解释为目前仍有六个任务在运行。该审计保留旧结果，没有伪造完成记录。

## 4. 最值得优先恢复的一项

`scikit-learn__scikit-learn-14894`／500万并非没有生成完。其原件记录 80 次 Agent 决定、82 次已结算模型调用、3,067,384 个 token，末次模型动作是 finish。

北京时间的证据次序如下：

| 时间 | 证据 |
| --- | --- |
| 14:18:20.002 | SDK 记录 finished |
| 14:18:20.018 | controller 记录 closed／native_finished |
| 14:18:21.049 | 派发关闭记录落盘 |
| 14:18:21.233 | 独立静止证明：all_quiet=true、无错误 |
| 14:18:21.289 | candidate-claim 已建立，状态进入 locking |
| 14:18:27.225—27.541 | 终态快照与来源 manifest 落盘 |

快照包含 1,586 个文件，252,857,250 字节，`truncated=false`，完整 JSON 可解析；SHA256 与原来源 manifest 一致，candidate-claim 引用的静止证明也匹配。冻结源码的顺序是先证明写入者静止并占用唯一候选，再捕获快照、导出补丁、写最终锁。

缺失的是 `candidate.patch`、`lock.json`、`candidate-result.json` 及 episode `result.json`。因此可以优先设计**从这份原终态快照恢复唯一候选，再评分**的流程，不需要重新让模型回答。当前尚未完成导出恢复或官方评分，不能提前计为成功；公开测试的通过记录也不能替代官方评分。时间与共同停止事件高度接近，但缺少最终 worker 退出回执，不能仅据此断言导出进程收到了某一种信号。

另外 13 项保留了一定的工作树、会话或中间记录，但没有同等完整的正常终态候选链。只评分残留工作区测到的是“中断时已有代码”，不能冒充原定完整预算回合的结果。如果以后续跑或重跑，应单独规定恢复状态、剩余预算与随机状态等边界并标识新运行，不覆盖旧未知或挑选多次结果中的最好值。

## 5. 对预算结论的影响

未知集中在较大预算组，缺失不是可以随意忽略的随机噪声。8 项由长回合触发以前短回合未覆盖的摘要路径；其他 6 项与运行时间上的共同服务停止事件有关。因此不能把这些未知填成模型失败，再推导“大预算没有帮助”。

同时，技术原因已查明也不等于代码结果已知。本次仍保留 **86 成功、100 未通过、14 未知**。本轮已知成功数和预算截止统计不变；高预算组的完成率界限仍应保留。

14 项合计已有 **23,936,174 个已确认 token**；另有 **421,967 个未确定预约 token**，不能将预约当作实际消耗。4 项账单完整、10 项不完整，与是否拥有可评候选是两个不同问题。详细逐项数据及原件引用见 [summary.json](../../artifacts/software-benchmark-v060/generation-unknown-analysis-r1/summary.json) 和 [unknown-cases.csv](../../artifacts/software-benchmark-v060/generation-unknown-analysis-r1/unknown-cases.csv)。原恢复记录见[摘要接口修复](software-benchmark-v056-empty-tools-r2.md)、[用户服务停止与恢复](software-benchmark-v056-session-stop-recovery-r1.md)。
