# v148：独立评分网络恢复监控器

本分支只读观察v146的Requests1766四个已预分配生成身份：10214、10215、10235、10236。每个身份最多为code和delivery各追加一次同候选评分，总上限8个新评分容器；不增加模型尝试，不改活动v146的源码、候选、评分记录或配置。

## 触发与停止规则

1. 生成结果必须为正常`closed`，并有完整生成清理证明。生成未知不借此伪装成正常回合。
2. 等待原协调器的最终评分：优先读取其第二次评分记录；若只有第一次未知，继续等待，直到原协调器结束。正常通过或正常失败都直接跳过。
3. 原评分最终仍为技术未知，且已消费的原评分／重评身份全部清理完整，才创建新v148评分。每次创建前重新核对同一最终候选和资格证据。
4. 使用已完成真实gold通过／empty失败控制的v147 idle180评分环境。原仓库、测试、补丁、CA及严格TLS校验不变，不重做控制。
5. 新评分只写`overlay-results.json`及独立收据，原记录保留。不同工作树的code／delivery分别评分；无合法交付候选不创建delivery评分。
6. 监控最多4小时，平时每60秒轻量只读检查。原v146结束且全部目标已处理或无需评分即退出；若剩余时间不足安全完成并清理一次评分，不再派发。新对象清理不明时停止后续创建。
