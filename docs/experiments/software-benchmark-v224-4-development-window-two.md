# 第二轮开发实验：第一轮学到的分工偏好能否迁移？

第一轮在 SymPy 上比较了维持分工与转交验证。两种安排均未通过官方测试，转交组少用 2,757 token，因此学到的方案偏好很小。本轮把这份参数记为 Q1，在两个不同的任务状态上使用它，保留每个候选的完整后继结果。[第一轮报告](software-benchmark-v224-3-oa-replay.md)

## 任务与条件

选择 v223.1 中全部两个具备完整保存点和组织 Agent 授权视图的开发任务。Astropy-14182 和 scikit-learn-13496 的任务身份、顺序、原始问题、图审阅、对话及成员私有工作区都在生成新方案前确定。两题属于已使用过的开发资产，适合检验执行和学习机制。独立确认需要另外的题目。

每题用同一个 DeepSeek Flash 非思考组织 Agent，根据保存点时可见的信息提出最多两种调整。允许一次格式纠正。每个保留方案以及维持原分工的 KEEP 各续跑一次，成员仍需亲自发出并接受请求。每个逻辑分支的500万输入加输出 token 包括历史共同前缀、原图审阅、本次方案生成和新续跑。账本只对本次新增请求结算。[回放清单](../../artifacts/software-benchmark-v224-4/oa-r1/plan.json)

冻结 Q1 后用原 seed 记录主选分支。全部候选均接受官方代码评分，并检查合法提交版本。只在本窗口所有已准入分支结束后，用候选齐全、结果明确、特征可区分的任务更新一次。对固定任务，C 为相对于同题加权均值的效用差，效用等于合法正确交付指示值减去逻辑 token 占500万比例的十分之一。N 表示当前选择概率对某类候选的欠覆盖程度。两者的权重、特征、拟合参数沿用第一轮。Q2 对本轮题目的回看属于开发内分析。[冻结的第一轮策略](../../artifacts/software-benchmark-v224-4/window2-r1/q1.json)

## 独立确认题的准备

先按固定哈希顺序从四个仓库各选一题，排除已列入历史组织实验候选清单的任务。随后在读取 scikit-learn 本轮官方成绩前扩大了历史清单核查范围，发现初选的 scikit-learn-10908 参加过 v203.1 和 v203.2。按同一顺序顺延到14710，其余三题保留。最终预选 Django-15467、SymPy-19040、Astropy-14508、scikit-learn-14710。两版清单均已保存。此处的独立性针对本次选择器开发；这些题可能有早期通用基准暴露。[最终任务清单与排除来源](../../artifacts/software-benchmark-v224-4/window2-r1/confirmation-task-ids-r2.json)

## 两次更新学到了什么

第一轮的参数在这两个新状态上的主选和均匀初始策略一致。第二轮对两个完整候选组拟合一次后，得到 Q2。对 scikit-learn，KEEP 的中心化贡献约为 +0.509，转交测试约为 −0.509。对 Astropy，三个方案的中心化贡献绝对值均小于0.001。Q1 接近均匀分布，两题最大的欠覆盖项 N 约为0.0000041。因此 Q2 的变化主要对应这次真实交付差异，对欠覆盖探索的证据仍弱。

用 Q2 回看本窗口，Astropy 的 KEEP 概率从约33.33%升到34.95%，scikit-learn 从约50.00%升到52.12%。沿用同一随机数，两题的主选身份均未变化。以上均为开发集内拟合结果，独立题的加权效用和交付率仍待测量。两轮开发中，有完整同题对照并实际进入拟合的状态共3个，第一轮1个、第二轮2个。

本窗口287次 API 请求全部结清，实际输入17,129,965 token、输出68,638 token，共17,198,603 token。新增费用22.48129256元，累计余额206.86845608元。[第二轮结果](../../artifacts/software-benchmark-v224-4/window2-r1/result.json)
