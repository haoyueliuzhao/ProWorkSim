# v054：Verified 500 题的 REF／MATCH／PROJECT 配对方案

日期：2026-10-20，Asia/Shanghai。本文取代 v053 的 SWE-smith 200＋40 重复面板作为后续正式评价方案；旧 v053 的 280 槽保持未启动和停止原件，不移入新分母，不恢复其监督器。

**当前授权是方案修订，以及用户随后明确要求的受管文件接口修复；不包括新增模型回合。** 本文、配置草案和 CPU 合成控制不构成模型准入。没有启动训练、多智能体、参数更新、配置搜索或新 GPU 占位。

## 1. 唯一任务集与比较对象

三组都使用 SWE-bench Verified 官方 `test` 全部 500 题，同一个原始 Qwen3.5-9B checkpoint，无 LoRA，一个实际 Agent，每题每组一次。官方任务身份、问题、基线代码和最终评分器相同；变化发生在求解配置与执行层。

| 组别 | 控制流、工具与历史 | 推理／资源配置 | 解释范围 |
| --- | --- | --- | --- |
| REF | 固定官方 OpenHands Agent／Conversation 与明确原生 preset | 单一外部参考候选 REF-P1 | 依据官方组件与通用建议建立外部参照；不是已找到的官方 9B SWE-bench 复现包 |
| MATCH | **与 REF 相同**的工具、模板、解析、condenser 和终端执行方式 | 与 PROJECT 匹配的数值路径及可匹配资源边界 | REF→MATCH 为推理模式、数值后端、容量和资源设置的组合影响 |
| PROJECT | ProWorkSim 实际 S1、受管工具、Γ1、分页和固定提交流程 | 与 MATCH 一致 | MATCH→PROJECT 为项目定制执行层的整体影响，不能直接归因于单个 API |

主比较为同题 `PROJECT − MATCH` 的 `R_code` 差；`MATCH − REF` 为预定次要比较，`PROJECT − REF` 只作整体描述。REF 仅在冻结后的完整相关配置、实际行为合同均与 MATCH 相同时才可兼任 MATCH；本候选的 thinking、窗口、输出、数值后端不同，不能合并。

本轮没有原 40 题重复子集，也没有第四个模型组。三组 1500 回合包含 500 个不同任务；不能把三组当作 1500 个独立任务。

## 2. PROJECT 修复的版本边界

初次审计发现现有 PROJECT 的 200 文件／2 MB 来源限制、缺失 create/delete/rename、目录与长文件呈现及候选过滤问题。用户随后明确要求“并行修复这部分缺陷”，因此本轮 PROJECT 应使用**明确标识并在模型成绩出现前冻结的 v054 修订接口**。

修复范围为完整公开仓库摄取、受管新增／删除／重命名、大文件的有界读取与目录分页、实际版本及固定提交绑定、候选变更完整导出。所有操作仍走原受管网关与版本账本，不新增不受管 bash，不绕开只读材料、同版本测试或交付要求。资源熔断必须显式报告，不能裁剪文件后冒称完整仓库。

这不是旧 v052 接口原封不动的复测；修复带来的变化不能称为训练收益或 ID-VTDO 算法收益。历史 R、未提交工作区及资格原件不补验。除用户授权的这些缺陷修复外，不顺便扩展任意命令、跨文件搜索或其他工具能力；缺失能力继续记录。

实际能力及代码依据见 [接口矩阵](software-benchmark-v054-interface-matrix.md)，实现与17项合成CPU控制见 [文件修复记录](software-benchmark-v054-file-repair.md)。接口的文件、schema、提示及部署限制应在正式阶段前生成完整 manifest，而不是仅记录“都用 OpenHands”。

## 3. 来源、镜像与材料边界

固定 Verified revision 为 `78f471bf655a3137b2e8a75af1501690ec009ec3`；目标 parquet 为 6,304,616 字节、SHA256 `030cfd7f2a704c4c0226e7f104c725a3b41230b1d3517f9c915ad7ea5be3fa25`。模型继续使用既有原始 revision `c202236235762e1c871ad0ccb60c8ee5ba337b9a` 及有效本地验证凭据。

准备时只投影 `instance_id/repo/base_commit/image` 形成完整 500-ID 清单。排序、清单 SHA、镜像身份及每题 seed 一次确定。不得按仓库配额、环境通过率、参考补丁触及的文件或任何模型表现筛选题目。全部 500 题在三组中保留原身份，环境故障不能补题。

截至方案修订时，国内 HF 镜像请求重定向到未批准的原站交付域，下载器停止，资产 payload 为 0；未回退代理或原站。同名 ModelScope 页面尚未证明包含同一固定文件。因此**500-ID 清单、1500 个具体运行槽、Verified 镜像和实际环境均未就绪**；不能把 v053 的 32 个 SWE-smith 镜像资格当作本批资格。详细已核实版本、获取状态及官方依据见 [来源与评分说明](software-benchmark-v054-source-and-judge.md)。

官方评分包候选为 `swebench==5.0.2` 的固定分发 SHA；其真实安装、依赖及与新版 dataset schema 的合同仍需准备。固定输入必须走本地文件和已准入镜像，禁止评分时隐式拉浮动 HF `main` 或 Docker tag。每题按数据的实际 `image` 字段取得官方当次 manifest、linux/amd64 config 和层 digest，再通过已核验国内直连服务只补缺失层。

2025-09 的官方 Verified Git 历史修复不等于所有缓存路径都已排除泄露。针对公开报告的具体路径核对 actor 可读状态；任何必要定向隔离规则在三组间相同并预先冻结，不盲删整个依赖缓存，不以 reference patch 设计工具能力。

Agent 只见原始问题、规定的公开仓库与自己的工作反馈。参考修复、`test_patch`、F2P/P2P 评分资料、评分脚本及隐藏结果只在可信评测侧；不把整行 dataset 放入观察、工作目录、可搜索日志或环境变量。不能将 Verified 的 `patch` 当成 SWE-smith 的缺陷注入，也不按 F2P 文件清单删去原公开测试。PROJECT 不重写题目成人工合同，不限定为答案涉及文件。

## 4. 配置与预算草案

REF-P1 的明确候选和版本缺口见 [参考配置](software-benchmark-v054-reference-configuration.md)。REF/MATCH 拟固定 SDK/tools `1.49.6`，同一 Terminal、FileEditor、TaskTracker、Finish、Think；关闭 browser、sub-agents、MCP，保持同一原生执行方式及 condenser。PROJECT 保留自己的受管工具／Γ1，不引入这些原生工具绕过管理。

MATCH/PROJECT 拟沿用非 thinking、18432 总窗口、2048 最大输出、T=0.7、top-p=1、top-k=0、相同 BF16 主干／FP32 head／项目 attention 和 sampler。MATCH 需要独立数值接缝，不能继承旧渲染器的项目 XML 提示、旧 terminal-only 限制或项目历史投影后仍称与 REF 相同接口。

REF-P1 为 thinking、131072 总窗口、32768 最大输出、T=0.6、top-p=0.95、top-k=20，外部引擎的确切版本及容量仍待冻结。它不是通过多配置跑分选出的结果。不能因为当前 GPU 不足而自动缩窗口、换量化或改模型。

| 范围 | 回合数 | 每回合输入＋输出上限 | 全部 token 上限 |
| --- | ---: | ---: | ---: |
| MATCH | 500 | 500,000 | 250,000,000 |
| PROJECT | 500 | 500,000 | 250,000,000 |
| 两主组合计 | 1000 | — | **500,000,000** |
| REF-P1 单列候选 | 500 | 500,000 | 250,000,000 |
| 三组都执行 | 1500 | — | **750,000,000** |

各组候选上限均为每题 128 次 Agent 决定、128 次全部实际模型 attempt；condenser 调用也计入实际 attempt 和 token，不开隐藏费用通道。所有实际输入重发、reasoning、工具调用文本、完整格式错误生成均计费。调用前预约完整输入＋最大输出，完成后结算实际 token；未知 usage 与中断保留未决预约，不能填零。

每题 90 分钟停止新模型请求，10 分钟只用于既定收口；硬边界 6000 秒。REF 单次生成时间候选与 MATCH/PROJECT 不同，明确列入配置组合差异。32 次受管公开测试上限是 PROJECT 的接口限制，不给 MATCH 引入一个可被普通 bash 绕开的“同次数”假门；记录全部实际命令、测试、子进程、反馈字节、CPU/GPU 时间。128 次模型调用不代表相同操作机会。

这些数字是上限，不是预计消耗，不包括镜像传输、环境准备和评分。旧 v053 的 1.4 亿预算不转入本轮；生成授权目前为 false，允许的当前实际模型回合数为 0。全局最多四个 resident 的候选策略不是每组四个，且 REF 容量不能沿用旧 45 GiB 门宣称已通过。

## 5. 计划槽、配对与执行顺序

实际数据取得后，以按 UTF-8 字典序排列的完整 500-ID 清单为基础。配对 seed 按 `SHA256("v054:202610200541:" + instance_id)` 的前 8 字节解释为无符号大端整数，再取模 `2^63`；同题三组共用该 seed，不保证跨接口产生相同动作。

调度 seed 为 `202610200542`：用独立 `random.Random(seed)` 对已排序 ID 洗牌；按该顺序循环分配 REF/MATCH/PROJECT 的六个字典序排列。三组对每题均从独立容器、工作树、会话、模型随机状态开始，不共享补丁、测试反馈或摘要。全部顺序、seed 和配置 SHA 在首个正式回合前物化冻结。

不能按前几十题成绩提前收口、调整提示或重挑种子。纯资源等待只有在有证据确认未进入模型时才能原槽重排。真实模型已进入后的中断不自动重采；共同故障暂停未启动库存，修订另存版本。某组先运行不允许将其结果作为另一组的提示或准备信息。

## 6. 同批生成的两个端点

### 6.1 统一代码端点

三组在预定结束边界停止修改，先锁定**唯一最后工作树**及其完整内容身份，再生成官方预测补丁并交给同版本官方评分器。`R_code = 1` 当且仅当该唯一候选的官方 `resolved` 为真；可确定的未解决为 0，导出／评分不可信为 null。不得按得分选择较早提交，不能把 v053 自定义“所有节点 PASSED/XFAIL”规则替代官方主分数。

即使 PROJECT 没有合法提交，评测侧也可在工作结束后离线检查这个唯一最后工作树。这只适用于本轮事前定义的新测量，不补验旧未提交工作区。锁定后无模型反馈、修复、重导出或候选择优。

导出应保持所有合法路径、内容、删除、模式和链接的语义。不能只接收旧三仓库的 `.py`，也不能无条件恢复 `pyproject.toml/setup.cfg` 等候选修改。不能表达的类型必须显式记录，不可静默丢弃后评分。

### 6.2 PROJECT 合法交付端点

PROJECT 另锁定**最后合法固定提交**，独立保留其源码版本、同版本公开测试执行、固定补丁及提交事件。提交资格保持项目实际语义；当前实现要求该版本执行过测试，而非要求公开测试全部为绿。

`R_delivery = 1` 要求合法交付证据成立且该提交候选通过对应官方终评。正常闭合但没有合法交付时为 0；交付或其评价证据不可信时为 null。REF/MATCH 记录 `not_applicable`，不填 0。

每题另报 `final_candidate_has_legal_delivery`、`last_delivery_tree_equals_final_tree` 和两棵树的内容身份，区分：

- 最后代码通过、该版本未完成合法交付；
- 最后代码未通过；
- 曾有合法提交，之后工作树改变；
- 候选／交付／评分技术未知。

最后工作树与最后提交不同，可出现 `R_code=0,R_delivery=1`，因此不能把两项均值相减统称流程损失。若两端点的完整内容与评价身份相同，可在同一 PROJECT 槽内复用同一权威评分回执并明确别名；不同树分别评分，不增加模型回合。

## 7. 官方评价与缓存

三组同数据 revision、基线、平台、官方评分版本及测试输入。不同 arm 和 endpoint 使用不同 `run_id`，例如 `v054-<config_sha>-MATCH-code`、`...-PROJECT-code`、`...-PROJECT-delivery`，每题保留原 `instance_id`。不得因官方按 run_id/instance_id 命中旧缓存而误读另一补丁结果。

每次评分另绑定补丁 SHA、完整树身份、dataset/harness/image/config SHA；不跨组搬用评分目录。只有同槽、同完整候选与同完整评价身份的双端点可以显式复用已经成功闭合的权威回执。评分异常后的技术修复只能重试已锁定的同一候选并保留全部原失败记录，不能恢复模型工作或修改补丁。

## 8. 全分母状态与统计

每组固定分母 500，逐题分别记录：

| 维度 | 记录规则 |
| --- | --- |
| 计划／覆盖 | 计划身份永不删除；公开预检证明的接口不可表达或部署限制单列；不据 gold 推断某工具是唯一必要操作 |
| 模型执行 | 在可信环境中产生可评候选时保留真实 resolved/unresolved，包括正常预算结束 |
| 技术状态 | 容器、账本、候选、评分或完整性故障单列；未启动与已进入后中断分开 |
| 过程限制 | 模型实际遭遇的工具拒绝、分页、调用／token／时间终止另计，不能直接宣称题目无解 |

若任一计划项未定，完整 `sum(R)/500` 点估计为 null。仍报告成功数 `S`、已知未解决 `F`、未定 `U=500-S-F`，以及 `[S/500,(S+U)/500]` 识别界限；覆盖限制与技术未知分别给数量。共同可运行／已知子集只能作为明确标注的辅助诊断。

主差保持逐题配对。未知对的差界限按各臂可知的 0/1/null 推导再按 500 等权求平均，不能只丢掉不完整配对。全部配对已知时报告配对差、discordant counts 和 exact McNemar；不对不同组使用独立样本差检验替代配对。

报告官方任务权重下的整体率和各仓库样本数／完成率。任务配对 bootstrap 在仓库内重采样并保持各仓库题数；整仓库 cluster bootstrap 作为敏感性分析，采用每次重采样的总成功／总题数，不把仓库简单等权当官方分数。两者 20000 次，固定 seed `202610200543`；Wilson 独立 Bernoulli 区间仅作有明确假设的辅助描述。有限仓库、单次运行和固定基准不支持自然软件任务总体或稳定性认证。

成本覆盖全部计划槽及所有实际尝试，分别报告输入、输出／reasoning、摘要、未决预约、公开测试、评分 CPU、GPU 驻留、工具操作与反馈分页；未知不填零，同一物理回执不重复计费。不给未启动任务制造实际成本。

## 9. 当前交付与正式启动前条件

本轮交付是方案、配置草案、能力审计，以及用户授权的文件接口修复和必要合成 CPU 控制。执行前仍需：

1. 取得并冻结真正的 500-ID 清单／1500 槽和实际 Verified 镜像、输入投影及泄露处理记录；
2. 完成 REF/MATCH 原生接口及 MATCH 共享数值接缝，冻结精确服务引擎和提示／工具 manifest；
3. 将修订 PROJECT 的真实受管能力、限制和唯一导出绑定进新运行器，不能由旧 v053 名称替代；
4. 通过必要的合成协议、公开初态、实际 tokenizer 和环境合同核验；不借此私自消耗模型资格回合；
5. 形成具体预算和准入文件，并取得对新增模型回合的独立授权。

所有尚未完成项在 [设计清单](software-benchmark-v054-design.json) 标为 pending。不存在后台自动拉取全部 500 镜像或自动启动三组的服务。
