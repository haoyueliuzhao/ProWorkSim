## v229 · 1. 实验怎样比较两种分工

两名 DeepSeek Flash 非思考模式工作成员在 ProWorkSim 受管 OpenHands 环境中修复同一公开问题。观察器分别读取每个成员有权看到的操作和测试回执。出现有关联工作包的异常时，保存当时的代码、分工、会话和已用预算。独立组织策略 Agent 根据该现场提名一个合法调整，也可以选择保持原图。

| 条件 | 实际执行规则 |
| --- | --- |
| KEEP，固定原分工 | 系统激活原有组织图，两人继续履行已有实现、复核与交付职责。 |
| CHANGE，执行调整 | 系统从同一保存点激活提名的新图，成员按生效的职责、权限和交接规则继续工作。 |

两臂使用相同的工作成员、工具、证据、官方评分器与正式提交合同。每臂限 500 万输入加输出 token，共同前缀及策略提名均计入这一逻辑额度。**代码通过**取最终工作树的官方评分；**正确交付**还要求成员完成正式提交，且提交版本通过官方评分。两臂结局相同的配对题在按题统计时只计一次。[实验协议与预定条件](software-benchmark-v229-controlled-graph-learning.md)

## v229 · 4. C/N 如何估计，为什么没更新

后继效用定义为“合法正确交付指示值 − 0.1 × 逻辑 token / 5,000,000”。**贡献 C** 是该方案效用相对当前策略加权平均值的差。**欠覆盖程度 N** 则衡量当前策略给某类合法响应的概率是否低于参考概率。Q0 在这个两方案现场对两臂各给 50%，与参考概率相同。

| 异常类型 | 有效配对 | 本期可用估计 |
| --- | ---: | --- |
| A1 持续修复失败 | 1 | KEEP 的 C 为 −0.00037854，CHANGE 的 C 为 +0.00037854；两者 N 均为 0 |
| A4 验证缺口 | 0 | 有 2 个单分支现场，缺少同状态另一种结果 |
| A2 依赖阻塞、A3 集成冲突或回归、A5 交付停滞 | 各 0 | 无配对估计 |

Sphinx 两臂都未正确交付，因此 C 的微小差异**完全来自调整组少用的 37,854 token**（约为 KEEP 逻辑用量的 0.76%）。它不能说明伙伴诊断提高了修复质量。该 C/N 是单状态诊断值，当前十个策略参数均保持初始零值。[策略计算代码](../../src/proworksim/software_graph_policy_v229.py) · [冻结窗口更新回执](../../runs/software-benchmark-v229/dev1-balance90-recovery-r1/window-result.json)
