## 2 工程修订服务于研究

### 交付状态及终止

`delivery_readiness`只读展示工作包完成与复核情况、尚未采用的贡献、最终版本公测、固定产物、已记录合并冲突及建议的下一步。它不会代替模型提交。

- `IN_PROGRESS`：尚未正式结束；检查表已就绪时明确指向`submit_integration`。
- `BLOCKED`：当前存在交付缺项，仍允许继续实施或修复；不停止整条队列。
- `DELIVERED`：实际正式提交通过合同检查。调度器在下一次模型机会前结束整个团队，不再预约普通模型调用。
- `ABORTED`：001明确放弃。保留唯一终点、全部费用及结果，不自动重采。

`DELIVERED`只表示合同接受，不表示已知道官方正确性。评分仍在生成结束后独立进行，因此没有利用隐藏评分来决定何时停止。

### 合并冲突与证据刷新

保留既有`reopen_work`和工作修订号，新增实际冲突记录与明确的返修提示。责任人必须自己重开、进入工作上下文、修复、测试、固定并取得新复核；旧作者、补丁和测试全部保留。带有已记录且未解决冲突的最终树不能正式提交。

证据包随最终树变化时，同样需要显式重开和重新完成。为避免复核者自己的不同代码再次阻塞证据核验，`adopt_evidence`现在可以建立不可变证据复核视图；随后显式`run_tests(evidence_id=...)`运行该版本的公测，再`review_evidence`。不覆盖复核者主工作树，也不放宽证据必须匹配最终整合版本的要求。

### 明确记录实际组织选择

进入一次冻结决策点后，001先调用`select_arrangement`，明确“尝试／保持／推迟”。当前待选状态下，普通修改动作会要求先完成这一选择；读取状态、明确拒绝和等待仍允许。

选择本身不修改owner。尝试方案时，仍需要实际owner发出offer，实际接收者接受或拒绝，并完成验证和协作配置。宿主只登记提案信息，不代替成员执行组织动作。两组采用相同合同、工具和权限，拒绝、推迟、部分执行和偏离都进入各自结果。

## 3 共同前缀与模型生成候选

每题共同前缀只执行一次。模型依据原始公开问题及已冻结的公开需求锚，自行建立2–3个工作包、安排初始负责人和验证关系，再实际修改代码并运行公开测试。达到以下首个状态即暂停：

1. 有真实代码行为，随后有实际执行的公开测试；不要求测试通过。
2. 仍有未产生代码贡献、未完成的叶工作包。
3. 各叶包已有负责人、独立验证人和协作配置。
4. 团队尚未DELIVERED或ABORTED。

共同前缀上限2M Token，最终逻辑任务总额仍为5M。前缀不合格时记录原因与费用，不根据成绩换题，也不运行半个对照块。前缀模型的真实分工并非宿主预写的固定组织模板。

随后由固定的DeepSeek Flash非思考生成服务，根据原问题、公开需求锚、实际工作图、负责人、版本／测试状态、成员已用Token、共享剩余预算和等待情况，提出两个不同组合方案。生成服务不是第三个自主成员，没有真实工作工具或联网搜索入口。

本版已接线的生成操作为：

- `SPLIT_WORK`：对未开工、无迁移歧义的包进行需求守恒拆分。
- `JOINT_ASSIGN`：完整提出新owner、独立验证人及implementation／evidence模式，经真实offer／accept生效。
- `ADD_COLLABORATION`、`CHANGE_DEPENDENCY`、`ASSIGN_VERIFICATION`。

未接线的删除协作、执行优先级、任务合并、新成员或子团队操作明确拒绝。已有代码作者及其责任不得通过调整被清除。首个机制阶段要求所选调整候选至少包含一次联合责任安排，以检验双向实际动作；可与拆分、依赖和验证调整组合，不等于一个固定TRANSFER模板。

候选先接受实际工具schema与结构约束检查，再按有效目标去重。原始模型输出、非法候选、拒绝原因和最多一次格式／合法性修正请求全部保存并收费；不根据后继成绩重新生成。过滤通过不等于运行必然成功：实际版本守卫及成员拒绝仍可能导致部分执行。

v216从合法候选中按事先固定的目标哈希排序选择一项ADAPT，与KEEP配对；不使用模型成绩选择候选。v217／v218需保留两个不同合法变换及KEEP，三个候选全部执行。KEEP也保留相同的显式选择协议，避免将“送达”混同于“实际选择”。

```mermaid
flowchart LR
    W[真实工作及测试] --> S[冻结同一决策状态]
    S --> G[固定模型生成器提出候选]
    G --> F[校验与去重]
    F --> Q[候选选择与实验分支]
    Q --> C[成员明确选择尝试或保持]
    C --> O[真实offer与accept]
    O --> X[责任变化及后续工作]
    X --> D[显式正式交付并终止]
    D --> E[独立官方评分与完整成本]
    E --> U[仅在开发阶段更新C N选择器]
```

## 4 费用与Token如何计入

设共同前缀实际用量为P、候选生成与必要修正为G、某分支续跑为L。每条逻辑任务均满足：

`T = P + G + L ≤ 5,000,000`。

P和G物理上各支付一次，在每个反事实分支的逻辑成本中都保留。候选面板生成是这次决策程序的共同准备，因此KEEP也承担该逻辑成本；不能将此直接当作“部署时完全不生成候选的KEEP”的费用。

SDK保留原始500万声明和全部前缀实际usage，不伪造额外模型请求。通过独立可用额度限制，把G从后续可用池扣除；账本中续跑最多为`5M−P−G`。这是分配剩余额度，不是重新授予一份5M或修改旧回合消耗。

预算沿用原700元账本：启动前已结算246.7108708元，余453.2891292元。本轮规划线为A 63元、B 189元、C 189元、共同准备10元，共451元。只是规划，缓冲很小。

普通完整分支按10.5元估计预约；共同前缀按2元、生成器按0.5元估计，并同时受各自最大Token的**全局最坏单价敞口**保护。较低准备预约不是费用保证。已经开始的工作不中断；预计无法负担下一完整比较块时停止新块，不能只跑一个条件。未定请求保持预约，独立留档，不自动重复已实际调用的回合。

## 5 v216机制准入门

按真实事件链逐题记录：

`生成候选 → 实际选择 → offer → accept → 责任变化 → 接收者后续代码或证据工作 → 正式交付 → 官方效用`。

进入v217至少要求：

- 两个不同任务出现真实中途联合调整，并有接收者后续工作；只有choice或accept没有后续工作不够。
- 两个不同任务的ADAPT分支完成正式合法交付。
- 至少一个已交付任务包含002实际代码贡献进入001最终树。
- 已交付任务的最终证据有效，正式提交后新增模型请求为0。

这是机制准入，不以官方正确两题作为工程门。官方正确性仍用于后续效用。逐题事实分别保留，不能用复合gate字段否认中间已经发生的动作。

未通过时，只定位已经观察到的阻塞路径，不自动整批重跑，也不启动开发或确认。

## 6 C N共享选择器的准备

v216不更新C/N。后续开发采用六个新状态，两窗各三状态，每状态KEEP及两个模型生成候选全部运行；第一窗得到q1，第二窗得到q2。确认采用六个开发未用状态，尽量按仓库隔离；实际题单和候选执行状态在相应阶段准入后冻结，不能用后继分数筛选。

整体效用保持：`U = 合法提交版本的官方正确性 − 0.1 × T/5M`。代码正确率另外报告，技术未知不填作正常失败，也不把部分算子或单个成员的名义行为当成Contribution。

C为相对当前q加权均值的中心化效用；N为`max(log(r/q),0)`。固定候选集中的r为去重后的均匀参照，不代表全体可能组织图均匀分布。

审计中最后一个softmax表达式本身不保证支持下界，本版明确区分：先算`pθ ∝ r exp(θ·f)`，再使用实际分布`qθ = 0.95pθ + 0.05r`，保证`q≥0.05r`及`N≤log(20)`。C/N经过有界正值变换、策略／参照双锚及支持混合后，得到目标分布，再拟合共享参数。

冻结七项特征：既有成员消耗与待办负载平衡、跨owner依赖、待验证义务、预计集成义务、变换工具步骤、预算压力与步骤的交互、依赖与验证的交互。成员没有独立等额预算，状态中的剩余额度始终是同一个团队池。特征不使用任务ID、仓库名或任意图名，不训练底座模型或LoRA。

当前离线实现的目标拟合为平均KL加`0.05‖θ−θ旧‖²`，梯度漂移系数0.1；三个状态窗口等价于KL求和加0.15倍漂移项。其余冻结值为ε=.05、δ=.05、两个温度1、α=β=1、ρ=.8、η=.5、学习率.05、400步，初始θ全零。不会根据中期分数搜索这些设置。

确认前冻结q0、qC、qN、qCN，用全部候选的同状态真实结果计算`Σq(z)U(z)`，报告逐题／仓库差异、目标拟合误差和留一敏感度。C-only与N-only为同一开发数据上的离线诊断，不追加模型分支。

**N-only有一个预期的零诊断：当初始q0=r时，N全部为0，独立N-only更新保持q0。** 这不证明N在C已改变分布后没有作用。完整候选面板也不能证明N提高了试验额度利用率或生成器节省了成本。
