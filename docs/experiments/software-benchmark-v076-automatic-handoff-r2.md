# v076：后台自然交接补充

本补充只修改尚未执行的新 v076 调度器。旧 Qwen／API 代码、模型服务、题单、seed、候选、token 与现金预算不变。原准备稿的授权、源码索引和服务规格需由操作者归档后重新封存；不把未运行的第一稿描述为已使用的部署版本。

较长的在途任务可能需要继续运行数十分钟至数小时。因此，计划中的 `proworksim-v076-primary.service` 先承担交接等待，再在同一进程中进入正式 Qwen 调度；没有额外新建一个监控服务。该服务仍为4 CPU／16 GiB、swap=0。旧主协调器仍存活时，新的16 GiB／4 CPU另以临时预约计入原832 GiB／152 CPU分配门，避免漏算重复驻留的协调器。

后台流程每15秒观察一次，最多等8小时。只有两侧生成、评分和资源达到旧交接程序规定的静止条件，进度时间均晚于暂停派发时间，并连续两次相隔至少3秒确认，才调用已审阅的精确pidfd交接。结束旧两个协调器后，确认其确实退出，恢复原字节模型发现标记，释放临时预约，将新主协调器计回原隐式基线，再准备完整接续库存。

随后进入原 Qwen 运行代码，同时启动一个普通线程等待新主队列写出cursor。此后只尝试一次API启动，失败独立留档，不中断Qwen。该线程没有GPU生命周期操作。调度目标44与实际已运行环境数继续分开报告。

8小时超时或发出任何协调器信号前的异常，只在原协调器身份仍一致时恢复旧发现标记及旧API并发控制，让旧队列继续。任何信号已经留档时都不假称可以回滚，而是保存明确的交接失败记录供处理。模型服务不卸载；API专用内存父组保留，只有既有授权的空组清理程序可以关闭。

必要控制覆盖：暂停之前的旧快照不能触发交接、静止条件反复出现时重新计时、8小时上界、信号后拒绝回滚、临时预约计入原预算、释放后禁止重用身份、只启动主协调器的等待模式、API一次启动及错误隔离、等待异常的清理与原队列恢复。7项新增CPU控制通过；异常记录结构修订后仅复查对应1项，不重复整套旧测试。尚未由此文档宣称后台服务或44并发已实际上线。
