# v232 首对实验｜组织图生效以后，新负责人做了什么？

2026 年 11 月 24 日。**在 Sphinx-9591 的同一异常现场，独立组织策略 Agent（OSA）选择新增诊断职责，002 实际执行了搜索、读文件和测试，并生成了引用本人证据的交接请求。该请求因多填一个参数而被工具接口拒绝，诊断意见未送达 001。** 维持分工组和 OSA 组的最终代码均未通过官方评分，均未形成合法交付。本次覆盖一个此前暴露过的现场，可用于定位行为链条，尚不足以估计哪种组织策略总体更好。[逐请求、行动、交接与评分证据](../../artifacts/software-benchmark-v232/first-pair-r1/results.json)

## 审计修订与实验条件

新组织实验通过统一入口使用 T1。T0 留作历史回归，T2 保留代码与旧结果，本轮两组均使用同一版 T1。此前三个现场中，排除 SymPy 后，T0 到 T1 的新增总 token 只从 3,502,752 降至 3,445,760，降幅 1.63%。这支持把 T1 作为工程基线，并在组织实验中持续计量。此前观察到 T2 请求增加，与信息碎片化、状态不确定性和生成随机性都相容，现有证据无法分离这些解释。[上轮审计材料](v230-v231-1-audit-report-20261124.md) · [当前组织 Harness 入口](../../src/proworksim/organization_harness.py)

**KEEP** 从保存点继续，固定原组织图。**OSA** 从相同保存点继续，由独立的 DeepSeek Flash 非思考策略模型读取授权异常证据、可选分工及剩余资源，自主选择维持或调整。两个执行成员的模型设置、工具、状态校验、公开测试和官方评分规则相同。两臂各有 **972,030 token**，来自原 5M 团队限额扣除真实共享前缀的 4,027,970 token。此次重新调用 OSA，花费计入 OSA 臂；旧提名没有作为新模型的选择。OSA 看到当前允许的证据与公开组织决策历史，本现场决策前的该历史为空。执行成员按自己的身份读取工作区和证据。[冻结条件与源码清单](../../artifacts/software-benchmark-v232/first-pair-r1/protocol.json)

系统先核查方案的异常范围、成员、负责人、依赖关系、工具权限及剩余资源。新职责、验证和最终交付各预留一次模型请求的容量，三次共按 393,216 token 的保守上界准入，实际用量另行结算。没有足够资源或没有可行动成员时，拒绝激活新方案。已激活的诊断职责会唤醒新负责人，提高其下一次行动的优先级，并显示工作包、交接对象及本人可引用的近期事件。验证、交付的预留只保证机会，业务动作仍由成员自行选择。这套规则在两臂都生效；只有存在待办诊断的成员会收到对应提示。[控制与校验实现](../../src/proworksim/software_organization_v232.py)

**交接停在了哪一步？** 002 最后生成了 `send_message` 调用，填写的收件人为 `member_001`，任务为 `work_root`，正文以 `DIAG 74` 开头。74 确实在当次请求展示的本人可引用事件列表中。正文 3,100 字符，低于 4,000 字符上限，必填参数齐备；模型又添加了工具未声明的 `recipe` 参数。原生 SDK 在公开参数校验阶段返回格式错误，未进入项目工具执行。随后的预算边界使该成员未能再发起一次修正请求。模型意图、语法拒绝、项目执行、合法送达在证据中分别记录。当前机制已观察到真实诊断行动，尚未观察到有效交接、异常解除或正确交付。[按机会关联的原始请求与接口拒绝证据](../../artifacts/software-benchmark-v232/first-pair-r1/results.json)

## 工程固化与观测边界

每次请求从本成员可见的观察建立起始快照。后续增量同时绑定前一状态版本和完整快照版本，使用显式删除列表，对重建结果校验摘要。每段最多包含八份观察，达到间隔或遇到新历史摘要时重建完整基准；基础引用缺失、类型差异或校验不符时回退到该成员的完整授权输入。完整日志、测试报告和模型实际收到的最终请求继续分别归档。SDK 对早期静态字段另有同请求引用，因此本轮还逐次核对了两臂实际请求中的 **379 次静态字段锚点**，确认可按原成员、原内容摘要取回对应字段。[状态构建](../../src/proworksim/software_context_v232.py) · [工程准入结果](../../artifacts/software-benchmark-v232/first-pair-r1/engineering-gate.json)

- **准入。** 上轮 89 次真实 T1 请求全部通过成员观察还原检查。真实 OpenHands 双成员 SDK 使用本地确定性响应，验证了资源不足时拒绝改组、资源充足时唤醒 002 并产生实际文件读取。实际首对共产生 28 次已结算请求，25 项进入项目工具的操作均能关联生效的组织图版本与真实模型机会。
- **可见性。** 每次调用均保存实际输入、消息位置、事件号、原生操作关联和成功回读结果。明示事件号、仅由操作号关联的事件、没有直接标识的事件分列。没有标识不能证明模型完全没有看到同义信息；成功回读也不能证明它理解或采用。外部事件索引没有作为提示发给模型。
- **来源。** 两臂供应商合计输入 **1,877,105 token**，本地完整输入 **1,874,869**。按实际呈现字段估算，组织相关约 514,998、项目状态 406,024、状态引用及相关元数据 229,695、工具定义 184,689、行动历史 143,589、文件反馈 117,473、测试反馈 115,940、异常材料 15,690、系统说明 9,737。伙伴消息、摘要、其他工具反馈、其他内容及本地模板切分差额分别保留。供应商只确认总用量和缓存统计，分项取决于字段分类与分词边界，不能冒充精确成本归因。[完整分项、逐请求可见性与回读记录](../../artifacts/software-benchmark-v232/first-pair-r1/results.json)
