# v245.4　让 OSA 依据现场证据选择分工

本次修改针对双成员完整任务中的一次组织决策。OSA 负责决定是否调整协作，两名 Worker 负责执行。新版要求 OSA 先回答“沿用当前分工，哪项工作会卡住”，再比较“换谁做、会多出什么产物、谁会用它”，最后指出哪条新证据值得重新判断。

例如，交付清单只显示作者尚未完成代码时，OSA 可以保留原分工。若有多次修改后同一测试仍失败的记录，并且现场提供了诊断路线，才有依据比较“作者继续排查”和“伙伴独立定位后把复现证据交给作者”。只有一次交付清单时，连续失败与长期停滞都缺少证据。

## 模型现在能看清什么

- **哪些分工能改。** 两名成员固定（D0）。当前可执行的方案可涉及诊断角色（D1）、未启动工作包的负责人（D2）或独立复核人（D5）。跨包交接（D4）和集成冲突处理（D6）要有对应现场记录。协作关系（D3）和行动机会（D7）可以随方案一起改变。每次只展示有可执行路线的补丁，另外标明谁先行动、谁承担新职责。每条可选工作指令列出可搭配的路线和证据。
- **复核到底到了哪一步。** 按每个工作包当时的公开交付清单显示复核要求。“当前无需复核”与“当前版本已获复核通过”分开；缺少足够证据时显示未知。选择新增复核人仍需解释这次复核能检查什么具体风险。
- **如何核对选择。** 仍通过同一个控制器提交一个动作。重新判断的条件要能由后续事件核对，例如同一失败再次出现，或当前补丁取得独立测试结果。补丁目录中的编号仅标识本次方案，不能当作维度或可执行路线。

## 离线验证结果

用 v245.3 的 12 份原始决策现场重建请求，并在实际 OSA 执行入口截取待发送内容。只读取决策当时的公开材料。12/12 次的可选路线均与原执行器一致；12 次均可维持原分工，11 次可指派复核，10 次可移交未启动的工作包，0 次有可执行的独立诊断。12 份清单均明确写明当时无需复核，新版全部正确显示。新版输入为 2,109–2,601 token，均满足该现场的请求预算。

另用历史异常现场检查正例，2 个现场保留了独立诊断路线，3 个保留了跨包交接指令，2 个保留了复核指令，2 个保留了集成指令。同一现场可能覆盖多个机制。另以 4 个构造用例核对复核可选、必需且已通过、必需且待办、证据未知四种情况。

以上验证覆盖请求内容和可执行范围。历史 12 题主要暴露了单次交付清单的信息局限；文字修订无法补出缺失的测试轨迹。本次 API 调用与费用均为零。改组选择及正确交付率的变化仍待在线验证。

完整任务入口为 `tools/run_full_osa_v245_4.py`，使用新批次提供的账本与命名空间。复核命令为 `.venv/bin/python tools/run_offline_scorer_v096.py tools/check_osa_prompt_v245_4.py`。
