## 2. 已定位的实现缺陷

`member_view`原来只将旧`model_budget_stop`事件识别为没有发生生成的预算停止。新的共享预算通过`model_boundary_error`返回`team_budget_exhausted`，没有发出那个旧事件。导出器因此把四个实际未生成的调用当成“应该存在、但缺少response”的动作，令record维度为未知；采集器按关键记录异常规则停止整个模型窗口。

这是记录解释缺陷。原团队预算拒绝本身正确，原业务验收不需要重跑，也没有证据支持把中断归为权限故障或模型服务故障。原CPU控制覆盖了共享预算拒绝和SDK八槽采集，但没有覆盖“真实共享token拒绝→完整成员视图→整窗记录门”的组合；本次补这条必要路径，不重复三题资格、近16K压力或整个旧测试集。
