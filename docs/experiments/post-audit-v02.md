## 4. 规则机制与结构矩阵

旧十二配置矩阵维持原边界：12/12 个世界最终通过，16 个工作义务、20 次提交、4 次真实返工、2 个来源谱系。见 [旧矩阵复验](v012-mechanism.json)。

新增配置：`seed ∈ {211,223}` × 四种拓扑 × 标准/移动布局，共 **16 个世界、2 个来源谱系，16/16 最终通过**。见 [结构矩阵](v02-structures.json)。

| 拓扑 | 每世界工作数 | 新增的实际差异 |
| --- | ---: | --- |
| chain | 2 | 模型与备忘录的两轮状态继承 |
| fork | 6 | 每轮 model 接受后，memo 和 note 分别成为可执行义务 |
| selective | 4 | 第一阶段三项工作；第二阶段 brief 改变，仅产生 note 更新任务 |
| coordination | 2 | 口径需实时澄清；矩阵故意漏改一次 memo 来触发实际返工 |

移动布局改变输入和输出表名、列及行位置。相同算术语义仍可被公开工具见证完成，不需要改内核或重写独立参考计算。

选择性测试另外验证：brief 改变后 note 失效，model/memo 仍为 current，三者原始字节都不会被后台自动改写。完整完成 selective 世界后，model/memo 各只有两个版本，note 有三个版本。测试还仅通过 JSON 规格增加第三次 brief 修改与 note 工作，未增加内核特例。

这些结果是任务可行性证据。规则见证有预设求解策略，因此不能解释为目标模型成功率；当前选择性影响也只覆盖产物级依赖，不代表通用字段级语义分析。

## 6. 匹配的历史上下文对照

### 协议

每个 seed（317、331）先由真实模型完成第一阶段，并独立验证通过。在第二阶段任务刚出现、尚未推进时保存快照，从同一快照创建两个新分支：

- **history**：保留第一阶段的实际模型上下文。
- **reset_context**：清空分析师当前模型上下文，将旧上下文归档；原始 calls 不删除，也不事后改写。

两个条件的文件、版本、时钟、角色、邮件、已读状态、工作义务、事件与布局完全一致，使用同一组工具与 60 次新调用上限。分别计算语义状态 SHA-256，两对均相等。唯一指定变化是模型上下文是否继承。

该实验测试上下文继承，不测试“持续项目训练”整体效果。条件按 history 后 reset 顺序运行，模型未提供可控完全相同的采样随机性；没有消除调用顺序或采样噪声。样本仅两个来源谱系，没有统计功效声明。

### 结果

| seed | 条件 | 第二阶段新调用 | 新调用总 token | 业务完成 | 独立验证 | 分支正向 SFT |
| --- | --- | ---: | ---: | --- | --- | ---: |
| 317 | history | 7 | 202,573 | 是 | 失败 | 0 |
| 317 | reset_context | 13 | 242,998 | 是 | 通过 | 11 |
| 331 | history | 12 | 415,181 | 是 | 通过 | 11 |
| 331 | reset_context | 9 | 130,105 | 是 | 失败 | 0 |

每个条件各通过 1/2。本轮没有看到跨这两例一致的上下文优势，不能据此认定保留或清空历史普遍更好。

两次失败都有具体产物证据：seed317/history 使用增长率 0.07，第二阶段应为 0.09；seed331/reset 使用 0.05，应为 0.07。两者都更新了披露材料，却没有取得第二轮 scope 回复，沿用了第一轮已确认的增长假设。因此工作簿与 memo 彼此一致，业务审阅接受，但独立输入及数值检查失败。

这两个案例支持“旧假设沿用是值得增加的诊断条件”，但不能证明错误由历史上下文保留单独导致，因为 reset 条件也出现同类错误。失败分支没有输出正向 SFT；历史继承调用也未被重复计作新分支目标。

第一阶段成本单独记录：seed317 为 15 次调用、174,331 token；seed331 为 16 次调用、197,272 token。四个第二阶段条件共 41 次调用、990,857 token。整个匹配实验共 72 次调用、1,362,460 token，不能只报告成功分支成本。

明细：[匹配实验](v02-paired-context.json)、[实际增长率与回复记录](v02-paired-failures.json)。

## 7. 真实参数训练闭环

### 数据、模型与权重

目标为本地 **Qwen2.5-7B-Instruct**，使用已存在的权重目录，没有通过 DeepSeek API 假装更新模型参数。Qwen 模型卡标明 Apache-2.0，并提供 Transformers 加载方式。[官方模型卡](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct)

数据取自经 finance-v0.1.2 复核的 DeepSeek Teacher 候选：三个原 episode 各取前两条可用调用，共 6 条、每步 452 个受监督 token。三者仍共享 seed101 来源谱系。其余条目按冒烟上限排除，未被悄悄当成已训练数据。

采用真实 tokenizer/chat template，转换工具参数的序列化形式；不迁移 Teacher 的 reasoning_content 到 Qwen 隐藏思考格式。历史、环境消息和前缀 token 的 label 为 -100，只训练本次目标模型输出。超长记录拒绝，不截断出新的伪上下文。最大长度 4096；本次六条长度为 2070、2858、2133、2947、2220、3373，没有触发长度拒绝。

冻结权重规则：每个 episode 等权，episode 内每个调用等权，每个调用按其监督 token 平均交叉熵。这里只防止长度直接决定样本权重，不声称此规则最优。

### 重载后进入环境

重载模型通过同一 `LocalModelBackend` 接口进入 seed702 的 short 世界，在预设 12 次生成后达到预算。记录了 8 次分析师工具动作，其中 7 次成功；另有一次环境审阅动作。模型有两次真实提交，但未在预算内完成并通过该任务。

因此最终结论是：**训练后端与工具环境回接成立；本轮没有证明任务能力提升，甚至没有取得该后续单任务的成功完成。**没有延长预算或用规则基线替它补齐结果。严格 on-policy RL 仍未接入。

## 8. 失败、重试与共享 GPU

所有失败保留，见 [训练尝试记录](v02-training-attempts.json)。

1. 首次选择 GPU 3 时，早先查询有约 79 GiB 空闲，但实际加载时其他作业已占用约 73.96 GiB。本进程在完成加载前 OOM，没有进行优化更新。不能把早先空闲查询当作资源预留。
2. 改用 GPU 0 后，完成了两次更新并保存检查点，但旧脚本把参数哈希与严格 loss 等值合并成一个报错，未保存各自数值，因此无法从该次日志准确重建是哪一个条件失败。后续单独重载逐一核对 112 个张量，全部与保存文件相同。
3. 修订后在 GPU 0 重试：参数哈希精确检查与 BF16 loss 复算分开记录，并将训练后及重载模型的 use_cache 都设置为 false。复算容差预设为 rel_tol=0.005、abs_tol=0.001；实际差值为零，没有靠容差放行非零差异。由于同时补了记录和配置，不能把前次故障唯一归因为某一个因素。

用户询问该模型参与另一项目的影响后，本项目曾暂缓新的 GPU 运行；随后用户明确允许继续共享 GPU，要求记录竞争。本轮照此执行，没有停止或修改其他项目的进程。

最终运行选择物理 GPU 0：运行前空闲 33,331 MiB；进程仍驻留模型时的结束采样为空闲 14,700 MiB。该结束采样包含本进程占用，不能当作退出后的残留，也不能用差值精确推断另一项目的用量变化。完整各卡快照在训练 JSON 中。

原始模型目录只作为 from_pretrained 的输入。新适配器写入 `runs/training-smoke-v02/checkpoint/`；源 safetensors 的大小和 mtime 与本次运行前一致，本项目没有向原始模型路径调用保存接口。共享的只是读取源与硬件资源，不会自动使另一项目加载本项目适配器。

共享期间存在资源竞争，可能影响另一项目的速度、余量和复算时序；本轮未测量另一项目吞吐或质量，不能声称它完全未受影响。最终本项目训练进程已结束。

## 9. 本轮可确认与不可确认的结论

可确认：三类已复现契约问题得到修复；原 37 条候选经原字节复核保留；有限分叉、选择性更新、信息协调与布局变化能实际运行；上下文对照在相同世界快照下可执行；本地参数训练与模型回接链路成立。

不可确认：金融专业能力提高、持续项目训练优于独立任务、反馈课程优于静态课程、未见结构组合泛化、环境角色共同学习有效。四种新结构仍属于同一个合成经营模型族。

下一轮应针对“更新数据却沿用旧假设”建立冻结的角色信息/版本诊断条件，并在独立来源与结构组合上增大匹配样本。若开展学习收益研究，需要额外的训练种子、基线参数对照和项目级统计设计，不能从本轮 2 次更新或 2 对上下文试验直接推出收益。
