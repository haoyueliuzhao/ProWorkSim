# v203.2.1：被动观测部署准入与12题REVIEW2 Pilot

日期：2026-11-12。依据用户提供的《v203.2实验审计与后续实验方案》；用户已明确本轮新增API预算为**150元**。本文件规定模型执行前的实验条件与分阶段准入，运行事实另见[部署报告](software-benchmark-v203-2-1-deployment-report.md)。

## 1. 研究问题与授权范围

验证原REVIEW2在真实执行时能否被可靠观测：请求、用量、工具动作、回执、成员、版本与阶段能否关联；故障后哪些证据可以恢复，哪些必须保留为缺失。不是组织调整效果比较。

采用原预留12题、10仓库。前两题预先固定为`matplotlib__matplotlib-26208`、`django__django-11095`，承担真实部署准入，同时计入12题分母；不能因测试或评分结果将其剔除。身份、题目、seed和第一波标记见[冻结题单](../../artifacts/software-benchmark-v203-2-1/pilot-design-r1/panel.json)。历史研究已覆盖Verified全部500题，未见仓库数为0；本批是前瞻性采集，不是独立泛化确认。

| 条件 | 本轮规定 |
|---|---|
| 模型 | DeepSeek Flash，非思考；发布文档版本DeepSeek-V4.1-Flash-1017 |
| 组织 | 原REVIEW2，001开发及最终交付、002复核；2个实际Agent |

## 2. 分阶段运行及现金规则

第一阶段为零API的源码、故障注入、真实SDK脚本接线和环境准备；这些结果不能冒充真实供应商调用验证。

第二阶段仅启动事前选定的前两题。要求实际模型调用、原请求／响应及usage关联、正常执行和资源清理、完整观测对账均通过，才能放行其余10题。准入不读取官方成绩，也不要求模型修复成功。若存在未决物理请求费用、丢失关键请求或版本证据，先保留两题原结果及缺口，暂停后续新题准入，不重采模型来补日志。

第三阶段运行原清单剩余10题。生成与评分异步；单题普通异常独立留档，评分失败不触发新模型尝试。真实共享身份或资源清理故障才停止新派发，已进入任务有序结束。

本轮不复用其他实验的旧账本；本轮r1及其后部署修订始终共用同一份150元账本。按已核对的高峰费率上界估算，每个Token按更高的输出价8元／百万Token预留，5M团队的最坏费用为40元。**启动时预约整队剩余最坏费用，结束后释放未使用部分**，同时满足150元现金额度与“已启动团队不因金额门被中断”的用户要求。账面初始最多容纳3队；这不是DeepSeek并发上限，也不是为每个成员各拨5M。现金实际释放后继续原队列。

短暂HTTP错误的有限重试保持相同逻辑请求和新的物理尝试编号，计入同一团队Token／现金账本。未取得usage的尝试保留预约上界，不能记为0消耗。没有获得明确执行结果的请求不会通过自动重新采样假装续接。初始两队的真实usage不完整时，后续波保持等待处理。

资源对象全部属于本批：最多12个actor、12个controller、24项gold／empty控制、24个代码／交付评分容器和12个专用卷。无宿主绑定、GPU、公开端口或新增系统slice；仅一个普通用户协调服务。必要环境控制按原题执行，不能根据gold修复所涉及文件给模型定位信息，也不因环境失败换题。

## 3. 观测和完整性口径

旁路写入使用SQLite持久日志及事务序号。世界动作仍由原Harness执行；观察失败不改变返回、不重放世界动作。图投影放在离线端，避免每次动作复制完整历史图。

必须把以下事实分开：工具是否暴露、基础前置条件、组织授权、操作必要性、模型决策及执行结果。前四层没有证据时保持未知，不能用工具调用次数填充“必要性”。

任务和每个分析维度分别记录：

| 状态 | 分析规则 |
|---|---|
| COMPLETE | 独立主记录与旁路原件覆盖闭合，身份和来源核验通过；可按规定讨论未出现事件 |
| PARTIAL | 保留有效局部证据及具体缺口；缺交付不抹去完整的早期责任记录 |
| INVALID | 对应证据链破坏或相互矛盾；相关维度不进入有效统计，其他独立维度单列 |

日志自身连续不等于捕获完整。对账分母来自独立controller账本、执行轨迹、工具／Harness回执和host物理请求账本；不能用观察器自己的计数证明自身没有丢数据。已执行动作在回执落盘前崩溃的窗口必须如实标记缺失。

每次请求保留实际HTTP请求体与响应体原字节，包括响应前的keepalive空白；保留逻辑与物理请求编号、成员、episode、SDK decision关联及供应商usage。HTTP调用线程与环境线程不同，各自在写入线程打开并关闭连接，避免SQLite跨线程失败被旁路异常处理掩盖。

## 4. 全局图、成员视图与阶段状态

全局图仅用于评估。成员视图只能取该成员在该时刻已经实际接受的请求内容，不自动拼回被摘要或裁剪掉的旧消息，不补入他人的私有代码，也不因产物发布就添加其全文。

T0—T6沿用上一轮操作化定义，按实际出现保存，不强求每题都有七阶段。首次采集时间持久化，同键重送复用首次时间，不能用恢复时间替换发生时间。阶段前后的新信息另记为责任、版本、产物或测试等客观变化，不直接推断需要调整组织。

依赖、失配和动作三个判断分别绑定episode、观察时间、任务和revision；它们不是永久任务标签。后续审阅隐藏未来事件、最终代码评分和算法预测。阶段点是同题的重复观察，不作为新的独立任务。

## 5. 停止、恢复和分析

原有5M、调用次数、上下文和时间限制保持。现金限制作用于新队准入；观察缺口不会变成模型代码失败。系统故障后先读取已经持久化的证据，不重复已经发生的世界动作；无法可信续接的模型回合保留独立身份和技术状态，新增尝试另行标识。

本轮分别报告任务正确率、合法交付率、每题与每成员实际Token、摘要成本、未定用量上界、环境／执行未知，以及观测CPU、延迟、内存、磁盘量。CPU脚本负载的观测开销不能当生产长期运行性能保证。

自然依赖与组织变化允许为0。没有阳性时不制造Recall／F1，也不修改标签凑数量。Pilot完成后再依据有效窗口数、阳性发生率、审阅一致性和仓库相关性设计v203.3样本；不自动扩展为固定24＋12或进入v204。
