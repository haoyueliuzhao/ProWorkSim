# v0.31 修订与CPU准入

本轮针对已记录的原生接口不一致及概率重算偏差修订，保留旧v0.30/r1报告和失败，不修改公共世界、六个开发案例、共享SDK或9B运行路径。新模块、脚本和测试均单独版本化；原9B完整12槽作为同一运行组合的历史参照，实际接续仅两个从未进入正式筛选的新候选。

## 有限CPU控制

- 数值图：8项TinyTorch控制验证原生缓存值、完整梯度、checkpoint、detach反例和原目标保留，见[设计与边界](../design/dense-replay-v031.md)。
- 原生协议：29项控制覆盖两组真实tokenizer、作者OpenHands前缀与多行参数、复杂schema、字符串空白保真、未知工具/多调用/后缀拒绝；来源与修订见[原生协议说明](../research/software-native-protocol-v031.md)。
- profile首次绑定：3项控制确认实际加载信息保留、新契约在首次owner身份之前绑定，原数值和长度门不变。
- GPU probe程序：4项TinyTorch控制验证4路径比较、实际backward、禁止optimizer.step，以及成功和异常后的完整恢复；不是GPU模型结果。
- 队列与总驱动：覆盖完整旧9B继承、失败数值门按臂停止、固定12槽/seed、原成本不重计、原件空间去重、预约身份核验及GPU4/6交接。各次必要运行存在重叠，不将15／10／2等运行次数相加当作独立测试数。

组件原件分布于`runs/v031-functional-dense-controls/`、`runs/v031-dense-probe-cpu/`和`runs/v031-controls/`。最终干净快照由[CPU绑定脚本](../../scripts/qualify_software_model_selection_v031.py)逐项核对测试返回码及当前文件SHA；这里不冒称原71项测试重新运行。

## 实际SDK与WorldCore控制

仅对两个已变化的原生接口运行新矩阵：**12/12模型/案例组合通过，48次脚本化原生往返、16次实际不存在路径错误回流通过**。真实模型调用、权重加载、GPU初始化、token_trace和参数更新均为0。

控制经实际共享SDK和新v0.30工作世界，执行真实最长180行源码读取、实际错误和staff_done，并检查真实回执完整进入下次原生编码；没有用新模型生成“正确答案”。新SWE fixture按声明XML编码，Devstral使用官方v13 assistant encoder。原9B接口未变，本次不重复其模板矩阵。

最大实际输入11,605 token，保留2,048输出后最小余量2,731，容量投影未移除工具轮。完整原件为`runs/v031-controls/native-templates/qualification.json`，命令及stdout单独保存。运行前后全部所需源码、开发资产、上游文件和tokenizer指纹一致；源码树SHA为`59470172876b1593246e8eb8f7b052f95452ea54f9c7ab58f8b49cdcdab863d7`。

## 接续条件

下一步先用旧失败trace在实际14B/24B上比较原整序列、原生缓存及新完整可微重算。该阶段零新采样、零优化器步数。只有数值证明通过的候选才进入新的4条原生资格生成、至多1次诊断更新与1个新身份片段，然后执行原6案例×2seed的12槽；失败臂保留终态，另一臂独立继续。

根据最新用户指令，先并行预约GPU4、6；两卡已分别保留76GiB，后续优先顺序为4、6、5、0、1、2、3、7。空卡、60秒观察、单任务、RSS、128GiB原件和20GiB卷预留门保持；累计GPU/worker/墙钟和队列截止继续不设上限。预约占用单列，不冒充模型计算时间。

CPU通过不代表真实数值偏差已消除、近16K完整训练已通过或软件能力改善。本轮仍为开发运行组合选型，不启动未冻结的B/G-raw/I-P。
