## 1. 按审计修订了什么

1. **M1降格为成本基线。** v175的34.14%输入节省是真实结果，但不能据此认定不会损害完整任务质量。后续保留M1-5和M1-10两个窗口。
2. **M2改名为“使用LLMLingua-2编码器评分的观察块筛选”。** 14.51%对应整块选择，不是token级LLMLingua-2的复现结果。旧数值不变。
3. **摘要改为有生命周期的对象。** 后续M3-R保存版本、覆盖范围、原文引用、生成时间、成本和失效检查，跨多轮复用，不在每个请求前临时重生成。
4. **补上模型可用性检验。** v176的CPU还原证明原件可取，本轮实际检查模型是否能找到、读取并正确解释证据。
5. **修正论文参数。** [The Complexity Trap附录E](https://arxiv.org/html/2508.21433v2#A5)确有OpenHands实验，不能把其SWE-agent主结果直接推广到本项目。原文摘要触发定义为`N+M`；`N=21、M=10`对应31轮，而非21轮触发。[ACON](https://proceedings.mlr.press/v306/kang26b.html)的正式ICML2026记录也已核验，本项目不声称一次提示修订就是完整ACON复现。

## 3. 发现的问题与修复依据

### 3.1 验证器本身不能制造失败

初始题目把`passed`同时用于整轮布尔结果和“通过用例数”；一个实际输出正确区分了整轮失败与1项通过，却被布尔精确比较判错。另外，要求整个7354字符消息全部读完，错误拒绝了已经读到必要版本和结果的按需恢复。多个安全决策标签也存在重叠。

v178因此明确`overall_passed`与`passed_count`，使用不含答案的类型说明，将决策改为可核验的布尔结论，并检查必要原文区间。未知控制的字段类型在已知／未知数据中相同，避免通过schema泄露答案。原始评分记录保留。

### 3.2 真正的版本和引用问题

澄清后v178的42项事实已有41项正确，但一例把`paged-public-test-feedback-v0.42`填成了工作区版本；正确工作区版本是`v2`。模型理由中同时提到两个版本，说明原呈现中的“version”层级容易混淆。

此外，5例把解释文字追加到`ctx`引用字符串内，另1例引用未读的动作编号。索引里只有工具名而缺乏明确调用配对，也增加了按相邻位置猜测的风险。

v179据此增加了通用、可核查的呈现：

- 分列报告协议版本、工作区版本、对象ID及文件树哈希。只有完整消息实际进入返回页时才附上来源字段，不额外透露未读内容。
- 索引列出工具调用ID及结果对应的原动作编号。
- 返回可直接复制的`citable_messages`引用对象，正文解释与引用身份分开。
- 对格式错误或没有读取凭据的引用给预算内反馈。反馈不评判事实答案、不返回正确版本、不泄露评分期望。

修复没有改变原始档案、成员权限、世界工具或仓库代码。

## 4. 最终12例验证了什么

| 能力 | 最终观察 |
|---|---|
| 历史动作 | 精确恢复旧replace_file的path、old、new，未执行修改 |
| 拒绝与失败 | 识别0次匹配意味着未修改；恢复失败测试节点、异常、版本和计数 |
| 公开成功 | 恢复256项通过的报告及哈希，同时拒绝把公开通过当隐藏验收 |
| 精确版本与路径 | 恢复最后修改的代码版本、完整哈希和测试文件路径 |
| 旧状态与当前快照 | 区分旧v5测试与最后v6快照，不把旧测试用于证明新版本 |
| 环境／测试状态 | 区分收集错误、零测试、明确失败和未知执行数量 |
| 深页定位 | 按索引跳至约第20页，读取最后一次修改结果而非早期版本 |
| 未知处理 | 缺失用例数保留null；没有隐藏评分观察则报告未知 |

v179实际调用`context_read` **22次**，每例1–2次；普通归档案例通过一次索引读取再定位证据，也允许直接访问已可见的原观察引用。实际共38次API请求，其中包括3次JSON回答格式修正和1次引用格式修正，费用与token均计入，未当作免费重试。

每例平均实际输入＋输出为 **19,122.42 token**。这是有明确恢复问题的定向验证成本，不是完整任务中自然发生的回读成本。本轮记录了案例总墙钟时间，没有独立记录每次读取工具的耗时；P1协议要求增加这一计时，不拿API周转延迟代替。

这能支持“模型可使用修复后的恢复入口完成这些定向事实任务”。不能据此断言它会在完整编码任务中自主察觉每次缺失，也不能证明遮蔽不影响正确率或摘要必然摊薄成本。
