## 3. 模型适配与前置pilot

ModelPolicy只接收本角色公开任务、工具定义、观察、实际结果及自身历史。它不导入领域算法，不获得控制器未来事件、独立答案或其他角色记忆。每次机会至多执行一个世界动作；原模型请求/响应、HTTP attempt、usage与动作执行分别关联保存。超时/限流、格式失败、真实业务拒绝和世界异常分开，原有效错误动作不重采样。

先以模拟transport验收角色上下文、返回保持、固定重试、usage缺失、预算、单动作协议和checkpoint；这只算接口测试。原decide超时落policy_error的路径已在模型传输边界修正。服务不返回usage时记录缺失并占用保守预留，不猜实际token。

| 真实前置pilot | 结果 | 范围解释 |
| --- | --- | --- |
| DeepSeek原生工具协议 | 首次返回两个read_object，整次model_format_error，0世界动作 | 全部调用原文保留，没有挑第一条执行 |
| DeepSeek单动作JSON | 7调用；真实读写、修正一次submit别名错误后提交，结束worker_waiting | 没有adoption snapshot，内容未评；规则审阅者无法据此完成审阅 |
| Qwen单动作JSON | 首次kind使用工具名而非act，model_format_error | 没有伪造执行或用规则策略补交付 |

这些是开发期真实HTTP调用，发生于完整公开说明补齐之前，且其他模块并行修改；原源码摘要/请求保存，但不冒称全树冻结实验。不同协议与公开合同条件不合并为同条件成功率。

DeepSeek原生Chat工具接口未见保证可关闭并行调用的正式合同，故显式引入single_decision_json：原工具定义放在公开user消息，严格解析一个act/action/arguments对象或wait/done对象；多动作、重复键或近似键名均不自动修复。DeepSeek使用[官方JSON模式](https://api-docs.deepseek.com/guides/json_mode/)，本地Qwen仅按相同提示生成，没有受约束解码声明。

模型试跑也暴露了规则策略掌握、公开任务却未完整呈现的形式知识。本版把两种报告句式、核对字段形状与未知值约定放进requirements.public_format，补充submit别名与adopt说明；不包含数据真值、正确问题或下一步业务动作。第一冻结之后又根据实际遗漏补写文件dependencies的现有合同，前后分开记录。

旧SQL规则矩阵原来只查本地result，因此58/58不证明覆盖了这条共享输入路径。旧矩阵与新反例不相互替代。工具说明同时明确：adopt或JSON sources不能自动替write_object登记文件dependencies。

## 6. B：真实可执行的四项目机制

固定[官方jaffle_shop_duckdb仓库](https://github.com/dbt-labs/jaffle_shop_duckdb/tree/36bde6cba69d962b83be1d52fc65a0dce1cb4ebb)的100客户、99订单、113支付虚构种子，保留Apache-2.0许可、源SQL/配置和文件哈希。原仓库是自包含测试/演示项目；四项目组织、权限、发布与变更是新增研究设计，不是原仓库提供的真实企业流程。

P0真实SQL整理并发布共同数据；P1生成客户指标，P2读取共同数据与P1接口产生客户分析，同时持有粒度需求；P3运行SQL核对P1/P2结果。初始customer粒度合同使P1可先独立生成接口，P2在真实发布后采用；初始指标文件仍为空草稿，避免把双方最终完成设置成互相等待。之后P2请求改为customer_month，按预声明事件写入并发布；P2角色真实读取旧P1固定版本并提出精确columns位置问题，P1实际观察后维护SQL/交付，P2/P3继续更新。

| 正式机制条件 | 结果 |
| --- | --- |
| static四项目 | 全部制度完成，4份接受交付独立内容通过 |
| dynamic粒度变更 | 7份前后接受交付独立内容通过；P1/P2各400行、P3四期；P0保持 |
| 等价SQL | 不同SQL、列顺序及行顺序仍通过 |
| 不等价SQL | 实际执行成功，但独立业务结果失败 |
| 篡改项目自测 | 自测确实全绿，错误SQL仍独立失败 |
| 复制正确结果JSON | 无可信执行凭据，新版本不能冒充实际构建结果 |

P1起点SQL含受控的缺失列问题，模型承担实际代码修订；这不是从零自由创建完整数仓。两次校准约束错误的外层工具返回ok=true，错误结果已形成版本，不能混称为权限拒绝或数据库引擎异常。

六条件合计58/58。包含真实BinderException→改代码→重新构建、查询文件和结果版本、固定提交、精确源绑定、不可变历史及实际端口对照。源码、场景和原判据见[v011-executable.json](v011-executable.json)。

执行能力为受限DuckDB1.5.5，不冒称完整dbt运行。代码/config保存在世界JSON版本，再投影成真实.sql与临时DB执行；输出保存实际表、错误、自测、文件与可信执行元数据。权威资料足以重建逻辑DB，不承诺物理.db逐字节恢复。SQL只能受限SELECT/CTE，外部访问、扩展安装、任意宿主命令和控制区不可经此能力读取，子进程清除密钥环境；CPU/墙钟/DB内存/输出行数受限。它不是任意恶意宿主代码沙箱。

## 7. 三个独立接口校准episode
