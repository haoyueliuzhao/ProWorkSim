# v051 仓库校准与条件留出：执行前设计

本文件补充[总协议](software-calibration-v051-protocol.md)和已提交的[静态库存](software-calibration-v051-repository-inventory.json)。这里记录尚未启动的 CAL2/HOLD 条件；任务环境资格、接口控制、模型输入容量、CAL1 闭合和正式启动资格分别记录，不能以文档代替其中任何一步。

## 固定材料和范围

使用固定 SWE-smith-py revision `77cab9055d42ab4a5c25c89a8f937096db13558e` 的公开仓库合成缺陷记录。CAL2 为 boltons、parse、xmltodict 各两题；HOLD 为 funcy、python-slugify、iniconfig、dominate 各两题。具体 instance_id、源码 revision、数据行 SHA、唯一 seed 和条件顺序已经写入静态库存。CAL2 与 HOLD 的仓库不重叠，也不复用旧 sqlparse/schema/textfsm 保留题。这些是公开仓库上的合成错误，不能冒称真实上游 issue，也不是官方 SWE-bench 分数复现。

只按已冻结的静态材料规则选题：原问题非空、测试列表有效、单个未重命名源码文件缺陷等；不按模型结果或环境资格成绩替换任务。先前因工具链未收录而调整仓库的事实保留在来源准备记录中，发生在实际选题和任何模型生成之前。固定后环境不合格的题保留为相应库存阻断，不能再换题。

模型只看到缺陷初始文件、原问题、公共文档、公共测试和允许工具。上游正确代码、引入缺陷的补丁、参考逆补丁、数据行私有字段、正确 Git 父历史以及评分材料保存在模型工具不可读的目录。R 的 Git 仓库只从缺陷字节建立一个初始提交，不带远端或上游历史。全部正式输入、工具反馈、实际工作树和固定提交各有来源记录。

## CAL2 的三个条件

| 条件 | 实际模型状态 | 执行器 | 人数 |
|---|---|---|---|
| R | 原始 Qwen3.5-9B，无项目适配器 | pinned mini-SWE-agent 2.4.6 原 DefaultAgent 循环，共用项目数值 provider | 真实单人 |
| P | 同一原始模型，无项目适配器 | ProWorkSim S1、项目推理路径 | 初始/活动/累计均1 |
| U | 已有 S* actor 4/4 | 与 P 相同的 ProWorkSim S1 和推理路径 | 初始/活动/累计均1 |

每题三个条件使用同一个 seed202610170551—556，先后顺序按静态库存循环排列。S1 只有实际 `member_001`，不保留隐藏伙伴，不改写原 checkpoint 的 critic 坐标来冒充单人训练。U 只复制原完整 checkpoint 中的 actor 张量；完整来源身份绑定，但不安装 critic、Adam 或旧 RNG，不称完整 learner 恢复。原 S* 未重新训练，也不替换为 v050 的 Q−。

R 保留原 DefaultAgent 的控制循环；同一原生工具桥接限定每次生成至多一个 bash 调用，一个命令内部可以组合操作。这与 mini 原提示“至少一个调用”并不完全相同，要在报告中披露。R 的命令、测试机会和 P/U 的项目工具不相同，因此 R−P 是包含工具与交付要求差异的执行器比较，不能只归于单一 SDK 或提示组件。P−U 才是在相同 S1 执行条件下更换 actor 的比较。三个条件共同使用项目 v020 BF16注意力、FP32输出头与同一只读采样provider；R不另切换到CAL1的reference注意力路径，以避免执行器比较同时引入数值路径变化。R因此是原mini控制循环接本地共同provider，不能称厂商官方端到端流程复现。

R 允许修改其工作树中的测试；最终权威验收使用宿主冻结的原测试重新构造评估树，测试改动另列。P/U 的公共测试和配置由宿主保持只读。R 的完整公共测试命令与 P/U 应使用同一冻结依赖、仓库根目录和测试实现，具体隔离接入须在启动前完成必要控制，不以仅设置 cwd/PYTHONPATH 冒称隔离。

## 结果定义与唯一验收

CAL2同时记录两类结果：

1. **原生代码正确性**：每个闭合episode的最终工作树接受冻结完整原测试，即使没有项目正式submit也记录；R还记录原生完成标记。它不是旧v050未提交工作区的补验。
2. **项目交付结果**：P/U仅对最后合法固定提交依原项目合同评分；未提交不因末工作区代码正确而变为成功。原生与交付指标分母、失败和技术未知分别报告。

若 P/U 最终工作树与合法固定提交的源码树 SHA 完全相同，复用一次权威测试回执，严禁重复执行同树验收。提交后另有真实编辑才分别评价两棵不同树。公开成员测试与宿主最终验收分别计数，宿主不提供额外模型反馈、继续动作或免费重试。任何关闭、账单或验收记录未知都保留 null，不盲填为0。

## 已完成的来源环境准备

六个固定CAL2任务已完成原始正确、缺陷、参考修复三态的源环境资格：boltons每题完整412节点、parse每题98、xmltodict每题60；缺陷态的原F2P失败而P2P全过，正确和参考态全过。目标模块实际从各自候选源码导入，未将正确仓库以 editable package 安装到共享环境。

首轮18次状态执行原件保留。boltons原测试使用字符串 `lstrip(BOLTONS_PATH)`，项目长路径中包含字符f会错误剥离`fileutils.py`，出现411/412；xmltodict未提供pytest配置，使父项目配置影响节点标识。只修共同环境路径为 `/tmp/v051c/<纯十进制>`、显式 `--rootdir` 和仓内/空配置，重跑受影响的boltons+xmltodict12状态；原parse6状态直接复用。共30次实际CPU状态执行，不把最终18格都写成一次通过，也不削减节点。

这些源环境资格尚不等于隔离评分器资格。boltons两条原测试需要真实本地TCP和线程；普通禁socket包装不能直接使用。新隔离适配必须保留这两条测试，不把缺失测试判成模型错误或悄悄删去。当前适配与必要控制另存；完成前CAL2模型不启动。

## HOLD 的条件进入与解释

HOLD静态任务和四个状态已同时冻结，但在CAL关闭、共同实现封存前不运行HOLD正确/缺陷/参考三态或业务验收，也不使用其内容修理CAL。之后按事前资格协议执行唯一环境检查；不合格即保留并停止对应库存，不按成绩换题。未解决的CAL输入、评分、状态或账目完整性问题会阻断相关后继，而不是用官方榜单分数作阈值。

HOLD保持严格O1两个固定成员，Γ1与两成员稳定会话/事件唤醒语义沿原研究条件；所有四个已有actor S*/B/Q+/Q−均评价，每题同seed202610170561—568、同先手。主指标为固定提交业务F；不对未提交工作区另做救援验收。技术未知、时间删失和模型业务失败分列。

新的公开仓库修复任务与v050四个手工家族只是同属软件域，并非已证明同分布；不合并旧8单位与新8任务作同分布确认。CAL若改变共同执行条件，报告明确为旧状态在新条件下的表现，而非原训练收益的无条件复现。

用户于2026-10-17运行期间要求让渡GPU5，后续允许物理GPU0/1/2/3/4/6/7，排除5，总驻留最多4及其余最新资源门不变；历史实际分配保留。让渡经过和CAL1原未开库存接续见[独立说明](software-calibration-v051-gpu5-handoff.md)。只有有凭据的零模型资源准入失败可新进程排队，生成开始后的异常不自动重采。旧训练、Contribution、独立确认、v046和缓存队列保持暂停；本轮结束无自动后继。

执行前设计勘误：最初未提交的仓库协议草稿曾将R写为CAL1 reference推理路径；这与三条件共用数值provider的设计不一致。任何CAL2模型前已改为三个条件同project路径。此修订用于分离数值路径与执行器比较，不依据CAL1成绩、不改其正在运行的冻结计划。

既有actor装载的新增窄门：默认接口仍只允许S*4/4；未来HOLD的5/5必须显式提供静态库存中checkpoint文件SHA、actor身份、历史步数和完整state文件引用，逐项匹配才可装载。实际装载仍检查完整state文件与tensor digest，只安装actor参数。新增3项纯CPU元数据控制与Ruff通过，未重跑原25项控制、未读张量、未执行HOLD题目；这不是HOLD模型阶段放行。CAL1独立快照保持6f56931原接口。
