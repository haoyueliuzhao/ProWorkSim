## GPU 时间、预算与墙钟分别记账

实测累计口径为：

```text
首次两次加载失败： 25.7421016693 + 25.4026296139 =   51.1447312832 秒
R2 原两条模型进程：2067.8324904442 + 4212.3232555389 = 6280.1557459831 秒
R3 恢复模型进程：                                  2556.8311848640 秒
合计：                                            8888.1316621304 秒
                                                   2.4689254617 GPU 小时
```

R2 第一条模型启动至 R3 最后一条退出的墙钟跨度是 **6408.898225 秒（1 小时 46 分 48.898 秒）**。两卡重叠运行，所以这个墙钟跨度小于各模型进程时长之和。此前长时间等卡、CPU 资格验证、C0 只读复核和报告生成不计入新模型 GPU 时间；v0.25 已发生的训练成本保留在原实验档案，本轮不将其重新归入 C1。

原始累计上限为 14400 秒（4 GPU 小时），原加载失败按每 worker 向上取整至 26 秒，总扣账 **52 秒**，R1/R2 两 worker 的初始可用上限各 **7174 秒**。用户延长预算并开放阈值后，累计上限为 **28800 秒（8 GPU 小时）**，GPU 4 原 worker 从原始启动时刻连续计时，上限改为 14374 秒；不是接管后重新获得 14374 秒。

R3 的启动预算预留为：

```text
首次失败取整扣账 52 + 原 R2 GPU 0 已耗取整扣账 2068
+ GPU 4 原进程最多 14374 + R3 最多 12306 = 28800 秒
```

**52 和 2068 是防止超支的预算扣账，不是实际耗时。**最终成本继续用 51.144731 和 2067.832490，不能把两者同时相加。R3 完成后相对 8 GPU 小时上限仍余 **19911.868338 秒（5.531075 GPU 小时）**；全部阶段均没有因 GPU 时间预算耗尽而停止。实测总量也低于最初的 4 GPU 小时，因此这次结果不能证明“延长时间预算带来了表现提升”或“必须达到 8 GPU 小时才能完成”。显存阈值变化与特定中断存在直接日志对应；预算扩展的收益没有独立对照。
