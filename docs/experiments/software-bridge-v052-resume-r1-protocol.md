## 信号证据与宿主改动

首异常 worker 为 boltons-2/PS1，原 exit=-15、reason=null，无 host-stop 回执。随后监督器日志记录自己收到 SIGTERM，并在异常清理分支停止三个兄弟 worker。历史发送者尚无凭据，不能称已证明由会话、某个用户或资源限额引起，也不能把三个主动清理的后继停止误报为三个独立来源不明信号。详细时序及限定日志查询由独立只读审计记录。

接续宿主使用独立 transient systemd 用户 service，`Restart=no`，只运行原三槽并在完整闭合或完整性暂停后退出。沿用原每个 worker/生成/评分/90+10 分钟及显存、CPU、磁盘、进程身份、子组清理资源门；不添加会在等待可用 GPU 时触发的额外全局短时限。GPU0—7、最多四驻留的旧上限保持，实际库存最多三槽，不恢复整卡 idle 要求。

服务中的 strace 只观察 Python 监督器的 SIGTERM/SIGINT，记录 si_pid/si_uid；不使用 -f，不追踪 native/GPU 子进程的系统调用，也不包裹或改变 native worker 的命令、PID 身份和数值路径。服务 cgroup、启动命令、监督器 PID、trace 和退出状态独立保存。该隔离是预防性改动，不能据后续成功反推历史原因。

唯一新 CPU 控制使用一个全新子进程向自己的全新父进程发送一次 SIGTERM，strace 精确记录发送者 PID/UID；独立用户 service 正常退出并回收，零模型、GPU 和业务测试。控制证明记录通道可用，不保证任何未来外部故障都能留齐证据，也不解释旧信号的发送者。
