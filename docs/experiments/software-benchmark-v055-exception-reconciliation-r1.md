## 评分异常的可定位原因与修复

DeepSeek 的 47 个评分未知分为 6 个 1,800 秒测试超时、8 个 requests 容器初态拒绝、4 个非 UTF-8 补丁读取错误，以及 29 个已经有官方 unresolved 报告、但未达到原适配器明确评分门槛的端点。

### requests 初态

`psf__requests-1142` 的实际 HEAD 和 Git tree 都与冻结映射一致，拒绝来自 `working_tree_clean=false`。一次隔离的本地官方镜像检查证明唯一未跟踪路径为 `build/`；其中 65 个文件的路径、字节数、SHA-256 全部与冻结映射的 `removed_public_build_duplicates` 一致。它们是官方镜像内既有构建副本，不是候选修改或镜像身份不符。

新评分修订只为这一已固定镜像允许这份精确文件清单，运行时仍检查实际 HEAD、tree、tracked diff 和每个构建副本哈希。它不删除构建文件、不修改官方镜像、不放开任意脏目录。此修复覆盖 DeepSeek 8 个端点及 Qwen 3 个端点。

证据：[官方构建副本核验](../../artifacts/software-benchmark-v055/exception-reconciliation-r1/requests-official-untracked-build-audit.json)。该核验没有运行模型或测试。

### 补丁编码

Qwen 1 份、DeepSeek 4 份原锁定补丁含非 UTF-8 字节。例如测试生成的 PDF 不含 NUL，Git 即使启用 `--binary`，仍可能把它输出为包含原始字节的文本 hunk，导致评分器的 UTF-8 decode 失败。

新增运输工具在临时 bare Git 仓库里用私有 attributes 强制标准二进制补丁表示。原锁定补丁和新运输补丁均实际应用到相同 baseline，并核对得到与锁定候选完全相同的 Git tree；文件内容、模式、删除、链接和全部合法产物均保留，不过滤测试产物或重选代码。原 request 的 patch 和 candidate lock 不改，新评分身份另绑定运输收据及新补丁 SHA。

5 份运输补丁全部生成并通过完整树往返。一次必要 CPU 控制覆盖非 NUL／非 UTF-8 原故障、完整树保持、UTF-8 二进制往返、损坏原补丁拒绝和异常后恢复，另通过限定 Ruff 检查。证据：[控制](../../artifacts/software-benchmark-v055/exception-reconciliation-r1/patch-transport-control.json)、[五份收据清单](../../artifacts/software-benchmark-v055/exception-reconciliation-r1/patch-transport-r1/manifest.json)。大体积候选和补丁继续留在本地。

### 超时与 CPU 可见性

一次针对正在运行的 Qwen `scikit-learn-14710` 评分容器的只读观察记录了：4 CPU quota、16 GiB RAM、`cpuset.effective=0-175`、pytest 有 303 个线程。原 eval.sh 没有 OMP／OpenBLAS／MKL 线程限制。该证据支持“4 核配额下根据 176 个可见 CPU 过量创建线程造成性能损失”的推断，但尚不能仅据观察证明所有超时都由它导致。

独立 r6 评分修订把可见 CPU 限定为 4 个，同时保留原 4 CPU quota、16 GiB、16,384 PID、1,800 秒和无网络。新评分身份包含修订和 CPU 集合；原评分器、官方 harness、旧输出与已经消耗的补评分尝试均保持，不把修订后的结果伪装为原运行结果。

Qwen 原末尾等待器已于 07:41 自动触发。前三份补评仍未知；第四份在 09:43 前后自然结束后也保留未知，不做第三次评分。随后仅接管宿主驱动，原逐端点 intent 和 grader 两把锁复用，改为两路补评分；原在途子进程没有收到停止信号。该两路流程于 09:49:10 完成清单处理：13 个评分端点补评后仍未知，15 个生成和 2 个完整用量异常保持；requests 三端点及编码一端点交给修复后的独立评分流程。13 个评分端点中，4 个仍没有完整官方报告，9 个具有官方 unresolved 报告但不满足原明确评分门槛，详见 [补评后两轴记录](../../artifacts/software-benchmark-v055/exception-reconciliation-r1/qwen-post-retry-dispositions.json)。

### 已存官方 unresolved 与技术未知两轴

29 份 DeepSeek 官方报告已有 `resolved=false`。但本地官方 `grading.py` 在没有可解析测试输出时也会保留 `patch_successfully_applied=false`，该字段不等价于 Git apply 失败。27 份 `infra_failure=false` 同样不能证明原因一定是模型代码；另 2 份标注网络不可达。

本轮保留原官方布尔结果和原适配器技术未知两轴。缺少可信测试输出、依赖或环境证据的端点不自动填成正常模型失败，也不为了消除未知而放宽报告门槛。相同锁定候选的补评分仍至多一次，原始报告与未知保留可追溯。
