# 通信试跑观测器修复与十四回合恢复

本轮保持24题、REVIEW2双人、C0／C1／C2通信条件及每队5M输入加输出token预算。用户明确允许14个原系统中断回合各独立恢复一次，总尝试上限由72增加至86，全部新旧费用仍受同一个500元账本约束。原15703已有可信最终候选，已补评，不重新调用模型。

## 已发生的故障

v157最先进入的15个回合中，14个因格式纠错反馈漏归因和错误的字节比例门中断，1个正常闭合。v159修复这些问题后，首波21个原未调用身份中15个正常闭合并完成评分，6个被另外两类观测器错误中断。这6个身份为15715、15718、15729、15730、15731、15732，不属于此次获准新增尝试的14题，保持原技术未知记录。

**四个回合误用了旧测试版本。** 受管执行器允许复核者修改、恢复代码，并在当前版本完成公开测试后接受固定补丁。旧观测器却只记得最初集成版本的测试，随后拿旧版本与当前版本比较；其中一例合法的返修意见也错误地被要求满足旧测试版本。执行器已经接受了动作，观测器却报告版本冲突。

**两个回合的测试报告超过单条观测事件上限。** Pytest任务实际生成177个测试会话。完整报告已保存，但观测器又把所有子会话结构塞入同一事件，超过元数据节点上限。故障不意味着公开测试没有运行。

共同放大因素是运行时把任何观测器错误都当作执行完整性破坏，拒绝下一次API调用并使最终候选导出中断。辅助统计因此改变了真实求解轨迹。这是系统缺陷，不能归为模型没有修好代码。

首波结束时没有模型调用、评分或API预约在途。仅向当前用户自己的空闲v159协调器发送一次SIGTERM，由其正常释放资源；清理结果无错误，没有中断在途回合。原第二波36个身份仍未调用，保留等待测量审查。

## 修复后的行为

复核观测直接绑定执行器实际保存的复核凭据，并检查成员、补丁、当前工作树和同版本测试身份。完整凭据单独存档。接受补丁仍要求实际执行当前版本测试；测试失败不会被改写为测试通过。返修意见可以针对可见固定补丁提出，不凭空添加测试前提。旧集成和旧测试记录不被重写，也不制造一次不存在的重新集成。

测试报告完整保存全部会话及父子关系，事件只记录根会话摘要、完整报告引用和会话总数。检查完整层级是否存在重复身份、缺失父节点或循环；子会话的通过数量不累加到根会话。

派生观测错误保留为测量异常，并阻止未经审查的后续波次；它们不再停止已付费的正常模型轨迹或抹去合法最终候选。物理请求原件、来源注释、成员身份和现金预算仍由实际捕获与账本校验约束。这次没有放宽工具权限、合法交付规则或模型网络权限。

## 必要验证

8项针对性CPU检查通过，覆盖修改后恢复的当前版本复核、返修意见、旧版本测试拒绝、错误成员与补丁拒绝、伪造凭据拒绝，以及真实177会话报告的回放与完整存档。

原生OpenHands SDK联调完成C0和C2共58次脚本物理请求，包含2次摘要、2次通信压缩及6次真实本地公开测试。复核者实际执行修改、返修、恢复、重新测试和接受，开发者完成合法提交。C0额外注入一次辅助观测错误，随后工具调用与交付仍然完成，测量异常继续保留。两组物理请求、原件、usage和来源对账均通过；此次验证没有真实API费用。

来源统计仍是用户已接受的双口径：供应商usage决定实际总token，来源分配使用明确标注的本地估算。本次检查不能被描述为供应商逐token精确归因。
