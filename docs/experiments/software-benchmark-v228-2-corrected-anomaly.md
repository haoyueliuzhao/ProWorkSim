# v228.2｜纠正测试证据后，组织策略会不会调整分工？

**决策问题。** 上轮两个真实配对都选择了维持原图，其中唯一异常现场的策略输入遗漏了目标测试失败的结论。修订版仅在稳定现场得到过正式比较。本次复用 Astropy-14182 第 47 次操作机会保存的真实异常现场，单独复验纠正证据后的自主决定与后续执行。此题已知旧评分，是机制复验，独立任务数仍为一。[原批结案记录](../../artifacts/software-benchmark-v228/paired-audit-r1/final-evidence.json)

## 为什么从这个状态续跑

对原八题的共同前缀按原先指定的观察者重新回放，只读取当时已发生的工作回执。两题出现过同一用例跨修改版本失败（Astropy、Xarray），三题出现过符合观察规则的稳定进展（SymPy、scikit-learn、pytest），未找到依赖阻塞或集成冲突的合格节点。这里统计的是历史轨迹中可见的现场；当时只有 Astropy 异常和 pytest 稳定状态保存了完整的可续跑检查点。缺少当时会话的事件日志无法直接组成同状态的模型对照。[逐题来源与首次观察位置](../../artifacts/software-benchmark-v228/diagnosis-supplement-r1/recruitment.json)

## 已完成的工程验证

从 Astropy 的原始保存点恢复一个私有副本，取出 v227 独立策略模型当时实际给出的伙伴诊断方案，按同一条命令回执把旧证据编号映射到新版短编号，再激活对应的局部组织图。实现责任仍归 001，新增的独立诊断责任归 002，接收人为 001。

在该副本上用脚本通过真实受管工具检查交接。002 引用不存在的证据时被拒绝；随后读取公开测试文件，取得属于自己的新事件 42，并通过消息事件 43 将观察交给 001。负责人实际读取到职责已交接，原有 41 个事件、工作版本、作者、测试与交付记录均得到保留。该控制验证了权责、证据与交接回执之间的联系。脚本发起了工作动作，不能据此声称自然模型已完成诊断、异常已解除或代码已修好。新增模型调用为零。[控制原件及受管操作回执](../../artifacts/software-benchmark-v228/diagnosis-supplement-r1/harness-replay.json)

**v229 接续条件。** 审计提出 4 个开发状态、另外 4 个开发状态和 8 个冻结确认状态。要比较的是同一控制式接口下“固定原图”和“执行有效图变换”。v228 的 W0 允许成员自主改组，不能直接充作 v229 的固定原图分支。各异常类型须单报贡献、欠覆盖程度与样本缺失。v229 的运行费用单列核算，本复验不训练或更新策略参数。

W0 的 002 自主发送了三条诊断或修复建议，三条消息均成功送出。W1 的 002 也实际查阅文件、运行测试，并用 DIAG 消息尝试交接；两条消息都被拒绝。第一次写的是事件 57，提交当时该事件尚未发生，事后该编号对应 001 的读取。第二次写的是 `DIAG 55:`，55 确实是 002 此前取得的公开测试回执，冒号使编号未通过纯数字检查。直到预算边界，新职责状态仍为待交接。接口拒绝意味着这两条正式诊断消息未交到负责人手里；无法据此判断诊断内容是否正确。

**可支持的判断。** 新版确实在一个真实异常现场改变了生效的组织图，指定成员也做了与新职责相符的工作。自主组同样会主动诊断，因此不能把查阅文件、给出意见等行为全归因于新分工。两臂均未完成正确交付，本题也无法估计组织控制对总体正确率的影响。旧版选择维持、新版选择改组只构成单例观察，模型采样也可能造成差别。

## 离线修订与接续判断

在本次 W1 已结束的世界副本上，使用该成员实际发出的两条原始消息参数复验。修订只规范 `DIAG` 数字编号后的冒号分隔符，保留原证据归属、收件人、职责与生效顺序校验。无法引用证据时，对承担该职责的发送方返回最近可引用的本人事件编号。第一次错误引用仍被拒绝；第二次有效引用通过，副本中形成了绑定实际测试事件 55 的正式交接回执。此次为零 API 离线回放，没有重跑模型或评分，也没有将真实运行中的“待交接”改写成成功。[原消息回放与修订结果](../../artifacts/software-benchmark-v228/diagnosis-supplement-results-r1/separator-replay.json)

当前证据支持组织控制机制在真实异常上激活职责，并促成成员尝试履行；正式交接的修订目前只有离线证据。后续可准备 v229 的受控原图／有效变换对照，在新任务状态上同时记录激活、交接和结果。仅有同一 Astropy 状态的一次复验，不能用于拟合两个开发窗口或宣布策略有收益。v229 的正式调用和经费尚未启动。
