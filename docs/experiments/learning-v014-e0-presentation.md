# v0.14 E0：公开返回与上下文的冻结推理对照

三臂的六个开发案例，原始回报逐项均为 `[0, 0, 0.2, 0, 0, 0]`。简明呈现减少了实际被投影的返回字节；12,288 上限下没有记录到上下文拒绝，但均未转成正确实现、充分复核或完整链交付。此结果不证明训练方法有效或无效：E0 没有参数更新。

运行源码冻结于 `00b5df83ea0f1001e54a5cdbcdb11ca9da2afe55`。每臂使用相同六个预声明业务情境、同一采样种子配对、同一初始 base/adapter、任务提示与角色预算；`full8`/`compact8` 的声明差异为返回呈现，`compact8`/`compact12` 的声明差异为上下文上限。实际上限分别为 8,192 / 12,288。

有一个影响因果解释的边界：各臂独立构造世界，公开 instance/branch ID 不同，真实输入不逐字相同。每例最早一次角色观察去掉这两个 ID 后相同；团队中后续角色的首观察还可能受前面已分叉的行动影响。部分行为在首个被压返回前已不同。因此这里报告实际观测和预算边界，不把所有行动差异唯一归因于呈现或上限。

## 原返回与公开返回字节

每个实际工具返回仅计一次，按项目审计 JSON 序列化统计；不是反复送入模型历史的字节数，更不是 tokenizer token 数。不同条件行动数不同，不能把跨臂原返回总量当作同一条轨迹的反事实。

| 案例 | full8 原→公开 | compact8 原→公开 | compact12 原→公开 |
|---|---:|---:|---:|
| f0-implement | 10,319 → 10,319 | 11,572 → 8,131 | 19,276 → 15,835 |
| f0-review | 15,494 → 15,494 | 20,150 → 16,884 | 26,726 → 23,460 |
| f0-chain | 19,049 → 19,049 | 19,600 → 19,600 | 22,140 → 22,140 |
| f1-implement | 10,324 → 10,324 | 17,923 → 11,029 | 5,870 → 5,870 |
| f1-review | 18,803 → 18,803 | 17,446 → 14,180 | 14,994 → 14,994 |
| f1-chain | 7,661 → 7,661 | 6,462 → 6,462 | 7,187 → 7,187 |

compact8 共 5 个返回被压缩；compact12 共 2 个。完整检视入口实际被调用后仍返回完整合同，错误返回、读取正文及 SQL 返回保持原样。所有原/公开 SHA 与实际 retained tool return 比较均通过，报告未重算 reward。总输入 token 随可用行动增加而上升，不能把局部返回减少表述成总资源节省。

## 固定版本与错误反馈

- compact8 的 f1-review 实际读过 result v1，而既有固定提交为 v2；compact12 同例也先读 v1，随后确实改读 v2，但仍缺少完整复核依据。后者不能概括为“始终未纠正版本”。这是实际引用差异记录，不推断模型阅读旧稿的主观意图。
- full8 f0-chain 的 seq 51 缺少 data adoption，随后 seq 120 实际采用 data，seq 154 build 执行成功。compact12 对应为 seq 51 → 120 → 153。相关后续实际请求含原拒绝反馈，因此计为这一前置义务的可核验恢复；它们仍未满足完整依据和正确交付，不计为业务成功。
- compact12 f1-implement 修改 code 后两次 build 仍为 execution_error，切换 sql_query 也被作用域拒绝；不计作执行恢复。
- compact12 f0-review 出现 approve 返回 ok，但原始奖励仍为 0，实际只读了固定 code，缺少完整结果/data/audit 依据。工具接受审批不是正确且有据复核。
- 其余不同工具、改变参数和随后某次操作被接受，在没有同一义务得到明确修复的证据时，只保留为行动调整。
