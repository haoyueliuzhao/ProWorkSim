## 稳定 O1 与当前学习状态

两名成员在初态拥有相同权能、独立工作副本和空任务表。模型自行形成任务与职责；不要求消息、多人编辑或伙伴采用。出生和永久退休操作不在公开接口，直接请求也不能产生该副作用。

`staff_done` 结束当前工作并休眠，保留身份、原 SDK 会话、历史、责任和计量。只有较晚真实可达的伙伴消息或已提交公共工作事件能够唤醒；清除 SDK 内部 `_done` 锁存必须有此来源凭据。私有 note 不唤醒，双成员休眠且无事件即自然闭合，不生成唤醒事件。因 context、成员 fixed meter 或团队预约不足而不可运行的会话不复活。

必要 SDK 程序控制观察到：`member_001` 先结束当前工作，在伙伴真实消息之后，于同一会话再次实际调用合成 transport。其本人共有 3 次、团队共有 5 次 fixture 调用，所有费用和决定保留，没有新身份或预算重置。

训练采集必须使用事前指定的共同 logical window；新运行器复用原 v033 的 quiescent slot guard。开发来源事前固定为 `policy_development`，不能提升为训练。控制显式把模拟当前学习状态设为 4/4，采集后仍为 4/4；新 collect 不恢复 common。scenario/manifest 预先记录用途、完整 case、学习分支绑定、当前身份与 steps、实际 recipe/hash、逻辑窗口及旧 critic 坐标到新成员名字的明确映射。

执行记录：初次整文件 9 通过、2 SDK 跳过；原 SDK 对这 2 项均通过；追加错误训练窗口控制及其相关初态复验共 2 通过，其中仅 1 是新用例。因此为 12 不同 / 13 次执行。可选采用工具的接入发生在这些控制之后；没有因此重跑旧初始化或完整 runtime 套件，其新路径由另外的 peer SDK 控制覆盖。

## 只读测量与已披露的 CPU 修复

新 reader 严格绑定 v049 接口、当前实际载入 actor/recipe、原 logical window，独立重建冻结 Γ1 的反馈投影、静态去重、同输入引用和容量选择，并核对真正送入模型的 selected input、本人 token trace 与实际账单。原 Γ1 元数据中的 `world_runtime_library=v047` 保留为继承库来源字面；实际 episode 世界/运行器单独绑定为 v049，不将两者混淆。

首次测试“两个成员均在首请求执行前被 context 拒绝、实际生成 0 次”的控制失败。原因是旧 v044 历史 replay 对每个成员要求一个来自首个实际生成的模板，访问 `templates[member_001]` 时发生 `KeyError`。原件保留在 pytest 临时目录；长期记录为本文件和机器 JSON，不保证临时目录永远存在。

窄修只作用于新的只读 reader：反馈生命周期只从已绑定的实际生成输入、响应、收费与原 runner 事件重建；被拒绝的请求另行验证，不制造首个生成模板，也不制造呈现。Γ1、采样、世界规则、预算、R、费用及旧文件均未改变。随后正常 O1 路径和 0 调用首 context 路径各一次复验通过。原普通路径因同一命令选择而重复了一次，这计入累计执行。

另保留原来源前提：格式拒绝反馈必须存在较早的同成员原 runner 错误事件；新增一条有限反例通过。因此本组最终为 15 不同 / 17 累计执行，而非此前中间状态的 14 / 16。

测量将真实 context、共享预约不足、成员 fixed meter 先拒绝分开证明；必须绑定来源、顺序、计量和无执行副作用。充分绑定的局部资源终止继续其他已授权独立槽；实际输入、身份、权限、收费或终态证据不足仍全局暂停或保持未决。反馈无后继不改成实见，当前工作休眠也不改称永久退休。

两条完整 reader SDK 控制使用原现场协议的序列化标签，但 owner、token 计数和 guard 回执均明确为 CPU 合成值。正常路径 5 次合成调用、1 个公共测试报告通过完整机械检查；首 context 路径 0 调用、两个局部拒绝及空 ledger binding 也通过绑定。此结果不代表真实模型容量资格。

## 采用工具的实施遗漏与补齐

冻结设计要求实际固定文件树采用通道。第一版 O1 从 v042 工具表继承，遗漏了 v047 原生 `adopt_candidate`。在任何模型工作开始前发现并补齐。

新接口复用其公开参数 schema 和文件语义：只能读取合法发布的固定 patch，核对发布文件哈希，将整个文件表替换为该树，保留传递固定来源依赖，并产生原生 `candidate_adopted` 事件及原返回字段。不把它改成 `integrate_patch`，不自动测试、fix 或提交。O1 没有人工 I 阶段，因此去掉该工具的 I 阶段选择限制及仅阶段使用的 `stage_id` 元字段；只保留两稳定成员、公开 schema 和原 WorldCore 事务路径。

另一个子任务只执行一次真实 SDK 程序 peer 路线并记录其 3 项断言控制，本表不重复计入。它故意保留 `cpu_programmed_fixture` 标签且没有真实 tensor/RNG guard 哈希；将原件送入严格生产 reader 得到标签不匹配和缺少 guard 哈希的停止，原件及结果保持。没有为让 CPU fixture 看似生产资格而放宽 reader。

## 监督器边界

固定 worker 是 `s0`、`collect-LA/LB`、`update-B`、`update-Q_plus/Q_minus`、`dev-B/dev-Q_plus/dev-Q_minus`。S0 完成后才能并行采集；两个采集 worker 都完成后才启动 B。B 完整回执和 direction wrapper seal、B update/support 引用绑定后，才按事前规则释放条件库存。

有可信基础材料但无可行 I 方向时，仅执行 B 的四个开发槽。没有可靠基础材料时，Q 和全部开发保持 `not_applicable`，未执行费用为 0；不转移额度、不追加采样。已经启动的分支不能被事后改称未适用。训练执行错误走全局暂停，不冒充无基础材料的正常分支。

保留仅物理 GPU 3/4/5/7、最多 3 驻留、容量稳定 60 秒、准入及自身上限 57344 MiB、活动余量 6144 MiB、每 worker 64 GiB RSS、128 GiB artifact 上限和 20 GiB 磁盘余量。启动一张卡后清除其旧空闲稳定样本，下一阶段必须重新观察容量。时间守卫为 loading 900 秒、boundary 600 秒、episode 6000 秒和逐 training step 900 秒；不对完整学习 window 增加总超时。

8 项调度/资源 CPU 控制全部通过。它们未调用 `Popen` 或 GPU 资源诊断。最后七个新增相关文件的 Ruff 已在采用接入和 reader 来源检查完成后通过；根代理的全仓 Ruff 是另外一个时间点的记录。
