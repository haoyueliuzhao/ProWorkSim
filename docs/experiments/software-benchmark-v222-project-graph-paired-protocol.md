# v222 项目图定位与组织分工配对实验

审计基准：2026年11月20日。按本次审计，先比较**普通检索和台账（L）**与**项目关系增强（G）**。固定4题、4个仓库、8条配对运行；B/V验证实验暂缓，C/N公式和参数不更新。本轮用于检查机制是否真实发生，不作普遍收益或统计显著性结论。

## 实际比较什么

| 条件 | 给模型的信息 | 不变的部分 |
| --- | --- | --- |
| L 普通检索与台账 | 从完整授权代码树检索文件和符号；组织生成器看到工作范围、负责人、进度与普通台账 | 双成员FREE2基础环境、57项工具、模型、测试入口和交付规则 |
| G 项目关系增强 | 在同样的检索和台账上，利用代码引用候选，以及工作、代码、补丁、版本、测试之间的关系帮助排序和组织提案 | 与L相同的权限、系统说明主体、调用机会及500万Token完整任务预算 |

例如，L可以检索题面中的函数名称并读取代码；G还可以沿公开导入关系找到相关文件，或看到某工作已经修改哪个版本、对应测试是否过期。这些关系是额外的结构化信息，不是参考答案。静态引用不证明运行时依赖，测试通过不证明题目已全部修复。

L同样拥有符号定位、`locate_work`、公开检查记录等工具；两组工具Schema相同，区别在检索是否使用关系排序，以及组织生成器能否看到项目关系。公开检查工具只是记录原有测试与需求声明，两组都不会采用v220的额外需求验证提示。

本轮估计的是**图信息对定位和候选生成这条路径的整体影响**。L/G可以生成不同候选，不据此把差异称为“选择器收益”。v223才会使用相同冻结候选面板，单独比较选择依据。

## 固定题单与共同初态

| 题目 | 仓库 | 公开问题与覆盖意图 |

题目从每仓库固定SHA256顺序的前三项公开题面中选择，排除v217/v218近期题单；未用历史分数或参考补丁挑选。上述类型是公开题面所提示的研究场景，并不保证实际修复一定跨模块。整个Verified任务池已有历史接触，因此本轮仍是开发机制试验，不是未曝光确认集。不因本轮表现换题或补题。

每题先用L路径建立一个中性、真实双成员前缀。模型根据两条原文锚点自行分工，不由控制器指定最终责任人。共同检查点按以下先到条件保存：

1. 已有真实代码进展、后续实际公开测试、仍有未完成工作；或
2. 达到24次实际工作机会，或累计实际Token达到120万。

前缀分配上限200万，提前边界用于在预算耗尽之前保留可恢复状态。第二类检查点不冒充“已具备责任变换条件”：原执行器仍会检查实际进展和测试，成员也可以拒绝或延迟提案。终态或基础设施失败不能被伪装成可恢复状态；若因此缺少配对，保留原题及原因，不换题。

L/G恢复同一工作树、消息历史、已付预算、测试次数和工具声明；前缀物理调用只发生一次。每路独立运行自己的后续模型调用，不能共享另一分支的新补丁或反馈。调度seed不能保证API逐次生成一致。

## 组织提案如何执行

每路生成器最多两次调用，第二次只用于格式或合法性修正；合计不超过20万Token。原始响应、规范化记录和错误全部保存。两组使用相同语法、指令和校验器。

预定选择规则是：**按模型返回顺序，选择第一个通过编译且与KEEP存在实质结构差异的方案；没有则采用KEEP。** 其他方案只作候选生成诊断，不另开分支，不用评分挑方案。保留原v219的有限语法修复规则，不能把离线修复后合法率称为原始输出合法率。

模型仍须自己选择attempt/keep/defer，原负责人发出提议、接收者接受，之后真实实施、发布、复核、集成和提交。控制器不会直接更改owner。编译合法、当前执行条件满足、真实操作成功分别统计；仅填补缺失复核者等设置不算新的结构变体。

所有4题都按L/G计划保留，包括只有KEEP的题。只有KEEP的题仍可用于定位结果比较，但不能贡献“组织候选选择有效支持”。

## 图关系与可信边界

| 等级 | 确实知道什么 | 不能据此推断什么 |
| --- | --- | --- |
| E1 真实记录 | 某工具实际执行、哪个版本被修改/测试、责任是否被接受、台账当前值 | 修改过某文件就一定修对；某测试通过就覆盖所有需求 |
| E2 静态源码 | 授权快照中的导入、符号及名称引用候选，绑定源码版本 | 名称相同就存在已解析调用或必要工作依赖 |
| E3 成员假设 | 模型声明的依赖、需求与工作对应关系、消息中的解释 | 声明即为真实工程事实 |

索引仅取当前成员可见的代码或已合法发布的固定补丁。未发布的伙伴私有代码不能进入生成器；图来源和允许读取对象绑定精确版本。后续版本更新、失效和实际成员事件持续记录，支持分析“项目关系→组织提案→成员动作→新项目证据”，但不新增第二个学习器。

## 指标与分析口径

主要按每题L/G并列展示，不把两个条件或候选当成独立任务。

- **结果**：官方代码正确性、原合同合法交付、是否正常闭合；技术未知单列。
- **定位**：查询、返回内容、真实读取、达到诊断与首次实施的成本。相关性须对照公开需求与真实后继事件审阅，不能用检索排名自证有效。
- **组织**：原始候选数、解析失败、规范化后编译合法数、独立结构数、选择、拒绝、接受和实际执行回执。未运行候选的执行有效性为未知。
- **关系质量**：按E1/E2/E3及版本分别核验来源；正确关系/已核验关系为P_edge。必要关系召回R_edge只有在独立于图生成器的公开事实参考集确立后计算。暂缺必要关系参考时报告未建立，不能把零个参考写成100%召回。
- **成本**：实际输入、输出、总Token，冷构建和热更新时间，检索返回量，估算索引对象内存，生成器图信息及新增Schema的本地Token估计。内存对象估计不是进程RSS，局部分片估计不是供应商逐Token精确归因。

权威总账来自供应商usage；缓存命中仍属于实际输入，不再额外相加。每路逻辑成本为共同前缀P＋本路生成器G＋续跑L；整批物理成本中共同P只算一次。图/Schema等分片估计单列，不再加到实际usage上。

Contribution的质量、合法交付、成本三个分量分开展示。提前失败虽然可能少花Token，但不能被直接解释为更好的组织方案。本轮没有C/N更新，也不根据中期得分调提示、图权重或组织规则。

## 预算与执行

沿用原共享账本，累计上限1100元；启动前已知费用峰值计价上界689.70007472元，剩410.29992528元。该现金数是冻结峰值费率计算的上界，不是供应商发票。

4题×2路×500万Token＝4000万逻辑Token。每百万按最高8元计，整批预留320元；前缀和生成器已包含其中，物理消耗更少时按实际结算。另保留20元准备规划和70.30元缓冲，未增加预算或运行数量。独立账本控制每阶段剩余量，不会为续跑重新发放500万。

最多8路生成、4路环境启动、2路异步官方评分。普通用户协调进程限制64核等价CPU、512GiB内存；生成/评分容器各4CPU、16GiB，network=none、drop ALL、无宿主绑定、无GPU。环境控制仅使用本批对象。已开始的工作不因金额触线被中断；完整配对预约用来预先保障费用。

单题异常进入异常集合，不阻塞其他题。三个不同任务重复出现同类公共基础设施故障时暂停新准入；已有真实调用不自动重采。同锁定候选技术评分故障最多补评一次，正常代码失败不重评。所有资源只按本批精确身份清理。

## 分阶段推进条件

**Gate A**核验版本、来源、隐私、等级及实际请求呈现。本轮CPU/SDK准入只证明接线可以运行；实际图质量还要从真实轨迹复核，不能在启动前宣称科学门已通过。

**Gate B**检查L/G方案是否有实质差异、差异是否造成真实成员行为变化、依据是否可追溯。它不要求G必须获胜，但没有有效组织差异就不能声称完成组织收益验证。

**Gate C**要求足够多任务形成多个实质候选、完整后继结果、同一冻结空间和可跨任务使用的选择器。只有满足后才另行安排v224/v225。当前余额与本次启动指令不自动授权后续18条或60条运行。

审阅为当前AI根据原始证据作出的核验，不冒充外部人类盲审。实验完成后生成逐题结果和门审查；未知关系与缺失证据保持未知。
