# v0.41 上下文—反馈闭环开发复测协议

日期：2026-10-10。依据用户提供的[v0.40审计](../reference/audit-v040-next-v041.md)。本协议在新模型采样前登记。v0.40的16槽及其正式R=0保持不变；它完整执行，但32名成员均在单请求容量边界停止，17次公开测试反馈没有进入之后的实际生成请求，因而不支持信息条件等价或模型不会协作的判断。

## 修订与信息边界

新增v041上下文投影，在同一成员自己的请求内，对预先声明的静态快照字段进行精确去重。同一成员、相同证据身份和版本、相同语义字段、完全相同值，才可移除较早副本；最新观察保留完整正文。共同根合同、适用说明和已授权初始诊断至少有一份完整值；动态任务、成员、版本和预算保留原记录，不把初态失败说成当前失败。原v034合同去重及较旧完整工具回合选择规则延续，最新完整工具往返按v040既定可见内容保护。

静态字段声明包括角色说明、初始诊断、原合同及根描述别名；另包括源码可证明固定的动作错误政策、验收要求、调度政策、成员上限、共享资源上限、隔离说明、观察投影说明、初始诊断来源与可编辑路径。后九项只在相同成员、root合同和接口身份下精确匹配去重，初始诊断来源另绑定诊断身份。`execution_condition`中的实时人数、`task_formation`任务数、成员注册表、预算和其他动态字段不因当前相等而删除。

删除值、保留路径、证据身份与原/selected请求均归档。不能通过后台报告向未授权成员补信息，不能以hash代替正文；不合并独立工具事件，不扩大原可见stdout/API细节，不摘要，不自动提交。共享信息较多的自然输入成本允许存在，不做无意义token填充。位置和重复次数改变可能影响行为，因此属于新呈现协议Γ，不能声称与v040行为等价，也不能合并新旧16槽。

## CPU容量准入

P0-A使用原32个生成前context拒绝请求、同一原生渲染器和实际tokenizer，分别保存旧/新selected完整请求，复核原记录token、记录新prompt、固定2048输出预留及16384总容量余量。不得加载权重或调用模型。32项必须全部可容纳且唯一内容及权限保持；它仅是历史前缀可容纳性，不是行为反事实。

P0-B覆盖两个原root×SB/ST/PB/PT×两个初始成员，共16种初始配置形状。使用明确标注为CPU私有程序的合法路线，依次验证初始化、正常读文件后的输入、公开失败测试后的完整既定可见反馈、合法修复及公开通过反馈、固定与提交机会；该路线不进入模型提示，也不规定真实团队行动。另以少量控制检查消息、格式拒绝、任务增长及新成员初始化。

P0-C事前固定的较大返回形状为：每个root实际文件中的最大180行合法读取页、真实修复差异6000字符页、4000字符合法消息；另四项任务增长、非空briefing的新成员初始化及一次普通未知工具名拒绝后的反馈。它们是有限代表形状，不声称穷举所有任意长度输入。

P0-C测完整原生请求编码后的token数，不以字符数或独立片段token相加代替；逐阶段保存最大prompt与余量，并纳入本任务较大的合法返回。16384−2048=14336是prompt硬边界。若任一路线或必需独特反馈仍不fit，停止在CPU准入阶段，不加载模型、不按结果追加样本；明确报告需要进一步界定的返回范围，不能在正式批次热改投影。

CPU资格报告以完整相关源码SHA绑定，新采样必须使用同一实现。必要控制只验证机制和容量，不冒称自主行为或参数收益。

## 首配对块门槛与调度

P0通过后，仅启动`block-r0-s0`的四条件，它们属于原16槽，不是额外试点。四槽全部结束后读取实际归档输入与反馈：必须使用v041投影，静态正文权限与唯一信息保持，最新完整可见反馈保持。

任何已产生工具反馈（包括读文件、编辑和格式反馈）之后，因`context_capacity`而无法进入下一次实际生成输入，视为明确输入/反馈阻塞并停止剩余未开始槽。旧投影、越权、正文或受保护反馈丢失亦停止；关键证据缺失、首块未完整执行导致无法判断时记录`gate_unresolved`或执行未完成，不放行。门槛不读取R、消息数、任务数或出生数；正常业务失败、合法结束、团队预算耗尽、等待无事件不因表现差而停止。

门槛通过后，其余三个root/seed块可并行，每块一份resident actor、四条件顺序执行，槽内成员共享actor并串行调用。失败或停止保留原记录，不热改、不重采、不补足库存。后续正常单任务与资源保护仍适用。

仅物理GPU3、4、5、7；v040额外空闲卡许可不延续。显存不足等待。单worker显存、活跃剩余显存、CPU RSS、单任务时限、产物体积及磁盘余量沿用v040；不恢复旧累计GPU/worker/统一墙钟上限。旧学习、Contribution、正式配置更新、TextFSM独立确认与缓存生产队列保持暂停；反向、actor/critic更新均0。

## 测量与报告

主结果为正式完整交付R，提交、内容正确、过程满足和技术未知分别报告。不补验未提交工作区，不把公开通过当作隐藏验收通过。四条件按预登记root/seed块配对：信息主效应=(PB+PT−SB−ST)/2，说明主效应=(ST+PT−SB−PB)/2，交互=PT−PB−ST+SB；任一所需槽未知或未开始，相应对比保持未知，不能填0。保留全部16槽，不筛选已收到反馈或工作较深的成员重做主比较。

新增反馈闭环表按工具事件记录产生/保存、是否进入后续真实生成selected请求、后续相关查询/修改/验证/交接候选、与最终固定交付的联系。无后续输入区分context、团队预算、主动结束、等待及真实故障并给分母。实际呈现不自动等于理解或因果采用；工作关系仅为辅助证据。初始环境诊断不算模型发现，消息/任务/人数只作过程诊断。

所有实际调用和消耗（含失败、技术未知）进入成本；初始准备成本另列且不重复计入复用槽。若反馈循环恢复但R仍0，分析真实内容、验证和交付断点，不继续全部归因于context。任何行为变化首先属于新呈现/执行条件下的开发结果，不能算ID-VTDO分配或参数学习收益。
