本协议落实原审计中“校准解释后，用四个已有检查点做一次保留评价”的已授权阶段。它记录实施边界，不宣称接口、环境、输入或模型准入已经通过。CAL2 的各次停止、未知及旧版本保留，HOLD 不用于修理或补齐 CAL2。

## 事前库存与共同条件

继续使用已冻结的 `software-calibration-v051-repository-inventory.json`：funcy、python-slugify、iniconfig、dominate 四个仓库各两题，共八题；每题分别评价 S_star、B、Q_plus、Q_minus，合计最多 32 槽。任务、原始 revision、数据行 SHA、seed 202610170561—568、先手与四条件顺序均从原库存派生，不重新选择。S_star 为原 4/4，另外三状态为原 5/5；每槽显式绑定该状态的 checkpoint SHA、actor 身份、历史步数及完整 state 引用，只装载 actor，不安装 critic、优化器或旧 RNG。

保持严格 O1：两个固定成员 member_001/member_002、两个真实独立 SDK 会话和私有工作树、同一个只读 actor、同一个 500,000 token／128 决定／128 attempt／32 次团队公共测试池。初态为空任务表和同字节缺陷源码，没有隐藏伙伴、人工双诊断、预分工或注入的 member 测试。责任可由成员自主建立，协作不是成功的硬条件。staff_done 结束当前工作并休眠；只有实际可达的后续伙伴事件才唤醒同一会话，身份、历史和预算不重置。

Γ1、18432/2048、非思考模式、原采样参数、3072 Unicode 字符分页、600 秒 HF 迭代停止设置、90 分钟软边界和 100 分钟硬边界保持。公开工具保持原固定成果、消息、精确版本采用、当前版本测试及主动固定提交语义；对方私有树和私有测试报告不能因同属团队而直接读取。新阶段总生成上限 16,000,000 token、4096 决定／attempt、1024 次成员公共测试；新增训练、反向、actor/critic 更新均为零，旧余额不转移。

## 先冻结接口，再打开题目

第一步仅阅读既有实现、静态任务身份、上游环境 profile 和 checkpoint 元数据，使用合成材料完成新的 HOLD provider、world、collector、measurement、executor、host 与资格脚本。所有新增必要控制及共同代码须提交封存。实际 HOLD 问题、缺陷／正确／参考源码及测试内容不得用于这一阶段的修订。

此装配层独立于 CAL2 的 S1 接口。它复用既有稳定两会话、事件唤醒、共享预算、Γ1 和固定交付算法，以及已控制的隔离／登记子进程实现；不直接启用旧人工任务的初诊断、contract.md 观察或额外 member_tests，也不调用 CAL2 的终态工作树验收。

静态身份已显示两处新增接缝，需要在实际题目内容访问前处理：python-slugify profile 声明原生 unittest 命令；iniconfig 同时可能是 pytest 的宿主依赖。前者必须保留原测试引擎或冻结可证明一一对应的 ID 映射，不能把未知语法直接当作 pytest nodeid。后者必须证明目标测试实际导入候选源码，不能将预先导入的环境包通过误记为候选通过。这些目前是由静态接口识别的风险，不能写成已经在 HOLD 实际发生的故障。新适配以合成样例控制，不能借此扩大旧 CAL2 修订范围。

HOLD CPU 测试环境采用上游 profile 声明的 Python 3.10，记录实际 patch/build 及依赖身份；模型 SDK 与数值运行仍使用原环境。该测试环境独立于 CAL2 的 Python 3.12，不改写旧环境或旧结果。原生 unittest 保留固定 profile 的 verbose 行解析，再以实际 case 事件证明原 ID 一一对应，不凭新的 TestCase.id 字符串替代原标识。

测试环境不安装 HOLD 目标库的正确源码。针对 pytest 的 iniconfig 依赖，实施方案为只接受预绑定只读配置路径及 SHA 的静态配置视图，不提供任意业务输入解析，也不把正确目标模块对象载入候选解释器。候选目标模块仍须从候选树真实导入。此适配需在内容访问前通过合成来源／权限控制；若不能证明该能力，保留对应两题的阻断，不通过声明或换题绕过。

第二步须待 CAL2 收口、关键接入问题解释及共同实现封存后，由独立阶段决定允许打开原八题材料。此时只作确定性来源导出、依赖／配置绑定、事前唯一环境资格和初态容量测量；不得依据 HOLD 的错误、资格或成绩调整共同工具、调度、Γ、评分器、题目或 seed。

## 唯一来源与输入资格

保留八题各正确、缺陷、参考三态，共 24 个逻辑资格单元。原正确与参考态应通过完整原测试，缺陷态应保留原 F2P/P2P 的来源区分及预期行为；测试节点、原配置、测试引擎、目标模块来源和隔离回执均须绑定。正式模型 provider 只加载问题与缺陷文件及原公开测试信息，正确树、参考修复及 F2P/P2P 标签不进入模型可见材料。

为避免冗余执行，按事前固定规则机械去重：只有完整候选文件 map、全部原测试标识与配置、依赖环境、引擎、runner 源码和执行参数身份严格同值的资格单元，才引用同一份物理执行原件。不得按结果去重或省略失败。24 个逻辑单元分别保留来源和共享执行指向，实际物理执行次数另列；旧 CAL2 资格不重做。

初态容量测量以八题各两个真实角色为 16 个逻辑形状，并保留四条件各自的必要身份实例，最多 64 个真实 SDK 初态请求形状。Γ1 内部渲染及底层编码次数另列，完全同字节渲染可精确缓存；64 不冒称底层 tokenizer 总调用数。来源阻断的任务不测。四条件业务材料和工具合同应同值；只有完整原始请求严格同值，才复用同一份测量，不能把角色形状相同当作原始字节相同。使用实际 SDK 序列化和原 tokenizer，要求每个实测 selected 输入加 2048 输出不超过 18432；不新增模型资格题、容量候选或额外工程余量门。未来独立会话的标识也可能不同，初态形状资格不保证所有未来输入容量，正式每次请求仍执行原硬容量门。

此处在实际 HOLD 内容访问及共同实现冻结前，修正了初版“最多 16 次编码并直接复用四状态”的假设。合成接口审视显示公开预算 state_sha256 派生于独立账本身份，会话／实例标识也可能不同；未证原始同值便复用会少检必要差异。原方案保留在提交 f334281，修订不改变 Γ、题目、seed、条件、模型调用、测试或生成预算，也不由 HOLD 成绩驱动。

不合格的固定任务保留原件并阻断对应四条件库存，不换题、不删除测试、不按成绩重试资格。若发现共同实现仍需修复，原资格与阻断必须保留；不能将修订后重跑描述为同一个事前候选。全部八题的合格、未执行与未知分母均需报告，不能只把可运行题作为完整八题结论。

## 固定交付端点与宿主规则

主业务 F 仅评价关闭时锁定的最后合法固定提交，使用其精确固定树及原完整测试一次。后续私有编辑不能替换锁定对象。没有合法提交且运行、费用和 guard 完整时 F=0，宿主业务测试次数为零；不补验未提交工作树。已提交树验收未知、输入／身份／权限／费用／终态 guard 缺证时保留技术未知，不能用“没有提交”掩盖机械问题。行政删失的 R_joint 与 R_token/Q_token 区别沿用原规则。

新模型根与每槽驻留独立，不承接 CAL2 隐藏状态。资源范围为用户最新授权的物理 GPU 0—7，总驻留最多 4，继续原显存容量、预约、内存、存储和时间门，容量不足等待。充分绑定的安全局部资源终止保留并继续独立槽；真正执行、权限、身份、评分或费用完整性问题暂停未开库存，在途槽依冻结规则闭合。旧阶段成本只作已结算来源引用，不在 HOLD 账本重复相加。

所有阶段的实际执行、控制失败与修订、正式未知和成本分别报告。HOLD 的模型准入须另绑定 CAL 解释、共同源码、来源／输入资格及四状态，不由本协议或单一控制自动放行。它评价旧检查点在本次新任务与执行条件下的表现，不与 v050 旧八单位合并，也不声称新增学习收益。原暂停的训练、Contribution、确认、v046 和缓存队列保持暂停；本轮没有额外自动后继。
