# v053：200 题主面板与 40 题三次运行诊断

日期：2026-10-20。用户本轮明确要求按新规模开展实验。本协议取代“六题完成率”作为本轮能力评价；旧六题只保留为历史接入材料，旧结果、剩余预算和中断回合均不转入本轮。此前“临时运行验证、不保留数据、不推送”的限制属于上一轮临时验证；本轮保留可审计的正式实验记录，按项目授权提交代码与说明。

## 预先固定的研究范围

本轮仅测原始 Qwen3.5-9B、原生 OpenHands 单 Agent。不挂项目训练适配器，不训练，不比较组织架构，不恢复任何旧训练或确认队列。本批属于单人能力评测／校准材料，不能在后续算法比较中重新称为独立确认集。

| 部分 | 不同任务 | 每题本轮新增回合 | 回合数 | 输入加输出 token 上界 |
| --- | ---: | ---: | ---: | ---: |
| 主面板 | 200 | 1 | 200 | 100,000,000 |
| 预选重复子集 | 主面板中的 40 | 2 | 80 | 40,000,000 |
| 合计 | 200 | — | 280 | 140,000,000 |

每回合最多 500,000 个实际输入加输出 token；请求在执行前按输入加最大输出预约。预算不跨回合转移。140,000,000 是全部回合的上界，不是消耗预测，不含环境准备、CPU 测试和 GPU 驻留。不存在达到某个成绩后提前收口或成绩较低时更换提示／题目的规则。

## 来源、环境和清单

来源固定为 SWE-smith-py revision `77cab9055d42ab4a5c25c89a8f937096db13558e`；官方环境代码固定为 `9b74ac08118a85c39c356802f7961893af73e07f`。全量实际清点、去重规则、代理缺陷类型、候选顺序和种子见 [来源说明](software-panel-v053-source-selection.md) 与 [候选机器摘要](software-panel-v053-source-inventory.json)。

所有筛选都在任何正式模型运行之前完成。最终面板选固定候选顺序中最先通过环境准入的 20 个仓库，每仓库恰好 10 题；每仓库预选两题重复，合计 40 题。仓库只有全部预选十题合格才能进入，不在同仓库内按环境或模型表现临时换题。明确来源问题可以记入排除表后继续下一个预排仓库；网络、公共依赖、Docker 服务等系统故障必须暂停准备，不能当作来源不合格跳过仓库。

环境资格使用官方原始镜像、固定 profile 的上游 commit、测试命令和日志解析器。官方构建流程在检出上游 commit 后重建 Git 历史，因此上游 commit 只表示来源身份，不能当作镜像内的 checkout 目标。另行冻结镜像实际默认基线的 Git commit、tree 和工作树状态，并记录实际 image ID／digest 与依赖环境；所有状态从该同一镜像基线准备。每种完整测试身份的 clean 状态运行一次；每题分别验证 bug 和逆缺陷 patch 恢复的 gold 状态，核对预定 FAIL_TO_PASS 与 PASS_TO_PASS。不是只确认容器能够启动。完整十题通过之后，记录该仓库的明确资格。

模型初态是在上述固定镜像基线上应用官方缺陷 patch，再隐藏 FAIL_TO_PASS 对应的整个测试文件。若其中也有 PASS_TO_PASS 测试，它们随同文件隐藏；完整原始测试只在独立最终评分环境恢复。模型可见的是题面、缺陷工作树和其余公开测试，不提供缺陷 patch、gold 恢复材料、隐藏测试或资格结果。

所有 actor／judge 工作树清除原 `.git` 历史及已有 Python 字节码，重新建立单初态提交，防止从历史或旧字节码直接取得修复前实现。每回合从独立容器、会话、工作树和随机 seed 开始，不共享其他回合的补丁或反馈。容器无外部网络，不挂载宿主实验记录。

正式启动必须同时具备：

1. 20 仓库、200 题实际环境资格和保留的排除／故障记录；
2. 一次冻结的 200 题、40 题子集、280 个 slot 与全部独立 seed；
3. 固定源码快照、原模型来源凭据、SDK／工具身份、全部数值和候选导出规则；
4. 200 个实际原生 SDK 初始请求的一次 tokenizer 容量测量，全部输入加输出预约满足上下文上限；
5. 独立模型准入文件明确放行。准备工作不得自动绕过以上条件。

## 评分、停止与技术未知

主端点 `R_code=1` 要求固定 FAIL_TO_PASS 和 PASS_TO_PASS 的每项均有可信完整记录，状态为 PASSED 或 XFAIL；其余可确定的候选失败为 0。SWE-bench 原评分工具可能从分母中忽略 SKIPPED／XPASS，本轮另外保存 `official_R`，不让遗漏测试制造完整通过。该差异事前固定并在结果中披露，不称 SWE-bench Verified 分数。

候选自身造成的导入、语法或断言失败，在执行环境完整可信时归为模型失败。执行器失联、OOM、测试系统超时、身份变化、账目不一致、记录缺失等不能判为模型失败，保留技术未知。已充分绑定的局部上下文／token／迭代／工作期边界会结束本回合并评价唯一候选；公共完整性故障暂停未开始库存，在途任务按原规则收口。

只有明确证明尚未进入模型加载、无 resident、无模型调用且实际 token 为零的资源预约失败可以新进程重新排队。进入模型加载之后不自动重采，不补算已中断请求。公共故障的修订使用独立版本、独立运行根和新说明；不同配置不混在同一个主结果内。

## 服务器执行与资源

GPU 允许范围继续为物理 0—7，总驻留上限 4。使用原 r3／r5 可复用显存缓存及容量门；80 GiB A100／A800 实际空闲至少 46,080 MiB 才考虑派发，不要求整卡空闲。以物理编号解析完整 UUID，并在加载时核对实际 CUDA UUID。容量不足保持等待，不降低精度或上下文，也不变换模型。

服务器旧内核的 Landlock 限制已由前序受限命名空间实现处理；本轮另将 GPU UUID 映射和可信 GPU 运行时 `/proc` 写权限适配部署，详见 [运行时记录](software-panel-v053-runtime-adaptation.md)。这些不改变采样和数值算法。

Docker 采用独立服务 `proworksim-v053-docker`，数据与其私有 containerd 均放在项目 `runs/software-panel-v053/docker` 下；不使用根盘空间紧张的默认 daemon，不修改其他业务容器。专用服务仅接入本机已有代理以下载官方镜像，任务容器继续无网络。环境 CPU 准入最多并行八个仓库；每容器默认 4 CPU、10 GiB 内存、512 PID。

模型监督器从只读源码快照启动，使用独立服务和 `Restart=no`，保存进程、阶段、资源、来源及账目凭据。不得在模型运行中修改其源码快照。结束后不自动追加题目或恢复旧队列。

## 预定分析

主结果仅为 200 个不同任务第一次预定运行的等权完成率。40 题分别报告三轮完成率、0/3／1/3／2/3／3/3 的任务数与未知数；不计算混合 280 条的主完成率，不把至少一次成功替代单次成功。

保留任务与仓库层级，完整结果时给 Wilson 95% 描述区间及固定 seed 的仓库整簇 bootstrap 区间。存在未知时，完整主估计与置信区间保持 null，另给固定分母的识别上下界。实际 token、未决预约、模型失败类型、技术未知、环境 CPU 和 GPU 驻留分开报告。具体计算规则和局限见 [报告口径](software-panel-v053-reporting.md)。

结论名称限定为“这一仓库分层任务面板上的完成率”。它不能直接外推为 SWE-smith 自然任务分布的无条件均值。三次重复仅提供有限波动诊断，不是稳定性认证。只有全部预定库存按事实闭合之后，才能称本轮实验完成。
