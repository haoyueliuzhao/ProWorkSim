# v193：正式模型调用前的控制器启动修复

本轮仍是用户确认的12题、12仓库、四条件48个主回合与12个预选重复，总计60回合；新增现金授权仍只有300元。完整方法、题单、指标及预算规则见[v192实验协议](software-benchmark-v192-critical-context-protocol.md)，P0结论见[v191离线审计](software-benchmark-v191-critical-context-p0-report.md)。v193是部署修订，不增加模型尝试、预算或实验条件。

## 诊断发现与原因

v192启动的4对零模型隔离诊断在控制器初始化之前退出，正式API请求和正式job均为0。8个诊断容器与4个卷均已清理，无其他用户对象或宿主配置操作。原源码、授权、账本、结果和失败归档保留。

原因是新增公共测试短页头已经由宿主配置生成器写入`common_public_test_view_revision`，但实际控制器CLI的允许字段集合遗漏了此字段。CPU脚本控制直接调用SDK工厂，覆盖了历史策略和观察处理，却没有经过CLI配置解析，因而未覆盖这处连接错误。

v193在允许字段中加入该字段，并检查其值必须等于冻结的公共视图版本。没有放宽为接受任意配置，也没有移除实际运行时绑定检查。新的9项CPU回归将真实配置生成器的输出直接送入真实CLI解析器，覆盖四条件×诊断／正式两种模式，并检验缺失或错误版本仍被拒绝；全部通过。此前18项策略、来源、预算、分页与宿主绑定检查，以及SDK控制保留复用，不为身份更名重新调用模型。
