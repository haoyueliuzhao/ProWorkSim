# v181：上下文审计后的完整任务试跑

本轮将 v180 已固定的任务方案接入真实 OpenHands SDK 和 ProWorkSim S1 执行环境。目的是检验输入节省能否在完整修复中保留，而非继续只比较固定决策点的输入大小。正式结果尚须由实际运行与官方评分生成。

## 固定比较

12 道题、6 个仓库，每题执行 M0、M1-5、M1-10、M3-R，主面板 48 回合。预选 6 题对 M0 和 M1-10 各增加一次，共 12 次重复；全计划 60 回合。主结果使用首次预定运行，重复另报，不混合加权。题单、seed 和顺序沿用 [v180 协议](software-benchmark-v180-context-task-pilot-protocol.md)。这些任务有更早的实验曝光，只能称开发性复测。

| 条件 | 实际处理 | 原文恢复 |
| --- | --- | --- |
| M0 | 原有 SDK 摘要，80 事件门槛、保留最初 4 事件 | 摘要附原始私有事件档案引用 |
| M1-5 | 遮蔽较早环境及工具观测，保留动作与最近 5 个完整工具周期 | 每条被遮蔽观测有确定引用；关闭旧定期摘要 |
| M1-10 | 同上，保留最近 10 个完整工具周期 | 同上 |
| M3-R | 持久摘要，原始未遮蔽动作及观测作为输入，正常触发为 21+10=31 周期，保留最近 10 周期 | 摘要附完整原始前缀引用；按完整事件边界分块，不能截断原文凑长度 |

四组使用同一私有 `context_read`，只能读取该回合、该成员已经保留的材料，不增加仓库或隐藏评分权限。读取消耗真实行动机会，返回内容及其后续重复呈现计入输入。M3-R 不采用比原文更长的摘要；已经失败的相同前缀不重复付费尝试。状态变更根据工作区来源引用、公开测试及固定／交付记录跟踪；旧摘要被后续完整观测覆盖，不能作为当前版本测试证明。记录的“版本仍一致的重复呈现”只是有效性代理，不能直接认定模型理解或使用了摘要。

模型固定为 DeepSeek Flash 非思考模式，temperature=1、top_p=1，总上下文 131,072，输入上限 98,304、单次输出上限 32,768。每回合共享 5,000,000 输入＋输出 Token，摘要与网络重试也计入。API 不支持可冻结的权重版本或逐请求 seed；框架 seed、响应 model 与 fingerprint 保留，不声称模型完全确定。

## 预算与恢复

用户授权沿用 v175 唯一账本，累计新任务准入线仍为 250 元。进入本轮前已知支出上界 21.86307688 元，余额 228.13692312 元。按历史同配置任务成本推算，60 回合可能超过余额；此估算不是承诺或必然消费。

按同题条件块准入，暂按每回合 5 元估计启动占用，避免并发启动时重复使用余额；每个实际回合仍受 5M Token 硬约束。启动后遵循用户要求，不因现金准入线触发中断，因此累计最终消费有超出 250 元的可能。5 元是调度估计占用，不是单回合现金上限。5M 在既定最高费率下的理论收费上界为 40 元，不能把它当预计费用。

保留旧账本的所有 policy、jobs 和 requests 原行；本轮添加独立 phase 和物理请求补充表。每次真实 HTTP 请求保留原始输入、响应、usage、调用身份和错误。临时 HTTP 故障最多 3 次物理尝试；未知费用和 Token 预约保留，不因恢复成功而退款或抹除。新的模型整回合不自动重采；异常评分仅针对原锁定候选处理。

## 执行与评分

本批最多 4 对生成容器、2 路异步评分、2 路环境启动。生成每对为 4 CPU／16 GiB actor 加 2 CPU／32 GiB controller；评分每个 4 CPU／16 GiB，普通用户协调器 8 CPU／32 GiB。资源总上界 40 核等价、264 GiB，保留主机实际可用内存和磁盘余量。只有本批普通用户服务和自建 Docker 对象；无系统 slice、宿主绑定、GPU、共享主机配置修改。

12 题均不属于需要出网的 Requests 环境。全部容器 network=none、drop ALL；模型 API 由宿主普通用户进程直连，不通过代理，也不提供联网搜索工具。先完成 4 个零模型 SDK／actor 诊断与每题 gold／empty 官方控制，共 24 个控制，再运行已准入题目。模型不能看到控制或官方评分反馈。

生成结束先锁定唯一工作树与最后合法交付，清理生成对象后异步评分。代码和合法交付分开，且相同代码树可在严格身份核对后复用本回合代码评分。没有合法交付记为交付未完成，不能自动提交。单题异常进入独立清单，不暂停其他健康回合；资源清理无法证明时停止新准入，并让已进入的回合排空。

## 测量和解释

供应商 usage 是 Token 总账，缓存命中属于输入子集。报告各组平均输入、输出、摘要、回读、实际总 Token、成本、代码正确率、交付率和技术异常；12 题规模仅适合机制筛选。来源分账保留实际 SDK 事件位置及请求映射，标为本地估算，不能冒充供应商逐 Token 精确归因。来源观测异常保留为测量缺口，不覆盖已经得到的代码与评分证据。

零 API 脚本验证与正式模型结果严格分开。实现说明、CPU 控制、部署诊断、资格控制、物理账本和最终结果分别保留在 `software-benchmark-v181` 对应目录；启动后冻结源码，不热修改正在运行的条件。
