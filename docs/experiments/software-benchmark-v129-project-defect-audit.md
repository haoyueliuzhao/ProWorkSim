# PROJECT成功率差异中的系统缺陷

**存在已证实的残留缺陷，可能影响模型表现；但尚不能把REF 72%与PROJECT 66%的全部6个百分点差距归因于系统。** 本次只读核对最终采用的50个PROJECT回合，并深入比较8道“REF通过、PROJECT未通过”题的实际请求、反馈、补丁与评分。没有新增模型调用、容器、公开测试或评分，也没有修改冻结运行代码和原始结果。

后续用户已要求修复，独立实现与验证见[v130修复说明](software-benchmark-v130-interface-defect-repairs.md)。本页保留审计时点的发现，不用后续实现改写旧成绩。

两组均以OpenHands为基础。PROJECT增加了受管工具、信息分页、来源版本与正式交付规则；本轮已经对齐主要推理预算、自检和摘要策略，但实际操作能力与测试反馈仍有差异。这是50题恢复后对照，包含获授权的独立恢复尝试，不是原始首次尝试成绩，也不是完整500题分数。

## 1. 已确认的缺陷

| 问题 | 实际证据 | 对成功率的含义 |
|---|---|---|
| 文件读取参数说明错误 | 实际发送给模型的`read_file.path`被说明成“可选的已发布补丁ID”，与其文件路径语义冲突。原因是`path`和`patch_id`复用同一个schema对象，后续修改后者说明时连带覆盖前者。 | 这是实现缺陷，可能误导参数选择；已核查轨迹仍存在正确路径调用，不能据此认定某道题因此失败。 |
| 零项测试被报告为通过 | SymPy-15345两次调用`run_tests(targets=['probe_max.py'])`，原输出明确为`0 passed`，结构化反馈却为`passed=true`。实际执行函数仅凭退出码0且未超时判通过，没有区分零项测试。 | 这是反馈语义缺陷，可能让模型误以为修改已验证。原日志仍可见，尚未证明它单独导致该题最终失败。 |
| 公开测试依赖不兼容 | Requests-2931原测试声明pytest 2.8.1，实际使用7.4.4，字符串形式的`pytest.raises`直接报错；原httpbin处理器又把生成器交给Flask JSON，导致HTTP 500。基线与最终测试文件字节相同，候选没有修改相关依赖。 | 两项具体错误可归为环境兼容缺陷，增加了与目标修复无关的排错噪声；不能据此把该题全部测试失败或官方失败都归为环境问题。 |

第一项已在真实API请求中确认，而非仅从未使用的源码推断。实际只有`read_file.path`这一处字段含义错误，不应写成所有工具参数被污染。源码位于[基础工具定义](../../src/proworksim/software_collaboration_v027.py)与[v117说明更新](../../src/proworksim/software_benchmark_tooling_v117.py)。

第二项的实际PROJECT调用链为`v119.ManagedOperationSession.execute → v110.execute → v064.run_public_entry`；判定在[受管执行函数](../../src/proworksim/software_benchmark_managed_actor_v064.py)第457行。`executed=true`可以表示命令确实执行，问题是将“执行了命令且退出正常”当成“确有测试通过”。不能用原生终端辅助脚本的实现代替这条真实调用链。

## 2. 接口负担与公开测试环境

**单动作和分页存在可观察成本，但其规则本身不等于实现bug。** 最终50题共71次格式拒绝，涉及39题，其中57次是同一回复发出两个工具调用，只有4次完全没有工具调用；另有8次重复JSON键、1次参数schema错误、1次未知工具。这些回复被拒绝后继续运行，没有复发旧版全队列中断。

另外49次业务拒绝包括15次游标／来源问题、9次路径／补丁身份问题，以及替换、空修改、测试选择和笔记边界问题。Matplotlib-20826一个测试报告长35,450字符、共14页，模型连续四次改动或猜测游标而被拒绝；没有发现原样使用已发出的合法游标仍被拒绝。文件读取上限4096字符／180行，测试报告每页3072字符，这些规则增加了回读步骤，但不能把模型没有读完的页面直接认定为系统丢失反馈。

**公开测试入口仍不等于原生终端的操作能力。** PROJECT可以选择pytest／Django／SymPy入口及当前树中的新增测试文件，但没有REF那样自由组合命令、运行临时Python复现的入口。Requests-2931的两项兼容错误由原测试、冻结依赖源码和实际报错栈共同确认；旧`pytest.raises`在发请求前就失败，HTTP 500则来自未改动的fixture处理器。该题最终官方失败是候选将bytes转成str造成的独立类型断言失败，不能改记为环境未知。这里没有重新运行基线，也没有把全部公开测试失败都归为环境原因；对成功率的具体影响仍未确定。

## 3. 当前差距不能仅用预算、交付或旧故障解释

最终50个PROJECT回合中，46题主动结束、4题因累计token预约不足结束；17道失败题中14题主动结束、3题预算截止。8道REF独有成功题中，**7题主动结束，只有Matplotlib-20826预算截止**。2,151条API响应未记录输出`length`截断或provider失败，也没有终态上下文、期限或执行完整性故障。只有一次输出预约缩至27,918 token，该响应实际输出570 token，不能记为输出截断。

这不证明上下文和预算完全无影响：摘要、回读和多次操作仍消耗预算。但本轮差距主要不是“多道正确修复被系统强行中断”的已证现象。历史27次参数键序误判及9次现金中断已另行恢复，保留原记录和成本，不能再次当作当前50题的失败原因。

| REF独有成功题 | PROJECT最终候选的具体不足 |
|---|---|
| Django-13158 | 对`Query.chain()`作用的理解错误，合并查询上的`none()`语义仍未修复。 |
| Django-15103 | 修改HTML工具，但遗漏模板filter的对应可选参数路径。 |
| Pylint-4970 | 关闭评分时仍输出`TOTAL`，自建断言反而要求这一错误输出。 |
| SymPy-15345 | 最后修订删除输出中的逗号后空格，并同步修改自己的断言；官方要求的格式仍错误。此前另有零测试假通过。 |
| Matplotlib-22865 | 增加边框对象，但遗漏dividers更新；自测仅计数新增对象，未覆盖官方失败情形。 |
| Matplotlib-23476 | 仅保护`_original_dpi`，未正确处理pickle状态，高DPI恢复结果仍错误。 |
| Requests-2931 | UTF-8解码仍将bytes改为str，未保留官方要求的原数据类型；REF用独立Python复现定位了该条件。 |
| Matplotlib-20826 | 末次自测2失败／1通过，之后再次编辑但未测试即到预算边界；最终官方代码也未通过。 |

以上说明评分有真实候选代码依据，不表示接口无影响：工具说明、反馈和可用操作可能影响模型如何形成这些错误候选。目前没有发现这8题中的合法操作被错误拒绝、最终候选丢失或官方分数被错误扣除。

**交付统计更正：**33个代码通过任务均交付通过，其中32题最终树与合法提交同版本。Pylint-6528最终树与最后合法提交不同，但两个版本分别评分通过；Sphinx-10614也有版本差异，两个版本均评分失败。因此任务级未观察到代码成功转成交付失败，但不能说所有33个最终候选均有同版本提交证据。v124、v128中的过强表述已更正，评分与用量不变。

## 4. 判断与修复优先级

应优先修复零测试反馈、schema对象别名污染，并核对旧仓库公开测试依赖的完整兼容性；再单独评估分页与受管复现能力的成本。不能为追平REF而一次性取消版本、权限和审计规则，也不能把这些规则的全部成本称为程序错误。

当前配对为28题双方通过、8题REF独有通过、5题PROJECT独有通过、9题双方失败，净差3题。PROJECT平均token比REF多10.87%，主要多在输入，但这不是已识别的失分因果。现有样本、不同恢复尝试与多项同时变更不足以计算“系统bug造成了多少个百分点”；修复后仍需冻结同题对照，不能承诺消除全部分差。本次仅完成审计，没有启动新实验或更改生产实现。
