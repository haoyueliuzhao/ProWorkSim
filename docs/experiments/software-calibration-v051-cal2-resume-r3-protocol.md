# v0.51 CAL2：socket 类型修复后的原七槽接续

本次接续属于用户“继续任务”授权内的执行缺陷修复，只承接原 CAL2 十八槽中仍未启动的七槽。它不增加题目、种子或模型样本，不重跑任何已生成轨迹。模型启动仍须独立阶段放行、修复控制、宿主控制及已提交源码共同满足；本文件不单独构成准入。

## 已闭合阶段与缺陷

初始阶段保持原记录：三个 P/U 槽共 22 个完整回包、227,876 token；一个 R 槽在首个模型请求前因文件字节／映射顺序校验失败。初始四个 worker 合计 413.1480391025543 秒。三个已生成轨迹不重采，原无真实 pytest 执行的终态不补验。

r2 使用独立快照，接续十四个原未启动槽及唯一有充分零请求凭据的 R 首次暴露例外。r2 实际启动八槽，全部自然闭合，253 个完整回包共 2,676,767 token，费用无未决；worker 合计 3429.4393272399902 秒。其余七槽从未启动。r2 原宿主终态为 paused，停止原件与全部原始判定保持。

首批真实测试发现共享 runner 的 socket 夹具把 `socket.socket` 替换为函数，导致原 P2P 异步测试在导入 `ssl.SSLSocket` 时发生类型继承错误。未修改生产文件的 boltons-1/R 直接提供反例；boltons-2/R 与 boltons-2/U 也有同源失败。独立只读审计绑定六份已有回执、1844 个已执行节点，未重新执行测试或评分。三条受影响轨迹的严格代码正确性和终态部分质量为技术未知，保留原 raw 值；boltons-2/U 没有固定提交这一独立事实及其 R_joint=0 保持。

修复保留原 `socket.socket` 类对象，只对其初始化、绑定和监听作有限 FD 适配。原两份 listener 及 4+1 个预接 client、Landlock/seccomp、测试节点和文件字节约束保持。一次真实隔离控制执行原异步测试及原两条 TCP 测试，3/3 通过，未重跑完整仓库资格。详见[窄修说明](software-calibration-v051-socket-type-repair-r3.md)及独立阶段报告；旧故障输入、反馈、结果和成本均不回写。

## 唯一剩余库存

新根固定为 `runs/software-calibration-v051-cal2-r3`，只从 r2 已闭合宿主的 `not_started` 且 `attempts=[]` 状态派生以下七槽，保持原顺序、种子和初态：

1. cal2-parse-2/U；
2. cal2-xmltodict-1/P、U、R；
3. cal2-xmltodict-2/U、R、P。

任何已进入 worker 的槽均不得加入。r2 的零请求 R 例外已使用，本次没有重试例外。每槽仍为 500,000 token、128 决定、128 attempt；五个 P/U 槽各最多 32 次公共测试，两个 R 保持原生执行器的动作约束，不冒称相同测试调用数。新阶段上限为 3,500,000 token、896 决定／attempt、160 次 P/U 公共测试。旧余额不转移；前三个已采样槽与 r2 八槽的 2,904,643 已结算 token 只计一次，另保留初始零生成加载成本。

三个条件仍共用原 project 数值推理路径、18432/2048、非思考模式、原采样参数和 600 秒 HF 迭代停止设置。P/R 为原发布模型，U 为原 S*4/4 actor；初始单成员、Γ1、3072 字符分页、工具、固定提交要求和 90+10 分钟时间规则保持。新 actor/critic 更新与反向计算均为零。

## 来源冻结与结束边界

r3 只允许共享 repository runner 相对 r2 发生上述源码差异。原宿主 worker 与监督算法通过独立命名空间复用，仅重绑新冻结计划、版本和 worker 模块入口。旧引用解析至其对应冻结快照，不能将主仓库修复解释成旧运行热改。独立报告的环境有效性层不修改旧测量行，也不据成绩筛选接续槽。

继续使用用户最新授权：物理 GPU 0—7、总驻留上限 4，保留原显存容量、预约、内存、存储及时间资源门。容量不足等待。安全且充分绑定的局部预算／context 终止不取消其他独立槽；新的执行、身份、评分或费用完整性问题暂停未开库存，已在途槽按冻结规则闭合。

七槽收口后按原十八个逻辑槽唯一合并，各阶段成本只计一次。因旧未知保留，完整六对 P−R/U−P 不以缺失填零。HOLD 仍须等待 CAL2 闭合、关键接入问题得到解释和共同实现封存后，按原条件独立准入；本次不读取其任务内容或执行环境资格，不启动新训练或旧暂停队列。
