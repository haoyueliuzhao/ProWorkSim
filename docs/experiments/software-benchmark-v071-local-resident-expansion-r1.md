# v071：本地 Qwen 增加至四个独立驻留

本次仅扩展部署资源。现有 Qwen 主协调器最多同时处理四个任务，新启动器最多新增两个原计划中尚未消费的模型身份，使四个任务可以在自然回合边界分配到最多四个驻留。不会迁移、取消或重跑已经进入模型的任务，也不申请第五张没有对应任务的卡。

| 原身份 | 指定显卡 | GPU UUID | 本次处理 |
| --- | --- | --- | --- |
| model-1 | GPU2 | 沿用原 spec | 保持原服务 |
| model-3 | GPU4 | 沿用原 spec | 保持原服务 |
| model-4 | GPU1 | GPU-1e059756-8c2e-bbd9-7aba-7e08af2be25c | 新增，容量满足后启动 |
| model-5 | GPU5 | GPU-1201ff43-02be-5111-36db-e33818319c6b | 新增，容量满足后启动 |

原 model-2 的退出与预约释放由单独核验处理；启动器只有看到原 `closed.child_exited=true` 和预约释放标记，才不再把它计为活动驻留。历史 model-0、model-2 身份不会重启。新身份仍属于原六个物理身份总数，不增加新的模型、任务、seed 或实验条件。

每个新增服务继续使用原始 BF16 Qwen3.5-9B、131072 上下文、32768 输出上限、0.6 显存比例，以及原采样、原中性准入和完整上下文缓存验证。各自保留 12 CPU、96 GiB 内存、无 swap 和原用户服务约束；启动器直接调用原 `make_spec`、`unit_command`，就绪判定与关闭清理由原生命周期承担。新启动请求成功不等于模型已经就绪。

`--prepare` 只读取当前状态并为两个身份分别写入不可变授权文件；不预约资源、不启动服务。准备时某张卡容量不足仍可封存该卡的固定授权，记录容量尚不满足。`--launch` 在原驻留分配锁内，分别复查 UUID、原 50176 MiB 剩余显存门、主机内存和磁盘余量，再由原共享资源账本执行预约。所有消费者仍受 152 CPU／832 GiB 总上限约束。单卡暂时不足不会消费其身份，也不会阻止另一卡尝试；某一项成功后，另一项失败不会回滚成功项。已消费身份、返回不明确或失败的启动均保留证据，不自动重启。

增加本地模型驻留会占用共享资源池，因此可能减少 DeepSeek 同时可用的环境数。新增两个驻留共预约 192 GiB、24 CPU；API 的实际准入继续按共同账本动态计算，不能同时声称本地和 API 的最大并发都不变。独立驻留有望减少本地长响应造成的同卡等待，但实际速度提升仍须运行后按完成率和请求耗时观察。

实现为 [launch_additional_qwen_v071.py](../../tools/launch_additional_qwen_v071.py)。本次必要 CPU 控制共四项：准确封存两项授权且不启动；首卡容量不足时第二卡可启动、后续只重试未消费身份；第二项启动回执不明确时保留第一项及全部身份；旧驻留清理未证明时拒绝新增。四项均通过，Ruff 和差异检查通过。测试全为临时目录和注入夹具，没有真实 GPU 查询、模型、API、容器或用户服务调用；本文件不将准备完成表述为真实启动完成。
