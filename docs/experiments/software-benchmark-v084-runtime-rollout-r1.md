# API 并发与 Qwen 恢复：2026-10-29 部署记录

本次只修订原实验的宿主调度与测量实现。DeepSeek 保持思考模式、REF／PROJECT 两组各 500 题、每题 500 万输入加输出 token；人民币总限额仍为原账本的 1500 元。Qwen 保持原六组、3000 个计划槽、原模型与采样。已消费身份不自动重跑，技术未知不改填失败或零费用。

## 已发现的问题与处理

| 问题 | 证据边界 | 实际处理 |
| --- | --- | --- |

旧 API OOM 的 33 个任务环境与 1 个评分环境已保存候选并清理。5 个只有预约、没有可靠实际用量记录的请求转为显式技术不确定，费用预约完整保留，不释放未知费用。详见 v080／v081 恢复报告。

## 上线范围

- 用户限定授权的 `proworksimv076api.slice` 已创建并核验：224 GiB、swap 为零；只在无子任务时最终清理。本次滚动升级复用它，没有再次创建或修改共享主机配置。
- v083 于约 14:37 启动，接续 325 个未消费 API 槽，目标及硬并发上限均为 48；每批最多 8 个环境启动。旧 API 已静止退出，675 条历史记录与 5 项待评分全部接管。
- 新旧 API 在交接期间共用同一个 1500 元账本，并通过互斥库存及共享资源预约限制总并发。没有按旧服务退出而重置预算。
- v084 于约 14:40 启动，接续 2770 个未消费 Qwen 槽。恢复时保留 110 条正常闭合、36 条技术未知、84 条未开始记录；四条停止后终态已从原件归并。
- 原四个模型进程持续驻留。短暂暂停 API 新补位后，Qwen 已恢复四题并发，再将 API 目标恢复至 48；没有取消在途 API 任务或重载模型。

这些并发数字是任务／环境并发，不能当成同时进行的 HTTP 生成请求数。公开测试、工具操作和环境启动阶段可能没有 API 请求。监测分别记录两者。

## 核验与解释边界

v082／v083 联合 32 项必要 CPU 检查和限定静态检查通过；v084 的 7 项实际准入回归通过。监测工具只读取服务、cgroup、进度和账本，并区分进程存活、独立心跳与主循环是否推进。未对完整仓库重复运行测试。

观察窗口只说明本次部署的短期运行状态，不能据此推算完整实验正确率或承诺稳定吞吐。旧 OOM、解析失败、取消与未知记录均保留。此前已出现的技术未知需要另行审查，不因恢复未消费队列而消失。

## 实际观察

先后完成 10 分钟、6 分钟两个只读窗口。第二窗口 API 任务预约并发由 36 升至 46，平均 41.77；13 个采样点的同时 HTTP 请求峰值为 14。这是已运行任务与请求的分别计量，不代表 46 个请求始终同时推理。最后观测 Qwen 为 4 个生成任务，API 与 Qwen 均无队列级 failure。

第二窗口末主机 CPU 空闲约 81.6%，MemAvailable 约 897 GiB；API 管理进程保守工作集约 15.75 GiB，硬限仍为 64 GiB。监测未检出服务死亡、主循环停滞、OOM 或现金越界；单题正确性、服务端每次请求是否成功不在该结论中。

同一时点账本已结算上界 939.05 元，不确定预约 47.19 元，另有 8 项在途预约；扣除全部承诺后的余额 471.82 元。余额随实验继续变化，未追加人民币预算。

Qwen 新版中 slot 308 另出现既有 PROJECT SDK 参数兼容异常：模型调用 schema 允许的 `list_files(cursor=null)`，SDK 参数转换触发网关完整性拒绝。原候选、费用与技术未知保留，队列继续补位；这项独立接口缺陷尚未修复，不应把本次调度恢复表述为所有实验异常已经解决。

证据：[首个观察窗口](../../artifacts/software-benchmark-v083/live-monitor-r1/summary.json)、[第二观察窗口](../../artifacts/software-benchmark-v083/live-monitor-r2/summary.json)。首个窗口的 Qwen 路径仍指向已停止 v080，不能用该字段判断 v084；第二窗口已改为 v084，另有原驻留进程身份核验。
