## 比较什么

| 条件 | 实际处理 |
|---|---|
| K0 原上下文 | 保持原v117历史呈现、摘要及最新观察 |
| K1 通用选择 | 在已向该成员呈现过的历史PROJECT观察中，按任务相关性和版本选择字段卡 |
| K2 角色选择 | 同一候选池、同一预算，增加开发／复核角色与当前验证职责的排序权重 |

实际干预是历史PROJECT观察中的消息、交接、候选、复核、测试、交付和版本字段，并非任意旧工具输出或整个对话。K1/K2先移除历史槽中全部可选字段的原默认呈现，再将选中的完整字段卡集中呈现一次；未选字段不继续隐藏在原槽中造成重复。最新观察、系统说明、题目、动作、工具原件和不可选字段保持；历史摘要算法不变。所选字段保留完整内容和真实v117来源定位，不伪造不存在的`context_read`工具。这些引用用于审计，不承诺模型能无损回读任意被省略历史；原有工具及其权限保持，信息损失属于待测结果。公开候选有权访问不等于已呈现，未向当前成员呈现的材料不进入候选池。

K1与K2必须保持相同选择预算；估算Token只用于本地选择，真实请求总账以API usage为准。记录可用候选、选中项、实际payload哈希、输入输出、缓存、摘要、回读和拒绝。不得把未选中字段的理论长度当作已经节省的实际Token。CPU控制须证明角色改变能实际改变排序及最终payload；若K1/K2退化为相同处理，先修实现，不把无效处理作为正式效果试验。

K0也使用与K1/K2相同的新测试取证接线和完整框架journal留存。修复插件启动缺陷属于所有组共同的环境修订，不计为K2收益。
