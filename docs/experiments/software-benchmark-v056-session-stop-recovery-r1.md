# v056 用户服务停止事件与恢复记录

记录日期：2026-10-24。本文时间均为北京时间（UTC+8）。

## 事件及影响

14:18:27，用户级 systemd 日志记录 `Stopped target Main User Target`，随后实验调度器和 GPU 0、1、2、4、5、6 上的六个 Qwen 常驻服务统一停止。15:36 查询进度时发现，队列状态文件仍停留在 14:18，账面的六个 `running` 已不能代表实际运行状态。

停止前，200 个计划回合中已有 **156 个完成官方评分（78%）**，另有 30 个尚未启动、8 个此前保留的技术异常，以及本次受中断影响的 6 个回合。各预算档已完成评分数为：50 万 42 个、200 万 40 个、500 万 37 个、1,000 万 37 个。

本次六个回合均缺少最终 episode `result.json` 和工作进程的 `completion.json`。其中五个控制器记录连接拒绝、服务断连或非 200 响应等技术错误；另一个（`scikit-learn__scikit-learn-14894`／500 万预算）虽已记录 controller `closed`，仍未完成可信最终候选导出及官方评分，不能计为已完成评分，也不能据此判为模型正常失败。

这些记录只证明用户服务管理器及关联实验服务停止。现有证据不足以确认由谁或哪一登录会话触发退出，不作进一步归因。

## 恢复措施与实验边界

发现时，当前用户 `zhuxinrui` 的 `Linger=no`。已执行 `loginctl enable-linger zhuxinrui`，并确认 `Linger=yes`，使用户后台服务能够独立于登录会话生命周期继续运行。该设置仅针对当前用户，不调整其他用户服务。

六张原 GPU 分别创建新的 `gpu0-r2`、`gpu1-r2`、`gpu2-r2`、`gpu4-r2`、`gpu5-r2`、`gpu6-r2` 常驻身份。GPU、端口、原始模型检查点、vLLM 版本和数值设置均沿用原配置；服务启动仍检查显存容量和资源锁。旧常驻目录及退出证据保留，不覆盖已经进入的服务身份。

恢复使用原 `queue-r2` 和原冻结 binding：

```text
25ae701022d4d6a3d650df8b75a1af19050c7edc160401e90482e555148102af
```

题单、四档预算、seed、生成设置和评分规则不变。不重新执行已经进入模型的回合；中断六回合由原队列恢复逻辑转入异常集合，剩余 30 个未启动回合继续按原计划调度。历史 8 个异常仍独立保留。原进度预估因停机失效，恢复后预计时间应重新测量。

## 恢复验收边界

15:42，六个新常驻服务均已就绪，原队列已重新派发六个未启动回合。此时为 156 个已评分、6 个运行中、24 个待执行、14 个技术异常（此前 8 个加本次 6 个）；评分结果没有被中断记录覆盖。

已核实本次六个旧 worker、对应 actor/controller、外层进程及 episode cgroup/slice 均无存活进程，相关锁可取得并已立即释放。依据该证据，释放了六份 64 GiB、合计 **384 GiB 的未来磁盘预约**；这不是删除了 384 GiB 文件。旧常驻隔离、原始任务状态和实际磁盘文件保留，实际占用仍受磁盘剩余空间门槛约束。

恢复只修改服务生命周期和调度资源记录，不改变题单、预算、模型推理条件或评分器。未补写失联任务的完成文件，也未重新选择或生成其候选。相同数值配置在重新加载后仍应记录服务身份变化，不能声称已验证逐 token 一致性。

相关恢复记录位于 `artifacts/software-benchmark-v056/session-stop-recovery-r1/`。运行记录与补丁、评分证据继续保留；本次恢复不修改冻结的生成及评分源码。
