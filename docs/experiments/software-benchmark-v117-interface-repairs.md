# v117：根据通过率分析修复执行接口

本轮已完成新版实现与离线验证。重点是减少重复输入、修正工具参数的不一致、避免非法参数导致历史处理异常，并补齐已确认缺失的公开测试依赖。**尚未运行新的真实评测，因此没有新的正确率，也不能把离线输入缩减率当作整轮token节省率。**

## 修复内容

| 问题 | 新实现 | 保留的规则 |
|---|---|---|
| 每步重复加入任务说明和静态观察 | PROJECT使用同一成员、同一输入内可逆的精简投影；最新完整观察保留，旧观察仅移除与当前相同的指定静态字段 | 原SDK事件和审计记录不改；历史工具结果、错误、版本、测试与交付证据保留；不能跨成员借用信息 |
| 旧静态去重未适配当前观察结构 | 支持当前字符串contract和以摘要身份表示的root_goal；计数与真实发送共用同一投影函数 | 不按容量任意删历史，不把摘要当权威证据；模型费用仍按实际调用结算 |
| `list_files`把目录名误解为补丁ID | 新增明确的`path_prefix`目录筛选，说明`patch_id`只能引用真实固定补丁 | 未知补丁不会静默回退当前工作区；分页仍绑定查询与来源版本 |
| 两个分页工具的`cursor:null`执行不一致 | 在新版实例中统一六种分页工具，仅恢复SDK省略、原始响应明确给出的null | 其他参数仍需与原响应严格一致，不接受猜测参数或宽松解析 |
| 错误反馈不足以帮助恢复 | 为缺失路径、非唯一替换、错误cursor及无工具正文提供具体下一步；已有测试报告可省略cursor重读首页 | 错误仍拒绝；不自动执行、重试、重跑测试、提交或补充预算 |
| REF非法工具参数造成后续历史解析崩溃 | 新controller接入有原响应、工具ID和真实SDK错误来源约束的历史恢复 | 原坏参数、费用与失败保留；没有被拒绝动作执行或旧回合重采 |
| Requests2931的公开httpbin父fixture未加载 | 从本地缓存准备公开声明的依赖层，两组同一建议测试入口只在测试子进程环境使用 | 原任务文件、解释器和pytest保持；不安装到宿主，不接入隐藏测试或评分CA |
| 完成自检可能只重复成功声明 | REF／PROJECT共同提示改为核对最终diff的实际行为、issue对应的验证和当前版本证据 | 仍只有一次自检，共享原预算与时间；不自动判正确、增加强制测试或自动交付 |

路径不存在、替换不唯一和跨版本cursor本身通常是应当保留的拒绝，修复的是参数表达与恢复反馈。语义遗漏、错误测试预期、代码仅改注释却宣称完成等模型行为，不能靠接口代码保证消失；新的自检说明只是针对性的提示修订。

## 输入负担的离线测量

从原48个已调用PROJECT回合各取预定中位Agent请求，用同一冻结tokenizer与编码规则比较新旧输入，没有按成绩选择请求。

| 指标 | 原输入 | 新投影 |
|---|---:|---:|
| 48份请求编码token合计 | 3,257,496 | 1,767,239 |
| 每份请求平均 | 67,864.5 | 36,817.5 |
| 相对减少 | — | **45.75%** |

共精简433份旧观察，48份请求均可还原原始输入。最新完整状态、工具返回与错误、历史版本测试和交付字段保留；原事件没有改写。这里使用本地冻结编码器且没有计量余量，数值不同于供应商账单中的实际输入统计；它只能说明这些相同历史请求的输入负担下降，不能外推整轮成本、缓存命中率、耗时或正确率。

首个候选对真实观察形状不匹配，48份请求均未精简；这项0节省结果保留。修正实际形状后才得到上述结果。之后仅做等价的lambda→def静态检查修订，原计量源码及AST等价说明一并保存，未重复48份测量。[完整证据](../../artifacts/software-benchmark-v117/history-controls-r1/summary.json)。

## 必要验证与实际接线

- 历史投影：8项控制通过，覆盖可逆恢复、伪造／篡改拒绝、成员隔离、真实SDK计数与发送一致。
- 工具接口：5项CPU控制和1项真实SDK脚本控制通过。无工具正文被拒绝后，下一合法动作可继续；原响应、决策数、实际脚本用量保持一致。
- 非法参数历史：REF和PROJECT均用原截断参数做新的脚本化SDK控制，各3请求／3决策／843脚本token，未执行被拒绝动作，未自动重试。脚本token不是实际API消费。
- 整体执行：7项运行接线控制通过；另1项真实SDK组合控制覆盖编辑、公开测试、摘要、一次自检及最终候选／旧合法提交的区分，共7个脚本Agent响应、1个摘要，三个账层一致。
- 公开依赖：真实pytest收集验证确认父fixture注册；另2项控制验证原baseline与实际actor回执绑定，以及依赖只进入测试子进程、异常后恢复原环境。
- 离线运行包：五个实际controller／actor／公开测试入口全部加载成功，SDK仍为1.49.6；当前205个打包源文件与工作区一致，Ruff通过。该检查没有启动模型、测试命令、容器、GPU或网络。

实际入口使用新的v117 controller、受管factory、actor与打包清单。宿主构建器保留已修复的有效deadline边界，并拒绝用旧任务身份或旧协议授权启用新执行条件。公开依赖descriptor同时绑定actor配置、公开控制文件、原baseline和ready回执；原public-environment文件保持原字节。两组真实模型、context、输入输出和5M累计上限仍沿用当前非思考配置，但新增工具和提示属于新的实验条件，不能与旧分数混合。

## 尚需真实评测确认的范围

公开依赖本次准备的是Requests2931对应的明确公开版本，不能宣称所有仓库测试环境已合格。收集验证使用现有SDK Python3.12.3和pytest7.4.4，没有启动正式Python3.9容器或HTTP fixture；旧TLS证书仍保留，完整HTTP／HTTPS测试资格尚未验证。REF任意终端命令仍有原生能力；依赖对齐保证的是两组声明的同一个公开测试入口，不能把原生shell的所有使用方式都称为相同受管接口。

旧v110–v116运行源码、记录、候选、账本与分数均保持冻结。新[实现配置](../../config/v117-interface-repairs.json)明确`execution_authorized=false`，未选新题单／seed，未启动真实API、Docker、GPU或评分，也没有修改共享服务器配置。v116剩余恢复的四个额外控制容器仍是独立待确认范围，本次代码修复没有将其视为已获批准。

下一次若评估修复收益，应使用新冻结配置，按任务配对统计实际输入／输出、缓存、有效动作、代码与交付双端点；输入精简和其他接口修复的联合收益不能再拆称某个单一机制的因果效应。
