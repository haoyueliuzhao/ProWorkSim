## 修复及可解释边界

评分收尾的停止触发来自Requests-1921：实际评分函数使用私有全局命名空间，旧TLS钩子却只修改官方模块的全局变量，导致容器先删除，再读取CA末态，404被混入物理清理失败。这是部署回归。本修订把收尾钩子绑定到实际评分函数，并区分物理对象清理证据与CA／评分有效性。保留原CA、TLS校验、官方测试及候选，不通过关闭校验消除异常。

旧1921两组还出现HTTP 502，修复清理记账不能自动恢复这些评分的有效性。只有按原对象ID只读确认不存在、评分进程及转发线程均已结束、原预约身份匹配时，才另存物理协调证明并释放旧评分预约；原评分未知保持。随后确认同名旧协调服务停止、无生成／评分活动预约，才释放其遗留协调器预约。

后续两个既定真实HTTP评分任务若出现明确的“预期其他状态码、实际HTTP 502”断言，保守归为待核评分并保留原官方报告。这不证明故障纯属外部服务：候选与HTTP服务交互也可能参与其中。该有效性分类不修改测试或补丁，不追加网络请求；物理清理可信时，不因此阻塞其他任务。
