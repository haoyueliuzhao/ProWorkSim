## 1. 修订范围

新工作关系表示由`software_method_evidence_v036.py`和`software_mapper_v036.py`实现。它允许实际可见信息先于同路径恢复编辑，再将非平凡公开生产单元保留到最终受测交付；要求所有关键导入状态可解释，至少一条被可靠消费。历史冲突、后续恢复、部分单元重写和弃用分别记录。旧v035源码、评分、映射与停止决定不改。

新成员自测runner对标准unittest成功退出建立完成见证；任意exit(0)、只打印OK、零测试、失败／异常或缺见证不被抬为通过。新世界与Γ绑定runner实现和driver SHA，原v034容量和合同去重算法保持。[成员自测说明](software-member-test-completion-v036.md)区分了新反馈语义与旧自测状态。

沿用原训练root与原五root资产，新增两个schema贡献开发root、两个TextFSM确认root；开发与确认各4root×4seed，训练／开发／确认用途分离。[来源说明](software-sources-v036.md)列出合同、许可证、来源pin及正反控制。

实际学习接口沿用原参数配方、本人原token／概率、完整原始分母和v035分配绑定。P2、采后冻结和P3入口均检查新窗口／Γ／Mapper seal，旧shadow无法进入正式支持。共享B首先执行完整实际材料的概率复算与反向，所有候选、正式分支恢复同一完整common；开发未知阻断选权。

## 3. 生产解释器核对

项目默认`.venv`当前为Python3.14.6。实际模型worker沿用v035的`runs/v016-sdk/resident-venv/bin/python`，Python3.12.3、torch2.6.0+cu124、Transformers5.17.0、jsonschema4.26.0。成员sandbox固定执行`/usr/bin/python3 -I -S`，也是3.12.3，因此原成员脚本专项已在该stdlib上执行。

为核对父进程世界组织和tarfile行为，另在辅助`.train-venv`下只运行成员测试／冷归档两文件，39项通过；该环境与实际resident使用相同Python3.12.3、unittest／tarfile原文件hash及torch2.6.0。其Transformers4.57.6不替代实际resident环境，tiny CPU控制也不因此成为9B资格。早期回执将辅助环境称为production interpreter，本记录据v035实际启动命令明确区分，原回执保留。

没有模型、GPU、旧交付重验或真实冷归档。初次pytest启动缺纯Python兼容shim、在收集前退出的记录保留；补齐测试专用shim后通过，未修改生产环境包或实现。

## 4. 旧16槽影子诊断

最终影子计数为10条`local_lineage_delivery`、5条`evidenced_peer_product_delivery`、1条unmapped（旧槽15未提交）。**新正式支持贡献为0。**旧R、旧Mapper、旧10条单类支持和P3停止决定保持。

首次影子为10／4／2。检查旧槽9的拒绝原因后，发现静态绑定器漏识别函数内部明确的`from reader import statement_records`；最终文件还存在一个冗余模块级同名import，导致该有限解析器错误报告依赖变化。修复的是通用词法作用域规则，spec未放宽，并用正反作用域控制验证。随后仅重建槽9证据，其余15槽复用已读原件并核对保留单元依赖；首次影子和一次汇总脚本的Path包装错误记录保留。

这不是“必须接纳五条”或新策略产出率估计。新规则是在这些旧开发案例上修订的，故需要独立新16槽；不能用影子10:5作为新n_z或进入P3。详细关系、控制范围及反例见[方法表示说明](software-method-representation-v036.md)。

## 5. 执行与资源接线

P2使用隔离clean源码工作树和一个resident owner。支持合格后，采后冻结器绑定实际材料、完整common、RNG、支持门与全部方向；P3执行器再次交叉这些绑定。共同B完成真实消费后保存全清单条件成本，之后完整试训、正式B／G-raw／I-P及独立确认按门推进。

监督器保持原加载／episode／边界、RSS、GPU和磁盘保护。训练只增加数值调用之外的透明进度记录，每个forward及其后backward／记账段有900秒保护；没有给完整窗口、累计GPU或整个worker恢复统一时长上限。CPU控制验证参数对象、返回值和异常传播不变，结束后恢复原数值方法。

最多4个P3 worker并行。仅在worker退出0、报告完整且没有写入者后，对其开发或确认目录逐字节核对并无损冷归档；支持材料及旧历史目录不动。归档不占GPU区间，暂存副本也计原产物上限。共同B、各方向、失败候选、正式更新和确认成本分别保存，不将嵌套区间重复相加。

P3复核发现并修正了两类记录风险：冻结common／支持门引用必须重新核对并与分配起点交叉；采后准备或报告异常必须持久化原错误，不能由finally覆盖为正常终态。未据此执行任何额外生产更新。
