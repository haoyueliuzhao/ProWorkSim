## 本轮具体运行

每个状态执行KEEP／REASSIGN各2次，最多16个续跑身份，顺序完全使用此前冻结的随机配对顺序。首对是同一Astropy状态的REASSIGN和KEEP。

KEEP没有额外续跑提示。REASSIGN只加入既定的诊断责任转交指令，通过原有offer／accept和信息交接执行；没有直接修改owner、注入修复答案、自动补做复核或提交。两个条件保留OpenHands基础框架和原受管接口。

每条分支继承该前缀的已用Token、测试计数、成员历史、工作版本和剩余时钟。暂停保存与进程停顿不占任务剩余时间；实际恢复与环境准备耗时仍保留。前缀费用只计一次，统计分支成本时另列前缀加续跑的完整方案成本，不能将检查点里继承的账面用量再次计为新增API消费。

生成最多2路。首对真实分支的恢复、请求和费用完整性通过后，再放行其余预定身份；通过率不参与这道工程准入判断。若首对出现执行异常，保留已调用数据并核查，不自动重采。后续一般任务异常独立记录。金额仅用于新槽位准入，先按剩余Token最大费用预约，已开始的任务不会因其他任务消费而被现金中断。剩余金额不足以预约一个完整槽位时，未启动身份保留，不更换题目、缩减单题上限或混称正常失败。

## 公开接口暴露的问题如何处理

前缀存在一次返回多个工具调用、使用不支持的读取参数等拒绝。这些是真实条件下的接口交互成本，不应删去或算成已执行的源码操作。为了避免同时改变实验条件，本轮不临时放宽工具schema，也不为某一分支额外提示如何修正参数。最终分析将分别统计请求数、实际动作、格式拒绝、诊断、交接、回读、测试、修复和交付；不能只用总Token推断全部开销来自通信。

## 异步官方评分

生成和评分是独立普通用户队列，最多1路评分。使用固定SWE-bench 5.0.2原评分器、原任务镜像及官方测试规则；四道题做gold／empty环境控制，评分侧信息始终不进入模型。Astropy首项gold控制已返回官方resolved=true，容器已清理；此结果是环境控制，不是模型成绩。

候选必须是生成结束后锁定的001最终工作树或最后合法提交版本，补丁进行无损导出并核对固定树身份。两个端点内容相同且代码评分明确时，可以复用同树评分；没有合法提交时交付记0，不制造一个提交。不同内容使用独立评分身份，绝不复用同题的旧缓存。

评分异常只保留相应候选的技术未知，不回传给模型，不再选择补丁，不影响其他已完成候选排队。常规队列不重跑已调用模型；后续若需要新增独立模型尝试，另行记录授权范围。

本次普通用户协调服务上限8CPU／64GiB；两个actor各4CPU／16GiB；评分服务4CPU／16GiB，评分容器4CPU／16GiB。总配置上限24CPU／128GiB，无GPU。所有容器network=none、drop ALL，无宿主绑定、监听端口或共享配置修改。只按本批所有权标识清理自建对象。
