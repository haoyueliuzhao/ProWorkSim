# v223：项目状态驱动的组织需求与独立组织推理试跑

本轮参照2026年11月20日《v217–v222近期实验综合审计与下一阶段研究设计》修订。先做4题、两种方案提出方式的配对测试，最多8条续跑。问题是：**在相同的任务进度和项目图下，由工作成员自己考虑分工，还是交给独立组织会话考虑，能产生更合适、能够真正执行的安排？** 本轮不以“增加一个角色”本身为收益，也不预设独立组织会话更好。

审计前半部分写6题，预算汇总及最终执行建议改为4题；本轮采用后者。已有余额349.84986584元，沿用累计1100元的共享账本，不增加现金额度。本轮只启动v223；v224的两轮策略开发和v225的冻结确认留到本轮准入审查后。

## 1. 本次修订解决什么

此前某些保存点只因达到固定行动次数而触发，当时尚未具备实施责任调整的条件。新版取消这一替代条件：**发现可能需要调整、具备提出方案的条件、实际成员接受并执行，是三件事，分别记录。**

项目图持续记录谁在做什么、改过哪些文件、发布了哪个版本、做过哪次测试及结果是否已过时。组织需求识别器只提出需审阅的线索，不把普通测试失败自动解释为分工失配，也不自动修改负责人。

| 需要审阅的线索 | 本轮如何识别 | 不能直接得出的结论 |
| --- | --- | --- |
| 责任缺口 | 未完成工作没有在场负责人 | 不能由控制器直接替他人接任 |
| 依赖阻塞 | 实际可见的受阻操作，同时存在未满足的跨成员依赖 | 有一条依赖边不等于协作失败 |
| 负担不均 | 至少两项尚未实施的工作，一人承担多项而另一人没有负责的未完工作 | 工作项数量不等于实际难度，转交未必划算 |
| 验证缺口 | 工作没有独立复核者，或复核者与作者/负责人重合 | 常规补齐复核设置可能就够，不一定要改组织结构 |
| 集成冲突 | 当前工作区存在实际冲突记录 | 不能仅因双方修改同一文件就判冲突 |

这些是有证据的筛查规则，**不是已获独立专家确认的失配标签**。识别出的需求在没有实际编辑、随后执行的公开测试、未开始的剩余工作、至少200万逻辑剩余Token时，只记录“等待执行窗口”。同一依据重复出现不反复发起决策；条件从不可执行转为可执行时可产生新的审阅事件。真正的动作还要经过原有权限、版本、offer/accept等检查。

## 2. 两组条件怎样比较

两组从同一个真实任务中途状态分叉；此前的代码、成员私有工作区、历史、原题要求和已花费Token都保留。

| 条件 | 谁提出方案 | 可见信息 | 后续执行 |
| --- | --- | --- | --- |
| W0：工作成员自行考虑安排 | 以member_001工作身份提出方案 | 相同项目图与组织状态，另有该成员最近一次真实请求中已经看过的完整输入历史 | 原来的两名成员决定是否接受，并执行实际工具操作 |
| W1：独立组织会话考虑安排 | 独立Organizational Architect（OA）会话 | 相同项目图、组织状态、公开问题和授权代码导航，不继承成员私有对话历史 | 与W0完全相同 |

W0用保存的真实请求历史作为带来源的引用材料，进行一次有界的方案读取；它不是重新创建或伪造成员记忆，也不是复刻原SDK会话继续调用全部工具。W1换用独立组织角色说明。因此本轮测的是**工作上下文＋工作角色与独立组织上下文＋组织角色的整体差异**，不能将差值单独归因于角色名字。

两组拥有相同的候选语法、动作范围、图证据、模型与预算。至多提出两个真正不同的方案，也可以明确KEEP或DEFER。控制器采用模型顺序中的第一个通过编译和已知执行前提检查的结构方案；没有合格方案就维持原安排。这里不使用评分挑方案，也不强求转交责任。单纯补齐复核设置不当作一个结构创新。

**OA只有提案权，没有执行权。** 它不能改代码、运行测试、提交产物、改变owner，不能访问伙伴未公开的材料或官方隐藏验收。仍只有两名真实工作成员；Graph与OA是有界的辅助推理调用，不是新增自主工作成员。

## 3. Graph角色与项目图维护

基础图由真实工作事件增量更新。新修改会改变版本，旧测试证据保留为历史，不继续代表当前版本；成员声明的依赖保留为待验证解释。

每个合格公共前缀另外运行一次Graph审阅，最多8万输入＋输出Token、一次逻辑请求，输出最多8项解释。它只能引用已可见的工作和关系编号，全部新解释记为E3假设，不能提升为已验证事实或执行权限。格式/引用不合格时保留原始图并记录回退，费用照实计入。该图审阅结果同样提供给W0/W1，避免一组额外获得图推理。Graph和OA不合并：前者解释关系，后者判断是否及怎样调整安排。

续跑期间继续逐工作机会记录关系新增、失效和需求状态。本轮只主动比较第一个合格中途决策点，后续变化被动观测，不自动开展第二次组织决策。审计提出的任务内最多两次主动调整归入v225。报告会核查是否实际观察到修改/测试后的变化，以及后续产物、依赖、冲突或验证变化；没有出现不能填成已满足。

## 4. 任务、模型和成本

4题分别来自Django、SymPy、Astropy和scikit-learn：14792、23950、14182、13496。只按公开题目和固定排序选择场景，避开v217/v218/v222面板，不依据新模型成绩换题。整个SWE-bench Verified曾被项目使用，因此它们是新的本轮运行，不是从未接触过的独立确认集。

固定DeepSeek Flash非思考模式，输入上限98,304、单次输出上限32,768；生成方案单次输出最多8,192，Graph审阅最多4,096。公开测试入口、57项工作工具、候选导出和官方评分保持原协议。两组都启用相同项目关系导航；采用v222.1已验证的版本身份缓存以减少本地等待，不更改工具权限。

每个逻辑任务上限500万输入＋输出Token，包含：

> 公共前缀 + 共享Graph审阅 + 本组方案生成 + 原两成员续跑（含历史摘要）。

公共前缀最多200万；方案生成最多20万，最多两次请求（第二次只能修正格式/合法性）；Graph最多8万。续跑额度用实际已结算用量扣除，不重新发放500万。公共前缀和Graph物理付费各一次，但在两组逻辑成本中分别计入。最终同时报告实际物理总账、各组平均逻辑Token及输入/输出分项，不能把重复计入的共享成本当作实际现金支出。

8条逻辑任务的最大Token量为4,000万，按账本最坏单价预留320元，包含共享准备费用；这只是现金保障上限，不是预计消耗。旧费用不改写，已开始任务不因现金达到启动线被中断，原Token和时间边界保留。

## 5. 准入、并发与异常处理

历史回放先用v216/v217/v222三个已结束前缀检验增量重建与重复事件处理。为避免权限猜测，只取member_001自己的事件。静态图保留首个非空事件快照，事件图逐条更新。没有历史Graph Agent产物，故**零API阶段的Agent-maintained组记为未运行**，不能用确定性程序冒充模型维护；真实Graph解释由本轮付费审阅另测。回放只能说明状态重建可靠，不能提供语义准确率或在线收益证明。

必要准入包括需求与权限分离、版本失效、可见性边界、真实SDK续接、共享预算守恒和4题gold/empty评分环境控制。正式运行前冻结源码、配置、题单和审计原件。

最多8路生成、4路环境启动、2路异步评分。公共前缀或某条续跑失败不阻塞其他任务；只有三个不同任务出现同类公共基础设施故障才暂停新准入。评分技术异常可用同一锁定候选重试一次，不修改候选、不重跑模型。未取得合格调整状态单列，不算模型代码错误，不换题；已发生模型调用的身份不自动重采。

采用普通用户协调服务，最多64核等价CPU、512GiB内存，生成容器4CPU/16GiB、评分容器4CPU/16GiB；无GPU、宿主目录绑定、宿主监听或共享主机配置变更。只创建和清理本批隔离容器/卷。

## 6. 本轮要得到什么结论

按4题逐题配对，分别报告：

- 哪些组织需求有真实依据，哪些只是缺设置或信息不足；需求出现与能够执行之间隔了多久。
- 项目图新增/失效、Graph解释及回退；W0/W1是否看过完全相同的公共图。
- 候选格式合法率、结构差异、执行前提、实际接受/拒绝与后续工作。编译通过不等于已执行。
- 官方代码正确率、合法交付率、各阶段Token、时间和费用；共同前缀、Graph、方案生成的成本单独列出。
- 第二次实际状态变化是否发生，以及其后是否出现新的组织需求。

只有4个状态，结论是机制筛查，不作显著性或普遍优越性声明。OA输出更多文字/更多方案不算改进；必须结合证据、实际动作、成本和最终结果判断。没有可靠独立标注时，需求识别和图关系的precision/recall记为未知。

## 7. 后续v224/v225怎样衔接

v223完成后先逐轨迹审阅：不同方案是否有证据、是否保持所有原要求、是否能实际执行；修复可复现系统问题并单列版本，然后再决定进入后两阶段。

v224拟用另外4个任务，分两窗、每窗2题，比较KEEP及最多两个结构方案，最多12条完整续跑。每窗各候选完成并正式评分后才更新跨任务选择器。输入为规范化项目—组织匹配特征与目标组织结构，不记忆任务编号。C比较完整后继任务效用与当时策略的加权平均；映射完整度、图边数及调整次数都不是奖励。N同时保留映射模式和组织结构的欠覆盖，作用范围仅限本状态合法候选。

正值变换遵循审计：C使用带温度sigmoid，N使用带温度的1−exp(−N/T)，两者加ε边界后相乘；再与上一策略和固定参考分布共同更新，保留探索混合。具体温度、权重、特征、参考支持及效用系数必须在v224调用前冻结，本轮不借机调参。

v225另用4个新状态、最多12条候选续跑，对初始/一次更新/两次更新策略报告冻结的加权效用及实际选择。每条任务最多两个由新项目证据触发的中途决策点；不能将第二次适配或跨任务学习误记成本轮已完成。确认结果不反向更新本轮策略。后两阶段按实际余额及完整配对可承受性另行准入，不因原审计总均费估算而一次占用全部32条。

协议与新代码均独立版本保存，旧v217–v222数据和汇报不改写。本文件是设计及启动依据，结果以运行目录和正式评分为准。
