# v054 PROJECT 受管文件接口修复

日期：2026-10-20。用户在三组方案修订过程中明确要求并行修复文件数量／大小限制及新增、删除、重命名能力。这里记录修复后的新 PROJECT 接口，不把它当作旧 v052 接口完全不变的复测，也不把这些工程变化计为训练或算法收益。

本次没有启动模型、GPU、真实 Verified 任务、官方评分或训练。旧源码快照与历史结果不改写；新实现位于独立的 v054 模块。

## 实际修复

| 问题 | 新行为 | 仍保留的边界 |
| --- | --- | --- |
| 初态最多200文件／2MB | 完整摄取可信、预先隔离的公开工作树；文件数默认不限，不按后缀或答案文件清单筛选 | 总原始内容默认1GiB、单文件256MiB为可配置部署熔断；超限整体拒绝，绝不截断 |
| 大目录／长行进入观察导致过大输入 | 目录和文本通过版本绑定 cursor 分页；观察只给数量、小页和导航 | 文件页最多4096字符／180行；目录最多40项并有字符界限；原问题也可按原文分页读取 |
| 无新增文件 | `create_file(path,text)` 创建 UTF-8 文件及隐含父目录 | 不覆盖已有路径，不创建特殊文件，不绕开只读前缀 |
| 无删除文件 | `delete_file(path)` 删除当前实际条目，旧版本仍可审计 | 单文件／链接操作，不提供递归目录删除或宿主删除 |
| 无重命名／移动 | `rename_file(path,new_path)` 支持跨目录移动并保留内容、类型和执行位 | 目标必须不存在；不覆盖只读条目、不穿过文件／链接祖先，不改写链接目标来隐藏错误 |
| 编辑后误用旧测试／固定补丁 | 每次有效编辑生成真实新版本；提交仍要求该当前版本的测试执行和固定补丁 | 公开测试不必全绿才允许固定交付；不自动测试、固定、提交或增加机会 |
| 新文件／删除／配置／二进制在导出中丢失 | 固定补丁按 baseline/current 全部路径并集计算，导出标准 Git binary patch 并验证精确 tree 往返 | 不使用旧三仓库生产域过滤，不静默恢复合法候选配置；违反只读策略则拒绝 |
| 最后工作树被最后提交覆盖，或无提交没有代码端点 | 同一次闭合分别锁定 terminal code 与最后合法 delivery；后者可以为空 | 不择优，不回填旧实验，不评分后重选，不把当前树替代较早合法提交 |

`files` 与 `entry_metadata` 同时版本化。初始二进制以规范 base64 保存，符号链接保存目标，Git 执行位保存为100644／100755／120000。正文编辑工具仍只处理 UTF-8 常规文件；二进制／链接可被合法移动或删除并保真导出，但本次没有新增二进制编辑、链接创建或 chmod 工具。

新部署上限不是对1GiB工作树吞吐或内存占用的性能认证。当前实现仍在宿主以完整版本化 JSON 保存树；分页限制模型可见输出，不意味着宿主已经改成流式存储。有效但超出资源或可表达域的仓库应记录部署／接口覆盖限制，不计成模型不会修复。

## 实际连接路径

1. [repository_sources_v054.py](../../src/proworksim/repository_sources_v054.py) 捕获完整公开工作树、绑定来源 manifest 和只读／容量策略，并验证公开测试回执对应完整候选树。隐藏评分材料不进入该 provider。
2. [software_benchmark_world_v054.py](../../src/proworksim/software_benchmark_world_v054.py) 注册新工具，沿用真实单成员 World、不可变版本、测试额度及同版本交付约束。大目录、文件、搜索、变化描述和测试导航有界，完整可见内容可继续读取。
3. [software_benchmark_managed_v054.py](../../src/proworksim/software_benchmark_managed_v054.py) 将新 World／Port 接到真实 `HarnessPort` 及既有单成员 SDK runtime。它只装配，不创建模型 owner、不推进模型、不授予评测准入；调度外执行仍被拒绝。
4. [software_benchmark_candidates_v054.py](../../src/proworksim/software_benchmark_candidates_v054.py) 在同一次 World 锁内选定最后工作树和最后合法提交，分别锁定内容与来源，再作标准 Git 补丁导出。该模块不调用官方 grader。

创建／删除／重命名都通过受管动作进入同一权限、版本与事件链，没有另接不受管 bash。公开测试 runner 必须由可信宿主明确绑定，只处理 actor 允许的公开树并返回完整树身份；本次合成回调不是已经完成的 Verified Docker 测试适配器。

组合候选入口为 `lock_episode_candidates(prepared, run_root=...)`，读取为 `read_episode_candidates(lock_reference)`。旧的只锁最后提交入口不应被新三组主代码端点误用。官方评价、REF/MATCH 新数值接缝和正式1500槽运行器仍属于后续准备，不由本次文件修复自动完成。

## 必要 CPU 控制

下表按不同控制计数；后续窄改动只重跑受影响项，不把重复执行计为额外覆盖。

| 层 | 控制数 | 实际范围 |
| --- | ---: | --- |
| 来源 provider | 6 | 超过200条、3MB单文件；完整类型／模式、只读策略、可配置整树拒绝、身份与篡改、链接链、公开回执绑定 |
| 受管 World | 4 | 真实注册与版本变化；旧测试／固定补丁失效；权限／冲突拒绝不改源码；211条目录与400KB长行、大文件写及 stale cursor；结构变更 patch 整合 |
| 候选导出 | 5 | 完整 Git binary patch 往返；空树／仅模式变化；真实 World 合法提交、提交后编辑双版本、无提交；固定 patch 或测试身份被篡改时拒绝 |
| HarnessPort／运行时组合 | 2 | 207条公开树经真实网关新增、删除、重命名、大文件修改并导出；单成员运行时真实绑定新工具且装配不采样、调度外执行拒绝 |
| 合计 | **17** | 均为合成 CPU 控制；不是500题能力或环境测试 |

17项控制各自通过，相关新 Python 文件限定 Ruff 通过。目录导航字符界限修订后只复核受影响的分页项和组合网关项；完整树候选绑定的窄控制也只复核受影响项，没有重跑旧实验或全项目测试。

纯 Git 控制使用隔离临时 bare 仓库，禁系统／全局配置、hooks、外部 diff、用户 filter 和换行转换，不操作项目 `.git`。二进制、CRLF、Unicode文件名、执行位、链接目标及空文件均保留，标准补丁应用后 tree ID 精确相同。

默认真实 OpenHands SDK 构造控制于北京时间21:56:59—21:57:03通过，见[原始r3凭据](software-benchmark-v054-sdk-construction-r3.json)。使用既有Python3.12.3与SDK1.49.6，未替换worker工厂，实际构造官方 `Agent`、`LocalConversation` 和项目单成员worker；33项受管工具注册成功，创建／删除／重命名必填参数及5项分页工具的cursor可见。World未改变，模型、工具、测试、评分调用均为0，权重／GPU设备打开与网络尝试均为0，128次attempt及500000 token余额完整。该检查只证明真实SDK装配，不是推理或500题环境资格。

前两次检查保留原始失败，不计入17项合成控制，也不隐去： [r1](software-benchmark-v054-sdk-construction-r1.json) 在导入SDK前将CPU隔离环境内普通空占位文件误判为GPU字符设备；改为核对实际文件类型后，[r2](software-benchmark-v054-sdk-construction-r2.json) 发现LiteLLM默认尝试刷新远端模型价格表，被网络守卫在DNS调用处阻止，记录1次网络尝试、0次连接和0次模型调用。r3只在该进程设置 `LITELLM_LOCAL_MODEL_COST_MAP=True`，使用已安装的本地价格表，未改SDK版本或项目源码。后续运行配置应显式保留该环境变量；账本仍以实际token为准，不把价格表当作实际费用凭据。
