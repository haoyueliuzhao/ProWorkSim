# v0.37：保持原加权反传数值路径的缓存优化

2026-10-07。触发请求：解释 v0.36 的长耗时并尝试优化。本文记录执行方式修订；不改变 v0.36 的支持窗口、方法定义、采后配置清单、开发集或独立确认集。

## 问题与实际证据

v0.36 P2 已闭合 16 条轨迹，14 条完整成功，其中 13 条可映射：本地产物交付 9 条、有证据的同伴产物交付 4 条。支持门已通过。冻结清单为 27 次试训（共享 B、24 个 G-raw 方向候选、2 个 I-P 方向候选）、432 条开发评估、3 次正式更新、48 条独立确认。不得根据运行成本或已见结果减少清单。

每次更新从相同完整 common 恢复 actor、critic、两套 AdamW、计数和 RNG，使用同一 16 槽学习材料。实际材料含 682 条决策、161,827 个原输出目标。当前学习器先对每条决策重算行为概率，再逐条重算并反传，最后才各执行一次 actor/critic optimizer step。

原功能式 Qwen 学习器保留所有前缀与解码状态的梯度依赖：32 层中逐输出 token 扫描，内外 checkpoint 重算，逐目标计算 FP32 输出头。本窗单次正向约涉及 515.7 万次解码层转换；这只是由实际 token 数与层数得到的操作次数，不是 CUDA profiler 测出的时间占比。主干已经是 BF16，LoRA 和输出头为 FP32，不存在通过简单“开启半精度”获得无语义变化加速的空间。

截至 2026-10-07 15:18，共同 B 反传完成 182/682；08:46 开始反传，已观测完整相邻决策周期均值约 129 秒。当前代码的串行重复反传，加上各候选的开发/确认评估，使整轮单卡外推达到数十天。该外推不是工期保证。

资源排查还发现 GPU 5 自 10:20 开始有其他项目任务。15:25 前本实验自身显存观测峰值 44,318 MiB；同时其他任务可占约 18,544 MiB。短采样能确认同卡竞争，但不同时间段决策长度不同，不能据两段平均时长推断争用带来某个减速倍数。CPU 空闲约 91%–93%，可用内存约 614 GiB；没有证据支持仅增加 CPU 线程即可解决主要耗时。

## 采用与拒绝的方案

**采用精确的 `(原决策, 实际 loss 权重)` 缓存。** 缓存缺失时仍调用原 `functional_qwen_v022` 学习路径，按原先顺序计算 PPO loss、除原 denominator、在 loss 端乘实际权重，再执行原 backward。叶梯度 hook 仅复制本次梯度，隐式返回 `None`，不改原生梯度累积。缓存命中时直接读取这个相同权重曾实际反传得到的 FP32 叶梯度，在原设备按原决策顺序累积，不再乘权，不按类别重排或聚合。

每个真实缓存未命中的 backward 还验证：反传前累计梯度加本次 hook 观察到的叶梯度，与原生 `AccumulateGrad` 的结果逐位相同。验证失败不会发布该缓存项，也不会继续优化器更新。

**拒绝把单位权重叶梯度乘新权重作为生产实现。** 虽然在实数微积分下目标对外部权重线性，BF16 反传中的量化次序不同。CPU tiny Qwen 控制测得该捷径的加权梯度相对 L2 差异约 0.008469（0.847%），未通过预设严格数值门。因此该实现只保留为明确标注“不准入生产”的比较诊断，没有放宽数值阈值后采用。

不安装或切换 FLA、causal-conv1d、FlashAttention 等内核，不截短上下文或输出目标，不减少训练行，不改变 dtype、学习率、奖励、优势、梯度裁剪、原分母或 optimizer。保留原功能式前缀图和 checkpoint 路径。

## 缓存绑定与执行边界

缓存绑定包含：

- 完整初始 actor/critic/两优化器/RNG/计数/窗口/profile 状态摘要；
- 原 entries、prepared rows、recipe、declaration、学习输入证据；
- 原 common、材料与源码引用，以及新执行器自己的干净提交身份；
- 每行完整摘要、call ID、实际 advantage；
- 权重的精确 `float.hex()` 表示，不作小数舍入或近似合并；
- trainable 参数名称、形状和 dtype。

每项缓存保留 tensor 原件、字节数、SHA256、元数据和 receipt seal。拒绝覆盖、残缺条目、参数结构变化或摘要不一致。并发进程用相同键的文件锁协调；拿到锁后重新检查，禁止两个进程同时计算和发布同一个键。等待缓存锁不计为实际模型反传，但真实占卡时间仍计入成本。

共同的无梯度行为概率核验也可缓存，绑定同一完整状态、原始行和源码。首次执行与后续复用分别计数。每个候选仍用原式逐行计算 critic loss/gradient；共同概率核验与每个缓存未命中的实际反传均要求 RNG 不发生消耗。所有候选必须从相同完整 common 恢复。

缓存的是**裁剪前梯度贡献**。各候选完成全窗口累积后，分别执行原全局 actor/critic norm clipping，再分别执行各自从 common 恢复的 AdamW step。不能插值已更新参数，不能重用其他候选的 optimizer 末态，也不能跳过每方法规定的正式更新。更新后概率诊断、开发评估、独立确认均继续实际运行。

复用已有梯度不再伪报一次新 backward。报告分别列出实际新反传数、缓存命中数、完整窗口已应用贡献数、原始行为前向数、行为缓存命中数以及真实 optimizer step 数。

## 计算量估算及限制

对已冻结 27 次试训的权重按原行和精确浮点值去重：

| 项目 | 原执行 | 精确缓存执行 |
|---|---:|---:|
| 试训原行应用次数 | 18,414 | 18,414 |
| 需新执行的加权反传键 | 18,414 | 4,338 |
| 反传调用削减 | — | 76.4% |
| 每个原决策仍被哪些候选使用 | 全部原候选 | 全部原候选 |

这相当于试训反传调用量约 4.24 倍的理论改善，**不是已经测得的端到端加速**。各行长度不同，首次缓存写入、并发等待、候选评估和归档仍有开销。

当前可调 member_a 决策有 227 行。正式 G-raw/I-P 的权重尚未由开发反馈确定，不能预填其缓存命中数；两者最多增加 454 个新加权行键。若从 B 开始建立缓存，正式 B 的权重均为 1，可复用已建立的相同键。全 30 次更新的唯一键数因此在 4,338–4,792 之间。原始叶梯度每项 1,114,112 个 FP32 元素，27 试训缓存纯 tensor 载荷约 19.33 GB，另有元数据和文件容器开销。

**本次实际接管另计**：导入的原 B 不提供缓存。剩余 26 试训自己需要 4,300 个唯一键，其中只覆盖 644 个 B 单位权重键；正式 B 还需 38 次新反传。再加正式 G-raw/I-P 最多 454 个新键，新执行器仍需 4,338–4,792 次实际加权反传；原 B 的 682 次反传属于旧执行成本，不能从上述计算量中再扣。只有“B 原本就以缓存实现运行”的假设下，B 后新增才是 3,656，不能把这个较小数字用于此次交接。

这份估算不删除 480 条开发与独立确认轨迹，也不将规则、CPU 小模型控制、9B 实际模型结果或训练收益混为一谈。新的实际成本应在候选缓存命中运行后重估，不能简单把此前整轮工期除以 4.24。

## 保留正在执行的共同 B

当前原 B 已运行近 10 小时。没有逐行叶梯度原件，无法从最终聚合梯度无损补出缓存；不能把已有工作伪装成已产生缓存。

因此先保留原 B 完整训练、16 条开发评估与无损归档。新接管进程在此期间只读等待。只有原 B 的 worker 成功退出、所有原概率与更新门通过、开发评估全部已知并完成归档后，才可以进入交接。

交接会核对旧 supervisor 的进程命令、工作目录、源码、PID 和进程开始标识，然后向**本实验的旧 supervisor**发出正常结束信号，由其原有清理逻辑停止可能刚刚启动的后续 worker。其他项目进程不接收信号。旧 finisher 写完原状态与报告后，新执行器在独立目录导入原 B 的只读引用，继续其余 26 次试训和 3 次正式更新。交接期间如果有原后续候选已经开始，其真实耗时和中断状态仍保留在旧记录中。

导入 B 的 optimizer step、开发轨迹和 GPU 时间归于原 v0.36，不计作新执行器再次完成。新执行器不重采 P2、不重跑已闭合的 B，也不从 B 的更新后参数继续训练其他候选。所有后续候选依旧从原 common 出发。由于原 B 没有逐行缓存，首次新候选需要建立缓存，这是预计成本中的真实工作。

原 B 失败、未知评估、归档失败或来源不一致时，交接停止；不自动重试或用零分填未知。

## 新执行器资源声明

新 v0.37 执行器独立声明资源边界，不修改已经冻结的 v0.36 规则：最多 4 个模型实例，每卡至多本实验 1 个 worker，优先空卡。稳定可用显存至少 56 GiB 时允许共享卡；本 worker 显存上限 56 GiB，卡上实时剩余显存至少 6 GiB。只停止自己的 worker，不抢占或终止其他项目任务。

此容量参考已观测峰值，不能证明所有尚未运行的长行都必然可容；触发保护时保存真实中断。继承单训练步骤 900 秒、host RSS、产物体积和磁盘余量保护。缓存锁等待单独标注；不设置新的整体实验 wall-clock 截止或通过放宽资源限制制造完成结果。

## 核验与结果归属

必要机制核验包括：缓存文件完整性与权重精确绑定；CPU 官方 tiny Qwen 的 FP32/BF16 两种配置；完整 updater 与原实现的冷缓存、热缓存、部分命中对照；原始非空 Adam 状态和 RNG 的同 common 恢复；调度、来源与接管边界。CUDA 小模型资格和 9B 真正运行分别记录，前者不替代后者。

已经完成的 CPU tiny Qwen exact-weight 对照中，梯度、裁剪后梯度、参数、Adam 状态及 critic 均逐位相同。完整 updater CPU 集成中：冷 B 32 次真实反传，热 B 0 次；加权候选 2 次反传/30 次命中，重复加权候选 0 次反传/32 次命中，完整状态与原实现逐位相同。它们只证明这些有限机制控制通过，不能证明 9B 训练收益或保证未来硬件时长。

CUDA tiny 探针同时包含原正式 mixed BF16 配置和额外全 FP32 配置。原正式 mixed BF16 + FP32 head/LoRA + `efficient_only` 路径的 21 项比较全部逐位相同；额外全 FP32 CUDA 配置出现约 2.33e-9–4.66e-9 的梯度绝对差异，未通过严格逐位门。因此**包含两个配置的整份 CUDA 探针报告 `passed=false`**，失败原样保留；不能称所有 CUDA 配置均通过。新执行器只使用早已冻结的原 mixed BF16 正式配置，没有根据这次结果切换 profile、放宽阈值或重试失败的全 FP32 配置。首次 CUDA 探针还遇到初始化顺序错误，发生在模型构造/前向前，单独留档后仅修正设备初始化顺序；不把该次失败计作模型数值结果。

实际小 CUDA 探针耗时约 28.86 秒，最高 allocated 18,733,568 字节、reserved 23,068,672 字节，未加载 9B，未采集真实任务，未更新真实模型。GPU 5 当时共享使用，探针计时不用于估计 9B 加速倍数。后续真实缓存缺失还必须逐次通过本机原生梯度累积一致性检查；这些有限控制不是对所有硬件与配置的逐位确定性承诺。
