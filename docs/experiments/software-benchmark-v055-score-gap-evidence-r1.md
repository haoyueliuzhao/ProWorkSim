# 九条件分差的执行机制证据：重点是 MATCH → PROJECT

这批结果说明，进入 ProWorkSim 后改变了模型定位代码、取得反馈、修改和交付的整个过程。现有证据可以定位明显的操作负担、配置与接口相互作用，以及明确的实现不一致；**不能把一个总分差解释为单个 API 的因果效应，也不能把 PROJECT 的全部下降解释为模型能力不足。** PROJECT 同时保留权限、版本、测试与提交证据，这些规则有其用途；其中的设计限制与实际实现缺陷需要分开。

本文不重复主报告的每组 500 题分数。原主库存正常闭合的 **4,324 个回合**全部纳入摘要提取：Qwen 1,485，DeepSeek 2,839，审计错误 0。原 15／161 个生成未知复用既有集中审计；后续六个零模型槽的首次恢复、评分修订与完整分母由统一结果报告另行关联。因此下文以“正常闭合 N”为分母的频数是机制描述，**不是完整 500 题的通过率，也不是筛出正常闭合子集重新计算主分**。

未运行模型、测试或评分；未改冻结源码或原状态。读取对象是 controller、managed-boundary、condenser 响应形状及既有异常摘要，没有扫描 rootfs、重新解压归档或扫描大的 experience 流。仅导出元数据，不导出模型推理正文。新增追查字段分别保存独立小文件，原首轮摘要不回写。

## 1. 项目环境具体改变了什么

| 环节 | MATCH 原生接口 | PROJECT 实际规则 | 对本批结果的可支持解释 |
| --- | --- | --- | --- |
| 定位与浏览 | 原生 Terminal/FileEditor，可在允许代码树内组合命令、跨文件搜索 | 无 shell；`search_file` 是已知单个 UTF-8 文件内的字面搜索；先用目录与文件工具定位 | 缺少跨文件搜索入口会把定位拆成多次调用；下文 Qwen 的大量目录翻页和路径拒绝是直接过程证据 |
| 读取与分页 | 原生工具输出及 SDK 历史管理 | 目录至多 40 条；源码每页至多 4,096 字符／180 行；搜索至多 20 命中；cursor 绑定操作与源版本，编辑后旧 cursor 失效 | 分页保留可追溯内容，但翻页、重新定位和重取 cursor 都消耗真实机会，不是免费读取 |
| 修改 | 原生编辑工具与合法 Terminal 操作 | 单个受管动作；UTF-8 replace/write/create/delete/rename；replace 要求唯一精确匹配；二进制／链接内容不作为文本编辑 | 可以跨多次动作完成多文件修改，但一次调用不是任意组合脚本；“128 次调用”不能视为两边相同工作量 |
| 运行与反馈 | 可自行选择合法公开测试、最小复现和脚本 | `run_tests` 只执行事前配置的公开测试入口；无任意命令／自选复现执行入口；同题至多 32 次，结果正文按既有 v042 协议分页 | 测试选择空间与反馈取得成本不同；没有把隐藏官方验收暴露给模型 |
| 历史 | 原生 SDK condenser，压缩与 Agent 共用模型预算 | Γ1、静态去重、已呈现反馈生命周期、原记录 recall；没有原生 condenser | 两者信息保留方式不同。PROJECT 避开了本批 native thinking 空摘要问题，但仍有保护输入/context 门和 recall 操作负担 |
| 单步输出 | 原生 SDK 消费自己的 tool-call 协议 | 每个机会恰好一个受管 tool call；无工具的文字不隐式等于 done，需显式 `staff_done` | 有些模型文字结束或多动作输出会成为可恢复格式反馈；拒绝仍扣决定与已有调用成本 |
| 交付 | 事前边界锁唯一最终补丁 | 同版本公开测试 → `fix_patch` → `submit_integration`；测试可以失败，但执行版本和固定提交必须一致；`staff_done` 不创建提交 | 最终代码正确与合法交付是不同端点，必须按最终版本证据拆分 |

以上规则可直接在 `src/proworksim/software_benchmark_world_v054.py` 的工具声明、`member_instruction`、分页实现和 `run_tests` 回调中核对。v055 公共测试宿主沿用该语义，实际命令来自固定 `public_test_entry.argv`。旧通用账本中遗留的“可选 member script”文字不代表本批 benchmark 提供了自选脚本入口，不能据它误述实际能力。

## 2. Qwen 的主要环境负担：定位动作占了多数

正常闭合的 496 个 Qwen PROJECT 回合共记录 **12,977 个已进入世界的动作**，其中：

| 操作／事件 | 实际次数 | 解释边界 |
| --- | ---: | --- |
| `list_files` | 7,703，动作数的 **59.36%** | 其中 7,626 次携带 cursor；这是目录分页成本，不能直接换算为 token 份额或反事实分数损失 |
| `search_file` | 1,955 | 单文件搜索需要先给出有效路径 |
| 其中显式 `ok=false` | 1,339 | **1,328 次路径不存在、11 次路径不规范**；不是正常的“未找到文本” |
| `read_file` | 1,534 | 304 个回合实际调用；不是所有目录遍历都转化成文件读取 |
| 修改：replace/write/create/delete | 259 | 调用成功也不等于修复正确；replace 有 40 次拒绝 |
| `run_tests` | 191 | 163 个回合至少调用一次 |
| `read_test_result` | 172 | 65 个回合调用；额外分页有实际动作成本 |

`search_file` 无命中时正常返回 `matches=[]`、`total_matches=0`；上述 1,339 次都有明确异常消息，不能把它们说成普通无命中，也不能全部说成执行器故障。不存在的路径通常首先是模型定位／参数选择结果，而“必须先知道单文件路径、无法直接跨文件 grep”是项目接口给出的工作条件。**大量分页、无效路径和少量实际修改共同支持：Qwen 在这个受管导航流程里消耗了许多机会。** 现有记录不能证明增加一个跨文件搜索工具会恢复多少分。

同一 PROJECT 接口下，DeepSeek 非思考正常闭合的 464 题只调用 `list_files` 116 次，`read_file` 4,843 次、`search_file` 2,788 次、`replace_file` 1,017 次；思考 472 题对应 138、3,628、2,239、474 次。这说明接口负担与模型使用方式有显著相互作用，不能把 Qwen 的导航分布当成所有模型必然经历的固定代价。

Qwen 另有 303 次公开参数 schema 拒绝，269 次 `minLength` 中 **258 次是空 cursor、8 次 text、3 次 patch_id**；另 33 次超出 `max_lines` 最大值。空 cursor 应省略，不能以空字符串替代；这属于公开 schema 下的参数拒绝，不是证据显示的执行器崩溃。可改进说明／提示清晰度，但不能把这 258 次自动登记成项目系统故障。原小型拒绝记录没有工具名称，本文不从 cursor 字段反推各工具频数。

## 3. 发现一个明确实现缺陷：diff schema 与执行器不一致

这部分不能归为“模型违反规则”。实际发送给 DeepSeek 的 `diff_workspace` schema 仍公开 `offset`、`max_chars`、`source_reference`，又加了 `cursor`；当前 v054 `_action_diff_workspace(self, actor, project_id, cursor=None)` 却只接受 cursor。实际正式请求与执行器签名均已保存小证据，没有通过新测试制造样例。

原正常闭合回合中，`diff_workspace` 因这些**已公开参数**收到 `unexpected keyword argument`：

| 条件 | diff 总调用 | 参数／执行器不一致拒绝 |
| --- | ---: | ---: |
| Qwen PROJECT | 3 | 3 |
| DeepSeek PROJECT 非思考 | 199 | 103（max_chars 79、offset 20、source_reference 4） |
| DeepSeek PROJECT 思考 | 384 | 260（211、37、12） |

这是可以明确定位的接口实现不一致，影响了模型检查已有修改的机会。它是后续修订的优先项，但本轮只读分析，不热改冻结工具、不重跑任务，也不估算“修好后分数必涨多少”。证据为 `diff-schema-executor-mismatch.json` 与 `project-operation-costs.json`。

## 4. 思考模式下，输出上限与两套历史／动作协议相互作用

MATCH／PROJECT 每次输出上限 2,048，**思考 token 包含在其中**。REF 上限 32,768。应区分三种不同事情：完整但没有修好代码；输出不完整而产生可恢复格式反馈；执行完整性问题导致技术未知。

### 原生 MATCH-thinking 的历史压缩

原正常闭合 434 个 MATCH-thinking 回合中，405 个触发 condenser；共 2,867 次压缩，其中 **484 次 content 为空、875 次 finish_reason=length**，236 个回合至少遇到一次空摘要。非思考 MATCH 的 479 个正常闭合中，406 个触发压缩，共 1,347 次，空摘要和 length 均为 0。两个 REF 条件在这批正常闭合记录中的 condenser 调用为 0。

按固定队列顺序选取的首个空摘要见证，响应报告完整输出 2,048、reasoning 2,048、finish=length、content 为空。这直接证明“有一次真实压缩调用消耗了预算却没有返回摘要正文”，不是猜测，也没有输出该思考正文。它不证明每次压缩都丢掉全部任务信息；更不能根据这个样例推定所有失败由压缩造成。

正常闭合之外，MATCH-thinking 原 66 个生成技术未知中：37 个 tool arguments JSON 解析异常，15 个 tool-call/result 配对问题，10 个 reasoning 历史／来源约束失败。37 个 JSON 异常中 36 个最后响应 finish=length，最后响应合计 73,812 输出 token，其中 68,456 为 reasoning。**短输出、thinking 与原生工具／历史协议之间存在明确的失败路径证据**；不能把全部 JSON 截断都归为系统 bug，也不能认为只增加输出上限就一定修好题。

### PROJECT-thinking 的可恢复格式负担

PROJECT 不走原生 condenser，因而避开上述具体空摘要路径；但 472 个正常闭合回合里有 458 个出现其他格式拒绝，共 **4,037 次**：3,359 次“需要完整未截断 choice”，676 次不满足“恰好一个 tool call／无工具文字不隐式 done”，2 次 JSON。全部能关联到原 call 的 charge；其中 3,343 次实际输出为 2,048。拒绝调用合计输出 7,326,018 token，其中 reasoning 7,237,370（98.79%）。

非思考 PROJECT 的 318 次同类拒绝中，315 次属于单 tool／no-tool 结束规则，只有 2 次完整 choice 拒绝、1 次 JSON。该区别支持“thinking 的输出形状与 2K 限额增加了动作闭合负担”，不是直接把该回合判为代码失败；这些回合仍可能继续、提交并通过官方评分。

**上述可恢复格式反馈与 54 个 PROJECT SDK 单机会第二次模型决定的 fatal integrity 事件不同。** 后者在原异常审计中明确为技术未知（非思考 31、思考 23），没有可信锁定候选，不能记成普通修复失败或伪装成一次免费重试。前者没有取消回合，只扣既有成本并反馈；二者不合并计数。

## 5. 预算、公开测试与结束方式：哪些限制实际触发了

500,000 是输入加输出的上限；每次还须有能力预约完整下一次输入与最大输出。它不是“有 128 次有效工作机会”的保证。condenser 也花同一预算；PROJECT 单动作与较长受管观察同样产生真实输入成本。

| 原正常闭合集合 | 总数 | 主要正常边界 |
| --- | ---: | --- |
| Qwen REF | 493 | 469 下一次完整 token 预约不足；24 SDK 自然返回 |
| Qwen MATCH | 496 | 469 token 预约不足；20自然返回；7 同卡排队期限 |
| Qwen PROJECT | 496 | 351 model_budget（335 总 token 预约、16 context）；109成员结束／无可达事件；36同卡排队期限 |
| DeepSeek MATCH 非思考 | 479 | 258题内 token 预约；217自然返回；2context；2历史全局预派发边界标签 |
| DeepSeek PROJECT 非思考 | 464 | 168 model_budget（至少156总 token预约、9context）；295成员结束；1软期限 |
| DeepSeek MATCH 思考 | 434 | 357题内 token 预约；72自然返回；其余5个其他边界 |
| DeepSeek PROJECT 思考 | 472 | 282 model_budget（至少242总 token预约、35context）；190成员结束 |

PROJECT 边界类型中有少量早期记录没有更细 limits 标签，因此表内细分不强行凑齐总数。`SDK 自然返回`／成员结束不是官方 resolved，正常 token/context 截止也不是技术未知。少数“global_cny”历史标签不能直接推定人民币 2,000 元总预算实际耗尽；总账与运行修订须另核。

Qwen REF→MATCH 还同时改变 thinking、采样、上下文、输出和推理执行条件，不能说是单独接口损失。两者正常闭合中几乎都大量撞到 token 预约门，MATCH 反而有更多 Agent 调用（中位数40，REF24），且 491/496 触发 condenser。仅凭“调用更多”不能声称获得更多有效能力；仅凭“2K 较小”也不能解释全部下降：Qwen MATCH 正常记录中 Agent 输出恰达2K仅23次，PROJECT仅18次。相较 DeepSeek thinking，其突出可见负担更接近历史、导航、受管输入与动作组织。

**32 次公开测试上限没有在这批正常 PROJECT 回合里被用满。** Qwen／DeepSeek非思考／DeepSeek思考的实际公开测试次数最大值分别为4／5／2，中位数0／1／1，至少测试一次的回合分别163/496、392/464、289/472。因而不能把当前分差主要归为“32次测试配额太小”。真正的设计差异是测试入口固定、不能自由运行最小复现，以及结果分页需要额外读取。原生的 `public_test_calls=0` 只是没有经过受管 callback，不表示原生没有通过 Terminal 测试。

## 6. 代码正确与项目认可交付：同版本拆分是关键

复用独立 [PROJECT版本分析](../../artifacts/software-benchmark-v055/final-result-analysis-r1/project-delivery.json)，不再读取补丁或 bundle：

| PROJECT 条件 | code resolved | 最终同树且同source-version有合法提交 | code通过但无任何合法提交 | code通过但最后合法提交为不同树 |
| --- | ---: | ---: | ---: | ---: |
| Qwen | 65 | 48 | 17 | 0 |
| DeepSeek 非思考 | 210 | 172 | 37 | 1 |
| DeepSeek 思考 | 237 | 185 | 52 | 0 |

三组同树但不同 source-version 均为0。DeepSeek非思考唯一异树题为 sympy 21847：最终工作树v5与最后合法提交v3都通过官方评分，合法 delivery 因而是173，而不是172。该组“code成功却无最终同版提交证据”为38，code减delivery的均值对应计数差却是37；**二者不是同一个流程损失指标**。

这支持一个明确工程判断：项目闭合流程确实使一部分正确最终代码没有成为该版本的合法交付。它不说明那些任务没有形成正确代码，也不说明所有无提交者都是系统故障；可能包含模型主动结束、耗尽预算前未完成测试／固定／提交，以及保留了较早合法版本。

## 7. 为什么 PROJECT 有时反而更高

同题配对辅助诊断（仅两边结果均确定的 K 题）为：Qwen PROJECT独胜42／MATCH独胜37，K=485；DeepSeek非思考33／75，K=434；DeepSeek思考55／25，K=405。这些不是替代完整500题的主结果。

PROJECT 并非对每个模型、模式都单向扣分。受管操作、明确版本、固定测试和Γ1可能减少某些无效探索；PROJECT-thinking 还确实没有原生 condenser 空摘要路径。因此“它避免部分 MATCH-thinking 的历史问题，同时受到自身2K动作格式及提交限制”与观测相容。**尚不能把净优势归因于Γ1、把非思考下降单独归因于无shell，或把一项规则视为唯一原因。** 工具、system说明、观察、历史和生命周期同时改变，需要独立单因素新协议才可分解。

主报告另有输入缓存命中率与费用差异；这属于项目环境的实际成本结果，但不能仅凭条件均值把缓存命中下降归给Γ1，需要逐请求前缀证据。本文没有重复计算费用或混合通过率。

## 后续优先级与证据边界

先修正实际声明／执行不一致的 diff 参数；再独立定位单机会第二次决定的 fatal 路径，并保留严格机会计量。空 cursor、非法路径、单 tool/no-tool 结束应作为模型与公开接口的适配问题分析，避免混称系统崩溃。随后才适合在新冻结协议中分别检验受管跨文件搜索、反馈／分页、thinking输出额度或同版本交付辅助；不能在看完本批结果后修改原配置并混入原分数。

可核对小证据位于 `artifacts/software-benchmark-v055/score-gap-evidence-r1/`：`summary.json`、`project-format-shapes.json`、`project-operation-costs.json`、`qwen-cost-and-schema.json`、`qwen-search-rejections.json`、`diff-schema-executor-mismatch.json`。首轮全正常闭合逐槽元数据在同名 runs 目录引用保存。首个样例均按冻结队列顺序选取相应机制的首个记录，不按成功、失败或接近成功选择。所有频数按明确端点、回合或调用计数，未把重复调用当独立任务，未声称取得单因素因果效应。
