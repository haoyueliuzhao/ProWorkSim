模型仍为原始Qwen3.5-9B，revision `c202236235762e1c871ad0ccb60c8ee5ba337b9a`，无训练适配器。保留vLLM0.32.0、BF16、思考开启、temperature0.6、top_p0.95、top_k20、原tokenizer与提示；上下文131,072、完整输入98,304、单次完整输出32,768。使用相同OpenHands SDK/tools1.49.6及原生终端、编辑器、任务跟踪、think/finish工具；无搜索联网、浏览器或额外Agent。

为避免大预算先撞上旧的128次或90分钟界限，**四档共同采用512次模型尝试、512次Agent决定、SDK每次运行最多512轮、6小时软期限和6.5小时硬期限**。每请求超时仍为1,800秒，宿主请求界限1,860秒。摘要调用与普通解题调用共用各档累计预算和模型尝试额度；完整下一次输入＋32,768最大输出预约规则保持。只有累计token上限在四档间不同。

本轮50万对照是重新运行的同期对照。由于共同调用／时间上限已改变，不能将旧九组的50万结果直接混入本轮；旧结果仅作为历史背景。本面板为仓库较均衡的校准诊断，不能称为完整500题成绩，也不再作为调整后方案的独立确认集。

## 怎样判定预算边界

分别记录两种完成：

1. **正常结束**：原生SDK实际进入finished状态，没有被预算、上下文、调用／迭代、时间或故障迫停。控制器普通返回不自动算正常结束。
2. **完成修复**：唯一最终候选经官方评分为resolved。已修好代码但被预算停止的回合可取得代码成功，仍不算正常结束。

每档报告正常结束比例、预算截止比例、官方代码结果及未知、实际输入／思考和其他输出、模型调用、墙钟时间。分母始终为计划50题，异常不得删掉或填成模型失败；保留逐题配对和仓库层级。

逐题记录首次出现“正常结束且官方通过”的档位；若较低档预算停止、较高档正常结束，可给出所测档位间的观察范围。四档全部运行，不因某题低档通过就跳过高档，不假定高预算一定更好；成功翻转或耗费反而增大要单列。最大档仍受限时报告右删失；触碰共同时间／次数上限时注明相应限制，不能宣称已经测到纯token边界。50题有限诊断不支持一个适用于所有任务的确定预算值。

## 执行、评分与资源

独立v056队列、原子一次性任务claim、每条件独立评分身份与缓存。生成和评分异步，最多6个生成回合、2个评分回合；每驻留模型同时一个回合。GPU0—7按UUID与实时剩余容量准入，不要求整卡空闲，不停止其他用户进程。模型持续驻留，单题关闭不会重载；全部工作完成后仅释放本轮拥有的驻留进程。

Actor沿用4CPU、16GiB和无外网边界；官方评分也限定4个实际可见CPU、16GiB及1,800秒，不向Actor反馈隐藏验收。候选必须在实际进程树静止后锁定，之后才发评分请求，不再修改或重选。

镜像、模型和固定数据复用本地资产，不下载新权重或容器层。旧缓存回收记录保留，新模板位于`runs/software-benchmark-v054/v056-budget-cache-r1`，仅为复用已验证准备器的路径合同；实际任务和证据在`runs/software-benchmark-v056`。预热提前最多2个任务；主盘扣除在途预约后保留至少128GiB。单题生成、环境或评分错误进入异常集合，其他任务继续；进入模型的回合不自动重采。公共来源、身份或账单完整性异常仍须停止受影响派发，不能以“异常不中断”掩盖证据失真。

模板回收必须确认该题四档生成和评分均终态、相关进程和锁已释放，只清理明确归属的新rootfs，保留所有模型记录、补丁、评分、清单和回收凭据。来源尚未准备好的题保留身份等待，不按表现换题。
