# v062 FIX：公开测试入口、解释器一致性与原生终端反馈

日期：2026-10-26。本文件记录新的 FIX 条件中公开环境与工具反馈部分。对应实现为 `src/proworksim/software_benchmark_public_context_v062.py`，版本 `v062-public-context-and-native-feedback-r1`。本轮仍使用原先预选的 50 道任务，BASE5M、FIX5M、FIX10M 的槽位、运行与预算由独立 v062 协议绑定。本模块不启动回合，也不授权 Docker、GPU、评分、网络或宿主操作。

## 来源核查与复用边界

检查了 v057 原生执行修复及集成说明、`software_benchmark_native_execution_v057.py`、`software_benchmark_execution_binding_v057.py`、v061 Docker actor 与 worker、v054 公开测试入口构造器，以及本地已安装的原生 OpenHands 工具源码。

可复用的是 v057 的公开字段白名单、来源绑定、仓库级前端和原生工具语义保持原则。v057 执行策略本身绑定旧的执行组、槽位命名空间与 hold；本轮不得直接把旧绑定当作 v062 的准入授权。原 v056/v057/v061 源码及历史记录不修改。

公开入口沿用 `tools/prepare_public_test_registry_v054.py` 中的仓库级规则：Django 为 `python tests/runtests.py --noinput --parallel 1`；SymPy 为 `python bin/test`；其余已准入的仓库为 `python -m pytest`。这里的 `python` 在实际提示中替换为该任务已有基线映射中的绝对解释器路径。规则不读取参考补丁、隐藏测试、官方评分或既有模型结果；不从这些内容选择文件、接口、测试节点或修复位置。

旧注册表的资格来自仓库与解释器 major.minor 家族的代表性帮助信息和依赖观察，不是逐题全套测试。新说明明确保留这一限制。公开入口是模型发现测试的起点，不表示全套测试通过，也不自动让模型运行全部测试。

## 解释器缺口与修复

v061 worker 在创建原生 terminal 之前已经要求 `PATH` 第一段等于公开解释器所在目录。原生 subprocess terminal 随后启动 `/bin/bash -i`，因此镜像自己的交互启动文件仍有机会重设 PATH。仅核对传入的环境字典，不能证明实际交互 shell 与预定 testbed 解释器一致。这是源码所支持的机制风险，不是对全部原任务均出现该问题的统计结论。

FIX 在同一原生 terminal 创建后、模型首次进入前执行一个明确记录的原生工具调用。该调用仅恢复公开镜像环境中已有的 `PATH`、`CONDA_PREFIX`、`CONDA_DEFAULT_ENV`，执行 `hash -r`，再运行 `python -c` 打印 `sys.executable`。不编辑 shell 启动文件，不创建替代解释器或新执行通道，不增加宿主权限。

验证同时要求：原生 action 原文相符、`is_error=false`、未超时、外层与 metadata 退出码均为零、metadata 的 `py_interpreter_path` 等于公开解释器、唯一身份探针也等于该路径。路径不符或缺证时拒绝把准备标为通过；不通过重复尝试掩盖失败。探针不是公开测试，更不是官方评分；它的工具调用和时间应在准备记录中单独保留。

模型可见说明始终给出公开解释器绝对路径。若后续模型主动改变了 shell 环境，工具返回中的实际解释器路径与预定值不一致时，只追加固定建议，要求显式使用绝对解释器；不会自动修改 shell 或重跑原命令。

## 公开投影与信息隔离

`prepare_public_context` 接受原始公开 task、注册表引用、基线映射引用和已构造的公开镜像环境。它验证：

1. 原注册表版本、500 题分母以及任务条目唯一性。
2. 条目已准入、来源为公开仓库、声明未使用隐藏材料、选择规则为仓库级默认入口。
3. 任务 ID、仓库、原始 base commit、actor image、actor head/tree 和解释器相互一致。
4. `argv` 精确等于上述仓库级固定规则；即使某个条目自称公开，追加题目专属测试路径或任意 `-c` 程序也不能通过。

模型可见数据只有 `/testbed`、公开解释器路径、仓库级测试前端、上述资格限制与固定 terminal 用法。注册表中的额外字段、版本自由文本、基线映射正文、资格输出、哈希和宿主路径均不插入提示。返回的 `sources` 仅供可信控制器单独存档；控制器只能把 `visible_text` 或其明确公开事实送入模型，不能发送整个返回对象。

通用需求覆盖、finish 自查和 stuck 纠正由独立 native-control 模块统一提供。本模块不再追加第二份覆盖清单，避免重复输入。原题正文由上层接口保留，不在本模块中重写。

## 终端允许命令与反馈

命令是否合法仍完全由原生 terminal schema、原生 Bash parser 与已有执行器判断。FIX 不将所有换行视为非法，不拆分命令，不自动替换换行，不包装或重写模型命令。原来允许的显式 `&&`、`;`、引号内换行、合法 heredoc 和脚本调用继续由原工具处理；原来拒绝的多条独立命令仍拒绝。

反馈投影只在收到原生 observation 后发生。对于精确匹配已审阅官方多命令拒绝前缀、`is_error=true`、外层无退出码、metadata 没有已执行进程或退出状态的反馈，追加固定解释：该 action 被执行前拒绝，可拆成不同工具调用、主动用 `&&` 表达依赖，或用 `file_editor` 编写脚本后调用；不能盲目替换换行。原始 observation、命令、原始 LLM 内容和 RPC 身份均保留。

普通程序执行后打印相同错误文字，不因文字相同而被当作执行前拒绝。未识别的工具失败继续保留原反馈；不会泛化为可自动恢复。仍在运行的命令也不自动中断或重试。

可信侧保留原 RPC transcript，并另记追加了哪类反馈。模型实际看到的 `llm_content` 是 FIX 投影副本，故必须披露工具呈现已改变；不能称作完全未经修改的上游输出。

## BASE 与 FIX 的明确差异

| 行为 | BASE5M | FIX5M / FIX10M |
| --- | --- | --- |
| 公开解释器与仓库测试入口提示 | 保留原条件 | 新增本模块公开说明 |
| 创建 terminal 后恢复 PATH/CONDA 并核验真实解释器 | 保留原条件 | 模型首入前一次原生工具准备调用 |
| 原生多命令拒绝 | 原反馈 | 原反馈加固定解释，仍不执行被拒绝命令 |
| 后续解释器漂移 | 原反馈 | 原反馈加绝对解释器使用建议，不自动改环境 |
| 原生命令语法、权限、actor 隔离 | 原条件 | 保持同一原生工具、原权限与隔离 |
| 参考答案、隐藏测试、官方评分进入模型 | 禁止 | 禁止 |
| 题目专属人工覆盖合同 | 无 | 无 |

FIX5M 与 FIX10M 使用完全相同的本模块修复，预算差异在上层协议中定义。追加公开文本和反馈会改变模型上下文，需进入真实 token 计量。准备 action 虽不调用模型，也必须如实保留。整体结果属于本项目明确修订执行条件下的 50 题校准结果，不能宣称未经修改的原生 OpenHands 官方分数。

## 必要 CPU 控制及结论限制

执行 `.venv/bin/python -m pytest -q tests/test_software_benchmark_public_context_v062.py`，首次运行 14 项全部通过，耗时 0.11 秒；对应两个新 Python 文件的 Ruff 首次通过。

控制覆盖三类仓库入口、私有 canary 字段不进入模型可见投影、错误来源拒绝、题目专属 argv 拒绝、解释器/镜像绑定、宿主路径与错误 PATH 顺序拒绝、真实解释器身份双核对、官方执行前拒绝与程序输出的区分、已有允许命令不被改写、原生 observation 不变，以及解释器漂移只追加说明不重跑。

这些控制只使用合成公开任务、合成元数据和合成工具 observation。Docker、namespace、挂载、服务、模型、GPU、网络和官方评分调用均为零；没有在宿主执行生成的 terminal 初始化命令，没有复验旧模型候选或旧成绩。真实原生 SDK 初始化与新 controller 的接线控制由独立集成验收记录，本文件的单元控制不能替代该验收。

目前只证明新模块的投影与反馈边界通过有限 CPU 控制。没有证据据此声称全部环境问题已经消失，也没有新增模型成功率、完整测试通过率或能力提升结论。
