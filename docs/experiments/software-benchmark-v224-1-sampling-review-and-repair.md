# v224实验审查与v224.1修复说明

日期：2026-11-21。范围：审查原始轨迹、修复后续执行入口、CPU及真实受管工具验证。**本次不重新调用付费模型，不补写旧结果，不将旧任务算成已完成的分工对照。**

## 一、审查结论

v224执行已结束，但没有完成预期的组织策略学习实验。4个前缀全部执行；只有Sphinx形成检查点，且模型只保留KEEP。实际只有1条续跑完成官方评分，代码与合法交付均未通过；没有C1/C2对照，C/N参数更新0次。

原`finished.status=completed`只表示队列闭合，不能表示研究目标达成。新版分别记录执行状态、科学验证状态和实际更新次数。

| 原任务 | 轨迹证据 | 为什么不能构成对照 |
|---|---|---|
| Matplotlib | 没有split_work；所有需求在work_root；001实际修改，第二次测试收集4例、3通过、1跳过 | 根工作包已有作者，没有剩余可拆分/转交的工作。不是一直没做真实测试 |
| Pytest | 没有split_work；002接受整个work_root并修改；三次测试实际运行79、79、2例 | 同样没有未开始工作；另有002测试对001私有的可见性问题。只去掉成员编号判断仍不能使它合格 |
| Xarray | 没有split_work；001修改整个work_root；作者测试运行5例，002随后对发布候选复核运行34例 | 真实测试和复核都存在，但不存在尚未开始的剩余工作 |
| Sphinx | 明确拆成实施和验证两个工作包；001测试收集并运行3例 | 检查点合格；架构角色认为只是常规配置缺口，纠正一次格式后主动返回KEEP，没有被编译器吞掉合法替代方案 |

三条未准入前缀消耗约198.44万、191.80万、196.20万token。Sphinx的KEEP逻辑任务消耗492.19万token。全批物理调用209次、实际输入加输出10,786,329token、17.39720624元；共同开销物理只付一次。累计账本830.60118256元，剩269.39881744元，无未定API费用和在途预约。

这说明当前瓶颈主要是**采集出的工作状态没有可合法调整的对象**。不能将它归纳为“模型选择器无效”，也不能仅提高前缀token额度：一旦所有工作包都有作者，现有合同不支持再拆分、改依赖或转交，继续等待不创造调整空间。

## 二、已完成的修复

### 1. 初始分工从模糊提示改为明确工具流程

新版明确说明：若原问题确有可分离工作，由当前负责人调用`split_work`建立有意义的子工作，再通过实际offer/accept设置责任和复核。口头计划、笔记和题文标签不会自动创建子工作。

同时保留不拆分的合理选择：若问题不可分，允许说明后作为一个工作包处理；采样器将它列为本轮“剩余工作调整”研究范围之外。不会强制按四段引文拆成四题，也不会强制制造一个暂不开始的冗余工作包。提示改动是否增加有效状态，仍需后续真实试跑验证。

### 2. 及时识别已经关闭的调整空间

新增逐步采样诊断，记录有无可变工作、可见同版本证据、剩余预算及终止状态。当所有叶工作都已有作者或已经完成时，立即保存状态与实际费用，标记`sampling_space_exhausted`，停止这个**状态采样前缀**，不再为了等待一个已不可能出现的检查点耗到200万token。

这不是普通修复任务失败，不等于官方评分失败，也不表示应在产品求解中提前终止任务。它仅用于本轮有明确研究目标的前缀采样。后续如需把该状态继续作为单Agent/团队正常求解对照，必须另行定义独立续跑，不能偷偷补成原实验结果。

### 3. 进展不再要求“001亲自写代码”，但保留权限边界

新门接受有权限查看的精确版本证据：

- 可见作者的实际编辑，加该版本的真实测试；或
- 成员已明确发布的代码补丁，加观察者对**同一不可变补丁版本**实际执行的复核测试。

因此002实现、001复核的正常分工能够提供进展证据。发布补丁本身、消息中的“测试通过”、另一版本测试、只有收集错误或零执行用例均不够。002未发布的测试和私有工作区不会被控制器自动搬给001。不可变补丁的复核只证明该补丁版本受检，不宣称伙伴后来修改的工作区已经验证。

准入、保存状态和候选编译使用同一组可见证据标志，修复旧capture的“任意成员编辑＋后续任意测试”全局时间戳判断与模型侧权限不一致的问题。没有增加不受管shell、自动修改责任或自动合并补丁。

**边界：**当前架构观察者仍为001，未开放任意成员私有历史。若002尚未公开可复核产物，只能等待合法交接，不能把这类限制写成已经彻底消除。

### 4. 没有发生策略更新，就不进入更新验证阶段

第一轮闭合后，只有至少一个完整、候选特征有差异的对照题真正改变了选择器参数，第二轮才自动准入。单KEEP、评分未知、特征退化或参数未变都不算学习完成。此规则与得分高低无关；不能因为成绩差就换题，也不强行加入替代方案。

本轮v224两轮都没有实际更新；旧第二轮原件保留。新逻辑只用于后续新版本，不追溯删除已花费用或修改旧分母。

### 5. 修复方案回退中的潜在二次异常

旧代码在未发出请求的token边界记录上读取不存在的`errors`字段，可能把正常回退变成KeyError。已改为显式识别未派发边界、格式/编译错误及主动KEEP，保留实际费用和原始原因。v224实际Sphinx没有触发该缺陷；这是代码审查发现的潜在问题，不能冒称本轮失败根因。
