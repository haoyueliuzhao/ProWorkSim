# 后续组织策略实验并发调整

2026年11月17日，按用户“后续批次尽可能提高并发，参照历史高并发”的要求实施。当前v204／v205运行进程和冻结实验条件不改动，本次没有新增模型调用、容器或系统资源组。

## 调整内容

| 调度环节 | 当前实现 | 后续实现 |
|---|---|---|
| 同状态候选 | 最多2路，第三个候选等待 | 开发组三候选可同时运行，确认组两配置可同时运行 |
| 不同状态 | 比较块逐个串行 | 完整现金准入后，多个状态块并发 |
| 生成调度上限 | 2 | 48；受批次任务数和资源保护进一步限制 |
| 环境启动 | 随生成线程启动 | 全批最多8个生成回合同时准备环境 |
| 官方评分 | 单线程 | 独立2路，可与生成重叠 |
| 健康反馈更新 | 等完整窗口 | 仍等完整窗口，不随中期成绩提前更新或换题 |

历史v076实际采用44路目标、48路上限；v131采用48路生成、2路评分，另有144核／832GiB系统聚合资源组。历史经验中可复用的是跨任务交错、控制启动峰值、读取整体CPU与内存压力、生成评分异步；不能只把线程数改成48而忽略当前运行方式和资源边界。

## 当前能落地的并发与上限区别

资源快照显示约917GiB可用内存、176个可见逻辑CPU、一分钟负载约23、主盘约1.7TiB可用，当前没有必须固定两路的硬件理由。负载不是CPU利用率，此处没有将其换算为利用率百分比。

后续开发窗口只有3状态×3候选=9条，确认阶段只有4状态×2配置=8条。因此本小批的任务数上限分别是**9路、8路**，不存在凑到40条的任务。

调度器的框架上限为48，但本次不新增需要root管理的系统聚合资源组。普通用户安全模式保留832GiB资源包，每个生成回合预留32GiB峰值空间（包含actor与控制进程），每路评分预留32GiB，先保留两个评分槽；因此其内存资源包最多容纳24路生成。**当前配置不能宣称在本服务器上已实测或承诺48路。** 当前9／8条小批都低于这一上限；更大批次若需要40路以上，应结合实际峰值和经授权的聚合资源边界另做部署配置，不能默默压低每回合测试内存上限。

启动器根据本批任务数量设置新的普通用户服务MemoryMax、MemorySwapMax=0、CPUQuota、TasksMax及文件描述符上限，不修改旧服务。下一开发窗口9条对应服务MemoryMax=184GiB、CPUQuota=3400%，actor各仍4CPU／16GiB，grader各4CPU／16GiB；这都是上限，不是预计实际占用。

## 动态准入

全批共享线程安全资源账目。新准入同时检查：生成48路框架上限、评分2路、启动8路、资源包额度、物理MemAvailable、磁盘余量和整体CPU压力。保留96GiB物理内存及128GiB磁盘余量；CPU忙于85%或整体负载挤压预设余量时只暂停新准入，不取消已有回合。

物理MemAvailable已经反映在途任务使用，检查物理压力时不再重复扣除所有活跃容器的完整上限，只计尚在启动的增长空间。资源包的峰值额度单独用于限制整个批次容量。这样区分物理压力、准备期突增和每回合上限，避免三个口径重复相加。

## 现金和科学约束保持不变

每个比较块的全部候选先由协调器一次性登记现金，再并发派发；子进程只能使用对应的pending登记，不能重复预约或因多个线程同时看到余额而超额入场。若资金暂被其他块占用，等待这些块结算；若全部活动块已结束仍不满足准入，就保留未启动块并报告，不删掉候选凑不完整对照。

**现金可能继续限制实际并发。** 现有v204仍采用完整块的最坏费用保障，三候选块约需百余元预约。即使服务器能跑9路，当前200元账本也未必能同时准入多个块。本次没有擅自增加金额、降低每题Token上限或削弱现金约束；“支持9路调度”不等于“当前余额一定能启动9路”。

角色、提示、工具、模型、采样、上下文、每队Token／时间限额、截止时间绑定和评分规则不变。窗口2仍须q₁存在，独立确认仍须冻结q₂；并行不能越过阶段依赖或用未闭合的部分样本更新。确认阶段只输出冻结q₀／q₂配对结果，不产生第三次更新。
