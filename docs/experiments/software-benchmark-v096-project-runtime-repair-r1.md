# v096：原零调用任务接续前的 PROJECT 运行包修复

本文件仅记录实现与 CPU 准备，不授权或宣称79个任务已经启动。Qwen 保持暂停；API 总现金上限仍为1700元。运行方案及具体新增对象范围由独立清单固定，启动前单独核对权限。

## 修复内容

原 PROJECT 镜像的部分文件属于其他 UID。旧同步器即使发现内容与执行模式都未改变，也会调用 chmod，导致 EPERM 并破坏后续同步状态。新入口使用 v095 同步器：未变化条目保留原 inode；确有内容或执行模式变化时，在原父目录创建自己的临时文件、设置模式并原子替换。真实父目录写权限不足仍拒绝，没有 chown、提权或修改共享挂载。

另外，原 SDK 会删除合法的可选 cursor:null，造成受管网关误报参数变换。新 aligned managed worker 保留原计费、上下文和生命周期父类，只在首次决定前安装 v090 已验证的四个分页工具参数恢复器；完整原参数仍需通过原网关校验。工具 schema、模型、采样、131072上下文、32768输出与5M累计预算保持。

## 新入口与不变边界

新 bundle 位于 `runs/software-benchmark-v096/sdk-bundle-r1`。原 REF worker/controller 文件保持原字节；PROJECT 的两个新脚本只改所导入的受管模块。新 actor 模块保留原 RPC 协议和验证器，只选择新同步函数；新 managed 模块只改变 worker 工厂，继续调用原 runtime 构造器。

不修改旧 v064／v066／v090 的源码、旧归档或候选，不向模型暴露官方评分器、参考补丁或隐藏验收。运行包只从本地既有 SDK 与依赖打包，没有下载、模型权重、API 密钥或现金账本代码。模型可见的有效工具能力保持，修正了实现与既有公开 schema 的不一致；这仍须以新执行修订记录，不能将历史异常悄悄改为成功。
