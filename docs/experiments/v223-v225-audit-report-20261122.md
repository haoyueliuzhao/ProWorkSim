**核对日期：2026年11月22日。** 本报告接续 v222 审计，覆盖 v223 的提案者对照、v224 系列的采样修订和两轮策略开发，以及 v225 的独立确认准备。历史保存点被复用时，只将本期新增调用计入本期账目。[前期审计](software-benchmark-v222-audit-report.md) · [本期账目及环境回执索引](../../artifacts/software-benchmark-v225/audit-20261122/reconciliation.json)

**审计结论。** 项目图支持模型提出具体分工，两名成员实际完成了责任转交，两轮真实续跑结果也确实改变了选择器参数。可用于学习的证据来自 **3个开发任务状态、7条续跑**。分工改变后的结果差异主要出现在 scikit-learn 的交付环节：两组都修对了代码，维持分工组完成正式提交，转交测试组多用889,727 token，预算耗尽时仍未提交。**新策略能否提高独立任务的完成率，目前尚无模型评测结果。**

## 一、对照的条件是什么

两个实际工作成员使用 DeepSeek Flash 非思考模式，通过 ProWorkSim 受管 OpenHands 接口完成原始 SWE-bench Verified 任务。项目图从成员有权查看的代码定位、编辑、补丁、测试和版本回执中提取关系。组织图记录谁负责哪个工作包、谁复核、工作之间有哪些依赖。图审阅者可以提出关系假设；组织 Agent 可以据此提议改变分工。责任转交要经过原负责人的实际提议和接收者的实际接受。

**KEEP** 指维持保存点的工作范围、负责人和依赖，成员继续修复、复核和交付。**C1、C2** 是组织 Agent 为某一道题提出的第一、第二个有效替代方案，每题的内容可以不同。每个候选从同一保存点独立续跑一次，共享的前缀、图审阅、提案和该分支后续求解合计最多500万输入加输出 token。最终代码按官方评分器评估；合法交付另外要求有符合项目规则的固定提交，且该版本通过验收。[自然协作协议](software-benchmark-v224-2-natural-validation-protocol.md)

**Q0、Q1、Q2** 分别是初始、开发一次和开发两次后的选择策略。策略给同题候选分配概率，实验会执行全部候选，因此可以同时检查“主选了谁”“成员做了什么”和“若按各方案概率加权，会得到怎样的效用”。更新对象是跨任务共享的12个选择器参数。[冻结策略及哈希](../../artifacts/software-benchmark-v225/frozen-policies-r1/freeze.json)

## 四、C/N 估计怎样影响选择

每条续跑的效用等于**合法正确交付指示值 − 0.1 × 逻辑 token / 500万**。C 是某个方案的实测效用减去当前策略下同题候选的加权平均效用。N 比较同题候选中某类项目—组织映射和组织结构的参考概率与当前选择概率，给欠覆盖的类别正值。实际采用补丁、完成测试或发生责任转移都能用于解释行为，奖励仍由最终交付和成本决定。

- **第一轮 Q0 → Q1。** SymPy两组均未交付。转交组少用2,757 token，C约为 +0.00002757。初始概率均匀，N为0。第一轮只形成很小的偏好。
- **第二轮 Q1 → Q2。** 在两道新开发题上，Q1与Q0用同一随机数选出的主分支相同。scikit-learn 的KEEP和转交组C分别约为 +0.509 与 −0.509，主要来自是否正式交付。Astropy 三个方案的C绝对值均低于0.001。两题最大的N约为0.0000041，当前样本提供的探索信号很弱。
- **更新后的开发集回看。** Q2将 Astropy 的KEEP概率从33.33%调至34.95%，将 scikit-learn 的KEEP概率从50.00%调至52.12%。沿用同一随机数，主选分支均未改变。在 scikit-learn 上，按两条实测后继加权的效用由 Q1 的0.40925变成 Q2 的0.43079；同一题的结果参与过Q2拟合，独立泛化效用仍待测量。[更新明细与概率](../../artifacts/software-benchmark-v224-4/window2-r1/result.json) · [逐题概率和动作](../../artifacts/software-benchmark-v224-4/window2-r1/summary.json)
