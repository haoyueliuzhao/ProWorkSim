## 3. N0：完整工具入口补证与修复

### 3.1 修复前证据

审计原先使用方法摘录及内存夹具。本轮进一步从 **a316f963f221b8ec2c909e654ab0ad0750583cbe 的完整 Git archive** 加载旧源码，隔离 PYTHONPATH，经真实 ProjectSession→WorldRunner→Store 建立世界与操作。原世界、工具往返、协议、冻结源码归档和摘要保存在 `runs/scope-paths-v07-before`，摘要见 [v07-scope-paths-before.json](v07-scope-paths-before.json)。

旧实现源码摘要为 `02a6dc1487d57387ffc88d7716140cc6a3073737589420a8537da29dce97ad6b`。以“合法路径应可执行”的同一验收口径，结果 **22/29，未执行 0**。七个失败观测对应两个根因，不是七个独立漏洞，也不能因错误符合复现预期就写成“29 项生产正确性通过”。

- F1：同项目 private v1 分享成功，但 Bob 仍不可读、观察仍不显示；跨项目精确分享对照可读。
- F2：合法窄对象/工作采用权限在真实入口丢失对象参数，初次/更新采用及其相应历史观察未得到应有结果。

本轮确认的是合法动作误拒，未将其描述成已证实越权。v0.6 固定 M1–M5 实例的原结果保留，[原报告](world-core-v06.md)补充了后续发现与边界。

### 3.2 修复后的合同

同项目也检查合法 shares，但分享 v1 不开放 v2 或 Carol。采用入口先在绑定项目中解析实际对象和所有目标工作，分别核对窄权力；fixed 仍拒绝直接换版。

初次跨项目采用尚无目标别名，不能因为引入 object_id 检查反而再次误拒。实现先确认精确版本真实可读与候选别名合法，再用只包含这个候选绑定的只读上下文检查既有 grant；成功后才写声明，不增加任何权力。空工作列表也不能绕过窄工作限制。

最终 29/29 包含上述正向路径及错版/错人/错对象/错项目/错工作/fixed 负向路径。没有通过全对象授权替换窄授权来“修好”实验，也不声称所有未来合法权限组合已穷尽。

## 4. N1：实际工作能力进入同一世界

一个世界内，A 通过公开工具创建受限工作簿，B 形成 JSON 交付，并额外创建同名工作簿作名称隔离对照。世界、主体、对象注册、时间与提交机制相同。

固定算式初始为 10−4=6；真实编辑将输入和公式改为产生 8，随后重算产生独立版本。**6 和 8 是预声明标量，不由被测引擎生成期望。**实验核对真实 XLSX 原始单元格、公式、缓存及文件摘要，而不是只看工具返回成功。

A 正确提交固定 v3。随后实际写入 `=1/0`，形成新版本并通过第二工作提交；其公式与错误缓存真实保存，独立评价拒绝。再评价旧提交时仍读取固定 v3，旧版本和原提交未被重写。

未经授权编辑会被拒绝，正式文件字节保持。同名对象的身份/路径分离。独立评价 read_set 对应实际固定版本与 sha256，不调用 Spreadsheet 计算一份“正确答案”，也不读取当前镜像替代历史提交。22 项全部通过。

这组证明有限表格能力接入多项目核心。它没有迁移完整经营估值任务、财务定义或全部 Excel 功能。XLSX 时间元数据的确定性序列化用于真实字节一致性；错误公式、数值和缓存均保留。

## 5. N2：草稿、发布、采用与内容变化

同一检查点中，世界 JSON 材料 v1 的值为 6；A 按 current_published 采用，B 固定 v1。v1 已有真实发布与分享，两个下游产物真实依赖该版。

创建 v2 草稿值 8 后，不追加正式 release，不发订阅通知，不授权新版本，A 的正式目标仍为 v1。无权发布也不产生正式发布/分享效果；有权发布 v2 后，只有明确范围及订阅路线获得新版本权限和通知，A 标记需检查，B 固定政策仍指向 v1。

从相同已发布检查点构造两个 A 分支：

| 分支 | 实际操作与结果 |
| --- | --- |
| 仅换标签 | adoption、正文 source_ref 和文件 derived_from 全部为 v2，但数值仍为 6；独立数值核对失败 |
| 实际更新 | 读取/使用 v2 后，正文为 8，精确来源与依赖一致；独立评价通过 |

采用工具本身不修改文件。B 的固定 v1 内容继续按其合同通过。17 项检查通过；没有将 adoption_view=current 当作内容正确性。

current_published 仅说明跟随范围内的发布接口，不证明新材料自动适合任意期间、用途或金融定义。提交固定当时采用和目标，后续发布不追溯重判旧提交。

## 6. N3：A 的成果被 B 继续使用

A 实际创建计算工作簿并发布可消费接口。B 只读取该接口，不能读取 A 私有上游；另外对两种身份/项目上下文进行了拒读对照，B 独立评价的实际 read_set 也不含私有对象。A 完成前记录发布文件字节，完成后再次比较，成果仍存在且未变。

六个策略分支从同一检查点复制，仍各为一个世界两个项目。历史 v1 接口值为 6，是可明确引用的中间版本；A 的更新合同要求 8，正常 v2 达到该值；错误分支又生成 v3=16。v1 不被冒称为满足最终 A 合同。

| B 策略条件 | A 独立评价 | B 内容/接口评价 | 正式制度结果 |
| --- | --- | --- | --- |
| 正确 current_published | 通过，v2=8 | 通过，消费 v2=8 | A 实际 Bob 批准并完成；B delivery_only 接受 |
| 旧版 fixed | 通过，A 最终 v2=8 | 通过，B 固定消费 v1=6 | 同上 |
| 旧版 current_published | 通过 | 失败，旧引用不满足提交时正式目标 | A/B 的正式决定仍保留 |
| 只换标签 | 通过 | 失败，引用/采用/依赖为 v2，数值仍为 6 | A/B 的正式决定仍保留 |
| 错误但正式批准 | **失败，A v3=16** | **通过，B 忠实消费该接口的 16** | A 的合法批准不被评价撤销；B 制度接受 |
| 两份合法文件 | 通过 | 通过，结果与来源分拆但贡献文件都声明精确依赖 | A/B 正式接受 |

所有 A 都真实执行了 Bob 的 approve 后再 close；所有 B 都实际提交并按 delivery_only 接受，包括内容失败分支。**因此，制度接受、A 的计算质量、B 对接口的忠实使用必须分别报告。**错误批准条件不是端到端质量通过。

11 项矩阵检查全部通过。它没有强制 B 重复 A 全部上游分析，也没有把某一种文件组织或固定轨迹作为唯一合法解。

评价按需读取：旧 current 分支在政策检查处已经失败，read_set 只有 B 的 JSON，没有读取源工作簿。不能把“没有私有上游读取”写成“所有策略都完整读取了同一套源文件”。

## 7. N4：公开会话工作人员与实际观察

程序工作人员只拿到一个暴露 `tools/observe/call` 的端口。它没有 WorldCore、Store、路径、state/spec 或隐藏对象 ID 接口。工作 ID、别名、字段/单元格、政策、精确版本及数值都由公开观察与实际读取取得。

它只支持一项当前责任工作与一项已声明的来源消费合同；不是一般规划器。工具预算上限与缺口出口明示，每次工作人员运行使用独立 run_id，工具动作以 run_id 和动作序号组成 request_key。实验在端口另一侧独立捕获真实返回，与工作人员保存的记录逐项/字节核对，不用最终世界重建当时观察。

| 主情境 | 工作人员实际结果 | 操作数 |
| --- | --- | ---: |
| 已有适用信息 | 实际读 JSON 值 13、采用并提交 | 4 |
| 可发现正式版本 | 选择公开发布的 XLSX v2，读取值 27；忽略后续 v3 草稿 | 4 |
| 已声明可取得路线 | request_information 只填公开 route/work，真实单步等待，精确授权后读取 33 并提交 | 7 |
| 缺少资料路线 | waiting，明确 missing_information_route；没有伪造请求或交付 | 0 |

四主情境 **4/4、28/28**，其中只有前三个产生交付。available 路线由合法项目包声明真实初始材料、对象提供者及对应权力；回复事件才将精确 v1 开放给责任者，不能读取未授权内容。

unavailable 补充单列：请求后两次单步等待，共 3 个动作；收到不可得回应后保持 private 材料不可读、没有提交。8/8 检查通过，但不是业务完成。

五份工作人员 transcript 与独立端口捕获的原始字节一致。保存的是实际返回的工具定义、观察、参数和响应，没有模型推理或重构历史。公开调用之外的测量程序可以在运行后检查世界，这是控制器权限，不能混称为工作人员具有后台访问。

## 8. 新能力的两个恢复切点

同一真实检查点包含受限 XLSX，并保留诊断用 `=1/0` 错误公式。检查点 revision 为 7。逐字节复制到不中断对照和故障世界；固定命令键使恢复重试表达同一次动作。

| 动作 | 真实切点 | 磁盘已提交 revision → 恢复后 | 结果 |
| --- | --- | --- | --- |
| sheet_update | after_apply，表格新版本已暂存、命令未提交 | 7→8 | 8/8 |
| 显式 publish | after_command_commit，已提交但尚未返回 | 8→8 | 8/8 |

两子进程均实际 `os._exit(73)`，不执行 finally。分别核对切点到达、提交前缀、恢复状态、不可变版本及镜像字节、公开结果、实际观察和再次重试效果，共 **2/2、16/16**。

完整状态只递归排除 wall_seconds 与诊断 state_digests；对象注册、发布、分享、采用、消息、交互和原始读取记录均保留比较。实际读取/写入记录和三个角色的观察也保存。表格切点隔离的暂存 XLSX 有独立字节摘要，错误公式不会被恢复过程修正。

这是表格写入与发布的两个指定位置；不扩大为任意操作、并发、断电、跨机或插件外部副作用保证，也没有重做原十故障点。

## 9. 开发过程、失败与必要回归

旧 F1/F2 已有完整冻结反例；另有一处本轮开发缺陷必须单独保留：**显式发布政策下，世界对象 writer 无 publish 权时保存草稿也被拒绝。**真实会话探针先成功创建对象，再在 write_object 被拒；publish 应当仍拒。

根因是 `_save_content` 沿用了旧世界写入时的 publish 权检查。现 explicit 草稿保存只依已有写 ACL，正式 publish 仍独立要求发布权；implicit_write 保留原政策约束。目标回归同时检查草稿 v2 成功、发布拒绝、releases 仍空。原探针、真实世界、源码摘要与结果保存在 `runs/v07-stage-b-readonly-probes`，归档于 [v07-validation.json](v07-validation.json)。这是 dirty v0.7 阶段 B 集成缺陷，不归因于 v0.6 或阶段 A 的正式结果。

其他开发记录：

- N0 修复后草稿 29/29、N1 开发 22/22；原始目录均保留。
- N2/N3 首轮 28/28。冻结前进一步把 A 关闭前后字节比较和 B 评价无私有上游读取集合写成明确检查，不更改原报告。
- 来源评价进一步核对实际贡献字段文件的 derived_from。负例的采用、正文引用和依赖都改成 v2，仍保留旧数值，以避免只测到元数据不一致而漏掉实际内容检查。
