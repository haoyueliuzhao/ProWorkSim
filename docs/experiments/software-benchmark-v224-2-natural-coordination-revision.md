# v224.2：减少实验对自然协作的干预

日期：2026-11-21。根据用户“不要过度约束妨碍自然运行”，本次修订采样时机、候选范围和队列行为。已完成实现与零API验证；未启动新付费评测，旧结果保持不变。

## 1. 问题不应继续由Agent迁就

v224.1第一轮两题均未形成对照。Pytest未拆分工作；Matplotlib虽拆为两个包，但两人都正常开始修改，触发“没有未开始工作”的采样退出。此前实际上要求模型遵循一套不自然的顺序：先有人改代码、再跑测试、另一部分工作还必须没开始，组织调整才有机会发生。

这套条件适合一个很窄的机制样例，不应成为一般协作运行规则。尤其不能一边要求并行开发，一边因大家都开始开发而结束任务。

旧轮实际47次API请求、1,974,455输入加输出token、3.0238304元；没有评分、没有C/N更新。新版本不改这些历史记录，也不把提前结束的旧前缀追溯称为完整任务。

## 2. 现在怎样运行

| 方面 | 旧约束 | 新行为 |
|---|---|---|
| 评估协作的时机 | 实际修改后还须执行测试 | 出现真实、有权查看的代码读取、定位、修改、公开补丁或测试即可评估，不必先跑测试 |
| 初始工作 | 提示成员拆分，并在测试前保留部分未开始工作 | 自然安排读取、定位、实现和测试；不规定包数，不要求有人闲置，不强迫拆题 |
| 任务都已开始 | 退出采样，原任务没有继续完成 | 继续原任务；允许评估已有公开成果的采用，缺少替代方案时执行KEEP |
| 分工提议 | 执行器也要求先有修改和测试 | 未修改工作的负责人可以直接提议，仍由接收者明确接受；无“先做一次测试才能派工”的前提 |
| 有效候选 | 必须改变任务结构、负责人等 | 也保留明确采用已公开伙伴补丁的候选；不把已有成果交接一律过滤为“结构没变” |
| 规划阶段达到额度 | 未形成检查点即结束前缀 | 保存原会话，以原500万总预算的剩余部分继续KEEP；不额外调用图/方案服务制造候选 |
| 第一轮没有参数更新 | 停止第二轮所有原定任务 | 可继续原定任务，标记“沿用未更新策略的补充观察”；不能声称完成更新后验证 |

“评估”不表示已经证明分工有问题。一次读取只能证明模型实际接触过材料；新方案仍需引用真实可见关系、说明收益和成本的假设。没有必要改变就KEEP，不按是否重组给予奖励。

新的观察点可能早于首次修改，因而不应把所有新运行称为“实施中途重组”。后续结果应按观察点所处阶段分别报告：定位、实施、测试或交接。当前实现仍是每任务一个冻结决策点的研究对照，不宣称已经实现任意次数的在线组织进化。

## 3. 已开始的工作如何处理

本次开放的是**协作信息与已公开成果的使用**，没有通过删除历史作者来强行转移正在修改的代码。模型可以继续原包、复核公开补丁、通过真实integrate_patch采用伙伴成果，再测试和交付。采用动作不是宿主自动执行，也不是已经通过验收。

候选编译器原本支持明确的补丁采用，但后置筛选只比较组织结构，导致这类方案被过滤。本次按“结构变化＋明确采用动作”共同判定并去重；纯配置补齐、空方案和重复方案仍不冒充新对照。

作者归属、明确接受、版本身份、独立复核和实际测试是保证结果可解释的运行规则；“先测试才允许提议”“留一个包不开始”“没有替代方案就中断求解”是实验人为条件，本次取消后者。

**仍有实现边界：**已产生代码贡献的工作包不通过旧的未开始工作转交接口直接换负责人；旧作者不能被抹掉后充当独立复核者。完整的在途代码责任迁移还需专门的版本交接实现。本次不冒称解决这一能力，也不因暂不支持这种动作而中止原任务。

## 4. 预算与结果含义

单任务仍共享500万输入加输出token，准备、方案和继续求解累计扣账。规划阶段结束时，KEEP继续使用500万减已消耗部分，不是新送500万额度。跳过图/方案服务时只登记零调用的阶段闭合，不伪造API记录或费用。若任务在前缀中自然完成，直接对已锁定候选评分，不重新运行模型。

没有参数更新不再阻塞其他原定任务，但研究标签必须正确：第二轮使用了新参数，才叫更新策略验证；否则只是额外观察。完整已知的候选对照才更新C/N，未知不能算失败，单KEEP不能伪造学习。

保留现有累计1100元预算和新批准入逻辑，未增加费用或自动扩大题量。实际新题单和付费部署尚未封存；本次是实现修订，不是已取得新的模型能力结果。
