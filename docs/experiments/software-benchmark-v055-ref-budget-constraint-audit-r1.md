# REF 三组预算约束核验

2026-10-23。**累计 token 上限确实频繁阻止 REF 继续工作：Qwen 最明显，两个 DeepSeek 组也超过一半。** 这证明预算改变了实际运行过程；尚不能据此计算它造成多少分数损失。

**统计范围与方法**

读取已保留的逐槽停止原因、用量和请求记录，按唯一任务槽关联异常处理后的官方代码结果。覆盖原正常闭合的 Qwen 493、DeepSeek 非思考 497、思考 493 题，共 1,483 回合；其余原生成异常及后续接续不混入停因分母。下面不是用闭合子集重新计算500题正式成绩，评分未知继续单列。没有追加模型运行、测试或评分。

三组 REF 均为 OpenHands 原生执行方式；总上下文131,072、输入上限98,304、单次完整输出32,768。每题累计输入＋输出最多500,000，最多128次模型尝试／128次Agent决定，90分钟软期限、100分钟硬期限。

**有多少回合被累计预算停止？**

“预算停止”指下一次完整输入＋最大输出预约放不进剩余额度，因此整个回合停止继续调用；与单次回答达到32K输出上限分开统计。

| REF条件 | 预算停止／计划回合 | 占全部计划比例 | 其中成功／未解决／评分未知 | 停止时模型调用中位数 | 剩余token中位数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qwen | 469／500 | 93.8% | 106／359／4 | 25 | 46,302 |
| DeepSeek 非思考 | 266／500 | 53.2% | 97／166／3 | 26 | 44,960.5 |
| DeepSeek 思考 | 286／500 | 57.2% | 122／163／1 | 21 | 49,385.5 |

**三组合计已确认1,021／1,500回合因累计预算截止，占全部计划的68.1%。** 另有462回合记录其他停止／返回，17回合未纳入本次停因审计；后者包含原生成异常及后续接续，不能全部称为当前生成未知，也不默认算作未触发预算。

上表后面三列仅针对预算停止回合。若改用有完整正常闭合记录的493／497／493回合作分母，比例才是95.1%／53.5%／58.0%，与计划500分母不同。所有预算停止回合的账本模型尝试次数都低于128，最大分别35、31、27。因此，单纯增加128次的调用上限，不能解除这批已记录的累计token阻断。

其余回合中，Qwen 24、DeepSeek非思考229、思考207题属于“控制器未记录明确限额返回”；不等同模型主动结束或SDK成功。DeepSeek非思考另有2题历史global_cny派发前边界，不能解释成2,000元总预算耗尽。三组可分析回合没有记录单次上下文或时间门作为终止原因；这不外推到被排除的生成异常。

**为什么调用二十多次就停止？**

50万计的是每次输入＋输出之和，不是50万新增文字。之前读过的代码、工具结果和对话再次发给模型，就再次计入输入。预算停止子集中：

| REF条件 | 输入占实际token | 每次调用平均输入／完整输出 |
| --- | ---: | ---: |
| Qwen | 98.59% | 18,101／258 |
| DeepSeek 非思考 | 98.97% | 17,425／182 |
| DeepSeek 思考 | 97.78% | 20,937／476 |

完整输出包含思考token。三组全部可分析回合的历史摘要调用均为0，因此这里没有额外摘要调用的消耗；主要消耗在解题输入。输入统计包含问题、提示、代码、工具反馈和历史，未把重复历史单独剥离，不能将98%以上全部称为“重复浪费”。

余额通常还剩约4.5万—4.9万，却不足以预约下一轮。按冻结题序选取各组首个预算停止题，均为 matplotlib__matplotlib-25479，没有按评分挑例：

| 条件 | 已用／剩余token | 拒绝依据 |
| --- | ---: | --- |
| Qwen | 452,941／47,059 | 下一输入精确计数41,636＋最大输出32,768＝74,404，超过余额；保留派发前计数记录 |
| DeepSeek 非思考 | 447,675／52,325 | 下一输入预约须大于19,557才会触发该边界；精确被拒输入未保存，不以最后成功请求冒充 |
| DeepSeek 思考 | 467,671／32,329 | 仅最大输出预约32,768已超过全部余额；精确被拒输入未保存 |

三例最终官方均未解决。它们证明后续请求确实被预算门拦截，不能证明放行后一定修复成功。预约未用完的输出额度不记成实际消耗；问题在于开始请求前必须容纳最大输出。去掉这条检查而不设计其他限制，也不能保证仍严格遵守50万上限。

**单次32K输出，是不是主要限制？**

Qwen的12,061次Agent调用中，28次输出恰达32,768，涉及23题；现有聚合未保留明确length停因，不能把28次全部称为已证实截断。DeepSeek非思考11,105次、思考9,230次调用均没有输出恰达上限。它与上表数百题的累计预算停止是两个不同现象。

**与小米60.0成绩如何对照？**

已取得并核对官方44页技术报告：第35页表6确认Qwen3.5-9B、SWE-bench Verified、avg@3＝60.0；仍未找到与该行唯一绑定的上下文、累计预算及完整运行配置。第36页另一张多框架表的mini-swe-agent分数为60.6，不能拿它替60.0确定框架。

| 限制 | 我们三个REF | 小米公开训练入口默认，非60.0实参 |
| --- | --- | --- |
| 总上下文 | 131,072 | 262,144：为我们的2倍 |
| 单次完整输出 | 32,768 | 32,768：相同 |
| 累计输入＋输出 | 每题500,000；历史重复输入计账 | 未取得与60.0对应的累计政策 |
| 次数 | 128次模型尝试／Agent决定 | 部分harness为500 Agent步，计量并不完全等同 |
| 时间 | 单请求1,800秒；回合90／100分钟 | 单请求3,600秒；顶层轨迹默认80分钟 |

上述训练默认可以被启动参数覆盖；默认验证重复为1，不能当成avg@3那次评测。avg@3也不等于三次取最好。**本次证据使累计预算及预约规则成为优先对齐项，但不能将我们与60.0的分差全部归因于预算，或保证把窗口调成256K就能追平。**

若要量化预算造成的分数变化，需要另外固定模型、工具、提示和任务，只改变累计预算或预约规则做配对实验。当前只完成已有数据核验。
