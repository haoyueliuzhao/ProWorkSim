# v203.2.2 自然协作机制审计协议

本轮使用已结束的 v203.2.1 十二题，回答：固定开发—复核流程中的交接、冲突、测试失败和预算终止，究竟暴露了哪些代码、信息、组织或资源问题。**不新增被测模型调用，不重新评分，不改变历史正确率；原150元账本已结案，余额不转入新实验。**

## 1. 数据与执行范围

完整保留原12题、10仓库及两个部署阶段的来源；以原请求、响应、工具意图／回执、版本记录和API账本为证据。旧汇总仅用于对账，不代替事件顺序。原回执、评分和源码不覆盖；新增分析、修复控制和解释均放入 v203.2.2。

并行开展三项离线工作：事件链恢复；失败测试与预算／提交分析；有限CPU观测成本控制。发现的测试接线问题在独立修订中复现和修复，未经真实环境准入不能称历史任务已修好。

## 2. 四种事件链

| 链 | 必须恢复的边界 | 不允许的推断 |
|---|---|---|
| A 交接—信息—采用 | 发布、定向交接、接收者实际请求呈现、显式读取、集成及同版测试 | 发送即已读、已读即使用、先采用后交接算交接收益 |
| B 冲突—处理—恢复 | 集成请求、回执冲突、实际版本变更、后续修正／再集成、验证 | `ok=true`即无冲突集成；冲突即组织失配 |
| C 复核—返修—交付 | 固定候选、复核版本、接受／返修、后续编辑与测试、提交版本 | 接受即测试通过、旧版证据自动覆盖新版 |
| D 预算—决策—终止 | 已结算用量、下一请求预约、首次预算门、终止动作与交付状态 | 接近5M即代码能力不足、失败必因预算不足 |

全局事件和成员实际输入分别记录。实际请求可证明呈现，显式读取回执可证明检索；对模型是否理解、采用了某段自然语言，只记录直接行为证据或未知，不能从文本相似度推出认知事实。

## 3. 决策窗口与盲审

在标签前固定触发规则：全部成功消息、交接、带冲突集成、复核、已执行但未通过的公开测试，以及每题首次团队预算门。同一原始截止记录重复触发时合并，不按最终成绩、是否提交或事后修复难易筛选。按原计数预计101个工具回执窗口与7个预算窗口；最终以原件恢复结果为准。

窗口截至触发记录，显示此前可用的必要证据、成员角色、版本、判断时间点及原件索引。后续动作、官方成绩、终态候选和其他审阅者标签不进入盲包。交接后的接收者输入仅能进入后续窗口或回顾性事件链，不倒灌至交接发生时。缺失上下文明确标记；全局观测者可见信息不冒充接收者已知信息。

对全部冻结窗口分别判断：

- 技术问题：代码、工具接口、测试、环境和依赖。
- 信息问题：尚未呈现、读取不足、信息不完整、版本过期。
- 组织问题：责任冲突、责任缺口、协调瓶颈、验证职责等。
- 资源问题：Token、时间、工具或环境限制。
- 实际工作依赖 D、未满足协作需求 N、组织失配 M：分别为 PRESENT／ABSENT／UNKNOWN。
- 行动：NO_CHANGE、ABSTAIN、INTERVENE；必须区分证据充分的不调整与证据不足的弃权。

每条标签保留支持证据、反对证据、置信度、来源、版本和截止点。D存在不推出N存在，N存在也不自动推出M存在。组织干预标签必须说明为何现有正常交接／复核不能解决需求。

依用户此前自行审阅的授权，本轮可由两路无历史上下文的独立AI作辅助审阅，再单列分歧仲裁。**这不是两名人类专家，也不是独立人工金标准。** 不由AI标签宣布 v203.3 科学准入；保留可供人工填写的盲审包。审阅者间一致性仅描述本批AI参考，不作为分类器性能。原12题已曝光，不承担独立确认。

## 4. 成本、失败与版本统计

测试失败分类使用实际输出和框架证据，区分断言失败、启动／依赖失败、框架观测异常及未知；一次测试可以出现多个原因，运行数与问题标签数分别统计。未执行的无效选择器请求不进入86次实际测试分母。

预算按物理API输入＋输出计量，缓存输入包含于输入，摘要调用纳入团队总额。分别报告成功／失败任务、开发／复核成员和预算门前状态，不能把复核成员的全部用量当作通信成本。当前窗口的组织判断不使用最终成绩；回顾性预算关联另表展示。

4题未提交和3题提交版不同于终态的原因逐题描述。它们是交付审计对象，不是按结果新增的独立盲审样本。原始基准环境、已验证评分适配环境和实际求解环境分列。

CPU成本控制使用同一合成序列、独立进程的观测开／关配对；测每操作延迟分位、CPU、峰值RSS、磁盘增长以及提交后故障恢复。它不模拟完整网络、全部归档或长期生产负载，不能外推生产开销。
