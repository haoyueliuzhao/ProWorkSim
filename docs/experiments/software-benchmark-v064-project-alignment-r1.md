# v064 PROJECT：真实数值资源对齐与受管执行

本修订用于新完整评测的 PROJECT 条件，不修改 v054–v063 已运行的配置或结果。底层仍为 OpenHands SDK 1.49.6 的一个实际 Agent；PROJECT 在此之上保留成员身份、受管工具、版本和交付规则。模型推理由与 REF 相同的可信 broker 提供，控制器不持有 API key，模型工具不能直接访问网络或 Docker。

## 资源对齐确实经过执行路径

仅修改条件 JSON 不足以完成对齐。原 PROJECT 的 worker、owner、成员账本和上下文选择器各有独立限制，现用新模块接入以下设置：

| SDK 输入历史 | 名义 full_history，实际预先只留最近四个工具回合 | 真正保留全部历史；仅在完整输入超过 98,304 时按完整工作回合处理容量 |

公开测试单次命令上限继续为 1,800 秒，来源是 v056 `COMMAND_SECONDS` 的实际执行设置，并受整题硬截止约束。成员的原 240,000 字节请求门不再先于 token 上限截断；新 128 MiB 原始历史 JSON 保护门是控制器部署边界，真正的模型准入依赖完整 wire 的 token 计数及 32,768 输出预留。

PROJECT SDK 每次 `Conversation.run` 的两次内部循环上限继续服务于“完成一个受管动作后暂停”的协议；整题可以有 512 次真实模型决定。这不是整题只有两步，也不能用一次原生 shell 可完成的工作量去等同一次受管动作。新运行记录明确区分两种计数。

## 历史、工具和测试

保留 Γ1 的身份权限、已呈现反馈生命周期、静态同值去重及满足原条件的字段引用。新增容量选择先测完整历史，未超限时不会预先删到四轮；超限才从最旧的完整工具回合开始处理，同时移除对应的旧动态观察。初始观察、最新观察、最新完整工具回合及其前置观察、未呈现反馈都保留。未引入模型摘要或额外的免费模型调用。实际 wire、计数方法、投影和使用量分别存档。

已接入 v056 的仓库搜索、空 cursor 和 diff 参数修复、当前版本交付提示及 S1 不可用协作入口裁剪。PROJECT 保留分页、单动作、固定公开测试入口和显式提交；没有额外 bash。控制器接收与 REF 相同的原始问题、公开解释器和测试入口事实及通用修复指引，隐藏测试与参考补丁不进入求解端。

模型原始响应先按实际 usage 结算。v057 的 reasoning 字段别名修复用于 SDK 呈现和后续真实输入，原响应和费用记录保持。Qwen 的本地 vLLM 与 DeepSeek 的官方 API usage 都标明来源；PROJECT 不再把 API usage 冒称为原生 token ID trace。API 金额预算的权威账本在宿主 broker，成员端不以零价 USD 账本代替它。明确证明尚未发送的停止可取消当前 token 预约；已经发送但用量未定不能这样释放。

公开测试由隔离 actor 接受受信任的 `managed_public_test` RPC，实际命令只来自事前固定的仓库级公开入口。模型参数不能换命令。每次测试输入绑定当前完整源码版本；后代进程只在该 actor 的私有 PID 命名空间内清理。没有宿主挂载、网络或服务修改。

为避免每次传输整仓，控制器根据双方一致的完整初始树生成差量。actor 从自身封存的完整基线重建候选，再核对完整树哈希；这不会过滤合法修改，也没有参考解选择文件。准备阶段发现单个 32 MiB RPC 帧若直接承载整个差量，会让原先允许的较大文件替换／重命名再次受限，因此在正式运行前改为可信内部 begin／chunk／commit 协议：每块原始数据 1 MiB、单帧仍至多 32 MiB，单次完整上传至多 2 GiB、仅一个 pending。完整顺序、长度和 SHA 校验通过后才执行原本的一次世界操作；模型工具、源码权限和 256 MiB 单文件部署门不变。旧 SDK r1 从未正式运行，其证据保留，新来源须进入 r2 包。原始公开测试输出仍有独立 32 MiB 保护门，序列化后的反馈也须满足单帧门；不截断后冒称完整结果。

## 终态代码与合法交付仍分开

结束模型和 SDK 运行后，在同一 World 事务中锁定终态工作树及最后合法提交。二者可以不同，不能用正确率差简单代表流程损失。控制器保留完整双候选、最后提交的固定补丁和同版本公开测试证据；随后只把已锁定的终态树同步给 actor，之后不再允许模型运行或修改候选。宿主再从停止后的 actor 导出代码候选，并独立导出最后合法提交候选。

`validate_delivery_evidence` 检查完整 delivery inventory 的最后一项、成员、源版本、内容／元数据哈希、固定补丁覆盖和同版本实际测试。它是纯验证器，不会补测试或创造提交；调用方还必须绑定原可信控制器输出、唯一槽位和清理凭据，任意自洽 JSON 不构成执行证明。两树相同时可以在满足相同评分身份的条件下复用代码评分；合法交付状态仍独立报告。

## 已完成的验证与边界

七项受管 CPU 控制覆盖三档实际 runtime 装配、真实工具可见范围、移除旧 32 次公开测试门、完整历史容量边界、精确计数绑定及不同终态／提交版本。四项 actor CPU 控制覆盖完整树差量往返、生成测试缓存清理、Git 控制元数据保留、篡改／只读保护拒绝、公开命令限制及超限不截断。初始合成 fixture 的 sink 与 Git 初始化错误均保留，只重跑受影响检查；未重测无关历史实验。

使用实际固定 OpenHands SDK 的程序化控制完成六回合：搜索、修改、公开测试、固定、提交、结束。人为设置每次 90,000 输入和 17 输出，累计假计数 540,102，用于证明旧 18K／500K 门不再截断；它们不是实测 tokenizer 或模型 token，真实模型调用和模型 token 均为零。该控制还验证 reasoning 回灌和正式同版本交付。前两次 fixture 启动因测试脚本的 socket 类型替换及私有 SDK 配置目录设置失败，未运行模型；修订后在私有项目目录完成，记录位于 `runs/software-benchmark-v064/project-sdk-cpu-r3/result.json`。

CPU 控制与源码检查不能代替 Docker actor/controller 的实际部署资格，也不代表任何新 500 题分数。本次主矩阵的环境准入、资源授权、收费预算和官方评分由独立调度器负责。

## 大文件内部传输修订

完整差量以分段 JSON 编码写入控制器临时文件，actor 顺序接收 base64 块并写入自己的临时文件。双方均不拼接一个巨大的传输字符串。块序号、字节 offset、每块 SHA、总 SHA／长度、任务及源版本、原回合截止时间全部绑定；有缺块、重复、乱序、截止、错误 ACK 或并发 pending 时均停止，分类为 `interface_unknown`。每侧最多 2 GiB 临时磁盘，故每活动 pair 的最坏额外暂存为 4 GiB；完成或拒绝后仅关闭回收自己的临时文件。

chunk 数据是已有完整 World 源版本的传输副本，日志保留块序号、长度、内容 SHA 及完整 wire SHA，不再把大文件重复保存为 base64。原 World 完整版本、模型原始输入输出、计费记录及 begin manifest 继续保留。内部 chunk 数不是模型工具次数或模型 token。

新增三项纯 CPU 协议用例通过：实际控制器 JSONL 编码接收器完成超过 33 MiB 的替换加重命名，36 个小帧只产生一次逻辑操作；另检查全部拒绝边界及临时文件回收。初次大包用例发现元数据键排序改变严格树哈希，编码器已改为保留原插入顺序，只重跑该失败用例。还修正了未运行 draft 中用缩进 JSON 写单行管道的断帧问题；新 wire 明确使用单行 JSONL，磁盘审计 JSON 可继续缩进。未执行 Docker、API、GPU、公开测试子进程或任何先前受阻动作，也未在此子任务打包。具体记录见 [managed-upload validation](../../artifacts/software-benchmark-v064/managed-upload-validation-r1/validation.json)。
