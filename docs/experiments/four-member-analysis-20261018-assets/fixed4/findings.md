# v038 固定四人：结果与轨迹原因分析

数据截至原24次冻结运行；本次2026-10-18只读抽取。O1为固定双人，O2为固定四人，O3为双人起步可扩编但实际未增员。三组各8次、同一50万token团队预算。本分析覆盖全部8次O2及job-policy、room-bookings四个配对块中的O1/O3，共16条原始轨迹；其余O1/O3只使用既有完整汇总。

**核心判断：四人组从3/8降至1/8，是少2次成功、下降25个百分点。原始过程更支持“同一总预算下，多分支阅读/实现未汇聚，单分支验证修订深度不足”，不是已证明四人本身有害。**七次失败全部没有正式提交；具体代码/API错误、未测试或改后未复验发生在预算终止之前。多数槽没有context拒绝，提前退出也只出现在唯一成功槽，均不能解释全部下降。这里只描述有限配对差异，不宣称统计显著。

## 四个最有解释力的配对轨迹

以下“机会N”均为相应槽`runtime-opportunities.jsonl`第N行（从1开始）。`exp#N`是`experience.jsonl`原始`sequence`，相应文件第N+1行。每条路径均在`evidence.json`的`episodes[*].source_files`；本文链接直接指向原机会文件。

### 1. job-policy / 101：四个分支都实现，仍未形成一个可交付分支

[org-r0-O2-s0](../../../../runs/software-organization-v038/root-0/actual/episodes/org-r0-O2-s0/runtime-opportunities.jsonl)：四人分别在自己的工作区写过`policy.py`和`consumer.py`，没有消息、整合、固定或提交。004的测试在机会20返回`module 'schema' has no attribute 'In'`（exp#337），机会28又返回`Schema.__init__() got an unexpected keyword argument 'exclude'`（exp#467）。003机会31错误为`'dict' object has no attribute '_schema'`；001机会37仍将合法队列拒绝；002机会38因不存在的`optional`参数失败。004与001随后继续改文件却没有复验，002先触及context，其他成员随后触及共同预算。

配对[org-r0-O1-s0](../../../../runs/software-organization-v038/root-0/actual/episodes/org-r0-O1-s0/runtime-opportunities.jsonl)的001也先在机会17测试失败，但随后修订，机会31通过、33正式提交（exp#551；累计团队384,987 token），最终R=1。其搭档随后继续消耗108,398 token而未完成自己的分支。O3同seed仍失败，说明并非双人必然成功。

**可观测阻断：**四人槽五次测试均未全过，且没有固定提交；代码/API错误确实存在。**机制推断：**共同费用分散在四套独立实现，而未将发现或成果汇聚成一个修正完成的版本，可能降低了单分支闭合机会；不能证明删去某个成员后可复现双人成功。

配对[org-r0-O1-s1](../../../../runs/software-organization-v038/root-0/actual/episodes/org-r0-O1-s1/runtime-opportunities.jsonl)的002机会17测试失败、19修订、21测试通过（exp#350）、23固定、25提交（exp#418，团队280,540 token）；O3同seed也在001经历多轮修订后成功。O2的阅读/格式开销与缺失修订闭合是记录事实；“减少人数就一定能把这些费用转成有效修订”仍是待验证推断。

## 原因的证据等级与边界

- **直接观察：**所有四人失败槽无固定提交；多数成员没有测试或没有完成最新版本复验；关键配对反复出现实际不存在的schema属性/参数和实现逻辑错误。共同预算确实阻止继续调用，但它是停止机制，不自动证明无限加预算就能成功。
- **有轨迹支持的机制推断：**成员增加没有增加团队token，总模型调用约相同，更多分支各自读取和实现，却没有消息/任务分工或成果整合把探索合起来。每成员约10至11次调用常不足以完成从阅读到验证修订的完整循环。模型能力与API使用错误和组织资源分配共同出现，现有记录不能独立识别各因素贡献。
- **不能作为主要通用解释：**四人组只有两名成员遭context拒绝；六次四人槽没有该事件。唯一两次done退出都在成功槽。四人组唯一整合也在成功槽，失败槽没有整合，故不能把多人失败概括成“合并冲突”或“队友退出”。
- **实际协作证据有限：**O1/O2/O3全部工具级`send_message`和招募调用为0；O2没有创建任务，七次失败无整合；唯一成功由001自己的版本完成。重复阅读不一定全无价值，独立探索也可能帮助发现不同解法，但本批没有可靠收益链把这些成本连接到最终成功。
- **不可外推：**四个人工业务root，每root两个seed；O1/O2仅4个配对出现胜负差，O2为1胜3负，其余4平。只能说观察到下降及上述过程模式，不能说“统计显著下降”或“所有四人架构都会下降”。

## 证据定位与抽取范围

`evidence.json`记录8次O2及8条选定配对轨迹，原文件路径、原JSON字段指针、原JSONL行号与experience事件序号齐全。`episodes[*].members`包含原费用、分析阶段费用、测试次数、编辑/阅读路径和原终止原因；`actions`包含每次机会及少量动作/测试摘录；`model_calls`把完整费用关联到原响应和工具事件。失败测试示例为原始公开测试回包，本文不据此假定每条回包都被后续模型完整读取或正确理解。

必要核对仅在抽取时检查逐成员活动费用之和等于原费用：8次O2、1次成功、336次真实输出调用、3,940,896 token。未重跑任何模型、测试、验收或训练，也未对旧轨迹重新评价。
