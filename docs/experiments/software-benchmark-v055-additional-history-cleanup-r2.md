# v055 追加历史清理与DeepSeek结束后的自动回收

## 用户要求与实际范围

用户要求继续清理无用历史数据，并核查DeepSeek各组实验结束后是否自动释放磁盘。本轮只处理当前明确终态共享缓存、已结束异常回合的展开根目录、经当前依赖排除的旧实验文本；不删除正式补丁、候选、评分、账本、模型权重或Docker镜像。原三卷2% root预留与项目100/128GiB门保持，本轮收益只统计真实数据回收，不再次计入此前643.856GiB预留配置释放的普通可用容量。

## 已落实的自动清理

23:35附近只读审计确认，DeepSeek正常闭合2652回合的actor/rootfs与公开测试rootfs均无残留；480份预热初始化回执均passed且记录临时clone已在静默后清理。正常闭合包括测试返回明确失败码的可判定情况，不要求模型代码通过官方测试才释放临时环境。

共享模板由实际active/running的`proworksim-v055-cache-reclamation-r2.service`自动回收，每10秒最多4项。按题核对Qwen三组和DeepSeek六组共九个消费者及其所有评分均终态、原cache独占锁、模板身份、进程/cgroup/scope静默及无内部mount。23:34审计时累计323个任务模板已回收，回收数继续变化。

因此清理不依赖“整组结束”钩子：正常临时环境按回合释放，共享模板按题释放。DeepSeek六组先结束时，Qwen尚待运行的同题模板保留；不需要等待Qwen全部500题结束，只要该题九组均闭合即可清理。PROJECT的managed-world、版本、补丁、候选及账单属于正式实验记录，保留；没有整组目录无条件删除。

技术未知的唯一现场不会直接自动删除。原63项及主盘53项是固定有限归档，不会自动接纳后来异常；本轮新增固定51项仍是独立有限批次，后续新异常继续留在异常集合。没有额外添加永久删除守护器。

## 本轮追加措施

### 三份共享缓存

`django-14170`、`django-15957`、`sphinx-7748`原历史静默记录不充分，原watcher保守保留。本轮使用已有r2 fresh-proof机制，在原独占锁内重新核对27消费者及69个scope，全静默后用原严格deleter处理。23:41:44—23:41:50三项全部成功，实际allocated释放9,274,740,736B（8.637775GiB）；旧false记录保留，另写forward completed供原watcher识别，不重启模型或队列。

### 51个新终态异常根目录

固定名单与原63+53项完全不重叠：主盘9项、副盘26项、第三盘16项，展开副本actual allocated共169,918,124,032B（158.2486GiB）。51/51通过原claim scope锁内现场静默预检，另外13项历史静默不完整的现场排除。

新r2 wrapper仅扩展独立namespace、固定51名单与第三卷精确路径/device绑定；原GNU pax tar+zstd1、全部内容/元数据完整回读、再次静默/源稳定检查、同盘存包与100GiB底线不变。最多2个slot并行，各2CPU/2GiB/低IO权重；普通失败保留原现场并继续，不能证明清理worker已退出则停止新清理，不停止实验。

实际批次于23:44:47启动，服务`proworksim-v055-terminal-rootfs-archive-batch-r2.service`；原生状态与逐项日志/验证/释放回执在`runs/software-benchmark-v055/terminal-rootfs-archive-batch-r2`及`terminal-rootfs-archive-r2`。展开158GiB不是净收益，须扣保留压缩包allocated。批次首6项已实际释放约11.24GiB，后续结果按新快照另记。

### 旧实验文本

独立历史文本r2按固定名单处理v047、v050旧runtime/experience以及v049/v050 entries/admission。先进行当前host/plan/bindings/source引用排除和可观察同UID进程排除，再流式指纹、内容寻址gzip1、完整解压核对、原路径侧车和raw释放。已有v050固定14项及v053下载35项不重复。
