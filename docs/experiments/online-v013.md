# v0.13 共享模型直接在线学习与工作接口验证

日期：2026-09-26。依据 [v0.12 审计](../reference/online-learning-audit-v012.md)与[事前计划](../online-v013-plan.md)，历史 v0.12 不改写。本轮已完成真实共享actor两次在线更新与初始/最终冻结评测。**在线工程闭环成立；八个内部锁定案例的任务回报逐项未变，尚无工作能力提升证据。**规则与CPU控制不作为模型收益证据。

## 修订与设计

`read_alias` 和 `read_version` 成为真实世界命令；完整公开字段 schema 在真实 command 内检查，不猜业务版本、不丢弃歧义参数。角色只获得本岗位工具，完整原观察及确定投影保留。critic 使用真实 `in_progress/in_review`，非未来状态或奖励。短任务以真实准备前缀开始，当前动作与奖励从准备后计；交接、实现、复核与整链按唯一成果而非操作次数评价。

一套 resident actor/LoRA/optimizer 被全部岗位共用，独立中央 critic。窗口内固定有效身份，更新后同步新参数并清 KV。没有旧 D0/完整成功/多类支持的基础 RL 门槛；初始 critic 输出零，零信号明确零步。按当前窗口诊断 ID-VTDO 支持，不能跨权重拼接。代码与正式 JSON 见[配置](../../examples/online-work-v13/)及[理论对应](../research/id-vtdo.md)。

固定任务期限是实验终点，非业务自然成功；每岗位独立预算和固定外部时钟记录。所有模型计算使用 resident_direct，网络 HTTP 调用为0。历史 ModelPolicy attempt 字段为适配接口命名，不能算网络请求。

## 结果解释范围

全体来源仅一个 SQL 构造家族，整家族仍属 development。内部 train/dev/locked 标签只隔离预声明数值实例；固定 split_a 布局，不支持独立来源、信息布局、四项目关系或跨领域泛化。单岗位与团队结果分列；冻结初始不是同总预算算法对照。两轮参数更新即使完成，也只能证明在线工程闭环。O4、信息结构贡献、强基线收益另需条件与正式实验。

### 对“新事实”的进一步限定
