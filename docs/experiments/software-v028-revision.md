## 已落实的修订

两个稳定成员可以在编辑前通过受管消息协商；消息可关联任务和固定引用，不自动领取或消费代码。转交有通知，已结束/预算耗尽成员不接新责任；责任可归还。等待由新消息、补丁或责任唤醒，不重置预算；所有成员等待且无可达事件时明确阻塞。范围仍是预定义子任务上的动态职责，不是完整任务分解或经理Agent平台。

新Mapper从固定正确交付的净AST反向追踪修改和输入。完整WorldCore反例证明：无关注释、保留注释、撤销后重写均不再抢占“最早相关编辑”；保留且实际执行的项目契约测试可构成相关净工作。无关断言、不能追踪的部分定义合并或未完成工作不强行分类。它输出可观察净工作相对导入的顺序，不宣称因果贡献或任意SWE通用性。

正式Mapper控制保存8条完整程序轨迹，独立验收7正1负，映射4条after、2条before、2条unmapped；这些不是模型样本。原始episode/版本、验收、净语义证据和mapping在 `runs/v028-controls/mapper-controls/frozen-evidence/`，各摘要在其summary.json。早期16个开发控制的原始episode另存prearchive，不因缺失当时的验收落盘就事后补造原回执。

分配器数值不变，仅为新计划登记线性N、q0=b的单窗口变体，分列Helmert坐标斜率与b中心化C。G明确使用共同类别支持与覆盖先验，其原始轨迹坐标不同于I类内共享，并非完全无结构基线。

## 轨迹与未知保护

SDK事件与公开捕获逐条fsync；模型worker在真实生成开始前另保存完整原始请求，返回/异常后保存实际结果。常驻backend的渲染prompt、input/output token和采样概率账也纳入轨迹索引。固定交付后编辑仍在原始事件中，但不改变该交付的语义路线。

技术故障注入实际核验了：服务失败时无提交的局部验收R0另存diagnostic，正式结果为unknown/R=null、不可评分、不产生方法支持。原请求和无响应事实保持；正常预算、拒绝、格式终止及死锁不因此全部改成未知。

新监督只管理自己创建并绑定PID/start_ticks的进程，采用两worker各3 GPU小时的新预算，不重启旧队列；每槽严格冻结状态与RNG检查，不更新参数。根任务被中断时已产生的JSONL、版本和快照保留，不补文本或评分。source冻结为独立工作树，主分支整理来源或报告不改采样代码。
