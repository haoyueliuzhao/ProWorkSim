# PROJECT测试同步与预算收尾接口修订

本次只修订后继实现并做CPU控制。原实验继续暂停，不创建容器、不调用模型、不重跑旧题，也不改写原成绩或合法交付记录。

## 测试同步与通道恢复

15题Matplotlib的首次公开测试在同步文件时触发权限错误，后续测试因同一RPC通道已退出而失败。内容未变也执行chmod的问题此前已有v095修复；本次新v103 actor明确接入该实现：未改变的文件保留inode，改变内容或Git执行模式时使用自有临时文件并原子替换，不调用chown。真实父目录写权限不足仍然拒绝。

本次新增的处理是将**完整上传和候选身份均已核验后、公开测试启动前的PermissionError**限定为单次未执行反馈。它保留`executed=false`、`candidate_synchronized=false`及原错误，消耗已申请的测试机会，不自动重试。RPC仍可接受后续由Agent显式发起的请求，不再把一次文件权限拒绝放大为永久断链。

未执行反馈不能满足正式提交门槛。完整性错误、错题错版本、传输损坏、其他未分类异常，以及最终工作树同步失败仍终止；不会把它们伪装成测试已执行或可信闭合。

## 分页参数与SDK生命周期

新worker复用v090的四个分页工具修复：仅恢复被SDK丢弃的合法`cursor:null`，随后继续原参数精确校验。非法字段、改变路径和非空cursor丢失仍拒绝。实际SDK控制还补齐了该包装执行器的`close`转发，避免关闭会话时缺少SDK执行器生命周期方法。

## 剩余预算与实际输出上限

新DeepSeek PROJECT路径将每次输出预约收紧到现有余额可承担的范围，上限仍为32768。输入、上下文、历史和总预算不扩大；本地成员、共享团队、模型适配器、宿主现金请求使用同一个实际输出上限。Qwen路径仍采用原固定输出预约。

以pytest-5787当时4,883,127的已用token为起点，在**脚本化98304输入token**控制中，剩余116,873可支持18,569输出预约；新路径可以继续一次调用，旧32768固定预约会拒绝。该控制没有重放真实历史，也不证明模型当时一定会提交成功。它不代替模型测试、固定或提交，输入本身已超过余额时仍停止，未知费用预约不会释放。

该调整改变了后继执行协议，必须单独标记；新controller ready/result和运行alignment均记录修订身份。不能将其未来成绩混入原配置。

`software_benchmark_sdk_bundle_v103`显式选择`run_managed_worker_docker_v103.py`和`run_project_controller_v103.py`；原REF别名和旧v090／v095／v096源码保持。新包准备函数可构建后继运行包，本次没有执行大型打包、部署或解除封存。

- 8项预算CPU控制通过：多层预约一致、常规上限不变、输入不够则拒绝、其他预约保留、未知收费不重放、超量仍收费并停止、篡改测量拒绝和Qwen旧路径保留。
