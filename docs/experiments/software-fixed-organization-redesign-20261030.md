# 六类组织重新设计与实现边界

2026年10月30日。用户要求降低原六组的重合度，重新选取设计并更新文档。本次只修改设计文档，没有改运行配置、工具权限或调度代码，也没有启动评测。六组完整的来源、说明与组织图集中在[汇总报告第四部分](software-benchmark-results-and-organizations-summary-20261030.md#四-六类协作方式的重新设计)。

## 重新选择的依据

旧DIALOGUE与REVIEW均为两节点反馈结构，旧SOP与COUNCIL均为三人全互联并按阶段轮换；角色名称与轮转次数的区别不足以解释组织差异。因此移除DIALOGUE和COUNCIL，加入SPRINT和MATRIX，并重设其余组的组织规则。

新六组为CHIEF 4人、PIPELINE 3人、REVIEW 2人、PEER 3人、SPRINT 4人、MATRIX 4人。旧SOP改为按实际产物进入下一阶段的PIPELINE；PEER由4人改为3人。不同人数与职能配置本身也属于实验条件，后续分数不能直接解释为纯通信图效应。

六种机制并非理论上完全互斥，例如Scrum也包含自管理。此处要区分的是每组**实际决定下一项工作、接纳产物与处理分歧的主要规则**，不是要求六张无标签通信图在数学上全部非同构。

## 不能只改提示的六项机制

1. **CHIEF：集中决策。** 只有001可批准跨角色的任务分配和集成选择。已有任务的实际责任转移仍由当前owner发起offer、目标成员accept，负责人决策不绕过原权限。复核意见是建议，001保留最终组织裁量。
2. **PIPELINE：产物驱动交接。** 记录设计、实现、验证、集成阶段，以及任务、固定补丁、实际测试等引用。下一阶段只有在所需产物具备时才能进入；时隙用尽不等于成功。阶段退回必须指明缺少什么。模型自行判断技术内容，系统不注入参考修复或隐藏测试。
3. **REVIEW：版本绑定复核。** 记录002对具体候选的接受／返修意见；001修改代码后，旧意见不能自动证明新候选已经复核。复核者可在私有工作区检查和试验，最终代码由001整合。普通聊天中的“看起来可以”不自动成为有版本身份的复核记录。
4. **PEER：平等领取。** 三名成员具有相同的组织操作权限，均可领取无主任务，不能强占已有owner。001只有共同交付出口的职责，没有独占排序、派工或额外读取权；任务冲突通过显式协商和原转交协议解决。
5. **SPRINT：周期性目标与检视。** PO管理工作项排序，开发者管理选择与实施计划，SM促进流程。记录周期编号、共同目标、选定工作和真实产物检视；目标不因遇到困难就任意改变，实施计划可以根据新证据调整。工作机会数定义的周期长度事前冻结，不按成功分数延长，也不把周期末检视做成禁止提前交付的门槛。
6. **MATRIX：两条决策责任。** 项目协调者确认工作范围和优先级，技术负责人确认接口及技术一致性。任务保持单一实际owner，两类意见以独立元数据绑定任务修订和候选版本；没有协商一致不能单方覆盖。缩小设计仅研究一个项目内的双权责，不能外推跨项目资源共享效果。

这些记录至少应绑定成员身份、任务修订、候选版本、真实证据引用和事件序号。记录失效、缺失和组织冲突应产生可追溯的局部阻塞，不得伪装成模型代码错误、环境崩溃或整个队列停机。

## 与现有实现的关系

现有v065已实现固定成员、合法直接通信边、预设行动窗口、共享预算、独立会话与私有历史，以及仅001正式提交。任务板、公开固定补丁、显式合并和offer／accept责任转移可以复用。**旧实现没有上述组织决策权限、产物阶段门、复核状态、周期状态或双权责协商。** 不能把旧22项CPU检查作为新方案的验证。

后续应在新的组织协议版本中增加这些状态与检查，保留底层文件、搜索、测试、固定和提交能力；岗位名称不自动改变文件ACL。工具操作与组织记录的实际开销均计入同一团队预算，不允许用后台免费Agent补齐计划、复核或集成。

所有组保持同一底座、共同工具基础能力与同一团队总额B。通信与阶段差异是组织条件，不能暗中给某组额外命令入口、隐藏验收或参考代码。代码端点始终锁定001闭合时唯一最终工作树；合法交付仍按原项目证据记录，组织协议遵循情况另外保存。不因组织规则未完成而删题、重采或改选其他成员候选。

当前运行层是逐机会推进的single-writer harness；图中的多条分支不表示已经实现物理并行。是否引入并发，以及具体周期／窗口配额，应在后续统一部署中单独冻结，不能把未验证的加速写成组织收益。

## 后续最小机制验证

每组至少验证一个区别于其他组的行为：非负责人派工被CHIEF拒绝；缺交接产物时PIPELINE保持原阶段；候选变更使REVIEW旧意见失效；三个PEER成员都能同权领取；SPRINT记录目标与周期检视且开发者保有计划权；MATRIX的单方确认无法覆盖另一条责任线。共同验证任务owner唯一、私有信息隔离、预算守恒和候选导出唯一。

这些是**待实现、待运行的验收条件**，本次没有执行或声称通过。正式任务、模型、预算B、seed、周期长度和调度配额仍未冻结，实验队列继续暂停。

## 来源与适配边界

六组来源已在各自图旁标明。所给Baker的Wiley链接实际为作者2002年《Chief Programmer Team》综述，其中列有1972年原论文；不把该网页冒称1972年论文全文。Scrum采用[2020官方指南](https://scrumguides.org/scrum-guide.html)，明确为单issue短周期适配；矩阵制补充了[Galbraith作者网站的1971年原文](https://jaygalbraith.com/wp-content/uploads/2024/03/galbraithmatrix1971.pdf)。固定人数、元数据检查和harness内的组织门均属本项目设计，不声称完整复现原研究。

ChatDev／CAMEL的对话机制可作为具体组内通信方式，AgentVerse的反馈讨论也可作为局部策略，但本轮不再将它们单独算作新的组织。AutoGen是可承载多种组织的框架名称，不能仅因换用该名称就增加一个架构条件。
