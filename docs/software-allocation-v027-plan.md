# v0.27 软件协作中的在线经验分配协议

日期：2026-10-02。依据用户提供的[当前审计](reference/audit-v026-next-software-v027.md)修订。主研究对象是经验分配对更新后团队工作的作用；软件工程提供可执行载体，不另立通用编程模型训练目标。本文区分已经实现的开发模块、CPU 控制和仍待冻结的真实模型实验，不把建议规模写成执行结果。

## 本轮修订范围

保留 WorldCore 的权限、不可变版本和操作账，保留 OpenHands SDK 接入、原始成员投影、共享 actor/critic/两个优化器及实际 actor 权重入口。旧零售 SQL 载体进入历史与迁移控制范围，不继续扩展为主实验；v0.26 原评分、加载失败、中断、恢复及成本不变。

并行补齐三个直接缺口：软件工作副本与任务组织；通用第一阶 B/G/I 配置；任务来源与用途划分。软件有效性和工作路线 Mapper 连接既有 TeamRollout、MemberView 与支持统计。对比入口复用现有更新器，不新建训练后端，也不把多个 Agent 框架叠加。

实施和核验记录见[对齐报告](experiments/software-alignment-v027.md)。原理论入口完整保存为[V1 至 v0.26 档案](research/id-vtdo-v1-through-v026.md)，[当前理论入口](research/id-vtdo.md)给出机制—实现—证据状态表。本次只获得粘贴审计正文；其中引用但未提供全文的图文稿、下载附件不冒称已经读取或完整实现。

## 软件工作合同

两名稳定成员各有独立会话和代码工作副本，都能阅读、编辑、测试、固定补丁和集成。公共任务板允许领取、委派和声明依赖；原子领取防止同时占有，委派只改变后续责任，不改写已生成动作的成员归属。环境不给出最终分工、代码答案、教师轨迹或自动完成的交付。

主接口是文件、定位替换、diff、实际测试、固定 patch 和集成，不要求模型为每次代码修改额外填写 SQL 式 basis/adopt 表。系统在下层记录源版本、补丁作者、真实输入与输出、任务责任、冲突和测试绑定；声明依赖或发消息本身不证明伙伴成果被消费。

首批仅包含两类目标：接口生产者—消费者联合变化；共享模块上的交叉功能与集成。分别检查双方要求可共同满足、修改会对另一部分产生实际后果。无关 issue 并排处理不能直接充当协作任务，不可共同满足的要求不能进入正常成功分母。

开发实现可以复用已有 Marshmallow 源码和独立验收边界。其用途固定为 `interface_development`，不重新充当训练样本、独立确认来源或新来源泛化证据。父进程对固定提交的实际 API 结果作判断，不采信可修改测试框架自行打印的成功；各补丁独立测试和最终集成代码通过分别记录。

成员串行共享一份模型，也可以研究职责选择与产物依赖；本协议不从这种执行方式声称真实并行加速。代码工作副本隔离、任务板并发安全和模型推理吞吐是不同事实。

## 来源与用途先行

训练任务主来源采用 SWE-smith 的仓库环境、任务构造和验证入口；SWE-Gym 为备选，不同时建设两条训练管线。采用的是任务与执行环境，不自动采用教师轨迹、SFT 或外部训练配方。[软件来源说明](research/software-sources-v027.md)记录官方入口和可核对边界。

在组合需求、信息分布和错误初态派生以前，先冻结四类用途：接口开发、策略训练、贡献开发、独立确认。来源标识覆盖仓库、commit、issue/任务、目标补丁、测试及共同派生祖先；共享来源形成传递簇，不能仅因数据集名称不同就当作独立。首版准入采取保守的仓库用途隔离，后续若研究同源划分，需单独明确更细粒度规则和可支持的主张。

真实任务清单尚未从 SWE-smith 导入并完成本地环境资格时，清单保持 pending；下载入口、可执行导入规则、CPU manifest fixture 都不等于真实任务已准入。程序见证、历史 Marshmallow、教师输出及不属于当前参数窗口的经历不进入当前模型支持。

外部评价分工为：内部独立软件协作确认为主比较；CooperBench 固定原生协议为补充；SWE-bench 固定子集用于个体代码与回归；AsynCodeBench 暂为待审计候选。CooperBench 原生逐 feature/逐 patch 结果不改名为全部补丁集成正确；若另外做组合测试，明确标为本项目附加指标。

## A 有限载体开发与算法实现并行

审计建议“4 个开发情境 × 2 次重复 = 8 条冻结参数联合经历”，只作为待评估的开发规模。当前已有的两个接口开发控制不冒充四个正式情境。本轮不继承 v0.26 的等卡期限、GPU 号、8 小时上限、学习状态终点证明或恢复授权。

真实模型 A 启动前须冻结具体情境、用途、初态、种子、模型完整状态、工具/调度协议、每成员决策预算、context/output、资源上限和停止规则。CPU 见证除可完成外，还应报告完整请求长度和探索余量，不能以仅剩几个 token 的存在性路线替代模型正常工作容量。至少保留合同矛盾、虚假测试成功、独立补丁通过但集成失败等负控。

A 只回答模型是否真正读、改、测、交付，能否选择有后果的分工和依赖路线，以及实际行为是否绑定到原始成员动作。允许少量预声明的全信息单人诊断定位编程/协作瓶颈，不要求团队先超过单人或达到稳定高成功率。先复用 9B 执行器；仅当小型任务基本工作不可达时，才单独比较一个代码适配候选并固定共同模型，不恢复无上限选型。

软件角色、任务及 critic 特征语义改变后，需为新实验固定共同的完整学习起点并重新通过必要准入。旧 SQL 的 3/3 计数或旧概率门不能自动证明新软件窗口已经完成完整状态迁移。首个 B/G/I 比较必须共享 actor、critic、两个优化器与声明的随机状态。

## B 预声明当前支持窗口

正式采样前，根据 A 的任务与成本结果固定每个精确情境的重复数 M、类别、最小频数、所有原始槽及总预算。M 暂不填写为 8、16 或更大的习惯数；不在看见支持不足后追加样本直到凑齐。

每个精确情境和稳定成员分别报告原始 M、类别计数 n_z、可重配 n⁺、v=n⁺/M、b_z=n_z/n⁺。保留启动失败、未知、可信失败及无自身动作成员；它们不能通过删除分母或伪造动作变成可配置支持。

方法类别来自实际责任与产物路线，如集中交付、分工后顺序消费、独立分支集成、发生真实冲突后的解决。声明某个 task/dependency ID 不是类别成立的充分证据。Mapper 只读实际工作账、固定版本与调用关系，不使用开发/确认成绩给轨迹贴有利标签。

不同情境指纹、初态、业务协议、参数窗口、角色布局和来源用途不能拼池。工作完整有效性、成员自身实际 token 资格、类别频数分别检验。软件 reward 已知为零的可信经历仍可按共同基础规则处理，不因方法无效就丢掉所有训练目标。

有至少一个真实可配置块即可研究局部作用；其余块与可信残余保持单位权重。若全部没有自由度，本次有限配置试验停止，不默认追加昂贵 Q=B 更新。这不改变完整在线算法对可信残余的定义，而是本次有限试验的停止规则。

## C 三种配置的共同条件比较

| 方法 | 输入与选择空间 | 改变的内容 |
| --- | --- | --- |
| B 基础 Q=B | 同一当前原始经历与共同完整状态 | 不作组成干预 |
| G 一般成员—轨迹重加权 | 同一合格分支、同类开发反馈、相同权重约束 | 根据原始成员轨迹的开发扰动结果选权 |
| I 第一阶结构化成员配置 | 同一合格分支；实际方法类别、依赖及稳定成员位置 | 在类别/成员块内估计价值并选配置 |

G 与 I 都必须有可用的候选和有限求解规则，不能给 G 无效的高维随机搜索或额外严格的重配范围。每种方法的自由度、所需成对探测数量、实际外层预算与未使用额度都记录；当冻结预算不能覆盖声明方向时，不静默删掉对照方向。

C 是移动训练比例对更新后开发工作效用的有限差分估计，来自相同学习起点、训练经历、开发清单和配对随机状态的试训回执。当前没有跨窗口校准标签，不宣称已建立可靠结构贡献预测器。N 仅来自当前真实支持的覆盖不足，不替代价值或不确定性；相应覆盖锚和基础锚进入明确目标，不能继续固定 beta=0 后声称完整 C/N 已启用。确切目标、候选、约束及回退见[配置器设计](design/experience-allocation-v027.md)。

约束保持情境与成员份额、合格分支质量、可信失败残余、原始分母及比例界。I 的 q/b 由既有支持物化器产生；G 在同一合格原始成员轨迹上物化受约束权重。二者均只作用于对应 actor 目标，不改变 PPO 概率比、critic 目标、优势计算或基础信用配方。

未知开发回执不能填零，也不能因未知删除固定评价槽。缺失配对或不可识别方向按预声明规则回退至基础配置，并记录原因。独立确认输入不能参与候选生成、开发有限差分或最终选权。CPU 合成回执只验证这些数值和边界，不是配置效果实验。

## D 独立确认与下一窗工作

主要量为 ID 相对 B 和 G 的更新后独立工作效用差：

`Δ_ID−B = J_test(θ⁺(Q_ID)) − J_test(θ⁺(B))`

`Δ_ID−G = J_test(θ⁺(Q_ID)) − J_test(θ⁺(Q_G))`

开发集只用于配置选择。确认集在选权前已锁定，预留执行资源，不按开发最优或确认结果换模型、情境或 seed。共同初态评价可以辅助说明基础学习，但不能替代分配主对照；不把新软件绝对成绩与旧 SQL 分数相减为学习或配置增量。

首窗三方法消费同一批当前经历。正式更新之后，各自新策略重新进入世界采集后继经历；不交叉借用另一分支、初始策略或程序见证的后继轨迹。后继窗口拥有各自的 policy/window 身份和实际 RNG 记录。

首轮优先保留两个可拆分消融：成员共用权重与成员条件化；仅信息关系与加入任务/责任/产物依赖。联合探测、图选对/随机选对、去 N 或锚留待第一阶主比较后分别冻结，不能一次增加全部机制而无法解释差异。

## 成本与报告口径

| 报告层 | 应回答的问题 |
| --- | --- |
| 功能和交付 | 两项要求、组合行为及回归是否正确，是否固定交付 |
| 协作过程 | 谁实际承担任务，哪些真实文件/补丁被消费，如何集成与解决冲突 |
| 学习结果 | 更新后在相同评价条件下是否改善 |
| 配置增量 | 相对共同条件的 B 与 G 是否改善 |

消息数、领取速度、测试次数、停止时刻只作诊断。失败但少做工作不是效率收益，多做必要回归也不自动扣分。完整成本包含数据采集、候选试训、开发执行、正式更新、独立确认和外层计算；正式更新次数另列。

固定正式更新预算用于机制比较。若要研究相同总成本的学习效率，另行事前规定 B 如何使用节省的外层成本做有效训练，不要求基础组空等。本轮 v0.26 的 2.47 GPU 小时不能预测软件训练费用。
