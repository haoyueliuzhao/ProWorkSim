# ProWorkSim v0.1 实现说明

## 1. 设计取舍与验收范围

本实现依据用户提供的两份资料，优先落实阶段 A“工作世界成立”，同时打通阶段 B 所需的真实模型经历编译。没有将“角色模型共同训练”“开放网络检索”“完整办公 GUI”或“训练收益证明”纳入已经完成的功能。

项目族收敛为**已有经营估值模型的假设调整、敏感性分析与解释**。这是透明的合成经营模型，不宣称等同于真实投行 DCF/LBO 的完整专业复杂度。工作范围按三种交付粒度控制：短回复不强制文件修改；文件任务不强制备忘录；连续项目才要求依赖成果同步与后续工作。

原始资料保存在 `docs/reference/`。原文中的 `chatgpt-content-reference` 是粘贴文本自带的不可解析引用标记，未被视作本项目重新核验过的文献链接。实现没有下载或复用 APEX 受限任务包。

## 2. 八个逻辑模块

| 设计模块 | 实现 | 职责 |
| --- | --- | --- |
| Project Designer | `designer.py`, `schema.py` | 生成项目、角色、来源谱系、交付与信息分布配置 |
| World Compiler | `compiler.py` | 建立真实旧文件、版本历史、当前披露与任务覆盖层 |
| Environment Kernel | `kernel.py`, `storage.py`, `spreadsheet.py` | 绑定身份、真实工具、离散时钟、文件版本、恢复 |
| Staff Runtime | `runtime.py`, `staff.py`, `tools.py` | DeepSeek 目标模型与固定条件响应策略 |
| Workflow Engine | `kernel.py` 的任务和事件处理 | 提交、审阅、返工、阻塞、需求版本和后续工作 |
| Validation Service | `validation.py` | 对绑定提交版本独立验证数值、证据、文件和可重算性 |
| Learning Bridge | `learning.py` | 保存真实调用、监督掩码、RL 交换格式与来源隔离 |
| Curriculum Controller | `curriculum.py` | 仅开发集反馈、可解释配额、并行生成新的训练世界 |

世界内部的负责人和审阅者是确定的条件策略，目标分析师可接入真实模型。合成器、独立验证器和课程控制器在世界外部运行。`baseline.py` 是透明的可行性见证程序，只访问分析师工具，不读取隐藏合成事实；它没有被描述成训练后的模型。

## 3. 世界文件与事实边界

```text
world/
  workspace/                         # 分析师可通过工具访问的实际文件
    evidence/financials.json
    artifacts/operating_model.xlsx
    artifacts/research_memo.json
    policies/working_guide.json
  control/                           # 后台及角色私有状态
    spec.json                        # 合成定义，包括尚未到达的外部材料
    state.json                       # 角色、工作、事件、版本索引、调用和评估
    role_files/private/manager_scope.json
    versions/<artifact>/<version>/...# 每个已提交版本的完整实际文件
    world.lock
```

每份披露记录来源 ID、公开逻辑时间、期间、单位、定义、材料类型和数值位置。来源是明确标记的合成披露；情景假设在负责人口径中标记为假设。隐藏参考计算仅用于评价，不能通过分析师工具检索。

旧披露为 `financials/v1`；项目开始时到达的披露为 `v2`。连续项目接受第一轮之后，修订披露成为 `v3`，生成独立的 `work-2`。新工作依赖旧工作的接受状态，旧工作及其已批准文件版本不被重写。

合成历史包括真实旧模型、旧备忘录、来源版本、初始披露事件和历史邮件。v0.1 没有生成完整多员工历史对话，也没有声称这些历史由专家真实执行。

## 4. 信息与权限

`WorkerSession` 在可信运行器中绑定角色。模型工具参数没有 `actor_id`；调用者不能通过工具参数变更身份。未知对象和无权限对象返回相同的不可用错误。

权限作用于文件内容、历史版本、搜索、邮件、附件与批准操作。只有 reviewer 具有正式批准权。文字邮件没有隐式批准效果。经理私有口径不落在 `workspace` 中，分析师需要读取获准的历史邮件或请求经理回复。

观察只包含当前角色、任务、时钟及未读消息数量，不自动附上重要证据、私有口径、未来事实或独立评价规范。邮件列表不会标记正文已读；读取动作更新各角色独立的访问记录。

存储与工具是可信服务端。目标模型没有任意 Python、宿主机文件路径或 Shell 工具。操作者 CLI 中的 `--role` 是管理入口，不是对不可信用户开放的认证服务。当前隔离适用于模型经工具调用的执行方式；若未来增加任意代码执行，必须提供独立容器、挂载白名单和后台隔离，不能直接把当前 Python 进程暴露给模型。

## 5. 实际文件与事务

每次修改保存完整文件版本、SHA-256、所有者、逻辑时间和显式输入版本。工作簿公式和结果均保存在 XLSX 中；没有单独的“正确后台工作簿”。独立验证从实际提交版本读取文件。

工作目录保存当前已提交版本的物化文件；不可变版本目录保留真实历史字节。状态变更使用同一世界的文件锁及原子 JSON 提交。单个错误动作回滚内存状态并恢复已提交文件；进程中断后的启动恢复使用已提交版本文件，不会替模型修正业务公式。直接绕过工具改写 `workspace` 不属于已提交操作，下次恢复会以已提交文件版本为准。

不同世界可以并行运行；同一世界的变更串行化。模型调用用 `call_id:tool_call_id` 幂等键关联到已执行动作，防止进程在工具执行后、记录响应前中断造成重复提交。

v0.1 使用单文件 JSON 状态而不是数据库。它适合机制原型与小批量运行，完整上下文逐次保存会增加存储开销；跨机器调度、持续高并发、目录 fsync 级断电持久性和分布式事务未实现。

## 6. 表格与计算

`openpyxl` 负责真实 XLSX 读写。它本身不计算公式，因此实现了受限表达式计算器，并将实际求值结果写回 XLSX 缓存。[openpyxl 官方说明](https://openpyxl.readthedocs.io/en/3.1/simple_formulae.html)

支持：

- 数值、单元格与跨工作表引用、绝对引用 `$`、有限范围。
- `+ - * / ^`、括号、百分号。
- `SUM`、`MIN`、`MAX`、`ABS`、`ROUND`；ROUND 的半数边界采用远离零方向。
- 增加工作表、编辑输入或公式、按实际文件重新计算。

不支持名称定义、外部工作簿、宏、动态数组、完整 Excel 函数集和任意代码执行。未知函数、循环引用、除零等产生显式错误；错误公式仍可写入，由审阅或独立验证发现。工具限制每次最多 500 单元格、最多 2000 行×100 列、范围最多 1000 单元格，以及表达式长度和指数大小。

计算工具只执行数值 AST 白名单，支持带变量表达式。它覆盖当前任务所需的计算与简单转换，不是完整 Python 数据分析沙箱。

模型语义：

```text
预测收入 = 披露收入 × (1 + 增长率)
经营利润 = 预测收入 × (披露经营利润率 + 情景利润率增量)
净利润 = 经营利润 × (1 − 税率)
权益价值 = 净利润 × 情景市盈率倍数 − 净债务
隐含股价 = 权益价值 ÷ 股数
```

敏感性表对两种增长率和两种利润率增量求隐含股价。短回复另用“已有模型股价 ÷ 指定披露 EPS”，不混同于模型自身 EPS。

## 7. 工作流、依赖与审阅

工作依赖保存为 WorkItem ID；产物依赖保存为输入 ArtifactVersion 引用。更新上游会传播 `possibly_stale` 标记，不改写下游文件，也不会更新它记录的输入版本。

状态集合为 `open / in_progress / blocked / in_review / revision_required / accepted`。支持并行可用的工作列表、实际反馈回环和连续需求版本；初始原型只有一个主执行者与两个连续阶段，并非任意复杂组织流程引擎。

提交绑定当前工作要求及指定产物版本。提交后再次修改相关产物，会使待审提交失效。审阅通过调用者权限检查才能批准；正确提交可直接通过。可见审阅检查公式错误、敏感性表存在、备忘录与提交模型的一致性等，不读取隐藏正确答案。

外部事件由编译器定义。内生事件由实际行动触发：询问形成异步回复，提交形成针对实际版本的审阅，接受第一轮后产生后续披露与范围变更。所有工作人员事件记录实际角色及文件变化。

逻辑 tick 用于事件排序；不会换算成业务工作小时。模型等待时间单独保留秒数。

## 8. 独立评价

独立评价按提交版本执行，保存所有历史提交的结果；评价版本变更保留旧记录。

| 层次 | 已实现检查 |
| --- | --- |
| 运行真实性 | 有真实提交动作、文件字节与已记录哈希相符 |
| 业务/产物正确性 | 来源位置、期间、输入口径、输出值、敏感性结果、依赖版本、跨文件一致 |
| 可重算性 | 修改提交工作簿的两组输入后，重算全部关键输出和四个情景结果，与独立标量公式比较 |
| 专业交付质量 | 解释存在性与最小内容检查；专业充分性保留为不确定项 |

公式扰动仅操作内存中的提交文件副本，不改世界文件、不发正确答案给工作人员。测试证明，把正确结果全部硬编码仍会在扰动中失败。

业务接受不等于独立评价通过。课程和数据编译要同时参考评价有效性与具体版本，不能把“主管同意”作为事实真值。

## 9. 训练与课程边界

真实调用保存完整请求消息、工具定义、返回内容、模型标识、返回的 usage、时延和系统指纹；没有返回的 token ID / log probability 保留 `null`。DeepSeek 适配器直接调用 Chat Completions，保留模型实际返回的工具调用和可选 reasoning 字段。[DeepSeek 官方工具调用协议](https://api-docs.deepseek.com/guides/tool_calls/)

SFT 只选择独立通过且业务接受的提交区间内的目标模型调用；发生失败的前缀仍可作为历史上下文，但其监督权重为零。其他角色与工具输出始终是观察。存在工具错误、分支继承记录、规则基线和测试 fixture 不形成正向 SFT。

这只是**结果通过条件下的候选监督选择**，并不证明每一条推理或中间动作都是最优行为。掩码是消息级，训练后端还需要正确分词与格式适配。RL 交换格式保留真实动作和观察，但缺少精确行为概率时不能宣称可直接进行严格的 on-policy 优化。

谱系由合成种子确定，同源的不同交付粒度和信息配置进入同一 train/dev/test 分组。课程只使用 dev 的有效失败诊断；生成的新世界限制为 train 谱系。压力配额按失败计数平滑分配，并映射到现有信息分布和交付配置。不同失败标签有时映射到同一模板，不能因此算作新的结构多样性。

尚未实现模型权重更新、偏好对构建、训练后对未见结构的提升检验，以及外层课程相对静态配额的因果对照。后续首先应接入一个训练后端并冻结评价、模型和环境策略，再研究阶段 B–D。
