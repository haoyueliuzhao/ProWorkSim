# 二、停止原因已经定位：测量器没有理解“终止动作的返回可以没有后续生成”

## 1. 冻结函数为什么会漏掉这次退休

源码中的`no_followup_reason`主要检查：

- context容量；
- 团队预算；
- `completed`或后继`model_control(kind=done)`；
- 无可达事件等待；
- 执行故障、未闭合；
- 最后落入`unknown_no_actual_followup`。

它没有处理已成功执行的直接`retire_member`。而且，它主要扫描**反馈之后**的事件；本次退休动作的提交发生在其工具返回之前，不会再出现一次后继`staff_done`来帮助分类。

报告给出的实际顺序是：

\[
\text{模型提出retire\_member}
\rightarrow
\text{合法性检查}
\rightarrow
\text{退休动作提交}
\rightarrow
\text{返回退休结果}
\rightarrow
\text{该成员不再生成}。
\]

**这条流程本身是正常的。**既然成员已经执行永久自退役，就不应再要求它获得一次新生成机会，才能把自己的退休返回视为“没有丢失”。

本地用冻结函数原文构造`closed＋role_stops=retired＋较早退休工具事件＋无后继生成`的合成输入，实际得到`unknown_no_actual_followup`。这复现了**函数级漏项**，但不等于已经重演了原PT的完整证据链。

**原运行器按冻结门停止，没有擅自越过资格。**
