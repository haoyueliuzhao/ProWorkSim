# 二、数值诊断已经足够指向下一实现，不宜继续重复同类前向

## 1. N真正推进了什么

本轮最重要的数值证据是：

\[
\text{缓存增量重演}= \text{原采样记录},
\]

而：

\[
\text{完整无缓存、无梯度前向}
=
\text{完整无缓存、有梯度前向}
\neq
\text{原采样记录}.
\]

三者使用固定原token与身份；实际分支也记录了缓存解码的 recurrent 路径和完整序列的 chunk 路径。**因此，在这条请求上，下一步不应继续优先猜测token日志丢失，或将train模式本身当作已证实根因。**

同时，差异在增量位置的第0个decoder块后已经出现，不代表定位到DeltaNet单一算子。该块包含多项计算；当前位置、形状、投影、卷积及后续累计误差都可能参与。即使部分层输出相同，末端head和归约也仍可能出现小差异。**不应据此再机械地把一整层或全部模块升为FP32。**

这一次诊断的价值，正是让我们可以开始选择实现，而不是再做一轮“同样失配、更多日志”。

## 2. 前向完全相同，也可能得到错误梯度

用户报告对“不能detach过去LoRA状态依赖”的提醒非常重要。本次我用一个两步递归模型实际检查了这一点：

\[
h_1=2a,\qquad h_2=0.7h_1-a,
\]

其中 \(a\) 是两步共享的可训练参数，递归系数固定。比较完整计算图、函数式checkpoint和截断中间状态三种处理：

| 本地CPU处理 | 最终logit | 选定动作logprob | 对共享参数的梯度 |
|---|---:|---:|---:|
| 完整计算图 | 0.1 | −0.64439666 | −0.19000833 |
| 函数式checkpoint | 0.1 | −0.64439666 | −0.19000833 |
| detach中间状态 | 0.1 | −0.64439666 | **+0.47502081** |

**前向值和概率完全相同，梯度却反向了。**完整图的梯度还通过了解析式和有限差分核对。详细代码与输出在核验包中。

这只是数学实现示例，不是9B的新故障复现；它说明：

\[
\frac{dh_{t+1}}{d\theta}
=
\frac{\partial F_\theta}{\partial\theta}
+
\frac{\partial F_\theta}{\partial h_t}
\frac{dh_t}{d\theta}
\]

中的第二项，不能因为基座被冻结就忽略。过去token经过的LoRA仍可能影响后续状态。

这里需要保留的是**单次模型请求内部的参数依赖**，不是要求穿过数据库、世界工具或同事动作做可微反传。

## 3. 下一候选应是“函数式状态＋可验证重算”，不是直接把推理缓存打开梯度

建议只开发一个候选：

**显式传入旧状态、返回新状态；避免checkpoint重放依赖可变全局缓存；保留prefill和后续token经过LoRA的依赖；按需要checkpoint或重算以控制内存。**

它必须有两个验证层次：

**小模型层面：**与不checkpoint的完整递归图比较前向、梯度和有限差分；加入detach负对照，确认检查确实能发现依赖被截断。

**真实候选层面：**先用本轮固定序列检验目标路径，再用事先选定、未用于修复选择的请求验证；实际执行反向，记录完整梯度依赖、概率差和资源，而不是仅看 `requires_grad=True`。

PyTorch文档也明确提醒，checkpoint重算若与原前向不同，可能产生错误梯度；默认的非重入确定性检查主要核查形状、dtype和device，并不自动证明数值或梯度相同。:chatgpt-content-reference{index="2"}

**我不建议承诺这一候选必然在当前资源内通过。**如果它代价明显不可承担，或有限验证仍不成立，就应结束这条候选，明确选择是否另冻mismatch处理配方，而不是继续无界增加补丁。

mismatch路线可以参考成熟训练系统对rollout、old learner和current learner的区分，但它属于**所有算法共同使用的基础优化协议变更**。不能将校正权重 \(c=p_t/s\)、PPO比率 \(r=p_\theta/p_t\) 和ID‑VTDO的 \(q/b\) 混为一谈，也不能只把分母换成重算值，使初始ratio看起来等于1。:chatgpt-content-reference{index="3"}

## 1. 六例应按实际断点解释

## 2. 复核公开合同的缺口需要修，但不能抹掉模型的真实遗漏

- target必须是固定提交中的**result对象**；
