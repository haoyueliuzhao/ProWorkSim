# v0.36 任务组织汇报材料修订说明

日期：2026-10-09。

本次修订针对[汇报材料](../experiments/software-organization-v036-briefing.md)及[配套讲稿](../experiments/software-organization-v036-speaking-notes.md)的理解成本。原稿在解释操作机制之前展开统计和多组案例，同时使用事件编号、职责标签及评估术语，读者需要自行建立这些概念之间的关系。

## 表达和结构调整

正文按“初始条件、任务与负责人形成规则、第13号槽实际过程、其他运行方式、证据支持的结论”展开。开头直接说明模型在固定合同范围内自行拆分任务，并通过工具形成正式责任记录；补充合同、私有副本、负责人和槽号的含义。

第13号槽作为主例，使用五个连续步骤解释先编辑、后登记、创建者与认领者不同、整合冲突、同范围重复建任务以及最终提交。第00、05、14、12号槽作为简短对照，保留职责标签变化、交付集中和未登记仍行动的事实。事件编号、种子、原分类、完整统计及原件索引集中到附录；讲稿按相同五节组织。

## 事实口径

- 明确 `return_task` 清空负责人、退回待认领状态，不自动退还原委派者。依据 `software_collaboration_v028.py` 的实际实现。
- 保留固定补丁发布至少关联一个本人负责的任务这一条件，避免将自主组织解释成没有交付条件。
- 区分正式责任记录、实际编辑和最终产物保留；创建任务、消息、补丁ID或任务名称均不单独证明实际贡献。
- 保留全部16槽的统计、五个案例的原结果、未提交不补验的边界及原始文件SHA256。未将第13号槽验收通过改写成已确认有效伙伴贡献。
- 删除对整个项目“当前仍停止等待审计”的旧时态描述。材料只解释已结束的P2窗口，后续执行范围以项目现行指令和相应实验记录为准。

## 必要核验

对照现有初始化证明、初始化与调度代码、任务操作实现，以及第13号槽原始事件，核验机制表和主案例。其余案例与统计沿用原材料，并与已有P2结果报告核对最终提交与验收口径。文档检查覆盖修改范围、格式和本地引用目标。

本次仅修订汇报与讲稿，没有新增模型调用、重跑验收或更改实验原件；没有运行与文档修改无关的代码测试。
