# 三、四次更新实际强化了什么

## 1. 不应继续说“只有交接信号”，但信号分布确实很窄

本轮有三个不同层次的正向工作事实：

**8个A全部完成合法依据送达；1个A还完成了正确构建；1个B对准备阶段已正确的产物完成了当前独立核准。**

最后一项是合法的当前工作，不能因为没有修复，就否认它的复核价值。但它也不能证明模型训练接触过成功的错误修复链。独立实现、独立复核各4例均没有取得评分项。

按源报告的角色计数复算，173个正优势决策中：

\[
158\text{ 个来自A},\qquad15\text{ 个来自首窗成功B}.
\]

即约91.33%的正优势**决策数**来自A。**这不是91.33%的梯度贡献**，因为长度归一化、梯度方向、共享参数和优化器都会影响实际更新。

这表明下一步最值得研究的是：

> **怎样让已有学习信号继续作用于正确实现与复核，而不只是重复加强最容易取得的上游部分成果。**

## 2. 正优势覆盖拒绝动作，不自动等于算法实现错误

终局回报乘整段已采样动作的策略梯度，是一种已有的估计形式；失败探索也可能出现在最终有效的轨迹中。因此，21个被拒动作和15个无世界动作决定具有正优势，**不能直接证明这些行应该删除，也不能证明它们导致了能力下降**。标准策略梯度与reward-to-go的区别，需要从相应目标和估计量解释。:chatgpt-content-reference{index="7"}

当前更准确的判断是：

**终局信用粒度较粗；其对本项目工作学习的影响尚未隔离。**

不能根据事后结果只训练“看起来正确”的工具调用，否则会改变基础学习分布，并掩盖真实失败。

## 3. 部分回报与完整职责，本来就不是同一个优化目标

这点比“错误动作得到正优势”更基础。

考虑一个纯数学示例：

| 假设策略 | 平均部分回报 | 完整职责成功率 |
|---|---:|---:|
| 总能交接，但从不完成交付 | 0.2 | 0 |
| 15%完整完成，其余得0 | 0.15 | 15% |

前者在部分回报上更高，后者在完整职责上更好。**这不是本轮模型的已证实行为模式，只说明加性部分回报 \(R\) 与主指标 \(Y\) 不完全等价。**

因此需要分开两个假设：

**目标问题：**当前部分回报是否足够促进完整工作？

**时间信用问题：**已经取得的交接奖励，是否应该继续分配给其后的全部行为？

下一轮建议先检验第二个，保持终局 \(R\) 不变，避免一次同时改变奖励、学习率、模型和任务。

## 4. 四次更新不等于充分训练，16.77小时也不等于大量学习机会

当前代价主要来自少量长请求上的计算。只有四次整窗累积更新，完整职责正例仅一条。**不能因消耗了16.77 GPU小时，就认为模型已经接受了足够多的有效训练。**同样，也不能仅因更新少，就自动要求增加几十个窗口。

第四窗更新后有一个已选token的概率比超过1.2，这与PPO的裁剪机制并不矛盾。裁剪作用于优化时的代理目标，不是step之后每个token概率变化的硬限制；它也不是原同参数数值门失败。:chatgpt-content-reference{index="9"}

本轮已经证明参数和概率确实改变，**下一轮无需再以“参数必须变化”为主要验收终点**。

# 五、建议 v0.24：同终局合同的时间信用对照

## 1. 两条训练方法，一个共同冻结基线

建议比较：

| 条件 | 定义 |
|---|---|
| **冻结初始模型 \(\theta_0\)** | 不更新，用于工作能力参照 |
| **MC** | 沿用全部终局回报广播到各决定 |
| **Handoff-RTG** | 只将已兑现的交接奖励提前结算，其余仍在终点结算 |

这是基础RL实验，**不是ID‑VTDO算法贡献，也不是以前未完成MC/RTG运行的续跑**。

保持同一公共9B基座和fresh LoRA、critic、optimizer；保持函数式学习路径、精度、native compact、工具与权限、任务份额、机会预算、终局评分、学习率和原数值门。继续 \(Q=B\)。

两方法使用相同的critic结构与初始化，随后分别拟合各自定义的回报目标。不能让RTG沿用MC更新后的critic，也不能把两种目标混在同一个优化器状态里。

## 2. 只改变交接项的时间分配

设A中首次合法依据送达的实际事件序号为 \(s_h\)，episode终点为 \(s_T\)，原终局回报为 \(R\)。

候选账本为：

\[
r(s_h)=0.2,\qquad r(s_T)=R-0.2,
\]

\[
G(s)=\sum_{u\ge s}r(u).
\]

没有合格的当前episode交接时，仍然只在终点记 \(R\)。

这样：

| 实际成果 | 交接前的目标 | 交接后的目标 |
|---|---:|---:|
| 只有交接，\(R=0.2\) | 0.2 | 0 |
| 交接＋正确构建，\(R=0.5\) | 0.5 | 0.3 |
| 完整交付，\(R=1\) | 1 | 0.8 |

**终局总回报不变，但后续动作不再获得已经结束的0.2。**优势还要减去critic，所以目标为0不代表梯度必然为0。

重复交接不能重复记分，准备前缀不能获得当前信用。若某项临时结算后来不再满足终局合同，负的终点补差必须保留，不能截成0使奖励凭空增加。事件只能根据当时已经发生的事实定位，不用未来结果倒填“早已知道”的正确性。

现有 `online_signals.joint_return` 已经支持事件账本、终点一致性与总和守恒检查，可以复用。**但当前工作适配层仍需添加实际ledger，不能以为换一个mode字符串就完成了改造。**

这项修改不会给actor额外的oracle、奖励提示或自动业务修复；也不根据“谁看起来有功劳”删除其他成员的目标。

## 3. 必须承认：在当前归一化下，它是一个新的 surrogate 选择

标准策略梯度中，过去奖励对之后动作的梯度项可以在期望中消去。:chatgpt-content-reference{index="13"}

但当前分母包含成员在整条经历中实际产生的输出token数：

\[
T_i(\tau),
\]

而这个量受未来行为影响。源码确实使用“计划槽数×活跃成员数×该成员全部输出token数”。

本次人工数学例显示：两个后续动作概率各为1/2、使轨迹长度分别为1和2，先前奖励为0.2时，未按长度归一化的过去奖励梯度期望为0；加入这个随机长度分母后，可以变为0.025。

**这个例子不是本轮下降的根因证明，也不是宣布当前实现有bug。**它要求我们准确表述下一实验：

> **在相同终局合同与相同归一化下，比较两种时间信用surrogate，而不是声称它们梯度无偏等价、只改变方差。**

所有后续ID‑VTDO和强基线，都应共同采用最终选定的基础配方，不能把这一变化混进 \(q/b\) 的效果。

# 八、ID‑VTDO与后续路线：不要提前调权，也不要要求先获得显著RL收益

当前的经验仍不足以进行有效组成研究：每精确情境最多两条、最低类频数两条，最多只有一个达标类；完整basis/delivery重配置有效性也没有由本轮奖励自动建立。

因此，上述信用对照继续 \(Q=B\)，不同时启用ID‑VTDO。

但后续也**不应设置“基础RL必须先显著改善”才能研究ID‑VTDO的额外门槛**。真正需要的是当前真实方法支持、可信的学习与开发效用、共同起点，以及能够执行的配置干预。即使基础平均变化不大，已有不同有效方法且可以比较其学习价值，也可以开展有界Contribution研究。

相反，若只有交接或程序见证，不能用它们凑出完整方法支持；正确初稿、错计数、错金额是不同初始情境，也不能拼成同一 \(\xi\) 下的多样性。

下一轮结果应对应不同决策：

| 结果 | 合理后继 |
|---|---|
| RTG相对MC改善完整工作 | 在新材料与独立训练seed上复验，再决定是否作为共同基础配方 |
| 只改变优势分布，工作不改善 | 保留机制结论；下一步单独研究目标对齐、能力瓶颈或训练剂量之一 |
| 两种配方都没有完整工作进步 | 不证明RL不可学，但不宜继续原样扩大单臂窗口 |
| 出现可信多方法支持 | 另冻同条件密度与Contribution实验，不从不同方法或窗口拼池 |

既定的多个同领域benchmark方向可以保留，但近期先用好已经接入的D2变体，不新增一轮平台清单。要提出广泛协作迁移结论，之后仍需真正独立的原生协作任务，而不是更多同一家族seed。

## 最终推进建议

**v0.23已经给出了重要信息：当前配置能稳定完成真实更新，但这四次更新没有把稳定交接转化为更好的完整实现、复核与维护。**初评缺失限制了主估计，却没有留下一个可以靠补值变成正向的结果。

下一轮最值得做的不是“再训练一轮看会不会好”，而是：

\[
\boxed{
\text{修正有限测量歧义}
\rightarrow
\text{同终局合同的MC／交接RTG对照}
\rightarrow
\text{完整配对评价}
\rightarrow
\text{根据机制与工作结果决定下一因素}
}
\]

**保留同一个共享模型、已有可微路径和工作世界；不删失败、不重判旧结果，不把时间信用修订当作ID‑VTDO创新。用下一笔计算预算取得一个能够区分解释的实验，而不是再增加一条缺少对照的学习曲线。**
