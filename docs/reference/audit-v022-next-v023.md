## 审计结论

**v0.22 已经建立了当前运行组合的真实学习闭环。下一步应转向“参数更新是否改善实际工作”的实验，不再重复缓存诊断、同类反向验收或一次更新桥接。**

但本轮同时暴露出一个比数值问题更直接的研究障碍：**桥接所用的每成员四次决策，容不下完整复核的必要动作；实际更新的非零信号，也全部来自一个联合 A 情境中的“依据送达”，而不是正确构建、完整交付或有效复核。**因此，“更新成功”和“已经开始学习完整专业工作”仍需分开。:chatgpt-content-reference{index="0"}

本次定向审读了冻结方案、函数式 Qwen 实现、复核证据判据、训练投影、桥接脚本和 PPO 更新器，并核对 W1、R1 专项归档；独立执行了报告数字及损失标量的算术复核。**没有重跑 GPU 模型、WorldCore、grader 或 OS 隔离，也没有再次读取远端 checkpoint 张量。**以下将源码推导、归档结果和新方案分别说明。

# 二、三个最重要的审计发现

## 1. 四次决策不只是“预算偏少”，而是使完整复核结构性不可达

这一点可以从代码直接推出，不需要根据失败轨迹猜测。

桥接脚本明确将每名活跃成员限制为四次决策，每次至多执行一个世界动作。复核判据则要求当前 episode 内实际发生：一次 `inspect_submission`，读取固定提交的 code、result，读取所采用的 data 和适用 audit，随后再作正式判断。准备前缀不能冒充本轮读取。

因此，在当前四个不同对象和单动作接口下：

\[
\underbrace{1\text{ 次 inspect}+4\text{ 次读取}}_{\text{完整复核证据}}
=5\text{ 次动作},
\]

\[
\underbrace{1\text{ 次 inspect}+4\text{ 次读取}+1\text{ 次正式判断}}_{\text{完整有据复核}}
=6\text{ 次动作}.
\]

而桥接给出的上限是：

\[
H_{\text{reviewer}}=4<5<6.
\]

**至少桥接中的独立复核，以及依赖复核完成的联合 B，不可能在该片段内完整完成。独立复核甚至无法取得对应“完整证据读取”的部分奖励。**

这不是要求每次实验都必须成功，也不是要求模型执行唯一参考路线，而是必要条件没有足够的动作机会。它不推翻“短片段接入验证成功”，但意味着：

> **不能直接沿用四次决策，研究模型是否能通过这些片段学会完整复核。**

还应区分两种期限。任务本身规定有限期限，可以按该期限内的结果学习；训练系统只是暂时截断仍会继续的工作，则不能无说明地把后续价值当零。终止与截断的区别，会直接改变学习目标和是否需要自举。下一轮建议先采用能够闭合的有限工作职责，不同时引入跨片段价值估计的新配方。:chatgpt-content-reference{index="7"}

## 2. R1 的更新确实有效执行，但其非零信号只有一个来源

原四个训练回报为：

\[
(0,\;0,\;0.2,\;0).
\]

预更新 critic 值全部为零，所以 24 次决策中，8 次优势为 \(+0.2\)，其余 16 次为零，没有负优势。全部非零优势来自同一个 joint A episode 的“适用依据已交付”，并通过 `terminal_mc` 赋给 provider 和 implementer 的实际输出。:chatgpt-content-reference{index="8"}

这次更新的含义应说清楚：

**有真实直接 RL 信号，但没有来自正确构建、完整交付、有据正式复核或有效修复的正信号。**其他三段经历在本步没有直接 actor 策略梯度；共享参数仍可能改变其他岗位行为，不能进一步说“其他岗位没有受到训练影响”。

按现有“计划槽—成员—本人全部目标 token”的归一化，更新起点 \(r=1\) 时，这一步的 actor 梯度可以写为：

\[
\nabla L_\pi(\theta_0)
=
-\frac{0.2}{4}\cdot\frac12
\sum_{i\in\{\text{provider},\text{implementer}\}}
\frac1{T_i}
\sum_k
\nabla\log p_\theta(y_{ik}\mid h_{ik}).
\]

也就是说，**本步强化的是那条获得交接部分回报的联合经历中的本人输出，而不是已经完成整套职责的成功工作轨迹。**这仍是当前在线 RL 配方的真实更新，不应改称为教师训练；但也不能把它解释成完整协作能力的学习证据。归一化与回报广播方式在冻结更新器中能够核对。

还有一个有用的算术交叉检查。这个起点上的 actor loss 标量应为：

\[
L_\pi(\theta_0)=-\frac{0.2}{4}=-0.05.
\]

它与 R1 保存的 `-0.05000000004656613` 一致。**这支持损失与分母的一致性，不是“损失下降”或能力改善；该点的标量值固定，也不表示梯度为零。**

此外，8/24 是决策数量比例，不是有效训练权重的三分之一；产生信号的 A 槽名义权重是四分之一，而非零回报的独立联合经历只有一条。

## 3. 当前 PPO 裁剪没有实际限制这一步更新

冻结更新器采用一次完整窗口累积、`epochs=1`，全部反向结束后才执行参数 step。梯度求值期间，每条记录还必须通过最大 logprob 差不超过 0.02 的原门。

于是，通过准入的概率比满足：

\[
e^{-0.02}\le r\le e^{0.02},
\]

这个区间严格位于 PPO 的 \([0.8,1.2]\) 裁剪区间内。本次更是逐项零差，所以梯度求值时 \(r=1\)，裁剪 token 数为零是符合实现结构的结果。

**这不是说代码没有实现 PPO 目标，而是说当前“一窗一步”的用法，不能凭 `clip=0.2` 宣称参数更新后的策略变化已经受到该范围约束。**PPO 原论文的裁剪代理目标支持在同批材料上进行多次优化；本项目当前使用的是其中一次起点更新，不能把论文中的多次优化效果直接带入这里。:chatgpt-content-reference{index="14"}

下一轮不必因此立即增加 epochs。更合理的是先保持基础配方，增加少量既有的更新后固定上下文概率诊断，观察实际变化。**以后另行实现多次优化时，必须将“相同参数下的数值一致性核验”和“学习导致的策略变化”分开，不能在参数已经改变后仍要求它与原采样概率保持数值相同。**

# 三、W1 的负结果应如何转化为下一步

## 1. 不应再把主要问题概括为“上下文不够”

W1 的两臂完整职责均为 0/6，所有中间版本中也没有首次正确构建或首次有据正式判断。compact 增加了 25% 的真实生成，累计输入反而增加约 20.22%；输出减少约 18.81%。部分执行时段缩短，但两臂走过的动作和输出长度不同，不能称为同等工作量的固定加速。

更关键的是，已有断点已经超出单纯的历史长度：

实现有错误 SQL 限定名、未修改初始程序便提交；复核有批准前未读固定代码；联合 A 有实际收到依据却未落实日期过滤，以及请求与交接没有正确关联；联合 B 仍停留在 inspect/read，没有进入实际修复。:chatgpt-content-reference{index="16"}

因此，**下一轮不能只把目标设成“更多读取、更多工具调用、更晚触发 context 终止”。这些都是中间条件，不是工作成果。**

## 2. 保留 compact，但不能说它胜出

compact 已被事前选作桥接的共同配置，并非根据 W1 成绩挑选。可以继续使用它作为下一轮固定实现，避免重新开始另一轮呈现选型；但应明确“继续使用”和“效果胜出”不是一回事。

需要修订的，只限于能够从公开合同证明的真实缺口。例如，若公开工具没有说明某种合法引用格式，或者合法 SQL 被错误拒绝，应窄修复；**不能把模型发起多余请求、漏读证据或漏实现政策一概改写为环境问题，也不能为提高成功率自动替它提交、批准或生成 issue。**

## 3. 不需要先跑出稳定成功率，才允许基础学习

应满足的前提是：职责在协议下可达、输入和回报可信、学习器可用。**不是要求训练前模型就稳定成功。**

但“环境中存在合法路径”需要在实际工具、消息呈现、tokenizer 和预算下成立。下一轮新情境的程序见证只承担这项存在性检查，不进入模型上下文或训练标签。一个见证的长度是可行路线长度，不是全局最短长度，也不能保证模型会找到该路线。

# 四、建议下一轮：72 例有限 Q=B 学习 pilot

我建议将下一轮收敛为：

> **固定一个可闭合职责的工作协议，进行四个真实在线收集—更新窗口，并在相同新材料上做预先冻结的初末评价。**

具体建议是 **24 个训练 episode＋48 个初末评价 episode＝72 例**。

这是对尚未启动的 144 例计划的**缩规模建议，需要另行确认**，不是自动覆盖。理由是当前应先研究基础工作学习，而不是为尚未建立的有效方法支持支付大量同情境重复成本。保留四个计划更新点和原初末评价规模，将每窗训练从 24 例缩至 6 例。

## 1. 固定结构

| 阶段 | 组成 | episode 数 | 参数更新 |
|---|---|---:|---:|
| 初态评价 | 12 个情境 × 2 个固定种子 | 24 | 0 |
| 训练窗口 1—4 | 每窗 2A＋2B＋1 实现＋1 复核 | 合计 24 | 每窗至多 1 次 |
| 终态评价 | 原 12 个情境 × 相同 2 个种子 | 24 | 0 |
| **内部合计** | 一个固定训练种子、四个窗口 | **72** | **actor 至多 4 步及配套 critic 更新** |

训练中联合 episode 仍占三分之二，单岗位占三分之一。每窗 A 的两次为同一精确 A 情境的固定重复，B 同理；各窗口使用事前指定的新材料，不根据成绩替换。

**这个规模明确不承担 ID-VTDO 支持密度研究。**同情境 \(M=2\)、每类最低两条时，最多一类达标，不具备组成自由度。旧 144 例中的 \(M=8\) 密度设计继续保留为后续方案，不与本轮混算。

72 例也不是充分功效保证。它能形成有意义的多窗口学习记录和配对工作变化，但四次小规模更新的负结果不能否定 RL 可学性。

## 2. 初始化与基础配方

主 pilot 建议从相同公共基座和 **fresh LoRA、critic、optimizer** 开始，不沿用 R1 那个只接受过一次交接奖励更新的 checkpoint。这样，主实验初态不会夹带未经配对评价的额外训练剂量。

继续固定当前 9B、存储精度、N1 函数式学习路径、native 工具、compact、温度、context、单次输出上限、`terminal_mc`、现有 PPO 代理目标及原概率门。保持失败、计划槽、成员和本人全部输出 token 的既有归一化。相关机制已在本轮实际接通，无需重建训练器。

**本次不同时更换模型、奖励、优化器、优势算法和上下文方案。**否则即使工作改善，也很难区分是参数学习还是协议组合变化。

## 3. 恢复完整职责的机会预算

不再使用每成员四次决策。建议先恢复 W1 的完整职责预算：

| 职责 | 建议沿用的角色决策上限 |
|---|---|
| 实现 | implementer 12 |
| 复核 | reviewer 12 |
| 联合 A | provider 6；implementer 16 |
| 联合 B | implementer 24；reviewer 28 |

这些上限来自现有工作合同，不是依据下一轮成绩临时增加。

在正式模型采集前，对新任务起点检查一次必要的合法完成路线及其实际输入长度。**不要求穷举所有路线，但要排除“必需动作尚未做完就必然耗尽机会或上下文”的结构性不可能。**

业务期限与计算监督期限分别设置。一个工作 episode 的期限，不应再次被误用为包含大量请求反向的完整更新窗口期限。

# 五、数据与评价怎样安排，才能测到学习效果

## 1. 新材料先分用途，再派生任务

本轮 W1 使用的是同一 UCI 来源内的新客户、发票和原行，而不是新的独立企业来源。下一轮继续扩展同源材料可以作为有限 pilot，但不能改称跨来源泛化。:chatgpt-content-reference{index="21"}

新材料应先按客户、完整发票和直接派生关系分为训练与评价组，再生成任务。已用于 v0.21/v0.22 开发或协议选择的材料不能重新标成未接触评价。

B 和单岗位复核继续覆盖正确、错计数、错金额准备条件，比例及顺序在运行前固定。正确初稿允许有据直接批准，不要求制造返工；host 的质量标签不进入模型观察。

## 2. 初末评价保持 12 个情境，而不是把重复当独立任务

建议评价结构为 **4 个 A、4 个 B、4 个维护情境**，每个情境两个固定种子，初末完全配对。

维护情境需要包含实际应更新与无需改变的情况。旧正确交付可以是明确的程序准备状态，但不能算当前模型功劳；变更必须实际触发并进入模型输入。**前项没有完成、后续事件从未触发，不能记为已经测过维护能力。**

若维护适配未就绪，应在模型启动前明确收窄研究范围，不能事后用普通 SQL 题替补，却继续报告维护结论。

## 3. 主指标是完整职责变化，而不是平均交接分

令 \(Y(c,j,r)\) 表示 checkpoint \(c\) 在情境 \(j\)、重复 \(r\) 下是否完整完成职责，主描述量为：

\[
\widehat{\Delta}
=
\frac1{12}\sum_{j=1}^{12}
\frac12\sum_{r=1}^{2}
\left[
Y(\theta_{\mathrm{end}},j,r)
-
Y(\theta_0,j,r)
\right].
\]

由于 A、B、维护各四个情境，这也对应三类结构的等权宏平均差。

同时保留正确内容、固定交付、证据完备性、错误批准、无据批准、错误问题、复核缺席与成本。**平均部分回报只作辅助结果，不能因为交接分提高，就宣称完整工作学习改善。**

初末评价使用固定协议、相同情境和种子，评价期间不更新学习状态；在四个训练窗口结束前，评价结果不得用于修改提示、选任务、调学习率或挑最佳 checkpoint。

24 次评价来自 12 个情境的随机重复，初末 48 次更不是 48 个独立测试任务。一个训练种子也不能估计算法训练稳定性。应报告逐对变化及结构差异，不给出未经来源簇和种子规划的“显著提升”或功效保证。

**已知失败保持零，未知不填零，也不悄悄从分母删除。**存在未知时，说明主点估计不能完整给出，并单列已知配对及不确定范围。

## 4. 每个窗口都要回答“这次到底在强化什么”

下一轮最值得保留的学习诊断不是更多总梯度数字，而是：

**回报来自哪里，哪些成员的哪些真实行为获得了正、负或零优势，以及这些信号是否已经到达正确构建、复核和修复环节。**

这些字段大部分可以从现有 admission、回报分项和优势记录读取，不需要额外模型评审。再启用少量既有更新后概率诊断，建议每窗最多六个预声明任务／成员代表决策，追加前向计入成本。

若四个窗口始终只有交接产生正信号，就应如实得出“本剂量仍主要在学习上游局部行为”；不能把它包装为完整协作训练，也不能因此归咎于 ID-VTDO 尚未启用。

# 六、外部 D2：下一步应跑真实模型，而不是再增加隔离控制数量

X1 已处理了一个重要边界：**grader 再次执行 actor 的代码时，该代码仍然受到隔离，不能因为进入评价阶段就获得 expected 的读取权限。**这支持继续开发指定 D2 变体的真实模型入口。:chatgpt-content-reference{index="22"}

建议外部实验单列为：

\[
3\text{ 个未用于修复选择的新 seed}
\times
2\text{ 个 checkpoint}
=
6\text{ 个 episode}.
\]

这六例不计入内部 72 例，预算单列；两个角色不算两个独立任务，新 seed 也不算新来源。

需要绑定真实角色调用、允许读取的资料、固定提交、verifier 的实际检查和最终声明。**修订 grader 分数与实际协作责任证据并列报告，不能只凭一个 `pass` 字符串认定独立复核发生。**

adapter 未就绪就保持未执行，不阻断内部学习，也不启动更多平台来寻找好成绩。

# 七、预算应从整窗成本出发，不能再由推理时间外推

本次算术复核支持总资源记录：

\[

# 八、ID-VTDO 什么时候进入，不应再增加什么门

**ID-VTDO 的进入条件不是先取得漂亮平均分，或者要求基础学习显著为正。**需要的是可信开发效用、实际可用学习信号、同条件下合格的真实方法支持，以及可执行的共同起点配置干预。
