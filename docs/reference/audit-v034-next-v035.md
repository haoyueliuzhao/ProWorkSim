# 一、本轮结案与9B选择均成立

## 1. 选择依据不是“9B更省”，而是成功覆盖更广

| 指标 | 9B | Devstral | 对本轮选择的作用 |
|---|---:|---:|---|
| 完整成功 | 2/4 | 2/4 | 第一项相同 |
| 成功覆盖根目标数 | **2** | **1** | 第二项决定9B优先 |
| 全四槽实际token | 1,981,827 | 1,908,379 | 尚未需要用此项破同分 |
| 固定提交 | 3 | 2 | 辅助诊断 |
| 记录与common恢复 | 通过 | 通过 | 两者均满足基础资格 |

冻结协议的排序确实是“完整成功数→成功根目标覆盖→全量token→固定顺序”。因此，即使Devstral的总token较少，9B仍应按第二项被选中。**不需要补充新阈值，也不应该在结果出现后改排序。** 

但选择结论必须保持原义：

> **9B是后续新来源支持研究的局部候选，不是普遍优于Devstral的模型，也不是旧选型结果被追认。**

9B两个根目标各只有一次成功，成功还分别对应不同seed和先手，不能据此宣称已经稳定掌握两种工作。

## 2. 四条失败不是同一种失败

八槽合计有**五份固定提交**：四份完整通过，一份内容失败。另三槽没有提交，其内容和过程没有进入最终交付验收。

因此，应保持：

\[
\text{完整成功}=4/8,\qquad
\text{已提交内容通过}=4/5,\qquad
\text{未提交内容未知}=3。
\]

其中9B目录任务的失败提交，规定过程和过程观测均通过，问题在内容；不能解释为没用指定API。三条未提交也不能写成三份代码已经被内容测试判错。

**本轮没有显示需要回退验收标准。**新的小任务已经产生真实合格交付，说明“保持完整验收、降低初期领域规则负担”的路线至少获得了局部可行性证据。

# 二、呈现改动可以保留，但必须进入后续学习与Mapper定义

## 1. 本轮明确承认有损投影，这一点是正确的

协议把两件事分开了：

**合同去重**删除相同文本副本；**公开测试反馈投影**则不再向模型展示全部通过值、stdout和API细迹，只保留通过标识与汇总，失败业务诊断和成员自测反馈继续呈现。

源码中的`project_public_test_feedback`与这一边界相符。后者不是无损去重，但它已经作为新Γ公开冻结，不能仅因有损就否定实验。 

真正需要防止的是后续偷换：

| 后续用途 | 应当依据什么 | 不能怎样处理 |
|---|---|---|
| 判定代码执行、版本和最终正确性 | 完整后台回执与独立验收 | 只相信模型说“通过” |
| 判定成员实际获得的信息 | 实际选中请求和输入token | 把未显示的通过值记成成员已经看到 |
| 构造actor训练项 | 原始输入、本人输出和行为概率 | 为方便学习而补回被投影删掉的信息 |
| 构建工作依赖图 | 可核对的取得、消费、修改、验证关系 | 用后台真值推断模型已经理解或采用 |

**训练侧可以掌握完整事实，但不能借此改写执行侧的信息历史。**这尤其关系到ID‑VTDO中的信息依赖和成员投影。:chatgpt-content-reference{index="7"}

## 2. 不需要再单独证明“压缩一定提高成功率”

本轮同时改变了任务合同和呈现，没有隔离两者效果。因此不能把新成功归因于提示压缩，也不能把离线token减少当成运行节省。

但当前主线是分配算法，**没有必要再补一整轮旧／新呈现对照才能前进**。只要后续B/G/I使用同一冻结Γ，就可以在这个共同载体内研究分配增量。

# 三、目前仍缺的是“可分配经历”，而不是另一个模型

这里需要明确一个容易跳过的区别：

> **存在完整成功，只说明载体可用；同一情境中存在多种可靠工作方式，才开始形成配置自由度。**

本轮简报没有给出四条成功的完整组织链和方法映射。因此，目前不能判断这些成功分别是集中完成、真实分工、伙伴补丁消费，还是其他路线，更不能预先给出类别频数。

建议将对**已选9B四条开发经历的一次只读方法复核**放入P2准备，而不是再开模型实验。重点检查任务怎样产生、责任怎样承担、伙伴内容是否实际进入输入、是否消费了固定产物，以及后续修改和验证怎样连接到交付。

这项复核用于确定Mapper边界，不把开发经历转成训练，也不要求每条成功必须有多轮交流。无法可靠判断时保留`unmapped`。V1.3明确区分了成员行动归属、工作过程和最终代码署名，不要求所有协作都能还原为唯一代码作者。:chatgpt-content-reference{index="8"}

**P1不需要因这些尚未统计的内容重新过门。**但P2不能跳过它们，直接把“2/4成功”当成“已经有两类支持”。

# 四、下一阶段应怎样冻结P2

## 1. 固定9B共同起点，不再复制筛选

使用本轮已经恢复并核验的9B完整common：actor、critic、两个optimizer、数值profile和随机状态规范。它带有历史项目更新，不改称fresh base；后续各分配方法从同一起点开始即可。

保留当前O1：**根目标由环境给出，执行任务、职责和依赖由成员形成。**两名成员固定身份、共享参数、独立会话与副本，不重新规定谁开发、谁测试，也不在这个窗口同时加入动态人数。

现有可微路径、原生格式、上下文和基础RL继续使用。需要新增的是来源与当前经历的绑定，不是又一次近16K资格、精度搜索或harness选型。

## 2. 新来源应先分用途，不能从P1成功池挑训练样本

| 材料池 | 可以做什么 | 不能做什么 |
|---|---|---|
| 当前及历史Marshmallow开发题 | 接口、方法表示和诊断 | 改标为训练或独立确认 |
| 正式策略训练任务 | 当前模型工作，产生更新材料 | 使用程序见证替代模型经历 |
| 贡献开发任务 | 试训后执行，估计C和选择配置 | 同时承担本轮独立测试 |
| 独立确认任务 | 冻结规则后的效用比较 | 反向挑模型、权重和超参数 |

可以复用已经审查过的仓库环境和隔离机制，不必重新铺开大量数据源。已有sqlparse、schema、TextFSM资源是否继续使用，应由实际合同、用途暴露和难度决定；**不能因为它们已接入，就默认旧sqlparse问题已经适合当前模型，也不能把每个仓库一题当成完整泛化研究。**

新根目标继续保持“较低领域负担＋真实API或产物依赖”，但不复制当前开发题的答案模式，也不预建执行任务。

## 3. 采集前与采集后，分别冻结不同对象

这是P2／P3衔接最重要的程序安排。

| 冻结时点 | 必须确定的内容 |
|---|---|
| **P2采集前** | 来源与用途、根目标、精确情境、θ与Γ、M与seed、Validity、Mapper、支持门、基础分母、候选块选择原则和停止规则 |
| **采集后、任何贡献反馈前** | 实际支持、类内核、候选坐标、探测方向与步长、唯一试训清单、共同B复用、正式更新和独立确认预算 |

第二次冻结可以依据实际 \(n^+\) 和 \(K\)，因为采集前不知道这些值；**不能依据哪个候选在开发集或测试集上更好，再缩减比较范围。**

首个局部实验按预定顺序选一个合格成员块是允许的，其他成员与经历仍进入原基础损失；不能挑掉失败或部分成功来让分母变得有利。

## 4. 重复数不能由本轮2/4直接推导

真正需要规划的是：

\[
p_{\xi iz}
=
\Pr\{V=1,\ \phi_\xi(\tau)=z,\ i\text{有可信自身动作}\},
\]

而不是两个根目标合计的成功率，也不是成功池内部的类别比例。:chatgpt-content-reference{index="9"}

人工算例：假设两类完整有效产出率分别为0.2和0.1，要求各至少两条，在独立重复假设下：

| \(M\) | 两类同时达标的概率 |
|---:|---:|
| 8 | 约7.1% |
| 16 | 约40.3% |
| 32 | 约83.7% |

**这些不是当前模型的产出率，也不是建议直接固定32次。**它们说明M必须结合真实任务、合理产出区间、估计精度与后续探测费用选择。不能采到出现两类才停止，再宣称执行了一个固定批次。

窗口结束应分别报告：无支持、只有一类、多类但频数不足，以及有形式自由度但梯度／更新差异很小。不能把这些情况都写成一种“算法失败”。

# 五、P3不需要重写算法，而要把已有正确接口接到真实学习后果

## 1. 当前实现状态应更新：对数N和G-raw区分已经有专门模块

本次核对的`experience-allocation-v030.md`已经明确：

- `base=b`、`history=h`、`coverage=r`分别传入；
- 使用对数N及历史／覆盖双KL；
- 区分`solve_g_raw`、`solve_g_lift`、`solve_i_p`；
- G-raw不接收专用类别或图；
- 历史转移、真实贡献反馈和完整运行器绑定尚不由该数值模块完成。

因此，**不能继续把v0.27／v0.29的旧线性N和共享类别先验限制，当成当前全部实现状态，反复要求重做。**

真正缺的是：将新模块与P2原始材料、当前支持、实际试训后的开发工作，以及独立确认接通。只给求解器传一个合成C，不构成Contribution已被实际测量。

第一窗可以明确设 \(h=b\)，先避免跨窗口历史映射的额外复杂性；这不代表历史转移已经实现。

## 2. 首轮保持三个主方法

| 方法 | 实际优化对象 | 必须保持的共同条件 |
|---|---|---|
| **B** | \(Q=B\)，不增加组成干预 | 同一当前窗口、学习状态、基础配方和分母 |
| **G-raw** | 合格原始成员经历的权重，不读取专用图／类别 | 同类型开发反馈、合理优化能力和透明成本 |
| **I-P** | 精确情境内的成员—工作类别组成，类内核固定 | 只改变actor经验组成，其他基础规则相同 |

G-lift仍是辅助归并对照，不能替代G-raw。I-P是局部第一阶版本，不冒称已经具有I-S的跨窗口结构共享或I-J的联合交互效果。:chatgpt-content-reference{index="11"}

## 3. C必须由更新后的工作产生

\[
F_t(Q)=\mathbb E[J_{\mathrm{dev}}(\theta_t^+(Q))].
\]

候选配置从同一完整状态出发，用同一批经历完成规定更新，然后在预先确定的贡献开发任务中真实执行。这个更新后差值，才用于估计C。

贡献开发面板不宜始终只有一个题和四个seed。**同题重复能够减少部分采样噪声，但不能代替不同根目标的覆盖。**具体面板大小和重复数应与扰动大小、预计效应和费用共同确定。

还应预先写清楚：开发差值全部观测为零时，说明本面板没有检出方向差，不等于真实C必然为零；未知结果不能填零。如果最终q主要因覆盖项变化，应明确报告，不能称为“发现了高价值经验”。

## 4. 正式更新不能累加试训

选定配置后，回共同起点完成B/G/I正式更新：

\[
w_{\xi ir}=
\begin{cases}
q_{\xi iz}/b_{\xi iz},&\text{合格重配分支},\\
1,&\text{其他基础残余}.
\end{cases}
\]

可信失败、未映射和低频经历保留；任务与成员份额、原始槽和本人token归一化保持。critic配方不随q改变。

新来源的真实概率和目标消费检查仍需执行，但可以与**共同B试训**结合，不必另开一串用完即丢的诊断更新。不能以技术奖励、删错误token或补入过去未见信息，让新窗口取得通过。

# 六、当前最需要预防的是试训成本，而不是继续扩大模型

本轮采样约1.395 GPU小时，不能用来估计完整P3。按完整方向有限差分，一个成员块有：

\[
T_{\mathrm{unique}}
=
1+2(n^+-1)+2(K-1),
\]

其中共同B只计算一次。

| 实际支持 | 唯一试训 | 加B/G/I三次正式更新 | 每候选若有 \(D\) 次开发执行 |
|---|---:|---:|---:|
| \(n^+=4,K=2\) | 9 | 12次窗口更新 | \(9D\) |
| \(n^+=8,K=2\) | 17 | 20次窗口更新 | \(17D\) |
| \(n^+=16,K=2\) | 33 | 36次窗口更新 | \(33D\) |

**支持密度增加有利于统计，也会扩大G-raw的搜索维度。**因此P2采集数量与P3探测方案必须一起规划，不能等到材料出现后才发现完整比较无法承担。冻结协议已经正确提出这一点。

规模较小时，完整有限差分可以作为清楚的参照；规模较大时，可以事前采用经校准的可扩展元优化。不能在看过开发成绩后删G方向，也不能为了便宜只保留有利经历。

同时，本轮9B四槽平均实际token为**495,456.75，约占单槽上限的99.09%**；Devstral为477,094.75，约95.42%。这说明新窗口仍可能很长，不能把“新任务较简单”理解为训练计算已经很轻。这个比例来自报告算术，不足以单独判定所有终止原因。 

不建议因此再开一轮压缩搜索或立即加预算。先固定现有Γ，将实际序列长度、本人目标token和完整窗口更新成本纳入P3清单即可。

# 七、独立确认与消融如何衔接

第一项P3应直接报告：

\[
\Delta_{I-B}
=
J_{\mathrm{test}}(\theta_I^+)-J_{\mathrm{test}}(\theta_B^+),
\]

\[
\Delta_{I-G}
=
J_{\mathrm{test}}(\theta_I^+)-J_{\mathrm{test}}(\theta_G^+).
\]

独立任务不能参与模型选型、Mapper开发或选权。主要指标是固定资源下的完整合格交付；内容、过程、实际组织和成本分列，不以通信更多、loss更低或权重变化更大替代。

后续机制实验仍按详细基线推进，但不要求第一轮一次跑完：

| 机制问题 | 对照 |
|---|---|
| 是否只是覆盖先验起作用 | I-P与B-cov、无N |
| 是否需要成员条件化 | 成员专属配置与合法共同配置／共享评分 |
| 结构共享是否有价值 | I-S与I-P，保留学习窗口验证 |
| 工作关系是否超出信息交流 | 一般特征、信息关系、完整工作关系 |
| 联合探测是否值得 | 单点、同预算随机联合、图引导联合 |
| 是否在持续学习中保持 | 多窗口B/G-raw/I-S各自新采、配置、更新 |

注意可辨识条件：\(q_t=r\)时N本来为零；历史锚与覆盖锚相同时不能分别识别其作用；只有一个联合候选对时，也不能证明图比随机更会选对。

**一次更新后重新采几条，只证明在线回流接通。**完整主线仍需下一窗继续配置和更新；O3动态人数仍是最终面板，不因当前两成员局部试验而被删除。:chatgpt-content-reference{index="15"}

## 最终推进建议

本轮最重要的变化是：**已经有一个按事前规则选出的、能够在两个新根目标上产生完整交付的局部载体。**不应再把它退回“仍需反复证明稳定工作”的阶段。

下一步应明确收敛为：

\[
\boxed{
\text{固定9B与当前Γ}
\rightarrow
\text{用途隔离的新训练来源}
\rightarrow
\text{当前真实方法支持}
\rightarrow
\text{B/G-raw/I-P选权与更新}
\rightarrow
\text{独立效用差}
}
