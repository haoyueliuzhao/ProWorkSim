# v0.8 持续工作：两阶段修订与验收计划

日期：2026-09-23。依据：[本轮审计](reference/continuous-work-audit.md)。任务先稳定评价与工作上下文，再组合事件和公开执行。原结果、反例及失败目录保留，不预设测试总数。

## 阶段 A：P0/P1

| 工作 | 实现合同 | 验收方式 |
| --- | --- | --- |
| P0 递归内容一致性 | 对象逐键、数组按序、bool/numeric不同；有限int/float沿既有等价，不深层合并/引入容差/选择正确文件覆盖冲突 | 完整旧版本真实会话反例；正反顺序明确真值；嵌套true/1、false/0、数组/相同/不同值/合法单文件与顶层拆分 |
| P1 采用绑定 | workspace别名只指对象；采用按work ID与需求版本绑定；每次提交独立快照；新工作显式建新绑定，旧记录保持 | 新版/旧版要求、同别名双工作、修订后继续、迟到旧回复、错项目/工作拒绝 |
| 合同政策 | input_policy/input_policies限定政策或明确允许集合；fixed精确版本约束不能绕过；current_published旧版可作为可执行错误但不能伪装fixed | 正向允许选择与反向绕约对照；评价与执行依据同一声明 |
| 信息路线 | 可复用定义关联稳定work node；实际request冻结work ID/需求/证据；修订后可新请求，不复用旧请求 | 旧回复保留但不满足新条件；新工作可经既有路线获取合适版本 |

P0、P1纯规则和后续事件规则设计可并行；阶段B运行器接入在阶段A正式冻结验收后进行。第一阶段相关回归聚焦原N1/N3内容与合法授权路径，不重做无关API或全部故障矩阵。

## 阶段 B：P2–P4

| 工作 | 实现与实验范围 |
| --- | --- |
| P2 事件产生义务 | 有限项目规则声明来源、目标root work、阶段、effect notice/revise/successor/ignore（maintenance关系由阶段规则组合）与授权主体；真实release触发独立事件提交；重复事件不重复义务 |
| 阶段对照 | 读取前、精确工作读取后、显式产物完成未提交、待审、已接受；分别判断后果，不要求状态相同；固定任务不自动重开 |
| P3 多源与局部更新 | B组合A发布接口与固定本地输入，有限显式算式；仅变一个来源，不改另一输入/无关项目，后台不代算；至少两种合法文件组织 |
| P4 公开继续执行 | 规则调度器只持有tools/observe/call，支持多项当前工作与多个绑定会话；A等待时B继续，合法信息恢复或新义务后再次进入正确版本 |
| 出口区分 | 策略等待、持久条件阻塞、预算截断、环境错误分别记录；缺路线是能力缺口，不虚构动作或后台答案 |
| 有限恢复 | 只增加工作绑定更新或事件生成后继义务的代表切点；同检查点、相同命令身份、完整正式状态与字节/O比较，不做全工具笛卡尔积 |

发布/修订/后继义务均不追溯重判旧提交；旧文件、签发、审阅和观察保持。后继ID由规则/事件/工作关系产生，不写死work-2。多源参考数值由预声明标量或独立简单算术确定，不用被测Spreadsheet造期望。

## 证据与完成条件

每次正式执行前冻结提交与脚本，记录测试/实验开始与结束身份。开发反例、测量脚本错误及正式失败分开，不补造过去缺失记录。支持一个世界两个项目、单写者；新schema优先，不以旧缓存兼容扭曲工作绑定。历史世界用冻结版本。

完成须逐项对应：评价顺序无关；修订后可真实新采用/新请求；声明事件产生恰当新义务；公开工作人员可以等待/切换/恢复；新内容与多源版本/依赖相符；旧与无关事实保持。真实金融资料仍用于未来校准，本轮无采集、模型训练或专业外部有效性要求。全部完成后自动提交推送。

## 阶段 A 冻结前收口

P0协议为9类内容、17个真实会话分支，逐分支4个命题加8个顺序诊断对照，共76项；P1为5组27项。旧P0首次测量把artifact_id/object_id字面表示当成不同依赖，原记录保留，更正测量后独立重跑旧冻结源。P1首次开发比较整个submission而忽略合法适用性标注，以及误用satisfied状态名，修正预期后复验，不归为新增内核缺陷。

阶段B的纯维护规则模块、单位检查和脚本骨架随并行设计准备，但尚未接入WorldCore或执行P2真实情境。第一冻结的正式能力结论只针对P0/P1及相关N1/N3；不会用准备模块的单位检查冒充持续工作验收。
