# 公开交付结构预检

`preflight_submission(work_id, artifacts)` 在当前可信绑定的项目/角色会话中检查模型选择的可读文件。调用仍进入实际工具经历，但不写文件、依赖、采用、提交、批准或知识读取记录；它返回结构观察，不冒称模型读到了整份源文件。

检查公开合同的文件数量/类型/角色、必要字段、内容检查入口路径，以及来源引用是否存在、是否匹配该工作确切采用和该文件依赖。支持object_id与artifact_id两种标准引用表示。多个文件冲突的来源引用不选赢家。非fixed采用应对应其当前公开政策目标。

实际SQL构建的 `source_references` 与查询的 `source_reference` 均规范化为 `execution_lineage.actual_inputs` 引用列表，代码版本另列。这仅描述真实工具输入；不等同于工作人员读过的一切，也不自动补齐业务口径。模型仍需自行选择、采用并用于计算/交付。预检不调用领域独立评价器、不读来源正文、不返回期望业务数值；数值错误但结构完整可以得到structurally_ready=true。

这是有限结构反馈，不是完整业务验收或权限授予。选中的每份文件先经过同一对象可读性检查，不能借预检读取另一成员私有文件。最终提交与历史独立评价的合同保持。当前不对JSON全部深层领域schema、公式正确性或任意文件类型声称完整验证。

六项真实WorldCore回归覆盖：缺字段/采用/依赖且业务状态不变；结构完整而数值错误仍通过并证明私有评价函数未调用；私有文件先拒绝；两种引用表示统一、错误确切版本不通过。D0两个接口配置都提供此公开能力，不能把它只交给后来的“算法”条件。

开发pilot中Qwen选择了合法原生工具，却将项目ID当作work_id，遭真实拒绝后等待。此失败保留。正式D0前，工作参数schema增加本绑定项目已经公开的work_item_id和合法local alias枚举，帮助区分项目与工作；不枚举私有文件名、不选择业务依据，也不改变世界授权。第五项检查核对此公开范围。

交叉审查发现查询使用单数source_reference时曾被呈现为空输入；真实SQL查询回归先复现该遗漏，随后补修并保留原失败日志。这是开发期预检反馈缺陷，不修改已有世界执行谱系。
