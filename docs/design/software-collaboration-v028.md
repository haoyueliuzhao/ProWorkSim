# v0.28 软件协作：实施前消息与有界职责调整

本版针对 v0.27 审计修订协作接口与机会调度。固定两名成员 `member_a`、`member_b`、共享模型、相同工具权限和事前预算；不固定实现、集成、测试的成员岗位。两项任务由材料预定义，模型选择领取、转交和工作顺序。本版没有新增经理、自动计划器、动态招募或自主任务分解。

实现位于 `src/proworksim/software_collaboration_v028.py` 与 `software_runtime_v028.py`。继续复用 v0.27 WorldCore 文件副本、固定补丁、三方合并、隔离执行器、独立父进程验收以及既有 OpenHands SDK。旧 v0.27 模块不变，内部项目 ID `SOFTWARE27` 保留为复用存储命名；接口与运行协议具有新的 v0.28 版本号。

## 消息与任务责任

`send_message(recipient, task_id, body, fixed_reference?)` 不要求先编辑或产生补丁。正文最多 4,000 字符，绑定稳定发送成员、关联任务、接收者和原始 WorldCore 操作回执。可选引用仅允许已公开的固定补丁或交付版本；消息不分享私有版本、不领取任务、不采用输入、不合并文件、不自动交付。伙伴内容是否进入实际模型输入，可从原始观察、请求和回执核验；消息数量不能代替业务使用证据。

`claim_task` 继续原子领取。`delegate_task` 只允许当前负责人转给仍能执行的另一成员，同时产生对方可观察的通知。接收者可调用 `return_task(task_id, reason)` 拒收或归还：责任回到 `owner=None` 的公开任务板，原发送者收到通知，系统不自动把任务派回给已完成或不再可执行的成员。原领取、转交、归还和文件修改的行动归属不变。

已 `staff_done`、预算耗尽或因模型/环境错误退休的成员，不能再接收消息、补丁交接或职责转交。等待且尚有预算的成员可以接收。这项权限来自控制器实时状态的公开投影，不是模型可以改写的业务字段；运行状态与控制事件独立归档。文件编辑、发布补丁与任务转交也不自动代表任务已通过验收；业务完成仍由实际固定集成交付和独立检查决定。

观察给出最新 4 条消息、4 条补丁交接、6 个补丁摘要、2 个交付及明确的历史事件/补丁索引。长正文仅预览前 500 字符，并标记截断。`read_work_event(sequence)` 可读取本人可见的完整历史消息或公开补丁事件。完整正文、所有原始输入和固定文件版本一直保留，不把预览当成完整文本。测试运行、编辑文件和补丁检索工具沿用原权限与固定来源约束。

## 轮转、等待与停止

每槽冻结 `first_member` 和 `role_decision_limits`。默认每成员 48 次决策，接口允许显式声明 1–128 的有限上限；实验采用哪个值，必须在采样前写入窗口。模型 `staff_wait`、`staff_done`、格式拒绝和普通动作都按既有 SDK 计入成员决策预算。运行器不根据隐藏评分提前结束。

轮转规则为 `round_robin_event_wakeup-v0.28`：

1. 从事前指定的 A 或 B 开始，轮流向当前可执行成员提供一次 SDK 机会。
2. `staff_wait` 记录该成员已经看过的最新业务事件序号，暂停后续采样；等待不持续重复消耗模型调用。
3. 新的定向消息、补丁交接、职责转交/归还通知，或伙伴新发布的固定补丁，唤醒仍有剩余预算的等待成员。事件只赋予继续决策的机会，不替成员选择回应、领取、编辑或导入。
4. 唤醒保存已有 SDK 会话、决策数、身份与工作副本，绝不重置预算。
5. `staff_done` 永久结束该成员自己的机会；另一成员保留全部剩余机会。即使一人已完成交付，另一人也不被隐藏验收结果取消机会。
6. 没有可执行成员且仍存在等待成员时，记录 `blocked_no_reachable_events`。此载体没有异步外部生产者，因而无后续事件能够到达；不后台补全上游工作。全员正常结束记录 `workers_done`，预算/错误退休保留对应原因。

职责转交的合法性以实际调度可执行性判断，不能静默落到终止成员名下。任务板仍可记录某个已终止成员原先持有的未完成责任，这应作为失败工作事实保留，运行器不会自动抢救或转派。

## 协议绑定与用途边界

采集入口为 `collect_software_window(owner, window_spec, output_dir)`。每个 slot 精确包含 `slot_id`、`case_id`、`sampling_seed`、`first_member`、`role_decision_limits`；窗口预算精确给出 `max_slots` 和全部成员决策数之和 `max_model_calls`。GPU 预算、排队期限与设备约束由新外部监督器单独冻结，不能继承过去实验的预算扩展。

精确情境标识为 `case_id + '::first=' + first_member`，初始指纹覆盖完整 case、reward_spec 和初始业务状态哈希。场景同时绑定先手、调度版本、逐成员预算、SDK 策略与源用途。不同先手是不同执行协议，不能混成一个精确情境的多方法支持；重复 seed 不改变成员身份。本轮计划采用两个情境、两种先手、两个固定 seed，共 8 个冻结参数开发槽；模型输出之前的正式窗口声明才是实验实际预算依据。

两项 Marshmallow 情境继续仅用于 `interface_dev` / `frozen_development`。不因成功或拥有 token 轨迹升级成训练数据、独立确认材料或 B/G/I 效果证据。v0.28 Mapper 由独立模块 `software_training_v028.py` 导出，使用净文件改动与实际固定导入的保守关系；运行器不修改方法分类或独立评分来追求支持。

## 轨迹持久化与异常

每次原始经验事件产生后立即追加并同步 `experience.jsonl`；每成员的独立公开工具、观察和调用捕获写入 `public-capture/<member>.jsonl`。模型请求、原始响应、实际 token trace 和 SDK 事件走相同流式经验记录；SDK 自身会话目录也保留。回放或复制捕获列表不会再次写入流，避免产生重复伪事件。

每个完整机会记录 `runtime-opportunities.jsonl` 和最新 `runtime-state.json`。WorldCore 在工具执行时保存原始回执和每个提交版本。每槽开始复制初始世界，槽结束复制所有历史文件版本及最终世界，关闭 episode 后立即独立验收并导出 `assessment.json`、`entry.json`、`team-rollout.json`、`mapping.json`、`software-evidence.json`，然后才进入下一槽。另存完整 `runtime.json` 和 `public-capture.json` 以便与流式文件逐项比较。

捕获到运行器异常或中断时保留异常类型、原始已提交效果、完整经验及世界版本；未闭合槽以 `interrupted` 边界收档，业务结果保持未知，不伪造成功、零分或正式导出。硬杀进程来不及执行清理时，已经同步的流式事件、活动世界和全部已提交版本仍存在；最后一条正在写入或尚未返回的模型响应不能被凭空补出。

SDK 若以模型服务错误、用量缺失、身份不匹配、环境错误或非动作策略异常返回，虽然可以闭合原 episode，仍将完整业务结果登记为 `unknown / R=null`，方法保持未映射。独立文件验收原结果另存 `raw-independent-assessment.json`，不能把“没有交付”的局部零分当成技术故障下可比较的模型失败。正常工具拒绝、格式预算、决策/上下文预算和合法无事件阻塞不自动归为技术故障。

## 必要 CPU 核验范围

测试覆盖编辑前消息可达且无文件/任务副作用、通知与归还、终止接收者拒绝、长消息完整检索、等待被消息/责任/补丁重新激活、预算不重置、无事件阻塞、单人结束不取消伙伴机会、先手协议、真实 SDK 原始捕获与逐槽导出，以及异常后提交版本保留。成功控制使用明确的程序动作与已知补丁，经过真实工具、隔离测试和独立验收；其 token fixture 明确标记为 CPU 合成，不计为目标模型经历或学习效果。真实 tokenizer 的请求长度资格与 9B 开发结果由实验报告单独登记。
