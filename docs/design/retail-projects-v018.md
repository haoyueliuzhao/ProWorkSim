# v0.18 四项目可评性与阶段诊断修订

本文件修订 [v0.17 四项目合同](retail-projects-v017.md) 中“终止格式错误一律 unknown、停止后续槽”的汇总语义。P1/P2 独立 Decimal 质量、P3 固定输入忠实性及整体目标的正式合同保持原定义；本轮没有增加求解器、改变工具权限或向工作人员暴露隐藏真值。实现位于 `retail_project_rewards.py`、`retail_project_collection.py` 及原文件名保留的 `retail_project_model_v017.py`。

## 三项信息分开保存

| 输出字段 | 回答的问题 | 依据 |
|---|---|---|
| `termination` | 为什么停止，各角色如何结束？ | 实际运行返回和原始事件；保留格式、预算、服务等终止标签 |
| `record_trust` | 当前行动记录是否完整、可归属、与真实操作一致？ | 实际模型请求/返回、原始响应正文、身份、关键 token 记录、独立工具捕获和内核操作回执 |
| `independent_assessment` / `independent_assessability` | 固定世界终态能否评价，按正式合同得到什么结果？ | 闭合 episode 的历史边界、固定提交、不可变版本及独立产品评价 |
| `assessment` | 本次采集是否可以作为当前研究的已知结果？ | 保留独立结果；只有具体行动证据缺口或独立评价自身不可用才为 unknown |

终止标签不再直接覆盖独立评价。完整保留的原始输出被协议拒绝、没有完成工作，仍为已知 0；如果固定成果按现有合同已完成，之后出现格式拒绝，成果评价仍可为已知 1。本合同没有新增“完成后格式错误撤销成果”的公开义务。

`assess_collection_records` 核对闭合经验字节及结束边界，逐个配对实际模型尝试，检查原始 JSON 正文和已解析正文相同、实际返回的 actor 身份与请求绑定一致、输入/输出 token 与有限 logprob 记录存在且未发生声明的原始记录偏移。格式拒绝必须有对应已完成原始返回。真实世界调用需与独立 `capture_port` 记录精确一致，并匹配结束边界中的内核回执和绑定角色。

服务未返回、实际身份缺失/变化、关键记录丢失、世界捕获与回执不一致仍是 unknown。没有关联具体模型拒绝的 Python worker 异常保留归因缺口；准确记录的普通工具拒绝属于已观察到的行为。这个判断依据记录事实，不把某个停止状态名当成充分条件。

记录核对只说明保存与归属，不重算模型概率，不替代数值 guard，也不构成四项目 actor/critic 训练准入。人工 transport 的占位 token 记录会明确标为 fixture，不能据此宣称真实概率或模型表现。

CLI 对已知结果继续原定后续槽；对真正 unknown 保留原“停止后续槽、无重试、不填零”的规则。独立世界可以可读为 0，同时采集研究分数因服务缺口为 null；两项均保存，不互相抹去。各角色的有限机会仍按原 runtime 合同运行，一个角色的终止格式失败不取消其他角色。

## E4 首版、触发、收件与后继

固定模型计划继续使用 [静态 2 次、变更 2 次](../../examples/retail-projects-v17/model-evaluation-plan.json)，没有增加成功重采。静态角色预算仍为 14/24/24/24，变更为 14/44/44/44。

采集开始即建立额外的 `initial-delivery-episode`，并保存 `initial-workers.json`。所有项目首版义务第一次制度上 accepted 时，先闭合首版快照，再执行原有客户端事件；未达到条件则在终局闭合并标明未达到。快照操作不改变世界、不调用模型，也不替下游读取、采用、写代码、构建或提交。派发事件仍只看原公开制度状态，不调用隐藏质量评价；首版业务质量在采集结束后独立评价，不能把 accepted 偷换成独立质量通过。

首版评价使用预声明的初始合同版本；终局评价仍使用静态版 1 / 变更版 2 的目标。`initial_delivery` 分别保存制度固定交付、发布、业务质量和 R。`inherited_fixed_deliveries` 要求本次首版选中的具体责任与固定提交已经在起始边界 accepted，避免把先前别的工作提交误称为本次初始成果。

`change.triggered` 只由实际已执行客户端事件确定。`handling_measured` 还要求后继义务至少进入一次真实模型输入。逐角色收件证据只接受具有成功实际返回与输入 token 记录的原始请求，其中 user 观察包含新 work_id 的 `is_current=true`；指派、环境日志、机械元数据观察和模型自己提到某 ID 均不计作收件。

报告逐角色列出新 work_id、首次实际输入 call_id/决策位置、当时已用与剩余决策预算、原末 SDK Conversation ID、是否同一会话、再激活次数与预算未重置证据，以及后继固定交付是否完成。完整再激活事件留在原经验中，摘要另外保存其哈希。原生模型策略没有 SDK Conversation ID，此项为 null，不虚构会话标识。

断点区分：首版未完成且未进入变更、客户端事件拒绝、新义务尚未进入实际模型输入、已进入变更但后继交付/质量未完成、终局完成。未触发变更的案例可以按终局目标为已知 0，但不能表述为“模型处理变更失败”。

## 真实运行边界

本轮修订不修改运行中的 H1 冻结源或旧成绩。最终候选必须继续由完整 H1 报告选择；四项目 CLI 从当前报告器导入精确 `VERSION`，严格接受对应最终报告，其他选择、模型/权重、profile、初始 actor、零更新与源码 guard 均保留。现报告器增加执行器暴露只读标注，不改变原 H1 的 R 或选择排序。

实际 resident 执行仍使用既有 CLI 和四槽生命周期；本次新增输出诊断不等同于已完成四项目真实模型评价。机制证据、人工 transport 控制和后续模型结果须分别报告，详见 [本轮实验记录](../experiments/retail-projects-v018.md)。
