# v0.35：把现有对数N规则绑定到原始软件经历

本轮不重写v0.30数值求解器。`experience_allocation_v035.py`负责真实窗口和原始成员动作的绑定、采后完整探测清单、有限差分C中心化及新学习器分派；求解仍调用[现有v0.30接口](experience-allocation-v030.md)。P2运行协议见[支持窗口协议](../experiments/software-support-v035-protocol.md)。

## 1. 采前支持门与采后坐标

支持重建复用`supports_from_entries`，不复用旧v0.27线性N求解。一个精确情境保留16个原始槽、两个稳定成员、min_class_count=2。按固定member_a→member_b顺序选择第一个有两类支持的块，其余材料继续基础权重1。无支持、单类、多类但频数不足、形式自由度已具备但梯度未验证分开报告；未知槽不补零或减少M。

| 方法 | 坐标与覆盖 | 不变部分 |
|---|---|---|
| B | 原支持b，Q=B | 所有基础份额、mask与分母 |
| G-raw | 每条合格原始成员分支一个坐标，均匀原始覆盖r | 同一原始合格支集，不从类别构造覆盖／N |
| I-P | 两个可靠工作类别，均匀类别覆盖r | 类内核为本窗冻结的均匀原始分支比例 |

G-raw与I-P在同一个先验声明的成员块配置。一般基线的数值调用仅接收原始分布、该坐标上的贡献、历史和约束，不接收类别或图。用于共同准入的支持事实不等于给G-raw传了语义覆盖先验。G-lift仍是另一个辅助规则，没有改名充当G-raw。

首窗历史h=b明确冻结到window／ξ／member／坐标系统及初始配置hash。没有实现历史转移，也不把初始化称为跨窗口学习。

## 2. 完整方向与真实贡献边界

`freeze_allocation_plan`只允许一个事前顺序选中的成员块，验证完整原始M、两类支持和不相交的贡献／确认根目标。全部Helmert正负方向在任何开发反馈前展开；对称半径先按TV=0.05确定，再受q/b盒限制缩小。共同B只列一次：

`1 + 2(n+ - 1) + 2(K - 1)`。

没有删原始成功支、挑方向、只探测“第一类”或按开发成绩调整预算的接口。若事前预算无法覆盖完整方向，冻结失败，不能默默截断。

`development_receipt`只是标准化已提供的更新后结果，不证明更新发生。实际运行器必须另行核对完整common／RNG恢复、真实完整窗口更新成功、更新后actor身份和随后贡献开发原件。P2监督器不调用贡献试训，本模块的合成CPU结果不充当模型C。

配对差值在全部预定开发单位上取固定权重平均，然后除以正负半径，重建完整单纯形切空间斜率g。实际传给求解器的是：

`C_a = g_a - sum_b(b_b * g_b)`，因而`sum_a b_a C_a = 0`。

G-raw调用`solve_g_raw`；I-P调用`solve_i_p`。两者继承对数N、历史／覆盖双KL和h中心TV约束。所有开发结果必须完整且已知才允许正式选择；None不是0，缺候选不能套用“贡献为零”。

当所有观测方向差值为0，记录“该面板未检出方向差”，不声称真实C必然为0。I-P仍可能因N和覆盖锚移动，按先验作用解释；均匀G-raw也可能出现约浮点精度的q偏移，因此分别记录精确权重hash相等、最大权重差和1e-12诊断，不把舍入放大成算法差异。

## 3. 原始目标与实际消费

`bind_candidate`与`bind_allocation`分别绑定试训和正式更新，包含完整原始entries、声明、records、支持、选权证据和物化权重。正式绑定重新执行冻结规则，不能仅接受调用者填的一份q。

`validate_allocation`按SharedActor准备的真实决策顺序返回actor权重，并逐项核对：

- 原slot、稳定成员、唯一call和实际response hash一致。
- input／output token IDs及loss mask与原本人MemberView一致，不能移交或复制别人的目标。
- actor分母保持`M×成员数×本人输出token数`，critic保持`M×成员数×本人决策数`。
- 原基础actor mask不可放宽；可信失败、未映射、低频及其他成员仍用1。

共享`online_training.validate_actor_composition`只增加v035验证器分派，原数值更新代码保留。`software_learning_v035`另负责重放冻结v034投影与原selected请求核对；actor目标始终取采样原token_trace，不能以重新渲染结果替换原历史。

## 4. 本轮控制与未取得的证据

新增合成CPU控制覆盖M／原始残余、不同支持状态、首块选择、完整原始方向及预算拒绝、共享B、C中心化、G-raw无语义覆盖、I-P对数N、开发未知拒绝、确认根目标隔离及新dispatch的本人token／分母校验。数值求解器原有14项控制不重复跑。

第一次新控制有3项通过、2项失败：未知状态过早交给需要episode路径的深入诊断，以及把浮点意义的均匀最优点误当成逐字节相等。只修对应边界／诊断并复核两个受影响控制；原失败历史保留，不能称为同源一次全套通过。

另由新学习适配器的极短tiny CPU模型控制实际采样与更新，验证新Γ去重后输入不再是纯消息子集、原行为概率一致、完整窗口反传及基础残余保留。它不是9B的新增技术资格、当前策略支持、贡献反馈或独立效用收益。

生产P3仍须等待真实P2窗口及采后精确计算清单。不同方法的正式更新从共同起点分别执行，试训不能累加；只有独立确认才报告I−B／I−G。当前模块和CPU控制不提供分配效果结论。
