## H0：有界兼容验收

每个角色有独立SDK Conversation。每次实际模型输出最多执行一个工具，执行器经唯一受管网关产生真实结果后暂停该角色，交还轮转调度。关闭SDK默认Bash、文件工具、子代理、MCP、隐藏critic/planner、自动补参数、摘要和重试。

首版支持：公开职责/合同，角色私有note/todo，仅检索本角色实际获取的局部历史，对已读JSON字符串叶的精确编辑，浏览固定提交及真实错误返回。notes/todos不进入正式世界状态，检索不产生新的资料读取凭据，机械元数据检查也不意味着模型已经在当次输入中看到它。文件版本、采用、发布、交接和复核仍由实际世界动作产生。

SDK事件全保留。实际模型请求采用公开的固定投影：system、最新本角色观察（含私有笔记/待办）和最近4个完整assistant/tool回合，丢弃记录可用显式历史工具查询。记录完整/选后请求SHA及消息索引；无后台语言模型摘要。SDK整理文本不能替代原backend token IDs/logp。基座、温度0.7、16,384上下文、2,048输出及原FP32/highest/LoRA范围保持，新增工具同样消耗角色决策预算。

CPU控制只覆盖真实SDK边界、角色隔离/暂停、实际WorldCore编辑、错误反馈及精确输出记录。随后在独立新开发情境中使用9B/GPU7做少量真实兼容交互，不称该模型已被原S1选中，不按成功重采。权重刷新后重建或清理SDK缓存并验证新调用身份，不混用旧窗口目标。

## H1：冻结的模型×harness开发比较

原S1完成后，使用两份已测可用的新候选（9B、27B）；若只有一个具有正常推理入口，明确收缩为单模型诊断，不补另一模型为0。仅比较native_v15与openhands_v16两个运行组合。

预算预案为2模型×2harness×6情境×2固定采样种子=48个episode；单模型为24。情境组成实现2、复核2、pair1、chain1。新素材来自另外12个客户、36张完整发票、164行，与原全部用途实体互斥，仍是同一UCI来源的开发用途。H0可以在这些开发情境上改进接口，因此H1不是未参与开发的泛化测试。

保持业务目标、初态、权限、实际工具后果、数值路线与角色预算一致；记录SDK组合加入的上下文/笔记/检索/编辑支持，不把组合效应归因于单一组件。主要看完整责任、真实依据使用、正确逻辑与执行、有据复核、具体反馈恢复和实际总成本。H1协议/源代码将在H0兼容通过后、H1首例采样前固定，失败不追加抽样。

27B需要三卡。新比较必须避开原执行图已声明的卡位；确认原线及实际占用后再安排，不驱逐其他项目、不暗改原并行lane。如果无法同时安排，显式登记串行调度及资源竞争，不伪称相同墙钟预算。
