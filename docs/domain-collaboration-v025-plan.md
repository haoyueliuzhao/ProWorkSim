# v0.25：当前联合支持与首个成员经验配置干预

依据[本轮审计](reference/audit-v024-next-v025.md)，v0.24按原有限范围保留，结束近期MC/RTG变体搜索。新目标是在真实当前支持内改变一个成员的有效方法组成，测量更新后工作差异；不要求基础RL先达到稳定高分，也不把支持不足称作ID-VTDO失败。

## 1. 固定起点和新增实现

共同起点明确选定v0.24 MC预定第二窗终态，包括actor、critic、两个optimizer、CPU/CUDA RNG和原学习计数（各2步）。这是依据已见开发结果选择的条件化起点，不是MC优势的独立复现。所有新分支从同一采样前完整状态恢复，不仅复制actor，也不在新支持稀少时更换旧checkpoint。

保持现有9B、native compact、函数式路径、存储/计算、EOS/采样、角色机会、terminal MC、终局奖励、原数值门和每成员实际自身token分母。LoRA与学习率不变。只新增完整工作有效性/Mapper接线、当前支持统计、actor成员条件化q/b，以及同起点有限贡献探测与正式配置。critic、优势、PPO比率、原始槽份额不重配。

新方法支持须同时满足记录、权限、依据、交付四项语义，且有当前目标模型完整可恢复的成员自身动作。复用既有独立业务谓词，不能仅以reward=1或completed替代有效性。可信失败、未映射和低频类保留原基础actor权重1；合法被拒动作不因ok=false删除。原始分母不按新权重和重新归一化。

## 2. 当前支持窗口和选择

新精确A、错误计数初稿B各8个固定seed重复，A/B交错，共16新episode。两个情境各占训练边际1/2；这一新边际与旧四类训练份额不同，不能直接与旧学习曲线相减归因。旧v0.24训练/评价轨迹不进入支持池。

A方法定义为主动合法交接／绑定实际信息请求的答复交接，两者须实际使用依据并正确固定交付。B定义为实现者自检后修复／有据反馈后修复，两者须从同一错误初稿完成合法正确固定交付及当前最终独立核准。读序、措辞、笔记及不同初稿质量不创造方法类别；歧义保持unmapped。采样前用真实世界程序路线证明同一初态、调度、权限及预算容纳两条路线，不把路线标签或步骤注入模型提示。

逐精确情境、成员统计M、各类n、合格n+、v=n+/M、b=n/n+；支持门为每类至少2条。程序准入后收窄的选择顺序固定为A实现者、A提供者；只选择第一个具备两类支持的块。B各成员本轮保持Q=B，仍记录完整有效性和实际方法支持，不开放B配置。A扰动方向预定主动交接类，不看开发成绩选块或选方向。B方法仍按自检／有据反馈记录，分类定义不因未获程序资格而造假。

采样前程序检查发现：A主动／请求绑定双路线通过，B自检路线通过，但B反馈修复在固定16384上下文、2048输出预留下仍未完成整个问题处理与复核链。开发期间仅对新训练B准备SQL作等义紧凑表示，保留原wrong_count缺陷和unique_customer测试，并纳入prepared_code_variant及新case指纹；未改harness、权限、grader或预算。该表示下仍未获B反馈完整路线资格，因此停止继续收缩材料，将可配置候选预先限定A；不把B反馈称作不可能或已通过。该变更发生在任何新模型采样前，全部比较分支共享最终catalog，失败程序记录保留。

若16例没有任何可配置块，则不启动重复探測：只执行一次基础更新、12例基础确认和2例新策略后继交互，总计最多30新episode；支持不足作为本窗口事实保留，不补采凑齐、不跨参数/情境拼池。

## 3. 探测、正式配置和独立确认

支持成立时，从同一完整起点、同一16条原始经历分别执行F0(Q=B)与Fε，仅一个选定成员块改为qε=b+0.1(delta_z−b)。q/b界固定[0.5,2]，非选定成员块保持B，残余经历保持1。每分支整窗一步，基础/探测/正式三次更新是三个独立状态上的步骤，不累加到同一策略。

两个试训端点各在6个新贡献开发情境（A/B/维护各2）各运行一次；完整职责均值差除ε得到有限差分Ĉ。开发案例、seed、初态按端点配对；开发结果仅用于预声明配置，不是独立确认。未知与无完整职责差均返回B，未知不当负贡献。

有已知非零开发差时，在选定二类块上采用一阶双KL锚：历史q0=b、覆盖r=支持内均匀、λh=λr=1、β=0（本轮不估计新颖度项），比例界[0.5,2]及TV(q,b)≤0.1。为使测得的方向导数与线性项一致，预定Cz=Ĉ/(1−bz)、另一类C=0；二类约束优化解在结果揭晓前冻结。不另拟合跨情境贡献模型。

配置改变才从共同采样前起点执行一次正式更新；不把探测参数累加，也不选探测checkpoint冒充正式配置。配置未变则跳过昂贵相同更新及重复配置端点评价，报告未干预。

另留6个完全新确认情境（A/B/维护各2，每情境2固定seed），F0与正式配置各12例。主量为配置−基础的完整职责配对均值差；按新交付、正确初稿核准、错误修复、维护分别报告。确认在配置决定封存后开始，其结果不参与选择；缺失不填零，完整主量不可算时保留未知和端点兼容界。

两个端点之后各自进入预定新A/B情境各1次，共4条后继rollout，只诊断新策略支持、不增加第二次优化。没有支持时仅基础端点执行；有支持但最终回到B时同样只保留基础端点。最大新采：16支持+12开发+24确认+4后继=56；最多3次16episode材料消费=48，不能按56/54推断比v0.24便宜。

## 4. 新预算与依赖停止

依据本轮执行请求及项目已有GPU授权，建立本轮独立上限**58 GPU小时**，不延用v0.24的36小时余额。此为可执行上限，不是预计一定消耗或完成保证。

| 阶段 | 新GPU小时上限 |
|---|---:|
| 当前16例支持采集 | 6 |
| F0、Fε、正式配置各一次整窗更新 | 每项12，共36 |
| F0、Fε开发6例 | 每项2.5，共5 |
| F0、正式配置确认12例 | 每项4.5，共9 |
| 两端点后继各2例 | 每项1，共2 |
| 合计 | 58 |

无支持时相关探测/配置阶段均不执行，上限降为23.5 GPU小时；有支持但配置不变时跳过正式更新、配置确认和配置后继。未用额度不自动增加样本或更新。

每episode最多20分钟；加载15分钟、边界10分钟；一次16例整窗更新最多11小时，阶段上限12小时包含加载/原概率门/保存。更新规模按v0.24实际token和反向成本放宽，不能沿用单episode时限。最多两张单卡A100并行、每分支单共享owner；可单卡顺序。GPU2–5优先、6及其他空闲卡随后，优先空卡，允许共享并记录竞争，不终止其他项目。训练入场空闲显存≥60GiB、自身≤56GiB；其他阶段入场≥40GiB、自身≤32GiB；host RSS合计≤64GiB、新产物≤32GiB；含等待墙钟≤72小时；外部API和外测GPU预算0。

复用现有监督器的资源、时限、失败和归档机制，只替换本实验依赖及预算，不建设新队列服务。原始可信失败保留；缺失/数值/资源失败不自动恢复或补采。不具备真实自由度、不具备可判定贡献、未真正改变配置与配置更新失败分别报告，不能统称算法比较完成。

## 5. 核验、报告和可声称范围

模型前仅做新增算法接线的必要CPU控制：真实四维有效性与四路线/反例；支持外拒绝与残余保持；显式Q=B恢复原loss与实际tiny更新；成员不串位、own-token分母不变、非均匀q/b改变真实梯度但critic不被重配；二类双KL和未知/零差停止。没有重复缓存/函数式大模型反向验收，没有换模型或扩大harness。

成功执行局部配置也只能称单块一阶ID-VTDO实验，不证明成员条件化优于统一调权、信息图优于一般元重加权、联合二阶项、跨来源迁移或总体效率。一般元重加权必须在后续强基线中获得相同开发信号与可比外层预算，不能据本轮独自宣称优胜。外部D2不阻断当前内部算法实验，也没有本轮新外测成绩。

结束后只读自动归档实际支持、配置选择、权重入梯度证据、独立确认、后继交互及全部成本；按已获授权提交并推送。运行源码/计划在模型前冻结，开发和确认材料分开。未知与未干预不造数、不以机制成立替代工作收益。
