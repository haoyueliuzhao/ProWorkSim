# v0.6 World Core：执行计划与验收协议

依据：[本轮审计](reference/multiproject-audit.md)。本计划在实现与正式实验前建立；开发中如发现协议缺口，将注明修订理由，不将计划计数冒充执行成绩。v0.5 继续作为冻结的单世界、单写者基线；本轮新增关系沿用其阶段回执、原子提交与有限恢复。

## 目标与顺序

| 阶段 | 交付 | 验收依据 |
| --- | --- | --- |
| G0 | 修复 E2 精确引用测量；独立预期与测量负对照 | 原检查点副本重投影；同样四条真实轨迹在新目录复验；保留旧 31/31 及其测量限制 |
| G1 | 独立世界规格、世界运行器、项目包、项目/世界/episode 生命周期 | M1 从零项目开始，装载 A/B、结束 A、继续 B、装载 C；非法包不留部分业务事实 |
| G2 | 世界对象注册、项目别名、可信项目会话、范围授权、动态产物与显式共享 | M2 正反成对权限/身份检查；M4 新文件与不同合法交付组织方式 |
| G3 | 当前/固定采用政策、局部需求变更、跨项目交错及有限恢复 | M3 定向影响；M5 旧回复、episode 边界和新增两类提交切点 |
| 接入合同 | 工作材料来源与证据状态 | 标记直接支持、工程重建、合成、未知；不虚构未观察的批准或返工 |

G0 的脚本工作、通用提交运行器提取、项目合同与作用域实现并行；新世界工具与集成由主任务负责。合同与运行器接口确定后，按 G1/G2/G3 集成，先目标测试再完整回归。正式实验统一在代码冻结提交上运行，文档归档另行提交。

## 实现边界

- 世界包含稳定身份、人员、受控 JSON 文件服务、全局对象注册、项目集合、逻辑时间、事件和历史；项目集合允许为空。
- 项目包只部署材料、参与者关系、局部授权、工作合同和已明确的事件。包不得隐式创建世界管理员或把局部权力扩到其他项目。
- 全局工作引用、对象身份、项目内别名与显示文件名分别存储。不同项目可以同名；模型工具不能通过自由填写 project_id 改变可信会话绑定。
- 共享精确版本与共享后续发布路线分开。读取共享成果不递归授予上游资料；已合法取得的信息不会因项目切换从人员观察历史中消失。
- 项目完成/归档只按声明合同停止其当前义务与局部待处理事件；对象、提交、确认及共享历史保留。世界可空闲后继续装载；episode 只记录选择的边界。
- 工作可选择需要审阅或交付即完成。内容错误可以合法提交并保留；制度许可与独立内容检查分开。
- 沿用 JSON 快照、不可变版本及单写者锁；不引入数据库、宿主 Shell、任意路径、分布式事务或额外故障类型。
- 当前两个冻结单项目适配器继续可独立复验；新世界核心不得继承经营状态或运行时默认假定金融对象存在。领域资料接入以 ProjectPackage 合同承担，不能将新世界变成套在多个旧 world 目录外的索引。

## 实验设计

每组使用新目录、固定初始身份与明确动作；检查直接事实和字节，另报告缓存及制度状态。预期由检查点合同显式给出，不能只判断“两边相等”。初轮失败与未执行分别保留。没有模型/API/GPU/训练要求。

### G0：测量修订

规范化目标、credential 和 attestation 的精确对象版本引用，并核验签发关联。独立检查：合法确认 true；缺登记 false；同对象错版本 false；签发关联错误 false；旧确认历史仍 true、对新需求适用性另判。原 22 个轨迹标记副本重算后，再运行原 2 条轨迹 × 2 模板；原协议 31 项与新增预期检查分开计数。测量负对照必须实际触发指定失败，不计导入/夹具异常为成功。

### M1：生命周期与包原子性

零项目世界创建世界材料；装载 A/B。A 完成/归档后，B 的未完成工作、待到消息和共享成果保持；同一世界装载 C。核对世界/主体身份、时钟连续、A 历史与共享对象、B 独立推进和 C 动态加入。至少一个含非法引用/授权的包整体拒绝；拒绝的交互记录可提交，业务状态和正式文件不能部分部署。

### M2：名称、职责与访问

A/B 同为 work-1、report.json。同一人员在 A 执行、B 审阅。成对检查同名对象不混淆、A 确认不适用于 B、B 审阅权不泄露 A、分享前拒绝/分享精确版后允许且不开放上游、同项目命令重试幂等与跨项目同文本键为独立命令、伪造上下文不扩权。保留人员真实阅读历史，不能把技术隔离解释为遗忘。

### M3：采用政策与定向影响

A 使用当前发布版，B 固定 v1。世界材料发布 v2 后分别检查关系、通知和文件字节；A 需重新查看/更新，B 的固定分析保持。局部 A 依据修订、交付受众修订与无共享对象编辑分别执行；B 的无关义务和共同模型字节保持。环境只改变关系或通知，工作人员显式行动才产生新交付版本；未知影响不自动判断内容错误。

### M4：运行中产物

合同指定产物角色/类型/要求，不列死文件名。对同一内容要求分别交付一份聚合 JSON 和两份分拆 JSON，另建中间草稿；真实创建、版本、引用与提交均需发生。负向检查跨项目覆盖、对象身份冒用和伪造确认。另保留可执行错误的实例：内容不足的合法提交保持正式历史，独立内容检查拒绝；交付即完成的工作不经过虚构经理审阅。

### M5：交错与恢复

A 等待回复期间 B 继续交付；A 要求修订后旧回复到达，不能满足 B 或新 A。结束 A 的 episode 不清空 B；同一人员切换后的正式操作仍绑定项目/义务。只针对新增共享发布，设置提交前与提交后未返回两个真实进程退出切点，与同一检查点的不中断对照比较项目注册、授权、别名、采用、历史观察、版本字节和重试正式效果。沿用 v0.5 仅排除 wall_seconds 与诊断 state_digests 的比较规范；不将该两例扩大为任意崩溃保证。

## 完成条件与报告

所有阶段要求逐项映射到实现、实验和证据；不能仅以总测试数作为完成依据。正式报告记录源提交/摘要、脚本摘要、执行/未执行分母、预期拒绝、开发期反例及修复、原始目录与精简证据。必要回归通过后，不重复无关实验。最后自动提交、推送并核对远端同步。

## 冻结前的检查计数与协议收口

正式代码冻结前，逐项断言已写入实验脚本：M1=13、M2=14、M3=10、M4=14、M5=8；新增恢复单列 2 个切点 ×8 项，共 16 项。G0 原 22 个快照副本重投影、9 个独立真值夹具、3 个测量层变异分别报告；真实四轨迹保留原 31 项关系检查，另加 22 项独立预期，不能混淆旧分母。

开发中修订了测量夹具：M2 的跨项目幂等正例明确使用同一主体、同一负载和同一文本键；先共享并采用 A 凭据后再检查 B 的不适用，避免仅测出“不可读”。delivery_only 断言检查 owner 与 decision_basis，不误把存储字段 review 的存在当成经理批准。M3 的共同模型实际分享并固定采用，不仅创建一个未使用对象。所有初轮输出保留；这些修订在正式执行前完成。

世界暂停／恢复、必须凭据的准入、对象范围提供者、future-project 预分享、两种归档政策以及显式 adopt_version 使用目标回归验证，不另扩充 M1–M5 的分母。完整旧经营 XLSX 模板自动部署和真实材料采集不在本轮验收范围。

## 归档核对后的有限补充

首轮正式 M3 只更换 requirements 中的依据引用，不能据此声称已经验证正式批准依据换版。保留其 10 项结果，另预声明 M3F 8 项检查：真实签发两版依据、A/B 实际提交批准、A 换版后新适用性、旧签发及旧批准保持、A 新义务待交付、B 局部事实保持、报告/共同模型及旧版本字节保持，以及独立副本分享/采用后对 B 仍不适用。只补这一要求，不重跑无关旧实验。

同时补齐项目观察中的公开交付合同、需求版本和可读别名，使绑定会话可直接取得行动所需要求；私有别名不展示。新增一项观察回归，并在最终冻结上复验受影响的 M1–M5 和两切点。G0/E2 不受此 WorldCore 观察字段变更影响，保留原冻结结果。补充提交与最初四任务提交在报告中分别标识。
