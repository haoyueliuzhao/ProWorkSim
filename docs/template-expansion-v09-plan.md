# v0.9 两模板与共同审阅关系：实施和实验计划

日期：2026-09-23。依据：[本轮审计](reference/template-expansion-audit.md)。v0.8基线为`5e2de883fd128716cd402f0c12a18f0f68d8a59d`；保持其有限持续工作结论，进入工作结构有区别的模板，不以增加旧来源消费状态组合为主线。

## 实施顺序和职责

1. 财务资料核对：两份有限记录表＋公开口径，检查并集覆盖、匹配键、单位换算、期间/定义/币种适用、真正冲突、缺失与歧义。领域字段不加入通用世界定义。
2. 研究报告审阅：实际正文与结构化claim同时核对，明确有限数字、期间、趋势及引用；开放文字质量未评。以实际固定提交为审阅对象，同一需求下withdraw/edit/resubmit修错。
3. 两模板需要的共享关系：精确问题位置、owner回应、有权主体处理确认。旧版完整源两项目的公开动作缺口证据先保存，再加入核心；不通过改需求模拟所有返工。
4. 分别通过公开会话后，同一世界连接A核对产物与B报告维护，控制器只作正常上游写入/发布，B从公开界面发现义务、读取及自主提出有限意见并修复。

财务领域、报告领域、拒绝归因与共同关系实验可并行准备；跨模板正式执行依赖双方公共合同与核心接口稳定。新schema `world-core-v0.9`、内容评价 `finite-products-v0.9`，不静默迁移旧世界。

## 最小共同关系合同

- `inspect_submission`公开查看真实固定提交，后续`read_object`读取确切版本。`raise_issue`须指向该提交内确切对象版本及实际存在的JSON位置，并已有真实读取；位置由文件适配层解释。
- 问题、回应、决定分别为追加的正式事实，独立key支持同负载幂等，不同负载冲突。权限按项目/工作节点/对象检查；字段不包含模板名称分支。
- 仅创建时针对当前待审提交的问题可约束同一工作/需求的批准。既有问题在重交后仍待处理；文件写入不会全部关闭问题。晚到旧版本意见保留为历史，不阻塞新的版本或新工作。
- 回应关联实际同工作提交；处理确认明确选择该问题、回应及决定，不能用另一问题或已过期的回应关闭当前问题。有依据反驳可以被接受；制度确认不是领域真值。
- 问题约束批准，不阻止本人撤回、局部修改和重新提交。资料获取条件继续用已有request/response语义，不将两种条件混为一体。

## 实验分组

| 组别 | 运行前要求 |
| --- | --- |
| X1 独立执行 | 两模板分别有正确完成、可恢复错误、合理不完备；策略只持tools/observe/call，保存真实返回 |
| X2 结构与合法变化 | 有限行序、别名、显示名、来源位置、综合/拆分文件及两种合法有限正文；比较独立真值，不只比较结果相同 |
| X3 同世界联动 | A更正一行，经自身义务和发布影响B；B真实读取、审阅和更新，固定历史工作及无关行/章节保持；区分A质量/B忠实性/B正文正确性/总体目标 |
| X4 共同关系与拒绝归因 | 两场景复用issue关系；逐项关闭、旧意见/旧回应隔离、幂等与错误负载、局部历史保持；仅增加一次处理决定提交后的真实进程终止切点 |

正式协议在运行前冻结各分支、检查命题与分母。纯领域测试使用手工有限真值；工作人员匹配/撰写与评价函数独立实现。少量负对照包含漏行、重复匹配、不可比强差、缺值置零，以及claim正确但正文错误。预期拒绝或未解决出口不是隐藏失败，也不算完整质量成功。

工具失败保留原始错误事实，另记录由实际校验边界声明的归因：策略参数/权限、业务约束、能力缺口、实现错误或未知。裸ValueError不根据文本猜测；旧pause情境实际拒绝仍成立，新版分类明确为业务约束。

## 冻结和归档

先保存开发失败和表达缺口；正式冻结后记录源码、脚本和测试起止摘要，再并行运行不同世界的模板矩阵、联动、相关v0.8机制回归及一次新恢复切点。旧JSON报告不改，不用新的细粒度身份倒填旧记录。只做与改动相关的必要回归与一次最终完整测试。

本轮以程序策略证明有限机制可操作，不预设恢复训练或GPU使用。模型公开界面试跑属于模板稳定后的独立研究阶段，不与规则机制结果混合。真实资料仍用于未来校准，未观察历史不补造。本轮完成后自动提交推送。
