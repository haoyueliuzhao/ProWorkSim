# v0.22：函数式梯度、公开工作合同与实际角色隔离

依据[用户本轮审计](reference/audit-v021-next-v022.md)。v0.21 原三线结果和六例分数保持；新实验不重判旧 issue、不重跑旧工作来回填原协议。只使用现有 Qwen3.5-9B 与 v0.20.1 存储/采样配置，不新增精度组合、模型或大型框架。

## 1. 本轮范围和资源

本次“参照审计修订并开展后续实验”结合项目既有 API/GPU 操作授权，建立新的有限资源账；不沿用已关闭的 v0.21 额度。用户随后明确要求尽快使用空闲 GPU、充分利用资源，因此允许准备就绪的 N1 与 W1 各一实例在不同卡并行，不要求彼此等待。

- N1最多1800设备秒，W1最多3600，条件式桥接B1最多1800；累计上限7200设备秒，即2GPU小时。并行时逐进程设备时间相加，不把墙钟时间当作总成本。
- GPU池2–5，6备用；启动时须无计算进程、空闲显存至少78000MiB、利用率≤5%，不终止或暂停其他项目。每线一张A100、一个模型实例；最大同时两个实例。B1仍是一个共享actor/optimizer顺序服务角色，不能变成双学习器。
- 每任务（一个N1请求、一个工作episode、完整更新）最多900秒，监督停止预留30秒。每线及各线合计观察RSS≤64GiB，自身NVML进程用量≤72GiB，新GPU实验产物总量≤8GiB；既有权重与数据不重复计入。
- 模型API调用0。N1/W1参数更新0；B1最多一次共享actor更新和配套一次critic更新。全部信号为零时如实零步，不人为制造参数变化。
- 每线只启动一次；真实失败、未知或资源停止保留，不重采、不换第三个实现、不花剩余额度搜索。独立的数值失败不阻断W1。B1必须等N1、公开工作协议CPU控制和最小训练投影通过相应资格，不以W1完成率或全部12例收口为门，144例始终不自动启动。
- 每条实际执行线独立冻结源码、计划和输入SHA，保留资源、进程和任务账。先就绪的线先执行，不为等待另一条线或长文档空置已就绪的实验。

## 2. N1：唯一函数式状态／重算候选

候选按decoder层重排同一因果依赖图；每层内保留完整prefill和逐token decode。卷积/recurrent状态及K/V显式传入并返回，无可变全局推理cache，无过去LoRA状态detach。层级non-reentrant checkpoint内固定完整prefill块及8-token decode块，head逐目标位置重算；固定这些粒度后再开封保留请求，不按结果调整。

CPU使用真实小型Qwen3.5＋PEFT，对照不checkpoint的完整函数式递归图、官方缓存teacher前向、固定有限差分，以及明确detach负对照。CPU值与梯度一致不能替代9B反向容量；默认checkpoint的形状检查也不是梯度证明。

实际请求在候选实现完成前已选定于[n1-heldout.json](../examples/id-vtdo-v22/n1-heldout.json)：旧8473＋146开发序列，加两个既有E记录中按长度客观选出的4251＋308、13275＋2048保留请求。它们未用于本候选修复选择，但仍来自既有开发来源，不冒充新的独立来源锁定测试。选择没有读取概率差或梯度结果；不新采样、不裁掉截断输出、不改原采样概率。

每请求均须原最大／平均logprob差≤0.02／0.002，再实际backward、检查有限梯度、完整目标及身份/零步。前向失败即终止候选；真实反向或资源失败也终止。通过后只将同一函数交给既有学习器，不更换基础PPO或组成权重。失败则记录明确候选决策，本轮不自动切mismatch路线。

## 3. W1：同合同、同预算的两种工作呈现

6个新同源开发情境×2臂：实现2、复核2、联合A/B各1。原始UCI新增完整发票/客户/原行组，排除既有v15各池和v16 harness使用实体，不把f0/f1/f2改名。新material manifest还单独预留4训练＋2桥接开发材料，不用于W1选择。

交付对象明确为当前固定供应材料的结果表，不追加通用管线隐藏测试。两臂共同公开复核合同：target为准确固定提交的result，locator为零基结果rows行或cell列路径，显式引用已读data和独立audit准确版本；结构示例不包含错误行、正确值或参考SQL。缺data仍是职责缺项，旧0.25不回改。

两臂仅比较本角色消息呈现：`original_history`保持原组织；`compact_work`对实际已有消息做确定性取舍，保留当前公开职责/状态、精确读取材料及配对工具调用、必要近期反馈。它不访问world/private数据/其他角色记忆，不代替正式采用，不自动提交或生成issue，移出的材料仍由原合法工具取得。

模型、实际工具、角色机会、业务判据、16,384总context、2,048单次输出及temperature0.7均相同。每情境两臂同一种子，按情境奇偶交错臂顺序，固定一次运行，不选较好样本。原角色机会每臂合计122；wait/done/格式失败仍消耗原机会。

除终态分项外，报告实际首次正确构建、固定提交、正式判断的时点及其剩余机会；对这类时点只读闭合历史，不自动执行业务动作。输出截断、上下文拒绝、真实工具拒绝、不可判定分别记录，不将重合事件相加为独立失败个数。两臂是不同Γ，改善若存在只能归于这个预先定义的呈现组合；12例只是开发比较。

## 4. X1：明确修订的D2角色执行隔离

只保留`proworksim-d2-quote-failclosed-v0.21`的评分修订基础，原官方失败与变体不混合。expected/grader留在可信评价空间；executor只得到brief和允许材料，verifier在自己的临时区验证，不能改被审workspace。选用现有合法rootless设施，不要求Docker，不提宿主权限。

## 5. 条件式最小训练投影与更新桥接

在任何B1模型样本开始之前修订阶段依赖：早先N冻结源的预案额外要求W1全12例结束，现按审计“数值与投影合格后桥接”及用户尽快用空闲卡的指示移除该串行等待。改为绑定N1完整资格、公开工作协议/来源/视图的已冻结字节、两臂CPU控制、W1不可变真实初始化身份，以及训练投影控制。compact选择、材料、种子、四次决策上限及7200设备秒总预算不变；不读取W1得分来决定桥接，不中断或重排W1十二例。N1释放后B1可与W1剩余部分并行，仍最多两个实例。

4个独立保留train片段覆盖实现、复核、A、B。显式训练准入必须连接真实TeamRollout/MemberView、实际请求token、本人全部生成输出、行为概率、actor/window身份、独立环境回报、角色终止与固定分母；改变model_training_eligible标志本身不构成准入。

准备前缀不记当前模型功劳，同事消息/工具返回不成为接收者标签，可信错误、部分成果与格式失败保留。非生成的本地context拒绝没有伪造输出。基础RL只依赖可信回报和自身完整轨迹，不以方法支持或V=true筛掉失败。工作有效性和ID-VTDO可重配资格另记，不能由分数反推。

B1事前选用compact_work（不是事后选W1最高分臂），沿用原terminal_mc基础PPO、一个actor与独立critic、固定4个slot×实际活跃成员×该成员全部输出token归一化，Q=B。数值候选对每个实际训练决策仍要经过原门；N1有限请求通过不豁免训练期检查。

本桥接的4个训练和2个后继开发均预先限定每个活跃成员4次决策机会；这是独立短片段Γ，实际policy身份和scenario记录该限制，原业务职责与部分回报定义不变。最多24次训练生成决策和16次后继开发生成决策；运行时末次无生成刷新／预算边界另记，不计新模型样本，不称完整W1任务预算，也不由这6片段估计工作能力收益。

四片段闭合后至多一次共享更新；参数真实改变则刷新身份、清缓存，再由该实际新策略执行两个新development联合片段。若零步则明确报告，后两例仍是该实际未变化策略的行为，不能写成更新收益。只有一次新组合接入验证，不估计学习效果，也不启动Contribution或144例主pilot。

## 6. 实测后的资源修订与同窗口恢复

原B1未在15分钟整窗更新预算内完成，按原监督停止，12/24反向的持久记录及失败成本保留。一次拟接管同一进程的资源修订因原进程已经结束被守卫拒绝，没有实际改变B1。不能将该尝试写成一次成功的连续执行。

在核实未到optimizer步骤、原pre-step快照完整且原四个rollout/admission可逐字段重建后，显式新增一次R1恢复。它重新加载同一θ0/critic/optimizer/RNG/窗口，不再采集四个train片段，也不改N1函数、PPO或部分奖励。此前丢失的梯度重新计算并计费；原B1失败不清除。

R1封顶2400设备秒，更新任务2100秒，其他任务900秒，仍留30秒停止余量。N1/W1/B1已花4117.379427433014秒，连同R1全部上限仍只有6517.379427433014秒，未突破7200秒总额；没有未记账的免费重算。至多一次最终actor/critic步和原先未开始的两例post，之后无自动后继。详见[资源修订与恢复依据](experiments/bridge-v022-resource-correction.md)。
