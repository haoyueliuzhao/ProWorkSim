# v0.24：同终局合同的MC／交接RTG在线对照

依据[本轮审计](reference/audit-v023-next-v024.md)，保留v0.23已结案的负向观察与五个缺失初评，不补跑以回填旧协议。本轮采用54个新内部运行、一个训练seed的小型基础RL对照，不换模型，不启用ID-VTDO，也不是v0.14旧MC/RTG的续跑。

## 固定研究问题与协议

共同fresh 9B/LoRA/critic/双optimizer初态；保留v0.22已验收函数式学习路径、v0.20.1存储/采样、native compact、工具/权限、角色机会、终局评分、actor LR1e-5/critic LR.001、epochs1、γ1、原概率门、6slot×实际成员×本人全部output token的分母。Q=B，没有按成败筛选或删除错误动作。

MC将全部终局R广播；Handoff-RTG仅将当前episode首次实际合法、适用依据送达的0.2在其事件序号结算，终点余项为R−0.2。重复交接不重复加分，准备前缀不记信用，若后续失效须保留负终点补差；无合格交接则只有终点R。事件位置只从当时前缀事实确定，不用终态正确性倒填时间。两个配方终局总回报相同，但随机成员token分母受未来行为影响，因此比较的是两个surrogate，不声称梯度无偏等价或仅方差不同。

新材料先按来源实体／完整发票／直接派生关系分用途，排除旧v15/v16/v22/v23。14个唯一新材料：共同第一训练窗4个；第二训练窗4个（两臂相同任务材料和seed、各自重新采样）；评价6个（2A/2B/2维护，维护一应变一无需改结果）。每采样窗仍为A/B/实现/复核/A/B共6槽，同窗A/B分别是真实同情境重复。质量及次序在模型前固定。

初态θ0、MC预定第二窗终态、RTG预定第二窗终态各评价同6情境×2seed=12例，按A/B/维护交错。主量是RTG−MC完整职责配对均值差；两者对θ0变化及结构分项为辅助。初评完整后才采集共同D0并启用分支，初评分数封存，不调参或换题；完整不等于成功。未知不填零或缩减分母，缺失时不给完整主点估计，并用已知端点给兼容界（非CI）。

新采样总数为6共同＋6MC第二窗＋6RTG第二窗＋36评价=54；共同D0被两个分支各消费一次，episode级训练消费24，不当作24条独立采集。D0来自本次实际θ0，不能替换为v0.23历史轨迹。原调用/episode/window ID保持；分支单独声明消费身份与credit配方。两个分支从同一完整actor/critic/两个optimizer/RNG快照恢复；先核对精确状态，之后仅改变credit_assignment。第二窗各自产生自己的on-policy数据，不交叉消费。

非业务可见标识使用预声明的确定性规则：相同情境、seed、历史和动作对应相同可见引用/宿主tool-call标识/回执hash；真实存储、episode、分支和审计身份仍独立。对象、版本、权限绝不合并。只在v0.24新运行中应用，旧记录不重写，不承诺GPU逐位确定性。正式模型前核对跨进程真实提示tokens和业务状态相等、不同对象/权限仍可区分。

## 新资源额度与停止

依据本轮执行请求及项目已有GPU授权建立独立上限36GPU小时：初态、MC终态、RTG终态评价各4.5小时；共同采集2.5小时；MC、RTG学习线各10小时（各两窗更新，其中首窗复用D0）。这些额度之和36小时，不复用v0.23余额。评价额度先保留，不按训练成绩挪用。两学习分支可在不同GPU并行，各自仅一个共享actor/optimizer；最多两个同时模型实例。

12评价槽×每episode20分钟=4小时，另预留30分钟加载/边界。每次完整更新独立5小时，不使用episode时限限制整窗。模型加载最多15分钟，普通保存/边界10分钟，监督留30秒退出。36小时是设备成本上限，不是完成保证；两臂实际反向消费仍有4个6槽窗口，不能按54/72同比承诺提速。v0.23实际训练16.77GPU小时是成本依据，不代表训练剂量充足。

GPU2–5优先、6备用、其他可用卡随后；训练入场free≥60GiB、自身上限56GiB，评价/采集free≥40GiB、自身上限32GiB；优先空卡，可共享并记录竞争，不停止他人进程。单模型与所有本项目模型合计host RSS≤64GiB；新产物≤24GiB。全部加载、核查、采样、反向、诊断、保存和失败都记账。模型网络API调用0。整轮含等卡墙钟最多48小时。

本轮不自动恢复中断、不补采失败或挑较好checkpoint。任何未知学习记录、同参数概率失败、数值/资源停止保持原件，受依赖影响的后继明确未执行。只有预定两窗均正常或合法零步闭合才发布该方法终态；一个分支停止不替代它的终态，也不阻断已获授权的另一分支。初评不完整则不启动共同训练/学习分支。

## 外部与收口

D2只窄修公开缺失值业务规则和verification分项，保留既有隔离与input-only限制。实际generator以−1表示缺失并按数值降序，所以缺失在正常0–100之后；审计中“之前”的方向描述需据源码纠正，不改generator。原六例/分数保留，旧seed作为开发资料。另留3新seed×θ0/MC/RTG=9例方案，本轮不启动、不分配外部GPU预算。

主学习/评价在冻结源码和计划下执行。结束后只读生成终态md/json，保留MC/RTG方法差、相对θ0变化、总回报守恒、交接前后目标/优势/真实动作、完整职责及成本。目标变小、loss变化、正优势减少、token概率改变不是工作收益。所有后续方法应共用同一选定基础配方，不能把credit改变混入q/b贡献。

新支持密度未建立：每ξ每策略最多2条，最低类频数2，最多1类达标。没有ID-VTDO组成自由度，不拼池不同任务、θ、配方或程序见证。基础RL不必显著为正才有资格研究ID-VTDO，但仍需真实有效方法支持、可信效用和共同起点干预。预算结束后不自动增加窗口或另一数值候选。
