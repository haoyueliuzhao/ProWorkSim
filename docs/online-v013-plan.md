# v0.13 共享模型直接在线学习与工作接口验证

2026-09-26，依据 [v0.12 审计](reference/online-learning-audit-v012.md)。历史基线 `94ab737a275d813cc016a4f019a4389174aae201` 的 D0–D3 失败、零支持和零更新保留。本计划及 JSON 在本轮真实模型生成前建立；源码冻结与结果另记实验报告。

## 顺序与预算

1. O0 定向修 critic 状态、公开引用 schema、实际参数刷新/概率。规则及 CPU 小模型只验证合同。真实模型用两组开发事实、旧/新接口共四段 provider 短任务配对，最多16次生成；同初始模型/种子/工作/时间协议，失败全留。新接口按角色缩减工具、去重复场景注册信息，保留真实工作合同/版本/权限/记录及原观察和投影依据。
2. O1 一份 Qwen2.5-7B-Instruct 基座、一份共享 q/v LoRA、一个 actor optimizer，独立 critic/optimizer。两窗，每窗四段（交接、合法前缀后 SQL 实现、实际正确/错误交付复核、完整链），最多36次生成/窗，共72次。固定槽不补采、不筛成功；更新后生成新窗。
3. O2 预登记八条新事实，分别冻结初始和最终检查点评测，各最多72次生成，无 learner 前向/反向。只用原定最终检查点，不依据锁定结果选模型。前三任务单岗位实例、chain 同权重团队分列。初始侧不是同总成本算法对照。
4. O3 每窗/精确 ξ/成员记录真实 M、V、映射、自身动作及支持。每 ξ 一槽、min_class_count=2；不跨 θ/ξ 凑支持。无支持保持 Q=B，不阻断基础 RL。
5. O4 待基础学习和当窗支持足够另立协议；本轮不宣称 ID-VTDO 收益。后续保留基础 MARL、共用成员权重、通用成员—轨迹元重加权、无信息依赖特征及同预算随机成员对等强对照。

## 冻结合同

[JSON 配置](../examples/online-work-v13/)显式使用 FP32、repeatKV/efficient attention、matmul_precision=highest，此为新 Γ，不改旧 v0.12。温度0.7，输出512，完整input+output8192，不裁剪；真实采样logp及更新前/梯度前向概率门保持max0.02/mean0.002 nat，越界停止，不调宽。LoRA r8/alpha16/q,v/dropout0；actor lr1e-5、critic lr1e-3，整窗一次 PPO 累积，clip0.2、gamma1、MC advantage、无标准化、entropy/KL0、梯度裁剪1。详见[训练实现](online-learning-v013.md)。

critic最后层零初始化，无已学习非零回报且全零真实回报时，actor零步；同值正奖励可更新。全部自身输出按固定slot1/N、活动role1/K、成员总输出token归一；未知材料mask、不重新分配份额。基础RL不要求V=true、多方法或旧D0通过。

岗位生成限provider4/implementer8/reviewer6。固定轮转，一个岗位停止不取消别人的机会；每圈外部时钟固定前进一步，只处理已安排送达，明确记录，不提供业务答案。额外无生成预算检查可记录最后工具反馈。期限是声明的有限任务终点（bootstrap0/无后续继续），不是自然工作完成。真实工具schema拒绝允许看到反馈并继续。

前缀是真实操作、单独归档，episode从准备后开始，不能算目标动作或当前奖励。奖励按确切版本/责任的一次成果，不按批准/消息/工具次数加分；短任务通过不是完整链成功。回报、四维三值V、组成支持分开。

全体仅一个构造 SQL 来源家族，均属development；内部train/dev/locked及新数值不是独立来源划分。本轮固定split_a布局，不宣称布局/四项目关系迁移。接回四项目与加入独立来源仍为后续工作。
